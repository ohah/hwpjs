# WASM 배포 산출물

웹용 WASM은 debug 최적화 모드에서 디버그 정보를 보존하고, safe/fast/small 모드에서는 strip을 켭니다. 이는 배포에 불필요한 DWARF 정보를 줄이는 설정이며 safe의 런타임 안전 검사를 비활성화하지 않습니다. native 모듈의 strip 설정은 변경하지 않습니다.

컴파일 설정을 바꾼 산출물은 export 이름이 같다는 이유만으로 실행 코드가 바이트 단위로 같다고 판단하지 않습니다. `tools/wasm-runtime-parity.mjs`는 DWARF와 선택적인 name 섹션만 제외하고 나머지 섹션을 순서와 payload까지 비교합니다. `stripWasmDebug`는 이 비교를 통과한 경우에만 기존 모듈에서 디버그 섹션을 제거합니다. 그 외 custom 섹션과 원본 버퍼는 보존합니다.

모듈 다운로드/컴파일 비용과 문서 파싱·조판 비용은 분리해 측정합니다. 첫 문서를 열기 전에 준비했는지, 같은 모듈을 다시 받았는지, 압축 전/전송 바이트와 캐시 조건도 기록합니다. 파일을 연 후의 시간만으로 초기 화면의 전체 비용이나 다른 기기에서의 속도를 비교하지 않습니다.

## 공개 0.1.0 크기와 후처리 후보

공개 `@ohah/hwpjs@0.1.0`의 WASM은 6,758,420바이트이며 SHA256은 `82031994b4b7f066c28c725495954eebc67bb25570869c06528ea328e0155ccc`입니다. 이 산출물에는 이미 custom/debug 섹션이 없습니다. 코드 섹션이 약 96.48%이므로 추가 debug 제거로 크기가 줄어들지는 않습니다.

Binaryen 132.0.0의 `wasm-opt -Oz --enable-bulk-memory --enable-sign-ext --enable-nontrapping-float-to-int` 후처리 후보는 5,847,288바이트로 911,132바이트(약 13.48%) 줄었습니다. 후보 SHA256은 `42c45c77db7920ff5670fedd0d5f16f730049dfb0087c6347f0bbe532263d17a`입니다. 원본 ReleaseSafe 산출물을 입력으로 사용했으며 런타임 안전 검사를 끄는 컴파일 옵션이나 trap 무시 옵션을 추가하지 않았습니다. Binaryen은 개발용 변환 도구이며 런타임 의존성으로 포함하지 않습니다.

후처리는 실행 코드도 변경하므로 위의 바이트 단위 runtime parity와 동일한 검증으로 취급하지 않습니다. export·import·메모리 계약, 실제 HWP5/HWPX 읽기·편집·저장 출력과 실패 동작을 별도로 대조해야 합니다. 알려진 엔진 해시를 사용하는 Worker·브라우저 경로도 별도 검증 대상입니다. 이 후보는 공개 npm·웹 데모에 적용되지 않았으며, 현재 배포본을 더 작은 후보로 교체했다는 뜻이 아닙니다.

npm 전체 크기와 WASM 크기도 구분합니다. 실제 레지스트리 tarball 기준 `0.1.0-rc.10`은 다운로드 17,243,878바이트·압축 해제 45,527,626바이트이고, `0.1.0`은 각각 3,346,605바이트·13,394,725바이트입니다. 전체 패키지는 약 80.59%·70.58% 줄었지만 WASM 단독은 기존 910,710바이트보다 커졌습니다. 두 버전은 엔진 구성과 공개 API가 달라 단순히 언어 교체의 효과로 해석하지 않습니다.

실제 이전 tarball의 압축 해제 구성에는 React Native 정적 라이브러리 27,599,086바이트, 글꼴 디렉터리 10,416,799바이트, NAPI 모듈 6,308,320바이트가 포함되어 있었습니다. 현재 패키지는 이와 같은 RN 기기별 사전 빌드와 글꼴 묶음을 포함하지 않으므로 전체 크기 감소를 기능이 같은 엔진의 순수 최적화로 설명하지 않습니다. RN에서 필요한 네이티브 통합과 검증은 별도 범위입니다.

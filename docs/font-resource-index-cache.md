# 글꼴 인덱스 후보 검증 기록

## 판정

2026-11-02 검증한 글꼴 인덱스 재사용 후보 r7은 채택하지 않았다. 정합성 검사는 통과했지만, 운영 버전과의 비교에서 입력·연속 실행 취소 후 응답 시간이 줄었다는 근거를 확보하지 못했다. 이 문서는 미채택 후보의 실험 기록이며 활성 기능·조판 동치·전체 O(N) 지원을 뜻하지 않는다. 제품 코드·정규 시험·CI·운영 데모·Pages 번들은 변경하지 않았다.

## 기능과 작업량

소스 검사는 순수 글꼴10·기존 HWP5/HWPX metadata6·고정 SDK05 Native1로 나누어 총17개가 통과했다. 별도 관측 경계4는 Fake binding을 쓰는 소스 모형이며 Native 성과로 합산하지 않는다. 선택한 제품·시험·고정핀12개 파일의 lint/format 검사도 통과했다.

실제 브라우저 시나리오4는 HWP5의40입력·40연속취소 후 즉시 재입력, HWPX의8입력·8취소 후 재입력, 각 포맷의 원본 복원 후 저장·재열기다. 텍스트·선택·현재 커서와 포커스를 확인했고 소유 브라우저 프로세스는 각 실행 후 종료했다. 저장 검사는 모든 편집을 취소한 원본 바이트의 저장·재열기이며 편집된 문서 전체의 저장 동치나 Canvas 픽셀 동치를 주장하지 않는다.

HWP5 기능 시나리오에서는 인덱스를1회 만든 뒤22회 재사용했고 추가 생성과 그래프 순회는0이었다. 글꼴 이름·참조·metadata 인덱스만 공유하며 언어별 탐색 커서는 공유하지 않았다. metadata alias, 현재 Native 증거·문서·lease·readonly 배열 identity, raw/custom 환경의 기존 경로, 단일 슬롯과 논리 단위 예산을 검사했다. 이 작업량 감소는 지연 개선과 별도 결과다.

## 속도 비교

A는 운영 actual65, B는 r7 후보이며 같은 SDK05·Worker·WASM과 Noori HWP5 입력을 사용했다. 디버거·프로파일러·캐시 통계 계측을 끈 새 브라우저에서 A-B-B-A 순서로 실행했다.

| 순서 | 버전 | 입력 시작부터 최종 상태 관측까지(ms) |
| --- | --- | ---: |
| 1 | A | 1111.396667 |
| 2 | B | 1115.107167 |
| 3 | B | 1138.926791 |
| 4 | A | 1101.409917 |

네 실행 모두40입력·40연속취소·즉시 재입력의 최종 상태 검사와 종료 검사를 통과했다. 두 짝의 B/A 차이는 각각+0.334%, +3.406%이며 각 버전 n=2의 중앙값 비율은+1.863%다. 사전 판정 기준인 두 짝 모두 개선을 충족하지 못했다. CDP 키 전달·DOM 관측 비용과 외부 CPU 부하가 포함된 제한 측정이며, 개별 키 지연·초기 파일 열기·일반 성능·통계적 유의성이나 외부 부하의 인과를 단정하지 않는다. 이전 후보나 기능 계측 표본은 합산하지 않았다.

## 후속 조사와 근거

미채택 B6 후보의 복원 경로 비용을 운영 버전의 원인으로 추정하지 않기 위해 actual65 자체의 메인 CPU 프로파일을 별도 수집했다. served JavaScript의 self 표본 상위에는 문단 캐시 lookup(가중59.977ms)과 FlowKeyBudget 키 순회(29.597ms)가 있었다. lookup에는 범위·서명 검사와 hit 분기의 structuredClone이 함께 있으므로 함수 전체 비용을 복제만의 비용으로 읽지 않는다. 단일 프로파일은 호출 횟수나 A/B 시간 비교가 아니며 Worker 비용을 측정하지 않았다.

다음 조사는 기존 문단 캐시와 후보의 복사·키 구축 책임을 구분하고, 원시 입력 관측·독립 반환값·현재 권위·undo/저장 계약을 보존하면서 반복 작업을 줄일 수 있는지 확인하는 것이다. 증분 scheduler와 표/페이지 배치 전체의 구현 완료로 해석하지 않는다.

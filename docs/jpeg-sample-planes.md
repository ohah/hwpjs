# JPEG 성분 평면 조립 작업

성분 평면 조립과 아래 범위의 검증을 구현했습니다. 출력은 원래 샘플링 해상도의 성분 평면이며 RGB 이미지가 아닙니다.

색 해석을 위한 후속 [JFIF 헤더 작업](jpeg-jfif.md)은 별도 계약과 검증 기록으로 관리합니다.

## 근거와 책임

[T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) A.1.1의 성분 크기는 `ceil(X * Hi / Hmax)`, `ceil(Y * Vi / Vmax)`입니다. 최대 샘플링 인수는 선택한 스캔이 아니라 프레임 전체에서 얻습니다. A.2.2의 단일 성분 스캔은 샘플링 인수와 무관하게 MCU당 한 블록이고, A.2.3의 interleaved MCU에는 끝 영역의 패딩 블록이 포함될 수 있습니다.

- `component_geometry.zig`: 파싱된 프레임·해결된 DNL 높이로 실제 성분 크기, 단일 성분 블록 격자, interleaved MCU 격자와 블록의 유효 영역을 계산합니다. 입력 메타데이터를 빌리며 할당하지 않습니다. 샘플링 최대값·올림 계산의 단일 출처입니다.
- `mcu_layout.zig`: 기존 스캔 성분 순서·블록 위치를 계속 소유하며 크기 계산은 위 모듈에 위임합니다.
- `sample_planes.zig`: 기존 sequential 프레임 디코더와 역양자화·IDCT·샘플 복원을 조립합니다. 프레임 선언 순서의 u16 평면을 할당하고 블록의 유효 샘플만 복사합니다. 전체 패딩 블록도 엔트로피 디코더에서는 소비하지만 출력에 배치하지 않습니다.

`decode(allocator, bytes, options)`는 EOI까지 스캔 커버리지와 마지막 엔트로피 패딩을 확인한 경우에만 `Image`를 반환합니다. 실패하면 그 호출에서 할당한 모든 평면을 해제합니다. 성공 결과는 입력을 빌리지 않으며 `Image.deinit(allocator)`로 해제합니다. 부분적으로 초기화된 평면은 외부에 반환하지 않습니다. 중복·누락 스캔과 블록 순서는 기존 프레임/스캔 디코더가 검사하며 별도 구현하지 않습니다.

`max_samples`는 프레임 픽셀 수가 아니라 모든 성분의 실제 샘플 개수 합계입니다. 평면 할당 전에 합계를 확인하며 u16 저장 바이트의 usize 범위도 검사합니다. 프레임 바이트·픽셀·스캔·블록 제한은 기존 디코더 옵션으로 별도 적용합니다. 정밀도는 결과에 보존하고 성분 ID를 색상 의미로 추측하지 않습니다.

각 평면은 기존 `FrameComponent` 값도 복사하여 소유합니다. ID·원래 H/V sampling 바이트·Q destination을 보존하고 H/V 해석은 기존 접근자를 재사용합니다. Q destination은 프레임의 원래 선택자이며 이전 양자화 테이블의 값을 보존한다는 뜻은 아닙니다. 같은 1×1 평면이라도 H/V가 3×1, 1×2, 1×1일 수 있어, 성분 크기만으로 샘플링 인수를 추정하지 않습니다.

## 현재 검증

- 가로·세로 AC 위치 검사와 원래 샘플링 보존 검사를 포함한 Debug JPEG 네이티브 83/83개가 통과했습니다. 수정 후 전체 회귀 결과는 아래에 기록합니다.
- 16가지 H/V 조합과 너비 1~65,535를 순회하여 실제 성분 크기와 단일 성분 블록 격자를 독립 정수 수식으로 대조했습니다. 높이는 `65536 - width`, 프레임 최대 H/V는 4로 설정하여 올림과 최대 치수를 검사했습니다.
- 너비·높이 1~65의 모든 조합에서 블록 유효 영역 합이 실제 샘플 수와 일치하고, 바깥 블록과 u32 최댓값 좌표가 null인지 확인했습니다.
- 1×1 성분 3개의 스캔 순서를 프레임 순서와 다르게 구성하고, 서로 다른 샘플 값과 ID가 정확한 평면에 들어가는지 확인했습니다. 모든 할당 실패 지점, 샘플 합계 한도 초과, 마지막 패딩 오류의 메모리 정리와 입력 버퍼 수명 독립성을 검사했습니다.

## WASM 독립 평면 대조

테스트 전용 mode 260은 u32 샘플 합계 한도와 JPEG 바이트를 입력으로 받습니다. 출력은 width/height/precision/성분 수의 u32 헤더와, 각 평면의 u32 ID/sampling/Q destination/width/height 및 row-major u16 샘플입니다. 제품 API에는 연결하지 않았습니다.

`tests/hwp5/jpeg-planes.mjs`는 독립 프레임·역양자화·IDCT 수식으로 블록을 만들고, 실제 평면의 각 샘플 좌표에서 해당 블록/블록 내부 위치를 찾아 기대 출력을 만듭니다. 제품의 clipped row 복사와 다른 순회이며 mode 259의 출력을 기대값으로 사용하지 않습니다.

- Debug 합성 비교 914건·한도 거부 2건 통과. 폭/높이의 블록 경계, 서로 다른 최대 H/V, 단일/혼합 스캔, 모든 유효 2성분 샘플링 조합, 스캔 재정렬, restart/DNL/Q 재정의를 포함합니다.
- 실제 HWP sequential JPEG 참조 7건의 19개 성분 평면, 샘플 총 1,237,819개가 정확히 일치했습니다. 같은 이미지를 여러 문서가 참조하므로 고유 이미지 수와 다릅니다. Progressive 참조는 보류합니다.
- `reference/rhwp/samples/s1.jpg`의 3개 평면·74,784샘플도 일치했습니다. 블록 패딩을 포함한 76,608샘플과 혼동하지 않습니다.
- 기존 mode 254의 비교 196건·거부 166건도 통과했습니다. 새 평면 비교는 정규 audit와 실파일 컨테이너 검사에 연결했습니다.
- 단색 DC 블록만으로 검출할 수 없는 행/열 위치 오류를 위해 가로·세로 주파수 1의 AC 블록을 추가했습니다. 정확한 8개 샘플 패턴을 모든 행·열에 대조하여 두 방향을 구분합니다.

## 적대적 검증

다음 업샘플링 단계 관점의 리뷰에서 초기 결과가 원래 H/V 인수를 보존하지 않는 누락을 발견해 수정했습니다. 입력을 지운 뒤에도 동일 크기 1×1의 세 평면이 서로 다른 sampling 값을 유지하는 네이티브 검사를 추가했습니다. 실행 중이던 전체 audit는 중단했으며 수정 후 처음부터 재실행했습니다. 수정된 메타데이터를 포함해 Debug 합성 914건·실제 HWP 1,237,819샘플·별도 JPEG 74,784샘플 대조를 다시 통과했습니다.

Debug의 17×17·3성분·역순 스캔·Q 재정의 입력에서 헤더/평면 메타데이터/모든 샘플을 포함한 출력 978바이트 각각에 XOR 1을 적용하여 전부 검출했습니다. 일부 첫 샘플만 비교하는 검사가 아닙니다.

별도 소스 복사본 `/tmp/hwpjs-planes-mutants.1RQ1vf/`에서 올림을 내림으로 바꾸기, 블록 내부 행 뒤집기, 마지막 디코더 오류 무시의 3종을 메타데이터 수정 후 세 모드에서 다시 검출했습니다. 모두 컴파일 후 실행 단계의 실패입니다. 올림 누락 변형은 Debug/ReleaseSafe에서 앞선 기대값 검사들이 실패한 뒤, 존재해야 하는 clipped 영역이 null이라 검사 코드가 중단되었습니다. ReleaseFast에서는 83개 중 13개가 실패했습니다. 행 뒤집힘은 새 AC 위치 테스트가 각 모드 1개 실패했고, 마지막 오류 무시도 기대 오류 테스트가 각 모드 1개 실패했습니다. 후자의 Debug/ReleaseSafe에서는 예상 밖 성공 결과를 기대 오류 검사기가 해제하지 않아 추가 누수 진단도 발생했습니다. 정규 소스의 성공·메모리 정리 검사와는 별도의 의도적 결함 검출 기록입니다.

수정본 ReleaseSafe/ReleaseFast 독립 WASM에서도 각각 합성 914건·한도 거부 2건, 실제 HWP 1,237,819샘플·별도 JPEG 74,784샘플, 출력 978바이트 개별 변조 검사를 다시 통과했습니다. 기존 프레임 비교 196건·거부 166건도 통과했습니다.

수정본 Debug/ReleaseSafe/ReleaseFast 전체 audit는 각각 20/20 단계, 네이티브 799/799개, 총 7,517,016건 검사로 통과했습니다. 로그는 `/tmp/hwpjs-planes-{Debug,ReleaseSafe,ReleaseFast}-audit.log`에 있습니다. 전체 회귀 합계이며 전체 문서 지원 완료나 한글과의 렌더링 동일성을 뜻하지 않습니다.

이 평면 작업의 완료는 progressive 복호화·제품 HWP 이미지 지원 연결을 대신하지 않습니다. 이후 [업샘플링](jpeg-upsampling.md)·[색 변환](jpeg-jfif-colour.md)·[JFIF RGB 조립](jpeg-rgb.md)의 계약과 실측은 각 주제 문서에서 관리합니다.

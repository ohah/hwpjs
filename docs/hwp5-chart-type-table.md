# 차트 타입 목록과 재등장

## 계약과 소유권

`chart/type_table.zig`는 호출자가 정한 한 차트 직렬화 범위의 타입 목록을 소유합니다. init 시 할당자와 한도를 받으며 deinit이 이름 사본과 해시 테이블을 해제합니다. 하나의 전역 목록을 문서 사이에 공유하지 않습니다.

readObserved16은 호출자가 null이 아닌 타입 참조 위치로 확정한 곳에서 u32 ID를 읽습니다. 처음 등장한 ID이면 [관측 타입 선언](hwp5-chart-type-declaration.md)을 읽고 이름을 복사해 등록합니다. 이미 등록된 ID이면 네 바이트만 소비하고 같은 이름/버전을 반환합니다. 반환 Reference의 introduced가 둘을 구분합니다. 이름 슬라이스는 입력이나 해시 테이블 슬롯을 빌리지 않고, 이 Table의 수명 동안 유효합니다.

객체 ID, null 참조, 객체 데이터 경계, 저장 타입 ID의 특별한 값이나 모든 버전의 직렬화 규칙을 판별하는 함수가 아닙니다. u32 키를 희소 해시로 저장하며 ID를 배열 크기로 사용하지 않습니다. 원본 이름에 임의 인코딩/정규화를 적용하지 않습니다. 중복 ID 뒤의 바이트를 새로운 선언으로 읽거나 기존 정의를 덮어쓰지 않습니다. 그 뒤 바이트가 올바른 객체 데이터인지는 소비자 책임입니다.

## 한도와 실패

max_types, max_name_bytes, max_total_name_bytes를 구분합니다. 재등장한 ID에는 이름을 다시 할당하거나 누적 이름 바이트를 더하지 않습니다. 새로운 선언의 이름 한도는 개별 한도와 남은 전체 한도 중 작은 값입니다. 실패하면 Reader 위치, 논리적 등록 내용과 name_bytes가 유지됩니다. 이름 복사 후 맵 삽입이 실패해도 해당 사본을 해제합니다. 타입 참조의 호출 횟수/객체 개수 한도는 이를 순회하는 상위 계층의 책임입니다.

## 실제 표본과 구성 실험의 구분

동일한 43개 관측 표본에서 타입 참조 위치 40/60/79/96/119의 ID는 0/1/2/3/4, 선언 이름은 VtChart/VtDataGrid/VtMatrix/VtCollection/VtObject였습니다. 선언 이후 위치는 56/79/96/117/136, 버전은 6/1/1/1/1입니다. 이름 바이트 합계는 NUL 포함 50입니다. 이 고정 위치는 조사된 표본의 기대값이며 제품 함수에 들어 있지 않습니다.

WASM 실험은 해당 위치를 두 번씩 읽고, 순서를 바꿔도 같은 ID의 정의가 재사용되는지 확인합니다. 두 번째 참조는 원본 바이트의 ID 위치를 재사용한 구성 실험이지 실제 객체 그래프에서 다음 참조 위치를 찾아낸 결과가 아닙니다. 특히 상속 타입과 일반 객체의 바깥 헤더를 같은 방식으로 자동 순회했다고 주장하지 않습니다.

## 초기 검증

네이티브는 희소·최대 u32 ID, 범위별 목록 분리, 원본 변경 후 이름 유지, 재등장 시 네 바이트 소비, 32개 타입으로 맵 확장 후 이름 수명, OOM 시 커서/등록/집계 보존, 모든 짧은 선언, 각각의 한도와 잘못된 이름을 검사합니다. 초기 4개 필터 테스트 이후 독립 한도 테스트를 추가했고 최종 Debug/ReleaseSafe/ReleaseFast는 각각 root 포함 5/5 통과했습니다. 정상·한도 오류를 포함한 실행 후 명시적 allocator 잔량도 0이며 모든 OOM 주입을 검사했습니다.

비공개 mode 309는 타입 수/개별 이름/전체 이름 한도 u32 세 개, 참조 수 u16, 각 offset u32, 원본 바이트를 받습니다. 별도 limit 인자는 참조 수를 제한합니다. 출력은 등록 타입 수와 이름 바이트 합계 u32 뒤 각 ID/introduced/소비 후 offset/이름 길이 u32·버전 u16·이름 바이트입니다. 10개 참조의 표본 보고서는 288바이트입니다. 공개 JS API는 바꾸지 않습니다.

세 모드 실제 WASM에서 각각 정상 86건·오류 258건을 통과했습니다. 개별 한도/누적 한도/참조 수, 뒤쪽 선언의 잘림·잘못된 NUL, 오류 후 원본 복구를 검사했습니다. 반환 288바이트의 각 바이트를 개별 XOR 1 한 응답도 각 모드 288/288 검출했습니다. LimitExceeded를 같은 메시지의 WebAssembly.RuntimeError로 바꿔도 정상 오류로 세지 않고 assertion 실패했습니다.

별도 `/tmp/hwpjs-chart-table-mutants.swniug` 소스 복사본에서 재등장 조회 생략(repeat), 누적 이름 한도에서 기존 소비량을 빼지 않음(total), ID 읽기 직후 원본 커서 갱신(atomic), 이름 해제 생략(leak)을 검사했습니다. 네 변형 모두 세 모드에서 실제 테스트 실패·종료 코드 1로 검출했습니다. repeat는 기존 ID 재사용에서 LimitExceeded, total은 필요한 LimitExceeded 누락, atomic은 커서 0 대신 4, leak는 OOM 주입에서 MemoryLeakDetected로 실패했습니다. 절대 소스 경로를 사용했고 컴파일 오류를 검출 성공으로 세지 않았습니다. 제품 소스는 변형하지 않았습니다.

소스·테스트를 고정해 Debug → ReleaseSafe → ReleaseFast 전체 audit를 순차 실행했습니다. `/tmp/hwpjs-chart-type-table-{Debug,ReleaseSafe,ReleaseFast}-audit.log`에서 각 모드 27/27 단계·997/997 네이티브 테스트·HWP/WASM 7,844,366회 검사 통과와 종료 코드 0을 확인했습니다. 포맷·JS 구문·공백과 문서 로컬 링크 17개 검사도 통과했습니다. 이 결과는 타입 목록의 검증이며 전체 객체 그래프나 데이터 해석 완료가 아닙니다.

최종 `zig build test --summary all`은 5/5 단계·997/997 테스트, `zig build -Doptimize=ReleaseSafe --summary all`은 5/5 단계로 통과했습니다(종료 코드 0).

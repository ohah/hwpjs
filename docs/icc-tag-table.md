# ICC 태그 테이블·저장 배치

기준은 [ICC v2 §6.2~6.3](https://www.color.org/specification/ICC.1-2001-04.pdf)와 [ICC v4 §7.3~7.4](https://www.color.org/specifications/ICC.1-2022-05.pdf)입니다. 현재는 테이블 경계·공통 태그 접두사와 선택한 저장 배치를 검사합니다. 헤더 의미·필수 태그·개별 타입 내용·등록 여부 검증은 미완료입니다.

## 책임과 수명

- `tag_table.zig`는 기존 extent 검사 후 태그 수와 테이블 길이를 확인하고 원래 순서의 descriptor 배열을 소유합니다. 입력 한도는 기본 64 MiB, 태그 수 한도는 100,000이며 조정할 수 있습니다.
- `tag.zig`는 12바이트 테이블 항목, 테이블 뒤의 4바이트 정렬 offset, 입력 안의 전체 data 범위, 최소 8바이트 타입 접두사와 그 예약 바이트를 검사합니다. 알려지지 않은 타입 서명도 원값을 보존하며 내용을 해석한 것으로 표시하지 않습니다.
- 서명 중복과 저장 순서는 임시 index 배열을 정렬해 검사합니다. 원래 descriptor 순서는 바뀌지 않습니다. 서로 다른 서명의 동일 offset/size 공유는 보존합니다.
- `tag_layout.zig`는 저장 배치 정책을 소유합니다. 추가 데이터 복사 없이 경계를 순회합니다. 정렬을 포함해 O(n log n) 시간·O(n) 추가 공간이며 원시 payload 크기에 비례하는 복사본을 만들지 않습니다.
- Table.deinit은 descriptor만 해제합니다. Tag.data는 원본 프로파일 버퍼를 빌리므로 Table을 사용하는 동안 원본을 유지해야 합니다.

## 명시적인 배치 정책

호출자는 `Options.policy`를 반드시 선택합니다. 버전 번호에 따라 조용히 약한 정책으로 fallback하지 않습니다.

`bounded`는 경계·정렬·중복 서명·타입 접두사를 검사하되, 배치의 겹침/빈 공간을 보고만 합니다. `layout_validated=false`이며 구버전 명세 전체와 호환된다는 인증은 아닙니다. `overlapping_elements`는 완전 공유를 제외하고 앞선 범위의 합집합과 겹치는 요소 수입니다(겹침 쌍 수가 아님). `unreferenced_bytes`에는 테이블 뒤에서 참조되지 않는 패딩·빈 공간·후미 바이트가 포함됩니다.

`icc_2022`는 최신 명세의 연속 배치와 마지막 요소까지의 0 패딩을 요구합니다. 같은 offset/size의 완전 공유 외 겹침, 테이블 직후/요소 사이/파일 끝의 불필요한 빈 공간을 거부합니다. 각 data size는 패딩을 제외하며 패딩은 따로 검사합니다. 성공하면 `layout_validated=true`이고 `unreferenced_bytes`는 검사한 패딩 바이트 수입니다. 이것 역시 개별 타입의 내용이나 유효한 색상 프로파일 인증은 아닙니다.

태그 0개·132바이트 입력은 테이블 구조만으로는 통과할 수 있습니다. 프로파일 종류별 필수 태그 검사가 별도로 필요합니다. PNG에서 어떤 revision에 어떤 배치 정책을 적용할지는 해당 명세 확인과 실파일 비교 후 연결할 예정입니다.

## 적대적 검증

네이티브 테스트는 뒤섞인 순서, 완전 공유, 동일 시작점의 다른 길이, 부분 겹침, 선행/후미 빈 공간, 0/비영 패딩, 중복 서명, offset·size·count 경계, 예약 바이트, 입력·태그 한도, 모든 할당 실패 지점 정리를 검사합니다.

추가로 작은 offset/length 격자의 모든 유효 범위 조합을 생성하고, 독립적인 바이트 점유 배열로 빈 공간·공유·겹침과 엄격 정책의 허용 여부를 대조합니다. 정상 접두사 조합 960건과 접두사 충돌 거부 336건이라는 정확한 검사 개수도 단언합니다. 기대값 계산에는 제품의 정렬·구간 순회 함수를 사용하지 않습니다. 합성 구조 입력이므로 실제 유효 ICC 프로파일 검증과 구분합니다.

재검토에서 마지막 패딩 잘림, 파일 끝의 불필요한 저장 공간, 정렬된 범위 밖 offset 분기의 직접 테스트가 부족해 보강했습니다. 패딩 각 위치와 예약 영역 네 바이트의 모든 비영 값도 검사합니다.

# ICC 파라메트릭 곡선 전체 정의역 검사

## 계약과 미완료 경계

[ICC.1:2022 §10.18 Table 68](https://www.color.org/specifications/ICC.1-2022-05.pdf)은 함수 0~4의 분기와 [0,1] 정의역을 지정하며 파라미터에 따라 복소수나 정의되지 않는 결과가 생길 수 있음을 설명합니다. `parametric_domain`은 역변환의 선행 조건인 전체 실수 정의역을 검사합니다. 검증 통과가 단조성·연속성·비상수·역변환 가능성의 증명은 아닙니다. 이 모듈은 점 평가기와 원시 파서를 변경하지 않으며, 기존 파싱/점 평가 성공을 전체 곡선 검증 성공으로 승격하지 않습니다.

`powerDomain`은 활성 거듭제곱 구간 [start,1]과 원본 signed 16.16 a/b/g를 반환합니다. type0은 전체 구간이며 a=65536,b=0입니다. type1/2는 −b/a를 i64 분수로 구하고 a=0이면 UndefinedIccCurveThreshold입니다. type3/4는 d/65536을 사용합니다. start가 0 이하면 0으로 제한하고 1 초과이면 거듭제곱 분기가 없어 null을 반환합니다. start=1은 닫힌 한 점 구간으로 보존합니다. i32 최소값은 i64로 확장한 후 부호를 바꿔 오버플로를 피합니다. 나머지 분기의 상수/선형 함수는 유한한 고정소수점 계수로 전체 활성 구간에서 실수로 정의됩니다.

`validate`는 활성 구간 양 끝의 affine 밑 부호를 정확한 정수로 검사합니다. 비정수 지수에서 음수 밑이 존재하거나, 비양수 지수에서 밑 0이 존재하면 UndefinedIccCurvePower입니다. 0^0 거부는 기존 curve_math의 명시적 계산 정책이며 명세가 정한 숫자 결과라고 주장하지 않습니다. 양의 정수 지수의 음수 밑과 내부 영점은 허용하고, 음의 정수 지수도 영점이 없는 음수 밑 구간에서는 허용합니다. 비활성 거듭제곱 파라미터는 평가하지 않습니다.

s15Fixed16 지수의 약분된 분모는 2의 거듭제곱이므로 비정수 지수의 분모는 짝수입니다. 따라서 음수 밑에서 정수 지수만 허용하는 조건은 1/3처럼 홀수 분모의 유리수 지수를 부당하게 제외하는 경우가 없습니다. 해당 지수는 이 wire 형식으로 정확히 표현되지 않습니다.

start 분자·분모는 최대 2^31이며 affine 시작점의 분자 크기는 2^63 이하, 끝점은 i64에 들어갑니다. 구현은 시작점에 i128을 사용하고 모든 비교에 부동소수점·샘플 격자·허용 오차를 사용하지 않습니다. 할당하지 않고 입력을 수정하거나 빌린 포인터를 반환하지 않습니다. 실제 거듭제곱 계산·단조성·평탄/점프 구간의 역상 선택·파라메트릭 역함수와 TRC/행렬 연결은 후속 작업입니다.

## 검증 기록

첫 네이티브 및 Debug 감사 빌드는 부호 있는 i32에 `%`를 사용한 문법 오류로 실패했습니다. Zig의 `@rem`으로 수정했으며 실패 실행은 통과 근거로 사용하지 않습니다.

네이티브 검사는 type0의 0/음수 지수, 구간 내부의 극점·음수 밑, 양의 정수 지수의 영점 통과, 비활성 분기, x=1만 활성인 분기, a=0, 음수 a와 i32 극값의 정확한 분기 분수를 포함합니다.

WASM mode179는 para payload를 파싱한 뒤 전체 정의역을 검증하고 32바이트 결과를 반환합니다. 활성 구간이 없으면 모두 0이며, 있으면 u32 LE 존재 플래그, u64 LE start 분자·분모, i32 LE a/b/g입니다. 독립 JS 기준은 구간 끝점·분기점·밑의 근을 임계점으로 열거하여 점별 정의 조건을 적용합니다. 제품의 양 끝 부호 교차 조건을 그대로 복사하지 않습니다. 모든 함수와 양/음/0/비정수 지수·계수 극값·정의역 안팎 분기점을 조합하고 잘림·한도·실패 후 정상 호출을 검사합니다. 전체 감사의 결과는 완료 후 기록합니다.

수정된 Debug WASM 직접 실행은 비교 3,537건·예상 오류 거부 1,731건으로 통과했습니다. 시스템 ICC 프로파일 5개(DCI(P3) RGB, Display P3, ITU-2020, ITU-709, ROMM RGB)의 para TRC 태그 15개(type0 3개, type3 12개)를 읽기 전용으로 검사했습니다. 모두 전체 정의역 검사를 통과했고 반환된 시작 분수와 지수가 원본 필드와 일치했습니다. type1/2/4의 실파일 근거는 아니며 공유 데이터의 고유 개수를 뜻하지 않습니다. 파일을 복사·수정하지 않았고 수동 검사 수는 정규 감사 수에 합산하지 않습니다.

적대적 실측에서 type3의 raw 파라미터 [-65536,49,-1,0,0]을 사용했습니다. 기존 점 평가에 x=i/1024(i=0..1024)를 넣은 1,025건은 모두 유한한 결과였지만 새 전체 검사는 정확한 x=1/49의 극점을 찾아 UndefinedIccCurvePower로 거부했습니다. 점 평가기의 버그라는 뜻이 아니라, 유한 격자의 성공을 전체 정의역의 유효성으로 확대하면 놓치는 사례입니다. 이 수동 결과는 자동 감사 수에 합산하지 않습니다.

최종 테스트 검토에서 음의 비정수 지수와 지수 필드의 i32 최솟값·최댓값 조합이 부족함을 확인해 정규 WASM 조합에 추가했습니다. 확장된 직접 실행은 비교 5,262건·오류 거부 4,381건으로 통과했습니다. 앞선 전체 Debug 감사는 확장 전 테스트를 읽었으므로 최신 테스트의 전체 감사 근거로 사용하지 않고 재실행합니다. 제품 코드는 이 테스트 확장으로 변경하지 않았습니다.

확장 전 Debug 감사 `/tmp/hwpjs-icc-parametric-domain-Debug-final.log`는 종료 코드 0, 20/20 단계·485/485·WASM 5,689,055건으로 통과했습니다. 확장된 ReleaseSafe 감사 `/tmp/hwpjs-icc-parametric-domain-ReleaseSafe-final.log`는 종료 코드 0, 20/20 단계·485/485·WASM 5,693,430건과 신규 비교 5,262건·거부 4,381건으로 통과했습니다. 나머지 최신 모드의 완료는 후속 기록으로 남깁니다.

확장된 ReleaseFast 감사 `/tmp/hwpjs-icc-parametric-domain-ReleaseFast-final.log`도 종료 코드 0, 20/20 단계·485/485·WASM 5,693,430건으로 통과했습니다. 신규 비교 5,262건·거부 4,381건도 일치했습니다. 최신 Debug 감사는 `-Debug-expanded.log`로 별도 실행합니다.

최신 Debug 감사 `/tmp/hwpjs-icc-parametric-domain-Debug-expanded.log`도 종료 코드 0, 20/20 단계·485/485·WASM 5,693,430건, 신규 비교 5,262건·오류 거부 4,381건으로 통과했습니다. 확장된 테스트를 세 모드 모두 확인했으며 위 진행 중 표현은 실행 당시 기록입니다.

최종 적대적 검토에서는 닫힌 활성 구간과 x=1의 한 점 분기, 비활성 분기의 미평가, 음수 a의 정확한 임계값, 양/음/0 지수와 실수 밑 조건, i32 최소값의 부호 확장, probe 한도·빌린 입력·출력 메모리 경계를 재검토했습니다. 추가 결함은 발견하지 못했습니다. 구간 결정은 powerDomain을 validate와 probe가 재사용하며 원시 파서·점 평가·전체 정의역 검증의 책임을 구분합니다. 포맷·변경 JS 문법·diff 공백·문서 로컬 링크 3개 검사도 통과했습니다. 전체 문서·ICC 역변환 완료를 뜻하지 않습니다.

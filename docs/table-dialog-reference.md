공식 참조는 [웹한글 기안기 공개 데모](https://webhwpctrl.cloud.hancom.com/webhwpctrl/)입니다. 2026-11-06 격리 headless Chrome의 1280×633 viewport에서 정상 UI로 빈 2×2 표를 만들고 조사했습니다. 업로드·로그인·쿠키 조회·저장·전송은 하지 않았습니다. 아래 값은 이 빈 문서·셀 내부 커서 문맥의 관측이며 모든 문서의 공통 기본값을 뜻하지 않습니다. HwpCtrl API로 보이지 않는 필드를 추정하지 않았습니다.

## 셀 테두리/배경

증거 `15-border-dialog`, `16-background-dialog`, `17-diagonal-dialog`, `18-background-color`, `19-border-custom-controls.json`.

표 메뉴에는 별도 `셀 테두리/배경` 하위 메뉴가 있습니다. 셀 내부 커서에서는 `각 셀마다 적용`으로 열었으며 `하나의 셀처럼 적용`은 비활성입니다. 창은 574×429 CSS px, 탭은 `테두리`·`배경`·`대각선`입니다. 오른쪽 세로 버튼은 `확인`→`취소`→간격→`적용` 순서입니다. `확인`의 의미와 `적용` 후 이력·저장 결과는 이번 읽기 조사에서 실행 검증하지 않았습니다.

테두리 탭은 `테두리` 그룹의 `종류`(선 모양 스와치: 실선), `굵기`(0.12mm), `색`(검정 #000000), 아래 `적용 위치` 아이콘으로 구성됩니다. 아이콘의 DOM title은 순서대로 `모든 테두리`, `바깥쪽`, `안쪽 모두`, `위쪽`, `아래쪽`, `왼쪽`, `오른쪽`, `안쪽 가로`, `안쪽 세로`입니다. 단일 셀 문맥에서 모든 테두리·안쪽 모두·안쪽 가로·안쪽 세로는 disabled class이며 나머지는 활성입니다. 드롭다운 내부의 모든 옵션 명칭·범위는 확인하지 못했으므로 열거하지 않습니다.

배경 탭의 `채우기` 그룹은 `색 채우기 없음` 라디오가 선택되고 `색` 라디오는 미선택입니다. `면 색`, `무늬 색`, `무늬 모양`은 처음 비활성입니다. `색`을 선택하면 이 세 항목이 활성화되는 것을 확인했습니다. 당시 화면에서는 면 색이 흰색, 무늬 모양이 빈 스와치로 보였으며 비활성 무늬 색의 정확한 RGB는 확정하지 않았습니다. 아래 후속 조사에서 활성 컨트롤의 실제 DOM 값을 별도로 확인했습니다.

`그림` 체크박스는 미체크입니다. 아래 그림 파일 `그림 없음`, 파일 선택, 채우기 유형 `크기에 맞추어`, 그림 효과 `효과 없음`, 밝기0%, 대비0%, 워터마크 효과 미체크가 표시되며 그림 관련 입력은 비활성입니다. 파일 선택과 업로드를 실행하지 않았습니다.

대각선 탭은 역방향/정방향 대각선과 중심선의 아이콘 집합이며 각각 첫 `없음` 모양이 선택되어 있습니다. 대각선 값의 저장·다중 선택 동작은 미관측입니다.

기본 대각선의 후속 구현·저장 계약과 검증 범위는 [원본 셀의 기본 대각선](table-cell-diagonal.md)을 따릅니다. 아래 채우기 후보의 두 탭·대각선 미지원 설명은 그 당시 이력이며, 새 `cellDiagonalAvailable` 엔진의 현재 범위로 읽지 않습니다.

## 과거 R4 후보 UI와 소스 검증 범위

통합 후보는 `table-cell-appearance-port/tool/view.ts`와 전용 CSS가 소유합니다. 표 메뉴/문맥 메뉴의 진입점 연결은 데모 controller·명령 registry가 소유합니다. 지원하는 테두리/배경 두 탭만 표시하며 단색 배경은 현재 셀에 제한합니다. 기존 독립 배경/테두리 구현은 호환 회귀 대상으로 보존합니다.

원본 선택 port가 발급한 lease의 WeakMap 연결과 공통 mutation admission을 재사용하며, 두 탭의 변경은 하나의 `cell-appearance` 요청으로 정규화합니다. 줄/칸 범위는 1부터 시작하는 양끝 포함 입력에서 planner의 0부터 시작하는 끝 제외 구간으로 변환합니다. `적용`은 응답 뒤 선택 복원과 재관측을 거쳐 같은 원본 셀의 새 lease를 얻은 경우에만 같은 창을 유지합니다. `확인`은 적용 뒤 닫으며, 변경이 없는 확인은 명령을 보내지 않습니다. 갱신 필요 응답·불확실한 응답·재관측 실패에서는 창을 닫고 자동 재시도하지 않습니다. Native 거부 메시지는 pending 해제 뒤에도 유지합니다.

검증 로그는 위 ignored reference 폴더에 둡니다. 최종 신규 세 진입점은 44pass·0fail·0skip, 기존 배경/테두리/크기 아홉 진입점은 136pass·0fail·0skip입니다. 별도 표 만들기 두 Bun 진입점은 27pass·0fail입니다. 신규 자체 검토는 초기38개, 선택·토큰·입력 변경 반례를 추가한43개, 거부 메시지 유지 회귀를 추가한 최종44개를 구분하며 중복 합산하지 않습니다. 선택 파일의 strict TypeScript·lint·format도 통과했습니다. CSS preload는 정확히 명시한 스타일의 JavaScript 평가만 생략합니다.

이 결과는 소스 계약·DOM 대역·SDK 명령 대역 증거입니다. 실제 Native의 원자 저장/undo/redo·제품 브라우저 배치/입력·배포 성공을 뜻하지 않습니다. 해당 단계와 독립 적대적 검토는 전체 후보의 별도 gate로 유지합니다.

## 과거 R4 최종 후보의 실제 화면

2026-11-06 R4 후보의 원본 Noori HWP5/HWPX에서 실제 셀 선택·통합 창 진입·테두리/배경 원자 적용·창 유지·변경 없는 확인·한 번의 실행 취소를 통과했다. 네 대화상자 관측은1280×633 viewport에서660×570 CSS px이었고, 보이는 label/control 겹침0 및 테두리 탭의 실제 포커스를 확인했다. 화면이 낮으면 본문은 내부 스크롤을 사용한다. 이는 공식의574×429 창과 픽셀 단위 동치를 뜻하지 않으며, 미지원 필드·대각선·무늬/그림 채우기는 계속 차이로 남는다. 모바일/다른 viewport나 실제 OS IME를 검증했다고 확대하지 않는다.

`integration/r3-browser-80138/`의 네 dialog PNG·geometry JSON과 `integration/R4-FINAL-AGGREGATE.json`을 근거로 한다. 새 문서6개는 다른 실행이므로 표2개와 같은 브라우저 실행의8개 성공으로 기록하지 않는다. 최종 세션은 모두 `active=false`, `pid=null`, 재조회한 소유 잔류0이었다.

## 공식 paired export와 현재 패턴 codec

[공식 HWP5 명세 revision 1.3](https://cdn.hancom.com/link/docs/한글문서파일형식_5.0_revision1.3.pdf)의 표29(PDF 0기반27쪽, 인쇄23쪽)는 무늬 값을1~6으로 기술합니다. 처음에는 이 표를 현재 원본의 직접 ordinal로 적용했지만, 아래의 공식 생산/가져오기 반례 때문에 그 가정을 철회했습니다. 이전 observer60/73 통과는 그 당시 가정의 source cohort로 보존하며 현재 호환성의 근거로 사용하지 않습니다. 미리보기의 drawing raw enum과 TABLE BorderFill raw codec도 서로 승계하지 않습니다.

후속 허가는 **자체 생성한 빈2×2 문서**만 공개 API로 내보내고 재입력하도록 제한했습니다. 앞선 읽기 전용/no-save 조사와 별도 cohort입니다. 공개 `GetTextFile("HWP", "", callback)`와 `SaveAs(..., "HWPX", "", callback)`로 저장했고 API가 반환한 같은 origin의 자체 download URL만 읽었습니다. 원본·SHA·정상 UI 선택 PNG/DOM·Python olefile/struct/zlib/ZIP/XML 독립 해석은 ignored `zig-out/verification/table-cell-fill-dialog-r1/pattern-oracle/` 및 `pattern-version-oracle/`의 HANDOFF/RAW-RESULTS/SUMMARY에 있습니다. 사용자 문서·로그인·쿠키 조회·외부 공유는 사용하지 않았습니다.

| 실제 공식 UI 선택 | HWP5 참조 BorderFill raw | 같은 문서 HWPX winBrush.hatchStyle |
| ----------------- | ------------------------ | ---------------------------------- |
| 수평선            | 0                        | HORIZONTAL                         |
| 수직선            | 1                        | VERTICAL                           |
| 하향 대각선       | 2                        | SLASH                              |
| 상향 대각선       | 3                        | BACK_SLASH                         |
| 눈금 무늬         | 4                        | CROSS                              |
| 체크 무늬         | 5                        | CROSS_DIAGONAL                     |

공식 문서의 첫 셀은 HWP5 list header와 HWPX tc의 참조 ID를 통해 해당 리소스까지 확인했습니다. 현재 TABLE codec은 이 paired export를 근거로 `js/hwp5-hatch-style.mjs`의 명시0~5 매핑을 사용합니다. raw -1은 단색 경로이고 raw6 등 미입증 값은 지원 값으로 재해석하지 않습니다. Native 내부 enum의 BACK_SLASH/SLASH 순서와 저장 raw2/3의 의미는 별도의 명시 codec으로 변환하며 배열 ordinal을 공유하지 않습니다.

버전 조사는 같은 자체 원본의 FileHeader 버전4바이트만 5.0.1.7·5.0.3.0으로 바꾸고 원본5.1.0.1과 함께 공개 `SetTextFile`로 입력했습니다. 모든 다른 stream의 바이트와 원본 SHA 불변을 확인했습니다. 세 입력 모두 현재 공식 importer에서 수평선 스와치로 읽혔으며 HWPX는 HORIZONTAL, 재출력 HWP5 raw는0이었습니다. **재출력 header는 모두5.1.0.1로 정상화됐습니다.** 입력 header와 출력 header를 구분하며, 이 결과를 역사적 생산 프로그램 전체 또는 실제 과거 파일 corpus의 일반 법칙으로 확대하지 않습니다. 초기 CSS 로딩 실패 화면은 rejected visual cohort로 보존하고 정상 재로딩 후 PNG만 UI 근거로 사용했습니다.

공식 선택 라벨·드롭다운 스와치·저장 raw/XML·본문 raster는 서로 다른 증거입니다. raw2를 적용한 본문은 `swatch-3-selected.png`, raw3 본문은 `swatch-4-selected.png` 뒤에 있지만 대화상자에 거의 가려져 있습니다. 실제 셀의 대각선 픽셀 방향은 **미검증**입니다. 선택기 스와치나 recording Canvas 호출을 공식 본문 raster 동치로 주장하지 않습니다.

## 새 capability의 소스·Native 검증 경계

현재 Native·wire·원자 변경·대기 편집값 조회와 sparse border 계약은 [원본 셀 테두리·채우기 배치](table-cell-fill-batches.md)를 단일 출처로 둡니다. 이 문서는 공식 UI/API 비교와 관측 증거를 소유합니다. 과거 R4 단색 전용 절은 새 capability의 제약으로 읽지 않습니다.

선형 그라데이션 시작/끝 자동 표시는 파생 stops가 아니라 검증된 원본 `fill.colors`가 정확히2개일 때만 수행합니다. 원본2색이4개 stops로 파생돼도 색을 잃지 않으며, 원본 색이 더 많거나 확인되지 않았으면 양 끝을 잘라 현재값으로 표시하지 않습니다. 동일한 view의 적용 후 실제 recapture에서는 새 token과 관측값을 사용하고 현재 배경 탭을 유지합니다.

검증 증거는 합산하지 않습니다.

- 공식 UI/API oracle: 위 별도 원본/PNG/DOM/독립 파서 및 header-only 입력3종입니다. 제품 기능·저장 성공 증거가 아닙니다.
- Native source gate: 기본 HWP5 12개·HWPX 12개·wire 12개와 pending hatch 전경 보존 반례 수정 후 HWP5 13개는 [배치 검증 기록](table-cell-fill-batches.md#검증과-제한)을 따릅니다. 13개에 앞선 12개를 다시 합산하지 않습니다. 재현 실패와 수정 성공, 새 shipping WASM 재승인 및 실제 SDK/브라우저 실행은 별도 cohort입니다.
- 소스 관측/UI: main formatter 후 observer91 및 UI/port/tool65가 통과했습니다. UI65에는 관측 기본값/dirty 분리, 범위·표 전체6조합, sparse 색만 변경, 실제 controller/view의 새 token 재관측·탭 유지가 포함됩니다. 기존 배경/테두리/셀 속성136 회귀와 구분합니다.
- HWP5 TABLE painter: focused `table-border-fill-plan` 3개와 `table-variant-fill-plan` 34개, 총37개가 통과했습니다. 기대 무늬는 공식 paired export의 독립 literal이며, 비대칭 BGR 색·red/blue stop 배열·Canvas 호출 인자도 독립 기대값으로 검사합니다. 그림·비영 alpha·미해석 꼬리·복합 fill·custom positions는 계속 거부합니다. 공통 선형 painter는 angle/stops를 소비하는 근사이며 centerX/Y까지 원본과 픽셀 동치라고 주장하지 않습니다. 기존 drawing 매핑은 이 TABLE 변경에서 수정하지 않았습니다.

아래 최종 후보 검증 절은 source gate 이후의 실제 Native·SDK·브라우저 결과를 별도로 기록합니다. 배포·CI·공개 live 검증은 배송 기록을 따릅니다.

## 최종 후보 검증 (2026-11-07)

현재 배치·조회·wire 계약과 Native 검증의 단일 출처는 [원본 셀 테두리·채우기 배치](table-cell-fill-batches.md)입니다. pending hatch 전경 보존 반례 수정 후 HWP5 집중13개와 shipping WASM3의 실제 Node24.20.0 단면17개가 통과했습니다.

# 공식 웹한글 표 대화상자 관측과 데모 UI

공식 참조는 [웹한글 기안기 공개 데모](https://webhwpctrl.cloud.hancom.com/webhwpctrl/)입니다. 2026-11-06 격리 headless Chrome의 1280×633 viewport에서 정상 UI로 빈 2×2 표를 만들고 조사했습니다. 업로드·로그인·쿠키 조회·저장·전송은 하지 않았습니다. 아래 값은 이 빈 문서·셀 내부 커서 문맥의 관측이며 모든 문서의 공통 기본값을 뜻하지 않습니다. HwpCtrl API로 보이지 않는 필드를 추정하지 않았습니다.

원시 증거는 ignored `zig-out/verification/table-range-new-document-r1/reference/`의 번호별 PNG·접근성 `snapshot.txt`·가시 DOM `dom.json`입니다. 프레임 상대 좌표와 화면 최상단 35px 헤더를 구분합니다. 중간 브라우저 초기화 뒤 빈 화면이 찍힌 `08`~`10`은 `rejected-blank`로 분리했으며 근거로 사용하지 않습니다. `07`, `11`~`18`, `22`가 유효한 대화상자/메뉴 증거입니다. 세션은 8분 이내 종료했고 최종 소유 상태는 `browser-status.json`의 `active=false, pid=null, own=0`입니다.

## 셀 테두리/배경

증거 `15-border-dialog`, `16-background-dialog`, `17-diagonal-dialog`, `18-background-color`, `19-border-custom-controls.json`.

표 메뉴에는 별도 `셀 테두리/배경` 하위 메뉴가 있습니다. 셀 내부 커서에서는 `각 셀마다 적용`으로 열었으며 `하나의 셀처럼 적용`은 비활성입니다. 창은 574×429 CSS px, 탭은 `테두리`·`배경`·`대각선`입니다. 오른쪽 세로 버튼은 `확인`→`취소`→간격→`적용` 순서입니다. `확인`의 의미와 `적용` 후 이력·저장 결과는 이번 읽기 조사에서 실행 검증하지 않았습니다.

테두리 탭은 `테두리` 그룹의 `종류`(선 모양 스와치: 실선), `굵기`(0.12mm), `색`(검정 #000000), 아래 `적용 위치` 아이콘으로 구성됩니다. 아이콘의 DOM title은 순서대로 `모든 테두리`, `바깥쪽`, `안쪽 모두`, `위쪽`, `아래쪽`, `왼쪽`, `오른쪽`, `안쪽 가로`, `안쪽 세로`입니다. 단일 셀 문맥에서 모든 테두리·안쪽 모두·안쪽 가로·안쪽 세로는 disabled class이며 나머지는 활성입니다. 드롭다운 내부의 모든 옵션 명칭·범위는 확인하지 못했으므로 열거하지 않습니다.

배경 탭의 `채우기` 그룹은 `색 채우기 없음` 라디오가 선택되고 `색` 라디오는 미선택입니다. `면 색`, `무늬 색`, `무늬 모양`은 처음 비활성입니다. `색`을 선택하면 이 세 항목이 활성화되는 것을 확인했습니다. 면색은 흰색 스와치, 무늬색은 검정 스와치, 무늬 모양은 빈 스와치로 보입니다. 이 값은 화면 스와치 관측이며 원본 리소스 값을 독립 저장 검증한 것은 아닙니다.

`그림` 체크박스는 미체크입니다. 아래 그림 파일 `그림 없음`, 파일 선택, 채우기 유형 `크기에 맞추어`, 그림 효과 `효과 없음`, 밝기0%, 대비0%, 워터마크 효과 미체크가 표시되며 그림 관련 입력은 비활성입니다. 파일 선택과 업로드를 실행하지 않았습니다.

대각선 탭은 역방향/정방향 대각선과 중심선의 아이콘 집합이며 각각 첫 `없음` 모양이 선택되어 있습니다. 대각선 값의 저장·다중 선택 동작은 미관측입니다.

## 후보 UI와 소스 검증 범위

통합 후보는 `table-cell-appearance-port/tool/view.ts`와 전용 CSS가 소유합니다. 표 메뉴/문맥 메뉴의 진입점 연결은 데모 controller·명령 registry가 소유합니다. 지원하는 테두리/배경 두 탭만 표시하며 단색 배경은 현재 셀에 제한합니다. 기존 독립 배경/테두리 구현은 호환 회귀 대상으로 보존합니다.

원본 선택 port가 발급한 lease의 WeakMap 연결과 공통 mutation admission을 재사용하며, 두 탭의 변경은 하나의 `cell-appearance` 요청으로 정규화합니다. 줄/칸 범위는 1부터 시작하는 양끝 포함 입력에서 planner의 0부터 시작하는 끝 제외 구간으로 변환합니다. `적용`은 응답 뒤 선택 복원과 재관측을 거쳐 같은 원본 셀의 새 lease를 얻은 경우에만 같은 창을 유지합니다. `확인`은 적용 뒤 닫으며, 변경이 없는 확인은 명령을 보내지 않습니다. 갱신 필요 응답·불확실한 응답·재관측 실패에서는 창을 닫고 자동 재시도하지 않습니다. Native 거부 메시지는 pending 해제 뒤에도 유지합니다.

검증 로그는 위 ignored reference 폴더에 둡니다. 최종 신규 세 진입점은 44pass·0fail·0skip, 기존 배경/테두리/크기 아홉 진입점은 136pass·0fail·0skip입니다. 별도 표 만들기 두 Bun 진입점은 27pass·0fail입니다. 신규 자체 검토는 초기38개, 선택·토큰·입력 변경 반례를 추가한43개, 거부 메시지 유지 회귀를 추가한 최종44개를 구분하며 중복 합산하지 않습니다. 선택 파일의 strict TypeScript·lint·format도 통과했습니다. CSS preload는 정확히 명시한 스타일의 JavaScript 평가만 생략합니다.

이 결과는 소스 계약·DOM 대역·SDK 명령 대역 증거입니다. 실제 Native의 원자 저장/undo/redo·제품 브라우저 배치/입력·배포 성공을 뜻하지 않습니다. 해당 단계와 독립 적대적 검토는 전체 후보의 별도 gate로 유지합니다.

## 최종 후보의 실제 화면

2026-11-06 R4 후보의 원본 Noori HWP5/HWPX에서 실제 셀 선택·통합 창 진입·테두리/배경 원자 적용·창 유지·변경 없는 확인·한 번의 실행 취소를 통과했다. 네 대화상자 관측은1280×633 viewport에서660×570 CSS px이었고, 보이는 label/control 겹침0 및 테두리 탭의 실제 포커스를 확인했다. 화면이 낮으면 본문은 내부 스크롤을 사용한다. 이는 공식의574×429 창과 픽셀 단위 동치를 뜻하지 않으며, 미지원 필드·대각선·무늬/그림 채우기는 계속 차이로 남는다. 모바일/다른 viewport나 실제 OS IME를 검증했다고 확대하지 않는다.

`integration/r3-browser-80138/`의 네 dialog PNG·geometry JSON과 `integration/R4-FINAL-AGGREGATE.json`을 근거로 한다. 새 문서6개는 다른 실행이므로 표2개와 같은 브라우저 실행의8개 성공으로 기록하지 않는다. 최종 세션은 모두 `active=false`, `pid=null`, 재조회한 소유 잔류0이었다.

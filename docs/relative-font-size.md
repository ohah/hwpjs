# 언어별 상대 글자 크기 표시

`character-font-metric-display.mjs`는 [원값 조회](character-font-metrics.md)의 relativeSize를 glyph font size에만 적용합니다. HWP5/HWPX의 유효한 명목 크기에 현재 표시 언어의 상대 크기 %를 곱합니다. 언어 선택은 기존 `displayFontLanguage`를 공유하며 새로 별도 판정기를 만들지 않습니다. 이 표시 언어 정책이 한글 프로그램의 전체 언어·대체 글꼴 판정과 같다는 주장은 하지 않습니다.

명세 범위 10~250의 정수만 적용합니다. 값 부재·범위 밖·형식 미상·빈 위치·객체 replacement character에는 기존 명목 크기를 유지합니다. 원값 API는 그 값을 지우거나 clamp하지 않습니다. 자동 번호 접두사는 실제 번호 문자열의 언어 선택을 확정하지 않았으므로 이번 적용에서 제외합니다. 위/아래첨자 등 기존 표시 효과는 base font 결정 뒤의 기존 경로를 유지합니다.

[공통 명목 행 높이](font-layout-metrics.md)는 변경하지 않습니다. 실제 charshape 자료는 한글 상대 크기 90%인 글자의 표시 CSS가 9pt인 반면 저장된 줄 textheight는 기준 10pt입니다. 표시 font size를 줄 높이에 그대로 재사용하지 않습니다. 장평·자간·글자 위치의 화면 적용은 아직 이 모듈에 포함하지 않습니다.

## 실제 근거와 검증

기존 `charshape.hwp`/`.hwpx`의 원값 API에서 상대 크기 한글90/영문100인 리소스를 독립 기존 `charshape_style.css`의 대응 클래스와 대조합니다. 수정 전 표시는 10pt, 기존 CSS는 9pt였고 수정 후 두 형식 모두 9pt가 됩니다. 영문은 같은 리소스에서 10pt를 유지합니다. nominal row height는 그대로 1000/75px이며 무변경 저장도 같습니다. 기존 CSS는 저장소 자료이며 이번에 한글에서 새로 출력한 것은 아닙니다.

명세 양끝 10/250, 범위 밖·문자열·NaN·Infinity·null·미지 리소스·문서 형식 격리·객체·언어별 선택·원본 불변을 검사합니다. 같은 글꼴 설치·ink/baseline·페이지 동치는 별도 검증입니다.

분리 최종 소스의 관련 42개 검사가 skip 없이 통과했습니다. text-style의 상대 크기 적용 한 줄만 제거한 음성 대조에서는 실제 양 형식 검사가 10pt 대 9pt로 실패했습니다. 실제 Chromium에서 같은 분리 JS와 원값 API 후보를 로드해 두 형식 모두 `12px sans-serif`와 직접 12px 측정 폭 10.379989624023438px가 같고, 기존 10pt 폭 11.530441284179688px와 다른 것을 확인했습니다. 명목 줄 높이는 13.333333333333332px로 유지됐습니다. 이는 통제된 sans-serif 측정이며 원래 바탕 글꼴의 동일성을 뜻하지 않습니다. 사용한 브라우저 세션·서버는 종료했습니다.

100% 초과도 기존 자료를 추가 조사했습니다. RHWP의 `task3307/issue3307_outline_number.hwpx`에서 한글 상대 크기 101%의 단일 리소스 문단 10개는 저장 textheight가 명목 크기를 유지했습니다. 그중 id64의 기준 12pt/상대101/저장1200을 독립 ZIP/XML로 확인하고 glyph 12.12pt/명목 줄 높이16px를 검사합니다. reference가 없으면 해당 추가 검사는 명시적으로 skip합니다. 이는 임의로 250%까지 모두 실측했다는 근거가 아닙니다.

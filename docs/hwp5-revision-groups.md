# 변경 추적 문단 병합 소유권 인덱스

[문단 흐름](hwp5-paragraph-flows.md) · [바이트 변환](hwp5-revision-projection.md) · [실측 근거](hwp5-merged-line-cache.md)

## 범위와 책임

`hwp5.revision_groups.Index.buildObserved(allocator, tree, flows)`는 **한 Section**의 원본 Tree와 그 Tree에서 만든 기존 Flows를 받아 관측 0/1 병합 표식의 인덱스를 생성합니다. 명세 표 58은 5.0.3.2 이상의 문단 헤더에 변경추적 병합 문단여부 UINT16을 정의합니다. 실제 바이트 연결과 0/1 동작의 대조 근거는 위 실측 문서가 소유합니다.

0은 해당 흐름에 새 묶음을 시작하며 1은 같은 흐름에서 직전 묶음에 참여합니다. 선두가 없으면 `OrphanRevisionMerge`입니다. 부재(null)와 2 이상 미지 값은 `UnsupportedRevisionMergeValue`로 거부하며 0으로 보충하지 않습니다. 원본 헤더의 값은 그대로 남습니다. 구버전/부재 표식의 일반 문단 처리를 완료했다고 주장하지 않으며 기본 문서·컨테이너 경로에는 이 관측 API를 자동 적용하지 않습니다.

리스트 경계·직접 문단 수와 소유권은 기존 `list_groups.Groups`와 `paragraph_flows.Flows`가 소유합니다. 새 인덱스는 레벨만 보고 문단을 합치거나 LIST_HEADER의 wire를 다시 해석하지 않습니다. 입력 Flows는 같은 변경되지 않은 Tree에서 빌드한 결과여야 합니다. 배열 길이·scope 범위·루트/리스트 종류와 부모 일치의 기본 검사는 추가로 수행합니다. 임의로 조작한 Tree/Flows 전체의 진위 재검증 API는 아닙니다.

각 흐름의 마지막 묶음을 따로 기억하므로 중첩 문단을 방문하고 돌아와도 바깥 흐름의 연결이 유지됩니다. 별도 셀·캡션·리스트는 기존 흐름 ID로 분리합니다. 호출마다 상태를 새로 만들며 구역 간 병합은 추정하지 않습니다.

## 소유권과 좌표

Index는 Member와 Group 배열을 소유하고 `deinit`으로 해제합니다. payload 포인터를 저장하지 않으며 원본 Tree·문단 ID·레코드 순서는 변경하지 않습니다. 인덱스로 원문에 접근하려면 같은 Tree를 유지해야 합니다.

- Member: 원본 문단 노드, 흐름 ID, 묶음 배열 인덱스, 묶음 안의 선언 유닛 시작 위치(u64).
- Group: 선두 문단 노드, 흐름 ID, 문단 수, 선언 유닛 합(u64).

Member는 원본 문단 순서이고 Group은 선두 발견 순서입니다. 중첩 때문에 같은 묶음의 Member가 배열에서 연속하지 않을 수 있으므로 `member_count`만으로 연속 슬라이스를 잘라 쓰면 안 됩니다. `group_index`로 소속을 확인합니다.

좌표는 `Header.characterUnits()`를 그대로 누적한 값이며 high bit를 별도 해석하지 않습니다. CR 제거·삭제 범위 적용·누락 텍스트 보충은 수행하지 않습니다. **선언 유닛 합은 렌더링 줄 위치나 최종 BodyText 위치가 아닙니다.** 64비트 합산을 사용하며 오버플로는 오류입니다. 큰 선언 길이만큼 메모리를 할당하지 않습니다.

시간과 임시 메모리는 Tree 노드 수 및 실제 문단 수에 선형입니다. 실패 시 흐름별 상태와 두 결과 배열을 모두 정리하며 부분 인덱스를 반환하지 않습니다. 텍스트 길이·스타일·변경 내용/작성자 참조와 줄 캐시 검증은 이 모듈의 성공으로 대체하지 않습니다.

## 실제 대조·적대적 검증

테스트 mode 101은 기존 Tree → Groups → Flows → 새 Index를 조립하며 각 Member를 문단/흐름/선두/문단 수의 u32 네 값과 시작/합의 u64 두 값으로 반환합니다. 이 32바이트 행은 제품 공개 ABI가 아닌 테스트 형식입니다.

`revision-groups.mjs`는 독립 JS 레코드 순회와 부모별 마지막 LIST_HEADER, 흐름별 마지막 묶음을 사용해 모든 행을 바이트 단위로 대조합니다.

| 문서·스트림 | 문단 | 묶음 |
|---|---:|---:|
| issue5169 BodyText | 228 | 228 |
| issue5169 ViewText | 590 | 524 |
| task2070 BodyText | 53,448 | 53,448 |
| task2070 ViewText | 53,448 | 53,448 |

issue5169 ViewText에는 루트 외 흐름에서 후속 병합 문단 1건도 있습니다. 각 실파일 스트림의 첫 루트 및 첫 중첩 문단 표식을 1로 바꾸면 선두 없는 병합으로 거부하고, 오류 후 원본 보고서로 복구합니다. 디스크 표본은 변경하지 않습니다.

합성 테스트는 여러 중첩/빈 리스트, 서로 다른 셀의 병합 고아, 구버전·필드 부재·미지 값, 부모 오류, 빈 입력, 0 길이, 호출 간 상태 격리를 검사합니다. 3개 문단의 합 6,442,450,941유닛도 선언 크기로 할당하지 않고 u64 행으로 정확히 반환하는지 확인합니다. 네이티브 테스트는 성공 및 늦은 미지 표식 오류의 모든 할당 실패, Flows 배열 불일치·범위·루트/중첩 혼동을 확인합니다.

이 인덱스와 바이트 변환기를 연결하는 명시적 경로는 [묶음 텍스트 조립](hwp5-revision-text.md)이 소유하고, 문단 내부 원시 유닛의 매핑은 [좌표 변환](hwp5-revision-coordinates.md)이 소유합니다. 미검증 줄 캐시 좌표 해석과 기본 ViewText 의미 검증은 여전히 후속 범위입니다.

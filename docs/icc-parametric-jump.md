# ICC 파라메트릭 분기 경계의 클리핑 후 점프

## 범위와 계약

각 구간 방향과 이 경계 순서를 합치는 [전체 단조성·상수성 판정](icc-parametric-trend.md)은 별도 계층입니다.

[ICC.1:2022 §10.18 Table 68](https://www.color.org/specifications/ICC.1-2022-05.pdf)의 하위 선형 분기와 상위 거듭제곱 분기가 모두 있을 때, 경계에서 **클리핑된 상위 실제 값 − 클리핑된 하위 좌극한**의 부호를 정확히 판정합니다. 공식 식의 하위 분기는 열린 끝점을 가지므로 하위 실제 함수값을 경계에서 조회하는 것이 아닙니다. 선형 식의 연속 확장으로 좌극한을 계산합니다.

`parametric_jump.inspect(precision, curve)`는 먼저 기존 `parametric_segments.assemble`로 전체 실수 정의역을 검증합니다. 결과는 다음 둘 중 하나입니다.

- none: 한 분기만 활성이라 내부 연결 경계가 없습니다. 연속성·전체 단조성 판정의 성공이라는 뜻은 아닙니다. 정의역 오류는 none보다 먼저 반환합니다.
- boundary: 정확한 Fraction 위치 at와 선택적 Order를 반환합니다. lt는 하향, eq는 경계 연속, gt는 상향입니다. null은 현재 정밀도로 결정하지 못함이며 경계 자체는 보존합니다.

경계가 x=0이면 하위 분기가 없어 none입니다. x=1이면 상위 한 점과 하위 열린 끝점이 연결되므로 boundary입니다. d>1이면 활성 상위 분기가 없어 none입니다. 이 조건을 따로 재구현하지 않고 기존 구간 조립 결과를 사용합니다.

이 단계는 분기 사이의 점프만 다룹니다. [각 분기 내부 클리핑 구간](icc-power-clipping.md)의 방향, 전체 곡선의 단조성·상수성, 열린 역상의 최대/최근접값 존재, 역변환은 별도 후속 계층입니다. 한 점에서 eq여도 곡선 전체가 상수라는 뜻이 아닙니다.

## 정확한 값 비교와 책임

분기 원본 계수·활성 구간은 parametric_segments가 소유하고, 선형 식의 유리수 값은 기존 affine_value가 계산합니다. 경계 비교는 아래 세 경우로 나눕니다.

1. 하위 좌극한 L<=0: 하위 클리핑 값은 0입니다. 상위 원값 P와 0을 기존 power_level_order로 비교하여 P>0이면 gt, P<=0이면 eq입니다.
2. L>=1: 하위 클리핑 값은 1입니다. P와 1을 비교하여 P<1이면 lt, P>=1이면 eq입니다.
3. 0<L<1: 클리핑은 L에 대한 대소 관계를 바꾸지 않습니다. 원시 상위 오프셋 e를 빼서 `(a*x+b)^g`와 `L-e/65536`을 [공통 유리수 거듭제곱 비교](icc-rational-power-order.md)에 전달합니다.

L=N/D일 때 목표 분수는 `(65536*N-e*D)/(65536*D)`입니다. normalized Fraction의 성분은 u64라 affine_value의 D<2^80이며, 내부 L에 대해 0<N<D입니다. 따라서 위 분자는 절댓값 2^112 미만, 분모는 2^96 미만으로 i128/u128에 들어갑니다. 외부 임의 u128 분모의 값을 이 내부 경로에 받지 않습니다. epsilon·f64·16.16 재양자화·입력 계수 보정은 하지 않습니다.

세 경우 모두 하위 비교기의 미확정을 그대로 전달합니다. 원시 para 입력으로 이 새 조립기 전체의 null을 재현한 사례는 아직 없으며, 기존 수치 비교기의 미확정 테스트를 새 전체 경로의 실측으로 확대하지 않습니다. 최대 정밀도에서 무조건 판정된다는 주장도 하지 않습니다.

## 검증 구성

네이티브 검사는 두 증가 분기 사이의 하향 점프, 상향 계단, 정확한 1/2^32 연속과 그 양옆, 상위/하위 오프셋, 양쪽 원값이 0 미만 또는 1 초과여서 클리핑 후 같아지는 경우, 경계 x=1의 보존, x=0·d>1의 부재, 경계 부재 반환보다 앞선 정의역 검사를 포함합니다.

WASM mode191은 precision u32 BE와 para payload를 받습니다. 출력은 24바이트이며 boundary 존재 u32 LE, order i32 LE(−1/0/+1/2=미확정), at 분자/분모 u64 LE입니다. none은 전체 0입니다. 제품 JS API에는 노출하지 않습니다.

독립 JS 기준은 기존 별도 정의역 참조를 사용하고, 정확한 BigInt 전체 거듭제곱·유리수 교차 곱으로 원시 식을 계산합니다. 중복되던 유리수 거듭제곱 기준식을 icc-power-reference의 rationalPowerOrder로 모아 기존 점 수준 비교와 직전 유리수 비교 검사가 함께 사용합니다. 제품의 기호근·방향성 정수 경계 알고리즘은 공유하지 않습니다.

다섯 곡선 유형, 양/음/분수/영 지수, 양/음/영 a/b/c, 음수·영·내부·끝점·범위 밖 d, 두 오프셋을 조합합니다. 네 정밀도의 작은 차이·극값 오프셋, 모든 입력 잘림·과잉 바이트·크기 제한·부적합 정밀도·실패 후 복구도 포함합니다.

## 실행 기록

초기 네이티브 검사는 5/5 단계·517/517로 통과했습니다. Debug 테스트 WASM 직접 대조는 comparisons=4073, rejected=10463, absent=9852로 통과했습니다. 공유 JS 기준식으로 바꾼 직전 유리수 비교도 comparisons=2894, rejected=779, undecided=1로 통과했습니다. 비영 점프를 연속(eq)으로 바꾸는 임시 호출 래퍼는 독립 검사에서 ERR_ASSERTION으로 검출됐으며 제품에는 남기지 않았습니다.

추가 반환값 변형에서도 raw `[65536,2,0,1,1,0,0]`의 1/2^32 상향 점프를 eq로 지우는 오류, x=1의 boundary를 none으로 지우는 오류를 각각 ERR_ASSERTION으로 검출했습니다. 분기 사이 작은 차이와 끝점 존재 여부를 따로 보호하는 증거입니다.

실제 시스템 Display P3·ITU-2020·ITU-709·ROMM RGB의 type3 r/g/bTRC 태그 12개를 읽기 전용으로 가져와 mode191에 직접 전달했습니다. 128/256/512/1024비트에서 모두 원시 d/65536과 정확히 같은 경계 위치, 기존 고정밀 조사의 점프 부호(앞 두 종류 gt, 뒤 두 종류 lt)를 반환했습니다. 총 48건이며 정규 감사 수에는 합산하지 않습니다. ICC.1:2022 식에 따른 해당 경계의 판정이며 OS 색상 엔진이나 프로파일 전체 유효성 검증이 아닙니다.

### 최종 확인

`/tmp/hwpjs-icc-parametric-jump-Debug.log`, `/tmp/hwpjs-icc-parametric-jump-ReleaseSafe.log`, `/tmp/hwpjs-icc-parametric-jump-ReleaseFast.log`의 순차 전체 감사가 모두 종료 코드 0으로 완료됐습니다. 각 로그는 20/20 단계·517/517 네이티브 테스트·WASM 검사 6,457,564건을 기록하며 신규 comparisons=4073, rejected=10463, absent=9852가 일치합니다. 공유 JS 기준을 사용하는 이전 수준 비교·유리수 비교·클리핑 검사도 포함합니다.

ReleaseFast 산출물 직접 대조 역시 같은 신규 검사 수로 통과했고, x=1 경계 삭제 변형을 ERR_ASSERTION으로 검출했습니다. 최종 적대적 검토에서 열린 선형 끝점의 좌극한 계산, 0/1 양쪽 클리핑과 내부 목표값의 순서 보존, i128/u128 오프셋 차감 범위, 전체 정의역 검증 우선순위, 경계 부재와 미확정의 구분, 끝점 경계 유지와 오류 후 복구를 재확인했습니다. 해당 범위에서 추가 결함은 발견하지 않았습니다. 변경 Zig 포맷·JS 문법·로컬 문서 링크 7개·diff 공백 검사도 통과했습니다.

다음 구현은 이 경계 순서와 각 클리핑 구간의 방향을 결합하는 전체 단조성/상수성 판정입니다. 역변환과 전체 문서 검증 목표는 아직 미완료입니다.

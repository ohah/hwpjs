# ICC 경계 근의 활성 구간 위치

## 범위

[정확한 근 비교](icc-power-root-compare.md)를 재사용하여 밑 근의 x 역상이 주어진 구간에 있는지 판정합니다. 근을 f64로 변환하거나 미확정을 근 부재로 바꾸지 않습니다. 이후 클리핑 분할에 사용할 위치 정보이며, 아직 클리핑된 구간을 조립하거나 전체 곡선의 단조성·역변환을 판정하지 않습니다.

`affine_root_location.locate(precision, root, a, b, interval)`는 `(a*x+b)/65536=root`의 역상을 찾습니다. interval은 기존 `unit_interval.Interval`이며 정규화 분수·순서·비어 있지 않음 검사를 공유합니다. 입력을 수정하거나 메모리를 할당하지 않습니다. 이 저수준 함수만으로 전체 곡선의 실수 정의역 유효성을 증명하지 않습니다.

## 위치 계약

| Location / 테스트 wire 값 | 의미 |
|---|---|
| absent / 0 | 구간에 역상이 없음. 제외된 열린 끝점의 근도 포함 |
| start / 1 | 포함된 시작점에 유일한 역상이 있음 |
| interior / 2 | 두 끝점 사이에 유일한 역상이 있음 |
| end / 3 | 포함된 끝점에 유일한 역상이 있음 |
| singleton / 4 | a≠0인 닫힌 한 점 구간에서 그 점이 역상 |
| entire / 5 | a=0이고 상수 밑이 근과 같아 구간 전체가 역상 |
| undecided / 6 | 선택 정밀도로 포함/부재를 확정할 수 없음 |

a=0은 시작점의 밑 값 하나만 비교합니다. 닫힌 한 점 구간에서도 상수 밑이면 entire이며, a≠0의 singleton과 구분합니다. 시작/끝이 같으면서 하나라도 열려 있으면 기존 Interval 검사에서 EmptyIccInterval입니다.

a≠0이면 선형 변환이 일대일이므로 밑 근과 끝점 밑 값의 순서로 x 역상 위치를 알 수 있습니다. a<0이면 순서를 뒤집으며, a 자체를 부호 반전하지 않아 i32 최솟값도 안전합니다. 시작점보다 작거나 끝점보다 큰 역상은 absent입니다. 끝점과 같으면 해당 포함 플래그로 결정합니다. 시작점보다 크고 끝점보다 작음이 모두 증명돼야 interior입니다. 한쪽이 미확정이더라도 다른 쪽의 정확한 끝점 등식이나 바깥 순서가 결과를 확정하면 그 증거를 사용합니다. 나머지는 undecided입니다.

## 실제 거듭제곱 분기 연결

`power_level_locations.inspect(precision, curve, target)`는 기존 `parametric_segments.assemble`로 전체 실수 정의역 검사와 활성 거듭제곱 구간을 조립한 뒤 `power_level.solve`와 위치 판정을 호출합니다. target은 원본 signed 16.16 정수이며 0/65536 외의 수준도 가능합니다.

- inactive: 활성 거듭제곱 분기가 없습니다. 하위 선형 분기의 해가 없다는 뜻은 아닙니다.
- entire: 활성 거듭제곱 구간 전체가 해당 수준입니다. g=0의 all_nonzero 해는 앞선 정의역 검사가 0인 밑을 제외했으므로 이 결과로 승격할 수 있습니다. a=0인 상수 밑이 개별 근과 같은 경우도 포함합니다.
- roots: 최대 두 개의 원본 기호적 근과 위치를 보존합니다. absent는 제거하지만 undecided는 남깁니다. entire는 상위 결과로 반환하며 목록에 넣지 않습니다. count=0은 이 거듭제곱 분기에 해당 수준의 해가 없음을 뜻합니다. count 이내만 초기화됩니다. 두 근의 순서는 원본 해 집합 순서이며 x 좌표순 정렬은 아닙니다.

함수 전체가 아니라 **활성 거듭제곱 분기**의 해만 보고합니다. 하위 선형 분기와의 합집합, 두 클리핑 수준의 경계 정렬과 구간 분할, 미확정 시 정밀도 승격 정책은 후속 책임입니다.

## 검증과 SSOT

네이티브 테스트는 모든 열린/닫힌 끝점 조합, 양/음 기울기, 내부 근, 상수 밑, 한 점 구간, 두 실근, 비활성 분기, g=0의 전체 수준과 잘못된 0^0, 상수 제곱 값, u64 Pell 구간을 검사합니다.

mode185는 precision/g/offset/target/index의 공통 20바이트 접두어 다음 a/b i32 BE, flags u32 BE, 시작·끝의 n/d u64 BE 네 개를 받는 64바이트 입력입니다. flags bit0/bit1은 시작/끝 포함이며 나머지 비트는 거부합니다. 위치 u32 LE 한 개를 반환합니다. mode186은 precision u32 BE와 target i32 BE 다음 para payload를 받으며, kind(0 inactive/1 entire/2 roots)와 count u32 LE, 위치 u32 LE + 기존 20바이트 근 표현의 항목을 반환합니다. 최대 출력은 56바이트입니다. 제품 JS API에는 노출하지 않습니다.

20바이트 근 출력은 `icc-power-root-wire`를 기존 mode182와 공유하고, 근 선택 접두어는 `icc-root-input`을 기존 mode183/184와 공유합니다. 새 테스트의 수학적 기대값은 기존 독립 BigInt 거듭제곱/교차 곱 비교와 정의역 임계점 열거를 재사용합니다. 제품 비교나 위치 판정을 호출해 기대값을 만들지 않습니다. 독립 위치 기준은 양쪽의 포함 조건을 먼저 결합한 뒤 위치를 분류하여 제품의 조기 반환 경로와 다르게 구성했습니다.

### 미확정 사례

√(1/2) 주변의 이전 u64 Pell 분수 lo=4866752642924153522/6882627592338442563, hi=11749380235262596085/16616132878186749607을 사용합니다. [lo,hi]에서 128비트는 undecided, 256/512/1024비트는 interior입니다. [hi,hi]에서도 128비트는 undecided, 512비트는 absent입니다. 한 점 구간이라는 이유로 미확정을 없애면 안 됩니다.

초기 추가 조사에서는 [lo,lo]도 128비트에서 미확정일 것으로 가정했으나 실제 결과는 absent였습니다. 정확한 부호와 일치하는 판정으로 제품 결함이 아니었습니다. 양쪽 좌표를 각각 128/512비트로 실측하여 미확정이 재현되는 [hi,hi]를 회귀 사례로 고정했습니다.

## 실행 기록

네이티브 503/503 테스트, 5/5 단계가 통과했습니다. 확장된 직접 WASM 검사는 위치 12,858건·실제 분기 조립 1,891건·예상 오류 거부 8,040건·의도된 미확정 2건으로 통과했습니다. i32 계수 극값과 2147483647/2147483648 경계, 비활성 분기와 빈 수준 집합, 잘림·과잉·잘못된 flags/좌표·자원 제한·오류 후 재사용을 포함합니다.

공유 wire 추출 후 기존 해 집합 비교/거부 656,341/14건, 근 비교 2,983건·거부 1,117건·미확정 2건도 직접 재확인했습니다. 미확정을 absent로 바꾸거나 열린 시작점을 강제로 닫는 임시 변형을 각각 ERR_ASSERTION으로 검출했습니다. 제품 파일에는 변형을 남기지 않았습니다.

초기 전체 Debug 로그 `/tmp/hwpjs-icc-root-location-Debug-initial.log`는 20/20 단계·503/503·WASM 검사 6,378,352건으로 통과했지만 새 JS 위치 검사가 연결되기 전 실행입니다. 이를 최종 신규 검사 근거로 대체하지 않습니다. 최종 세 모드 감사는 `/tmp/hwpjs-icc-root-location-Debug-final.log`, `/tmp/hwpjs-icc-root-location-ReleaseSafe-final.log`, `/tmp/hwpjs-icc-root-location-ReleaseFast-final.log`에 순차 실행 중이며 완료 후 결과를 확인합니다.

시스템 ICC para TRC 태그 15개(type0/type3)의 원본 payload로 활성 거듭제곱 분기의 0/1 수준 해 집합 30건을 읽기 전용 확인했습니다. 이 실제 태그들은 양의 a·비음수 b·양의 g이고 출력 오프셋이 0이므로 포함 가능한 밑 근은 0/1입니다. 정확한 `(target-b)/a`와 활성 시작점·1의 정수 교차 곱 비교로 빈 집합, 시작/내부/끝 위치와 반환 근 부호를 독립 확인했고 모두 일치했습니다. 파일 복사·수정은 없으며 수동 건수는 정규 감사에 합산하지 않습니다. 하위 선형 분기와의 합집합·픽셀 결과·전체 곡선 단조성은 이 조사 범위가 아닙니다.

Debug·ReleaseSafe 최종 로그는 각각 20/20 단계·503/503 네이티브 테스트·WASM 검사 6,401,143건으로 통과했습니다. ReleaseFast 산출물 직접 실행에서도 신규 위치/분기/거부/미확정 12,858/1,891/8,040/2건, 공유 입력의 기존 근 비교 2,983/1,117/2건, 공유 출력의 해 집합 비교/거부 656,341/14건을 재확인했습니다. 활성 분기 전체가 해인 entire를 inactive로 바꾸는 임시 반환값 변형도 독립 검사가 ERR_ASSERTION으로 검출했습니다. 제품 파일에는 변형을 남기지 않았습니다.

### 최종 확인

세 모드 순차 감사는 종료 코드 0으로 완료했습니다. 최종 로그 세 파일 모두 20/20 단계·503/503 네이티브 테스트·WASM 검사 6,401,143건을 기록합니다. 앞의 실행 중 문장은 진행 이력이며 최종 결과는 이 절이 소유합니다.

최종 적대적 검토에서 열린 끝점의 배제, 감소 변환의 순서 반전, 한 점/상수 밑의 구분, g=0의 전체 정의역 검사 선행, 비활성 분기와 빈 수준 집합의 구분, 미확정 보존, 최대 두 결과의 초기화 범위와 실패 전 할당 여부를 확인했습니다. 해당 범위에서 추가 결함은 발견하지 않았습니다. 기존 입력 선택·근 직렬화 SSOT 공유와 포맷·JS 문법·로컬 링크·diff 공백 검사도 확인했습니다. 실제 클리핑 구간 조립과 전체 문서 기능 검증은 아직 완료되지 않았습니다.

# JPEG sequential DCT 계수 블록

## 근거와 책임

[ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf)의 F.1.2, F.1.5 및 F.2.2를 참조합니다. 외부 구현 코드를 추가하지 않았습니다.

- `amplitude.zig`: EXTEND 부호 확장과 추가 비트 읽기만 담당합니다. 폭 0~16의 수학적 변환이며, lossless category 16의 특수 의미를 구현한 것은 아닙니다. 실패 시 비트 리더를 보존합니다.
- `sequential_symbols.zig`: 파싱된 8/12비트 Huffman sequential 프레임에 맞춰 DC category와 AC run/size를 검사합니다. EOB와 16개 0을 나타내는 ZRL을 구분합니다. progressive·lossless·산술 코딩은 거부합니다.
- `sequential_block.zig`: 기존 비트 리더·Huffman 디코더와 위 두 모듈을 조합해 한 블록의 64개 계수를 반환합니다. 출력은 원시 zigzag 순서이며 자연 행렬 순서가 아닙니다. 호출자가 제공한 DC 예측값에 차이를 checked i32 연산으로 더합니다. 실패 시 블록 일부나 변경된 비트 커서를 외부에 반영하지 않습니다.

입력과 Huffman 심볼은 불변 바이트를 빌리며 코어는 할당하지 않습니다. DC/AC 테이블 class 및 기존 process별 테이블 제약을 재사용합니다. ZRL은 정확히 블록 끝까지 채울 수 있지만 경계를 넘을 수 없습니다. 비영 계수의 run은 계수를 놓을 한 칸을 남겨야 합니다. 마지막 계수를 채웠으면 EOB를 추가로 요구하지 않습니다.

## 아직 하지 않는 일

MCU 순회·스캔 상태 연결의 진행 현황은 [sequential 스캔 복호화 작업](jpeg-sequential-scan.md)이 소유합니다. 아래는 블록 모듈 자체의 책임 경계입니다.

MCU 순회·성분별 DC 예측값 관리·RST에서 예측값 초기화·전체 스캔 계수 개수 검증·역양자화·IDCT·픽셀 출력은 후속입니다. 예측값 덧셈의 i32 오버플로는 검사하지만, 변환 전체의 물리적 계수 범위를 인증하지 않습니다. 호출자는 프레임/SOS와 활성 테이블 선택을 기존 계층에서 검증해야 합니다.

단일 블록 성공은 이미지 전체의 정상성이나 픽셀 동일성을 뜻하지 않습니다. 제품 JS API와 HWP JPEG 미지원 집계는 그대로입니다.

## 검증 기록

- 네이티브 신규 8개, 기존 JPEG 검사 포함 Debug/ReleaseSafe/ReleaseFast 각각 56/56 통과. EXTEND 폭 0~16의 모든 131,071개 값, 8/12비트의 모든 DC/AC 심볼 값, 정확한 ZRL 끝 경계, 계수 63, 잘림·예측값 오버플로·실패 원자성을 검사합니다.
- 테스트 전용 mode 252는 프레임·DC/AC 테이블·초기 예측값·bit offset·엔트로피를 받아 원시 offset/남은 비트와 signed 계수 64개를 반환합니다. JS는 독립 prefix Map과 비트 문자열, 부호 비트 반전 및 가변 길이 계수 배열로 대조합니다.
- 세 모드 WASM 각각 독립 비교 70,422건, 오류 거부 613건 통과. 짧은 probe 입력 9종도 별도로 거부했습니다.
- 실제 HWP JPEG 참조 8건 중 sequential 7건에서 각 첫 스캔의 첫 블록 64계수와 커서가 세 모드 모두 독립 JS와 일치했습니다. progressive 1건은 이 검사에서 제외하며 기존 progressive 구조 검사를 유지합니다. `reference/rhwp/samples/s1.jpg` 첫 블록도 세 모드에서 일치했습니다. 나머지 블록·전체 이미지 패딩·픽셀은 이번 실측 범위가 아닙니다.
- mode 252 출력의 offset·잔여 비트·계수 0/1/47/63을 각각 XOR 1로 변조한 6종을 세 모드 독립 대조에서 모두 검출했습니다.
- 추가 일회성 입력 변형 조사: xorshift32(시드 `0x91a5c38f`, shift 13/17/5)로 스터핑 전 길이 0~32, byte 0~255, 예측값 -2048~2048, skip 0~7, finish 여부를 생성했습니다. 네이티브 블록 테스트의 DC/AC 테이블을 사용한 10,000건에서 세 모드 각각 수락 728건의 전체 출력과 거부 9,272건의 판정이 JS와 일치했습니다. 이 별도 조사 수치는 정규 audit 합계에 포함하지 않습니다.

### 소스 결함 주입

별도 소스 복사본의 결함 3종을 Debug/ReleaseSafe/ReleaseFast에서 각각 실행했습니다. 모두 컴파일 성공 후 테스트 실패로 검출했습니다.

- 음수 EXTEND 계산에서 `limit - 1` 대신 `limit` 사용: 각 모드 56개 중 3개 실패.
- ZRL 경계 검사를 `>`에서 `>=`로 변경: 정상적인 정확한 블록 끝을 거부하여 각 모드 1개 실패.
- DC 차이를 읽은 즉시 원본 커서에 반영: 뒤쪽 오류의 원자성 위반으로 각 모드 3개 실패.

Debug/ReleaseSafe/ReleaseFast 전체 audit는 각각 20/20 단계, 네이티브 772/772 테스트, 총 7,312,215건 검사로 통과했습니다. 전체 회귀 합계이며 JPEG 픽셀·전체 문서 구현 완료를 뜻하지 않습니다.

# 언어별 장평 표시

`character-font-metric-display.mjs`는 [조판 원값](character-font-metrics.md)의 ratio 중 명세 범위 50~200의 정수를 수평 배율로 변환합니다. 상대 크기와 같은 표시 언어 판정·리소스 색인을 공유합니다. 부재·범위 밖·형식 미상·객체 표식은 배율 1을 유지하며 원문 값은 수정하지 않습니다.

`text-style.mjs`의 horizontalScale을 renderer의 글리프 측정과 그리기가 함께 사용합니다. `glyph-horizontal-scale.mjs`는 측정 폭의 배율·유효성 검증과 글리프 원점 기준 Canvas transform 수명을 소유합니다. 세로 크기·행 높이·줄 좌표는 수평 변환에 넣지 않습니다. relief/outline/fill은 같은 transform을 거치며 선택·caret·배경·밑줄/취소선은 이미 배율이 적용된 경계 폭을 사용합니다. 그리기 예외에도 caller transform을 복구합니다.

현재 grapheme별 측정·그리기의 기존 구조를 유지합니다. OpenType shaping·커닝·글꼴 동일성이나 원본 한글의 전체 폭 동치를 완료한 것이 아닙니다. 자동 번호·수식·덧말·그림 등 별도 측정 경로에는 새 배율을 적용하지 않습니다. 자간·글자 위치의 적용도 별도이며, 원문 자간 값을 기존 HTML의 letter-spacing으로 단순 치환하지 않습니다.

## 검증

실제 facename.hwp/.hwpx의 95% 장평 리소스를 읽어 동일한 배율이 측정·줄바꿈·caret·hit-test·선택에 전달되는지 검사합니다. 통제된 원래 폭 20px가 19px가 되고 두 글자의 경계는 0/19/38px입니다. 이 테스트는 실제 리소스 값과 통제된 측정기를 조합한 것이며 원래 바탕 글꼴 폭을 실측했다고 주장하지 않습니다. 50/200 양끝·언어별 배율·부재/미지 값·측정 overflow·그리기 예외·배율1의 원좌표 유지도 검사합니다.

실제 Worker와 renderer를 연결한 simulated DOM 회귀에서는 8px 측정 대역의 경계 0/7.6/15.2px와 각 글리프 scale(0.95,1)을 함께 검사합니다. 저장 바이트는 바뀌지 않습니다. 이는 브라우저 검사와 별도로 남기는 재실행 가능한 연결 검사입니다.

분리 소스의 실제 Chromium renderer에서는 원래 폭 8.0859375/10.379989624023438px가 7.681640625/9.860990142822269px가 됐습니다. 1배·1.5배 확대에서 논리 경계가 같고 그리기 변환은 직접 Canvas 기준과 일치했습니다. Canvas의 0.95 변환은 0.949999988079071, 1.5배와 합성한 결과는 1.4249999821186066으로 반환됐습니다. 이상적인 소수와 직접 비교한 최초 검사는 실패했으며, 허용 오차를 임의로 넓히는 대신 제품 코드를 거치지 않은 동일 Canvas 연산을 기준으로 비교했습니다. 원본 한글 픽셀 동치로 해석하지 않습니다. 전용 브라우저·서버는 종료했습니다.

분리 최종 소스의 관련 49/49 검사가 skip 없이 통과했습니다. renderer의 측정 배율만 제거한 음성 대조와 그리기 배율만 제거한 음성 대조에서 양 형식 연결 검사 2개씩 모두 실패했습니다. 측정만/그리기만 반영하는 결함을 독립적으로 잡습니다. 앞선 47개·작업 트리 집중 검사와 중복 합산하지 않습니다. native 확대 실행과 전체 할당 실패 전수 실행은 별도 gate입니다.

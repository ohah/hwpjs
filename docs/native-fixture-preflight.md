# Native 픽스처 사전 점검

`tools/native-fixture-preflight.mjs`는 이전 `FileNotFound` 결과의 테스트 이름을 선택한 Zig 소스의 실제 선언과 대조하고, 해당 파일에 적힌 입력 경로를 점검합니다. 컴파일·테스트 실행·픽스처 복원은 수행하지 않습니다.

## 입력과 경계

명시한 격리 소스와 선택한 `src/*.zig`만 읽습니다. 현재 지원하는 `cwd().readFileAlloc`·`openDir`의 문자열, 괄호, 같은 파일의 모호하지 않은 `const` 문자열 연결만 해석합니다. import는 따라가지 않습니다. 배열·루프·동적 경로·외부 별칭·런타임 디렉터리는 미해결 상태로 남깁니다. 한 소스 파일의 다른 테스트 입력도 포함될 수 있어 테스트별 호출 그래프와 다릅니다.

허용한 공식 픽스처 디렉터리 밖의 참조와 보호 경로는 파일 조회 전에 거부합니다. 심볼릭 링크 대상은 읽지 않으며 디렉터리를 열거하지 않습니다. 경로 존재와 관측 SHA는 커밋 출처나 Native 동작의 증거가 아닙니다.

`present`, `missing`, `unresolved`, `denied`를 구분합니다. 종료 코드 0은 선택한 정적 관측에서 차단 사유가 없다는 뜻이고, 1은 차단·미해결, 2는 설정·입출력 오류입니다. `allNativeFixturesReady`는 항상 false이며 이 도구로 전체 테스트 준비를 인증하지 않습니다. 출력은 새 검증 파일에만 기록합니다.

## 확인 결과

기존 실패 30개 라벨을 선택한 소스 21개의 실제 테스트 선언과 대조했습니다. 해석 가능한 허용 입력은 고유 경로 3개가 현재 존재했고, 미해결 참조·힌트 4개와 허용 범위 밖 참조·힌트 23개가 남았습니다. 이 숫자는 경로 관측 단위이며 테스트 통과 수가 아닙니다. 참조 아티팩트를 조회하거나 복원하지 않았고 Native 테스트도 실행하지 않았습니다. 과거 실패가 현재 통과한다는 결론은 내리지 않습니다.

합성 검사는 주석·문자열 분리, 모호한 const·동적 경로, 금지 경로의 조회 전 거부, 심볼릭 링크 차단, 새 출력 강제, 실제 선언과 실패 라벨의 대조를 확인합니다. 근거는 `zig-out/verification/native-fixture-readiness-r1/`이며 실행법은 [개발 명령](development-commands.md)을 따릅니다.

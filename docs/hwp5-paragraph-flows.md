# HWP5 문단 흐름 소유권

[본문 계약](hwp5-body-contracts.md) · [모듈 인덱스](hwp5-modules.md)

## 현재 계약

- `paragraph_flows.Flows`는 같은 Tree/Groups의 문단 소속을 매핑합니다. root 문단은 scope 0, 나머지는 직접 소유 LIST_HEADER 노드 인덱스이며 키는 구역 내부에서만 유효합니다. Group.begin/end와 subtree_end를 재사용해 중첩 자손을 바깥 리스트에 포함하지 않고, 같은 부모의 별개 리스트를 합치지 않습니다. payload·선언 문단 수를 다시 읽지 않으며 누락/중복 소속은 오류입니다. 원시 Tree는 변경하지 않습니다. mode 93에서 문단 노드/흐름 키를 검증하며 문서 필드 범위 검사 연결은 별도입니다.

## 구현·검증 기록

2026-09-07. 메모 시작/끝의 범위를 구역 전체 하나의 스택이나 문단별 독립 스택으로 검사하면 각각 별개 리스트 혼합/정상 다중 문단 범위 거부 위험이 있습니다. 먼저 기존 Groups의 직접 형제 목록을 이용한 paragraph_flows.Flows를 구현했습니다. 이것은 문서 필드 범위 검증의 선행 계층이며 범위 검사 자체의 완료가 아닙니다.

root 문단은 scope 0을 공유하고, 다른 문단은 자신을 직접 소유한 LIST_HEADER 노드 인덱스를 키로 사용합니다. 키는 같은 구역의 변경하지 않은 Tree 안에서만 유효하며 HWP instance ID나 문서 전역 번호가 아닙니다. 리스트 아래 중첩된 개체의 자손 문단은 자기 리스트에 속합니다. 바깥 문단 흐름은 중첩 개체 뒤에서도 이어지며 같은 부모 아래의 서로 다른 리스트는 합치지 않습니다. 이 매핑으로 표 셀/주석 등의 별도 흐름을 구분하되 페이지 배치나 컨트롤의 의미를 추정하지 않습니다.

Flows는 관측 노드 수에 비례한 소속 배열을 소유합니다. Groups.build가 이미 계산한 begin/end와 Tree.subtree_end를 사용하며 레코드·리스트 payload·선언 개수를 다시 해석하지 않습니다. 초기/최종 노드 순회 및 각 그룹의 직접 형제 순회로 소속을 확인하고 원시 Tree를 수정하지 않습니다. 잘못 전달된 그룹 경계는 InvalidFlowGroup, 문단 소속의 중복/누락은 DuplicateParagraphFlow/MissingParagraphFlow입니다. get은 문단이 아닌 노드/범위 밖 접근을 InvalidParagraphNode로 거부합니다. 모든 실패에서 배열을 해제합니다.

테스트 mode 93은 기존 list-probe의 Tree/Groups 생성 경로를 공유하고 문단 노드/흐름 키 쌍을 반환합니다. mode 15/88의 출력은 유지했습니다. 문서 검사에 불필요한 배열을 매번 할당하지 않도록 아직 section에 연결하지 않았으며, 다음 필드 범위 검사기가 이 결과를 소비하도록 할 예정입니다.

6개 실제 파일의 41개 구역/41,051개 문단을 검증했습니다. 독립 JS 기대값은 원본 레벨과 부모별 최근 직접 LIST_HEADER로 계산하여 WASM 매핑 전체와 대조합니다. 텍스트 없는 문단도 제외하지 않습니다. 메모 28쌍 모두 같은 흐름에 속하며, 문단 간 사례 1개와 root 아닌 리스트 내부 사례 1개를 포함합니다. 끝 토큰 번호 식별은 앞 단계에서 독립 대조한 mode 91을 재사용하고, 범위 소유권의 기대값은 제품 Flows로 만들지 않습니다.

적대적 검증은 중첩 리스트 전후의 바깥 흐름 유지, 빈 리스트와 같은 부모의 다음 리스트, unknown 형제 삽입, 여러 root 문단, 빈 Tree, 고아 리스트/문단, 선언 개수 불일치, 레벨 점프, 직접 전달한 그룹의 누락/중복/범위 초과 및 모든 네이티브 할당 실패를 포함합니다. WASM 합성 정상/복구 9회·거부 4회를 검사합니다. 시작/끝의 짝·닫힘·중첩 규칙은 아직 다음 범위이며 원본 fixture는 수정하지 않았습니다.

최종 Debug·ReleaseSafe·ReleaseFast audit 모두 네이티브 244/244, Node 47/47, HWP5 WASM 1,370,253회 검사 통과했습니다. CFB 12,000회 변이 trap 0이며 Zig 포맷·변경 JS 문법·diff 검사도 통과했습니다. 로그는 `/tmp/hwpjs-paragraph-flows-{debug,safe,fast}.log`입니다. 이 결과는 문단 흐름 소유권 계층의 검증이며 시작·끝 범위 검증 완료가 아닙니다.

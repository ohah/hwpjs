# 입력 표면 응답과 콜백 오류

`packages/vanilla/src/core-bridge.ts`는 입력 표면의 요청과 코어 응답을 연결합니다. Native/core의 적용 결과와 UI 응답 콜백의 예외를 별도로 처리합니다.

## 계약

- 성공 응답을 전달한 뒤 UI 콜백이 예외를 던져도 미적용 응답을 추가로 보내지 않습니다. 이미 반영된 텍스트나 이력을 자동으로 되돌리거나 재요청하지 않습니다.
- 대기 상태는 요청 고유 ID와 문서 ID·generation을 함께 확인해 해제합니다. 콜백이 같은 문서 또는 새 문서의 다음 요청을 보낸 뒤 예외를 던져도 그 다음 요청은 대기 상태를 유지합니다.
- 응답 전달 뒤의 UI 오류는 `InputSurfaceAcknowledgementCallbackError`로 보고하며 원래 오류를 `cause`에 보존합니다. 오류의 문서 ID·generation은 원래 요청을 가리킵니다.
- 응답 전 요청 실패는 기존 오류 응답을 한 번 전달합니다. 닫힌 표면의 늦은 응답은 UI 콜백을 실행하지 않습니다.

## 검증 범위

기존 HEAD에서 콜백 재진입과 예외가 성공 응답 뒤 미적용 응답을 추가하거나 다음 요청의 대기를 해제하는 반례를 재현했습니다. 수정 후 같은 문서·문서 전환·요청 실패·정상 연속 응답·close 반례를 검사했습니다.

명시한 `3fc` WASM의 실제 HWP5/HWPX 검사 2건은 텍스트와 Native 이력 revision, 저장 결과의 독립 CFB/XML 비교, 잘못된 기대값 거부, undo 원본 바이트 복귀, redo·재열기를 확인했습니다. 프로토콜 6건을 포함해 Bun 실행 8건이 통과했습니다. 기존 bridge 회귀 4건도 별도로 통과했습니다.

이 검사는 UI 콜백 예외 조건의 기존 결함에 대한 근거입니다. 모든 빠른 입력 손실의 원인이나 입력 성능 개선·전체 조판 동치를 증명하지 않습니다. 실제 브라우저 E2E와 데모 반영은 별도 검증입니다.

명령은 [개발·검증 명령](development-commands.md#입력-표면-응답-검증)이 소유합니다. 정규 테스트는 특정 WASM SHA를 강제하지 않으며, `HWPJS_TEST_WASM`을 생략한 실행에서 Native 2건은 명시적으로 skip됩니다. 코어 소스의 JSON import를 사용하는 Native 검사는 Bun으로 실행합니다.

# JPEG 양자화 테이블 보존과 역양자화 작업

양자화 테이블 보존과 정수 역양자화를 구현했습니다. 출력은 변환 계수이며 픽셀은 아닙니다.

## 근거와 책임

[ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) A.3.4~A.3.6 및 Figure A.6을 참조합니다. Figure A.6은 렌더링한 공식 PDF로 직접 확인했습니다. 텍스트 추출에서 한 자리 숫자 앞에 잘못 붙은 `1`을 매핑 값으로 사용하지 않았습니다.

- `zigzag.zig`: 행렬 위치별 wire 인덱스 64개를 단일 표로 소유합니다. 역방향 표는 컴파일 시 생성하고 중복을 거부합니다. 범위를 벗어난 양방향 조회는 null입니다.
- `dequantization.zig`: wire 순서의 i32 계수와 파싱된 양자화 테이블을 받아, 같은 wire 위치끼리 곱한 i64 결과를 8×8 row-major 순서로 반환합니다. i32×u16의 전체 범위가 i64에 들어가므로 잘림·포화·부동소수점 반올림을 하지 않습니다. 명세는 역양자화 결과가 기대 범위를 벗어날 수도 있음을 명시하므로 임의로 계수를 clamp하지 않습니다.
- `sequential_frame.zig`의 반환 블록은 기존 스캔 계수 구조를 `coefficients`로 포함하고 당시의 `quantization` 테이블 뷰를 함께 보존합니다. 필드를 별도 복제한 구조를 만들지 않습니다. 이후 같은 destination이 재정의되어도 앞서 반환한 뷰는 이전 입력 바이트를 가리킵니다. 입력 바이트는 디코더와 반환 뷰를 사용하는 동안 불변·유효해야 합니다.

코어는 할당하지 않습니다. 테이블 원본 검사와 프레임별 사용 제약은 기존 DQT 파서/스캔 선택 계층이 소유합니다. 역양자화 함수는 그 검사를 통과한 테이블을 요구합니다. IDCT·레벨 이동·픽셀 clamp·색 변환은 이 모듈의 책임이 아닙니다. 제품 JS API는 변경하지 않았습니다.

## 검증 현황

- 새 네이티브 5개와 기존 JPEG 검사 포함 Debug/ReleaseSafe/ReleaseFast 각각 71/71 통과. 독립 대각선 순회로 양방향 인덱스 64개를 확인하고, 모든 위치의 impulse 계수와 부호·최솟값/최댓값, 서로 다른 8/16비트 양자화 값을 대조했습니다.
- 모든 nonzero u16 양자화 값 65,535개에 i32 최솟값/최댓값을 곱해 모든 64개 출력 위치를 i128 기반 기대값과 비교했습니다.
- 테이블 destination 재정의 뒤 보관한 이전 블록들의 테이블 값이 유지되는지 확인했습니다. 스캔 순서와 다른 프레임 위치, 서로 다른 destination 3/2/0도 별도로 검사했습니다.
- Debug WASM mode 255는 매핑 양방향 128바이트와 i64 역양자화 값 64개를 반환합니다. 서로 다른 16비트 Q와 교대 i32 최솟값/최댓값을 JS BigInt 곱셈·대각선 순회 기대값과 대조해 일치했습니다.
- mode 256은 기존 mode 254의 프레임 보고서 헤더를 공유하고 각 블록에 성분/좌표, 보존한 Q 메타데이터·원값, i64 행렬을 반환합니다. Q를 1→4→5로 바꾼 3스캔 합성 프레임이 Debug 독립 기대값과 일치했습니다. 기존 mode 254의 바이트 형식은 유지했고 196건 비교·166건 거부 회귀 검사도 통과했습니다.

- 세 모드 각각 독립 mode 255 비교 66,686건·거부 392건, mode 256 프레임 비교 37건·출력 한도 거부 1건이 통과했습니다. 빈 테이블은 기존 공통 테이블 커서의 `EmptyJpegTableSegment` 오류로 거부합니다. JS는 대각선으로 생성한 순서와 BigInt 곱셈으로 기대값을 구성합니다.
- 세 모드에서 실제 HWP sequential JPEG 참조 7건의 20,089블록에 대해 성분·좌표·Q 메타데이터/원값·역양자화 행렬 전체가 독립 기대값과 일치했습니다. `reference/rhwp/samples/s1.jpg`의 1,197블록도 세 모드에서 확인했습니다. Progressive 참조는 명시적으로 제외하며 픽셀 검증으로 간주하지 않습니다.
- 세 모드 출력 변조는 mode 255의 모든 640바이트, mode 256의 3블록 프레임 헤더/메타데이터/모든 Q 값/모든 i64 상하위 워드 603곳에서 XOR 1을 각각 적용해 모두 검출했습니다.
- 별도 12비트 연결 조사: 1×1 SOF1 프레임에 DC category 15, AC size 14를 사용해 wire 위치 0/1/16에 계수를 배치했습니다. DC와 AC의 최대 magnitude에서 부호를 반전한 두 입력, destination 3의 16비트 Q 값 `65535 - 997*i`를 사용해 엔트로피→테이블 선택→역양자화 전체 결과가 세 모드 모두 일치했습니다. 이 별도 조사 수치는 정규 audit 합계에 포함하지 않습니다.

### 소스 결함 주입

별도 소스 복사본의 결함 4종을 Debug/ReleaseSafe/ReleaseFast에서 각각 실행했습니다. 모든 변형은 컴파일 성공 후 네이티브 테스트 실패로 검출했습니다.

- Zigzag 표의 인덱스 1/5를 교환하여 잘못된 순열 구성: 각 모드 71개 중 2개 실패.
- Q 조회에 wire 인덱스 대신 raster 인덱스 사용: 각 모드 1개 실패. 균일한 Q만 사용하는 검사는 이 결함을 잡지 못하므로 서로 다른 값과 모든 impulse 위치를 검사합니다.
- i64 곱셈 결과를 i32로 잘라 저장: 각 모드 2개 실패.
- 성분의 실제 destination 대신 Q0 사용: 각 모드 1개 실패. Destination 0만 쓰는 재정의 테스트와 별도로 서로 다른 destination을 검사합니다.

Debug/ReleaseSafe/ReleaseFast 전체 audit는 각각 20/20 단계, 네이티브 787/787 테스트, 총 7,382,297건 검사로 통과했습니다. 전체 회귀 합계이며 픽셀 동일성이나 전체 문서 구현 완료를 뜻하지 않습니다.

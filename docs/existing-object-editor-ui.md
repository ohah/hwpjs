# 기존 차트·수식 편집 도구

데모의 **도구 → 기존 차트 데이터 편집 / 기존 수식 편집**은 문서에 이미 있는 HWPX 개체를 수정합니다. 새 개체를 생성하는 명령과 구분하며 HwpCtrl 호환 API는 구현 범위에 포함하지 않습니다.

## 책임과 현재 범위

- `apps/demo/src/chart-data-port.ts`는 현재 문서의 차트 대상·편집 한도·원본 값과 revision을 확인합니다. `chart-data-controller.ts`는 창의 수명과 비동기 응답을 관리하며 `chart-data-view.ts`가 목록과 입력을 표시합니다. 변경된 값만 기존 `chart-points-set` 명령 한 번으로 전달합니다. XML과 OLE의 동시 변경·유효성·저장·이력은 기존 Native 구현이 소유합니다.
- `apps/demo/src/equation-port.ts`는 현재 Core token으로 목록·script 조회와 수정 요청을 연결합니다. `equation-view.ts`는 기존 `web/preview/equation-controls.mjs`와 `equation-edit-state.mjs`의 목록·초안·revision 검사를 재사용합니다. 별도의 수식 편집 모델을 만들지 않습니다.
- `demo-controller.ts`는 공개 메뉴와 도구의 가용성·포커스 복귀·종료를 연결합니다. 텍스트 선택은 필요하지 않으며 현재 문서와 엔진의 명시적 기능 관측이 필요합니다. 읽기 전용·오래된 문서 상태·미지원 형식을 임의로 활성화하지 않습니다.

차트는 기존 지원 값의 숫자·문자열 편집만 제공합니다. 차트 생성·종류 변경·축·범례·색상 설정, HWP5 차트 데이터 편집은 이 도구의 범위가 아닙니다. 수식은 기존 script 수정이며 새 수식 삽입이나 한컴과 동일한 수식 조판을 보장하지 않습니다.

## 실패와 이력

조회는 `readResource`로 수행해 편집 이력을 만들지 않습니다. 수정은 Core의 기존 입력 정착과 token 검사에 참여하는 `requestExperimental`을 사용합니다. 포맷별 source 좌표를 UI에서 재발급하거나 변경된 revision에 자동으로 맞추지 않습니다.

창이 닫히거나 문서가 교체되면 늦은 응답을 설치하지 않습니다. 명시적인 미적용 거부와 전송 뒤 결과 불명을 구분하며 결과 불명에는 같은 명령을 자동 재시도하지 않습니다. 차트의 여러 값 수정은 하나의 배치로 제출하므로 기존 Native 트랜잭션의 한 번 실행 취소 단위를 유지합니다.

## 검증의 구분

포트·컨트롤러 단위 검사는 capability, token/revision, 오래된 응답, 중복 요청, 종료, 오류 후 상태를 검사합니다. 이 검사는 실제 파일 저장이나 Canvas 실행 증거를 대신하지 않습니다.

실제 수식 확인 대상은 공개 픽스쳐 `latex.hwpx`입니다. `chart.hwpx`에는 이 도구가 다루는 차트 XML/개체가 없으므로 차트 편집 양성 증거로 사용하지 않습니다. 차트 편집 확인에는 기존 공개 `noori.hwpx`에 자체 작성한 차트 XML과 일치하는 OLE를 추가한 합성 문서를 사용하며, 원본 한컴 문서에서의 검증과 구분합니다. 합성 문서는 검증 산출물로만 보관합니다.

브라우저에서는 실제 메뉴 열기·수정·단일 실행 취소/다시 실행·파일 저장·재열기의 결과를 확인해야 합니다. 배포 여부와 실제 완료한 시나리오는 검증 산출물에서 별도로 기록합니다.

2026-11-14 확인: Native879를 유지한 production 데모를 Vanilla 브라우저에서 검사했습니다. `latex.hwpx`의 첫 script 수정 후 내려받은 파일은 20개 script 중 하나만 달라졌고 나머지 19개 및 다른 ZIP 항목은 동일했습니다. 저장 파일의 새로 열기와 별도 script 변경의 한 번 실행 취소·다시 실행도 확인했습니다. 자체 합성 차트에서는 범주와 숫자 두 값을 한 배치로 바꿔 한 번 실행 취소·다시 실행·저장·새로 열기를 확인했습니다. 독립 ZIP/XML과 SheetJS CFB 읽기로 대응 차트 XML/OLE 및 비대상 보존을 대조했습니다. 첫 SheetJS 작성 합성 픽스쳐는 엄격 CFB 검사에서 거부됐으므로, 엄격 검사를 통과한 자체 CFB writer 픽스쳐의 성공 증거와 분리했습니다.

초기 브라우저 관측에서 문서 입력 textarea와 수식 창 textarea를 구분하지 않은 값 조회는 무효 증거로 보존했습니다. 최종 관측은 수식 창으로 selector를 한정하고 비동기 조회 완료와 실제 값을 기다립니다. React/Svelte의 실제 편집·저장, 한컴 원본 차트 corpus, HWP5 차트 편집과 전체 조판 동치는 이번 브라우저 검증에 포함하지 않았습니다.

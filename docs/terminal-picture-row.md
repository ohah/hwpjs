# 마지막 개행 뒤 삽입 행

`picture-page-text-line.mjs`는 마지막 hard break 뒤에도 원문 끝 UTF-16 위치의 빈 행을 한 번 생성합니다. 빈 행의 글꼴 높이는 기존 `pictureFlowLine` 측정 결과를 재사용합니다. 행이 페이지에 안 들어가면 기존 페이지 넘김을 사용하며 그림 예약 영역도 피합니다. LF·CR·CRLF를 구분 없이 유효한 표시 개행으로 처리하되 원문을 변경하지 않습니다.

`pageParagraphCoverage`는 마지막 문자가 hard break일 때만 원문 끝의0길이 삽입 행을 한 번 허용합니다. 중간 위치·중복 빈 행·개행 없는 문단에 붙인 빈 행은 거부합니다. 빈 문단은 기존대로 정확히 하나의0길이 행을 요구합니다. 이 검사는 원문 구간 보존이며 픽셀 배치나 모든 glyph의 동치를 보증하지 않습니다.

`terminal-picture-row.test.mjs`의4개 회귀는 수정 전 모두 실패했고, 수정 후 LF/CR/CRLF·큰 글꼴의 다음 페이지 이동·그림 예약·중복/중간/가짜 삽입점 거부가 통과했습니다. 격리 게시 소스의 관련11/11, skip0입니다. 추적 HWPX XML의 읽을 수 있는 구역에서는 마지막 개행 패턴을 찾지 못했으며 암호 구역1개는 조사하지 못했습니다. 실제 사용자 파일 전체에서 재현했다고 주장하지 않습니다.

현재 작업 트리의 주변 그림·페이지 검사는37/37입니다. 초기36/37에서 실패한 줄 간격 기대값은 기존 HEAD 함수와 수정 함수를 같은 의존성으로 호출해도 둘 다48px였습니다. 게시된 HWP5 행간 계약상 원값7200은 거리3600/75=48px이므로 기존 로컬 미추적 테스트의 기대를48/68/48px로 맞췄습니다. 그 미추적 테스트 전체를 이번 커밋에 포함하지 않고 제품 행간 산술도 변경하지 않았습니다.

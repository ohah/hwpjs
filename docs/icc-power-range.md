# ICC 거듭제곱 분기의 정확한 출력 범위

## 계약

`power_range.build(precision, curve)`는 활성 거듭제곱 분기의 전체 clipped 출력 범위를 반환합니다. 결과는 inactive, undecided, range이며 미확정이면 일부 경계를 반환하지 않습니다. 전체 곡선의 실수 정의역 검증은 기존 power_partition→parametric_segments 경로가 먼저 수행합니다. 비단조 곡선도 출력 범위는 구할 수 있으므로 역변환 적격성 검사를 추가하지 않습니다.

활성 분기의 원래 입력은 닫힌 [start,1]이고, 정의역 검증을 통과한 실수 거듭제곱과 클리핑은 그 위에서 연속입니다. 따라서 출력은 양 끝을 실제로 포함하는 연결된 구간입니다. 반환 lower/upper는 각각의 정확한 출력값과 그 값을 실제로 만드는 입력 at을 보존합니다. at은 증거점이며 F.1에서 선택해야 하는 우선 역상이라고 보장하지 않습니다.

출력값은 rational(클리핑된 정확한 0/1) 또는 power(base^(g/65536)+offset/65536의 정확한 식)입니다. power는 엄격히 0과 1 사이임을 확인한 값이며, 반드시 무리수라는 뜻은 아닙니다. g=0 또는 base=0 등 유리수로 평가 가능한 경우도 식으로 보존할 수 있습니다. 근사값이나 완전한 기약식 표준화를 제공하지 않습니다.

## SSOT와 파일 책임

- `same_power_order.zig`: 동일한 지수를 적용한 두 유리수 밑의 출력 순서. 기존 rational_power_order의 0 대상 비교로 양쪽 정의역·부호를 검증합니다. 이 경로는 정확한 부호 조기 판정이므로 정밀도 부족이 없습니다. 같은 부호에서는 밑의 절댓값 교차곱을 u256으로 비교하고 음의 지수와 음수 출력의 순서 반전을 적용합니다. 공통 offset은 순서에서 소거됩니다. 서로 다른 지수/offset의 값 비교 API가 아닙니다.
- `power_ordinate.zig`: 포함되는 한 점에서 출력 0/1 클리핑을 정확히 판정하고 식으로 보존합니다. 기존 power_level_order를 재사용하며 null은 정밀도 부족입니다. 점의 정의역과 포함 여부는 검사하지만 전체 분기 정의역 검증은 caller 책임입니다.
- `power_range_types.zig`: 범위와 증거점 결과 타입.
- `power_range.zig`: 기존 단조 조각들의 끝점에서 원시 최솟값/최댓값을 고른 뒤 두 값에 클리핑을 적용합니다. 내부 밑 영점도 기존 partition에 포함되므로 접힌 곡선의 내부 극값을 놓치지 않습니다. 조각의 열린 끝점도 원래 닫힌 활성 분기에는 속하므로 실제 증거점으로 사용할 수 있습니다.

g/부호/정의역·밑 영점·클리핑 경계를 이 계층에 다시 구현하지 않습니다. 유효한 i128/u128 밑의 절댓값 교차곱은 u256에 들어가며 minInt(i128)의 절댓값도 unsigned로 유지합니다. 코어는 할당·파일 접근·부동소수점 계산을 하지 않습니다.

## 검증 진행

신규 네이티브 5개가 통과했습니다. 같은 지수의 홀짝·음수·역수 부호, 양쪽 입력 검증, 넓은 분수, 접힌 곡선의 내부 최솟값, offset 후 클리핑, 감소/비정수 지수 출력, g=0 상수 증거점, 비활성·마지막 단일점과 전체 정의역 오류를 검사합니다.

정밀도 반례는 type4 `[131072,65536,0,0,0,-32768,0]`, 즉 clip(x²−1/2)의 포함점입니다. x=11749380235262596085/16616132878186749607은 정확히 2*n²−d²=1인 양의 출력점입니다. 128 정밀도에서 출력 클리핑 판정은 미확정이고 512/1024에서는 양의 power 식을 보존합니다. 반대쪽 x=4866752642924153522/6882627592338442563은 2*n²−d²=−1이며 128에서도 정확한 0 클리핑을 판정합니다. 이는 단일 출력값 helper의 반례이며 전체 range.build가 이 입력을 생성한다는 주장은 아닙니다.

## WASM 독립 대조

테스트 mode205는 precision u32 BE와 para 태그를 받습니다. status u32 LE는 0=inactive, 1=undecided, 2=range이고 앞의 두 결과는 4바이트, range는 172바이트입니다. 두 증거점은 각각 84바이트로 x n/d u64 LE, 값 tag u32 LE, payload 64바이트를 갖습니다. rational payload는 n/d u256 LE이며 power payload는 base n i128/d u128 LE, g/offset i32 LE와 24바이트 0 패딩입니다.

mode206은 precision 뒤 x n/d u64 BE와 para 태그를 받아 단일 점 helper를 검사합니다. status 0은 4바이트 미확정, status 1은 88바이트 증거점입니다. probe가 전체 curve를 검증해 활성 source를 구성한 뒤 점을 평가합니다. 성공 결과 할당 후 오류 가능한 작업은 없고 모든 바이트를 초기화합니다. 제품 JS API는 변경하지 않았습니다.

독립 JS 기준은 source 양 끝과 내부 밑 영점을 후보로 열거하고 작은 정수 거듭제곱을 BigInt 분수로 직접 계산해 최솟값/최댓값을 정합니다. 명시적인 비정수 예제는 완전제곱의 정확한 제곱근으로 계산합니다. 반환 증거점의 활성 구간 포함, 실제 함수값, 식의 base/g/offset, 0/1 클리핑과 패딩을 따로 검증합니다. 제품의 same_power_order를 기대값 생성에 사용하지 않습니다.

직접 Debug WASM 실행은 ranges=1743/inactive=324/rejected=1271/points=3/undecided=1로 통과했습니다. 각 수치는 별도 호출이며 합계는 3,342건입니다. type0..4, 음/양/0 지수, 밑/offset/활성 시작 조합, 네 정밀도의 접힘·상수·비정수·terminal, 실제 정밀도 반례, 잘림·과잉·한도·정밀도·점 좌표/범위·비활성 source·오류 후 복구를 포함합니다.

최솟값/최댓값 교환, 최솟값을 최댓값으로 덮기, power 식의 offset 변경, 미확정 점을 정확한 0인 것처럼 반환하는 네 변형을 각각 ERR_ASSERTION으로 검출했습니다. 제품 소스에는 변형을 남기지 않았습니다. 전체 세 모드 감사는 진행 중입니다.

## 실제 ICC 태그 대조

시스템 DCI(P3) RGB·Display P3·ITU-2020·ITU-709·ROMM RGB의 RGB TRC 태그 15개를 읽기 전용으로 검사했습니다. type0/type3, 양의 지수·기울기, 0≤start<1, a+b=65536을 확인했습니다. 활성 거듭제곱 분기는 증가하므로 독립 기대 증거점은 start와 1입니다. type0의 출력 0/1, type3 하한의 정확한 affine 밑·원본 지수·offset=0·0<base<1, 상한의 정확한 1이 모두 일치했습니다. 비정수 하한은 소수 근삿값으로 비교하지 않았습니다.

이는 상위 분기 출력 범위 15건의 수동 확인으로, 하위 분기와의 점프·전체 역변환·렌더링을 검증한 것은 아닙니다. 정규 audit 호출 수에는 합산하지 않습니다.

## 최종 감사와 적대적 재검토

Debug·ReleaseSafe·ReleaseFast 전체 audit가 각각 종료 코드 0, 20/20 단계, 네이티브 575/575, WASM checks=6,569,472로 통과했습니다. 신규 3,342건이 이전 6,566,130건에 추가됐습니다. 각 모드 신규 결과는 ranges=1743/inactive=324/rejected=1271/points=3/undecided=1입니다. 로그는 `/tmp/hwpjs-icc-power-range-{Debug,ReleaseSafe,ReleaseFast}.log`입니다. 앞의 진행 중 문장은 이력이며 최종 결과는 이 절을 기준으로 합니다.

ReleaseSafe·ReleaseFast 산출물 직접 실행도 같은 신규 수치로 통과했고 최솟값을 최댓값으로 덮는 변형을 각각 검출했습니다. 변경 Zig 포맷·JS 문법·diff 공백·문서 로컬 링크 1개를 확인했습니다.

최종 재검토는 양쪽 밑의 정의역 선행 검증, 음수/역수 부호, 같은 지수와 offset 조건, 기존 단조 분할의 내부 영점 보존, 원래 닫힌 source의 증거점, 클리핑 후 범위의 연결성, 미확정의 부분 결과 비노출, 정확한 식 보존, 결과 버퍼 전체 초기화를 확인했습니다. 이 범위에서 추가 결함은 발견하지 않았습니다.

## 남은 범위

하위 선형 분기와 전체 출력 범위 조립, 서로 다른 기호적 출력값의 거리 비교, 최근접 출력의 존재/동률과 F.1(a) 연결은 미완료입니다. 전체 ICC 역변환이나 HWP/HWPX 문서 기능 완료로 해석하지 않습니다.

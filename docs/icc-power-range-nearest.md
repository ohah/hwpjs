# ICC 거듭제곱 분기의 최근접 출력

## 계약과 책임

`power_range_nearest.select(precision,curve,target)`는 원본 곡선의 상위 거듭제곱 분기에서 목표 u128 분수에 가장 가까운 출력값을 선택합니다. 전체 곡선의 두 분기를 비교하거나 역변환 입력 x를 선택하지 않습니다. 결과 타입은 power_range_nearest_types에 분리합니다.

- inactive: 상위 분기가 비활성입니다. 전체 곡선 출력이 비어 있다는 뜻이 아닙니다.
- undecided: 출력 범위 또는 목표와의 순서를 현재 정밀도로 확정하지 못했습니다.
- target: 목표값 자체가 실제 출력 범위에 속합니다. 입력 분수 표현을 그대로 보존합니다.
- endpoint: 목표가 범위 밖이므로 가장 가까운 끝점의 정확한 출력 식과 증거점을 반환합니다. 증거점은 F.1 우선 역변환 좌표가 아닙니다.

먼저 목표를 검증하고 [상위 출력 범위](icc-power-range.md)를 생성하여 전체 실수 정의역을 검증합니다. [출력 순서 비교](icc-ordinate-order.md)를 재사용합니다. 목표가 하한보다 작거나 상한보다 크면 해당 끝점을, 끝점과 같거나 두 끝점 사이면 목표를 반환합니다. 한 끝점과의 확정된 비교만으로 선택을 증명할 수 있으면 다른 비교의 정밀도를 요구하지 않습니다. 판단 근거가 부족하면 미확정을 유지합니다.

실수 정의역을 검증한 거듭제곱 식은 닫힌 활성 입력 구간에서 연속이며 클리핑도 연속입니다. 따라서 출력은 닫힌 연결 구간이고 그 구간 안의 목표는 실제로 존재합니다. 원본 입력 함수가 접히더라도 이 결론은 같습니다. 출력값 기준 최근접은 하나지만 해당 출력의 입력 좌표가 하나라는 주장은 아닙니다. 임의로 구성한 범위 구조를 받아 연속성을 가정하지 않고 원본 curve로부터 공통 factory를 호출합니다.

## 검증 진행

신규 네이티브 3개가 접힌 입력·내부 출력·감소 구간·상수·마지막 단일점·비활성·잘못된 목표와 실수 정의역 오류를 검사해 통과했습니다. 실제 정밀도 반례는 type3 `[32768,0,32768,0,0]`의 상수 sqrt(1/2)와 목표 11749380235262596085/16616132878186749607입니다. 128에서 undecided, 512에서 실제 끝점 출력이 선택됩니다.

테스트 mode209 입력은 기존 precision u32 BE + 목표 n/d u128 BE + para 태그입니다. 출력 status u32 LE는 0=inactive(4바이트), 1=undecided(4), 2=target(36, 목표 n/d u128 LE), 3=endpoint(88, 공통 끝점 wire84)입니다. 길이·한도·정밀도·원본 태그·목표 유효성을 검사합니다. 결과 할당 이후 오류 가능한 연산은 없으며 모든 출력 바이트를 초기화합니다.

독립 JS 기준은 기존 후보점 열거·정확한 BigInt 출력 범위 oracle을 공유합니다. 목표를 그 범위에 투영한 기대값과 실제 반환 상태·분수·끝점 함수값·증거점 포함·식·패딩을 대조합니다. 기대값을 제품 range 결과로부터 만들지 않습니다. 입력 형식과 타입 필드 수는 기존 preimageInput을 재사용합니다.

직접 Debug WASM 실행은 targets=3597/endpoints=3293/inactive=1308/rejected=4881/undecided=1, 총 13,080건이 통과했습니다. 기존 powerRange 3,342건과 parametricRange 3,292건도 oracle 추출 후 같은 결과를 유지했습니다. 항상 목표값 반환·미확정을 비활성으로 변경·목표 출력 변조를 각각 ERR_ASSERTION으로 검출했습니다. 제품에 변형을 남기지 않았습니다.

전체 세 모드 audit 결과는 아래 최종 확인 절을 기준으로 합니다.

별도 `/tmp` 소스 복사본에서 마지막 미확정을 target으로 바꾸는 네이티브 변형을 실행했습니다. Debug·ReleaseSafe·ReleaseFast 모두 실제 sqrt(1/2) 정밀도 반례에서 TestUnexpectedResult로 실패하여 잘못된 구현을 검출했습니다. 원본에는 변형을 적용하지 않았습니다. JS의 목표 변조는 다른 유효한 정규화 분수 0/1 또는 1/1로 바꾸는 경우도 별도로 검출했습니다.

## 실제 프로파일 대조

시스템 DCI(P3) RGB·Display P3·ITU-2020·ITU-709·ROMM RGB의 RGB TRC 15개에서 목표 0/1을 대조했습니다. type0은 두 목표 자체를 반환합니다. type3은 양의 g/a, 0<d<65536, a+b=65536과 0<(a*d+b*65536)/65536²<1을 먼저 확인하여 목표 0에는 시작점 d/65536의 상위 출력, 목표 1에는 1 자체가 가장 가까움을 독립적으로 정했습니다. 반환 시작점·정확한 affine 밑·원본 지수·offset=0·패딩 및 목표 분수가 모두 일치했습니다. 30건의 수동 확인이며 정규 audit 호출 수에는 합산하지 않습니다. 전체 곡선의 선형 분기와 비교하거나 OS 색변환·HWP 렌더링을 검증한 것은 아닙니다.

## 최종 확인

Debug·ReleaseSafe·ReleaseFast 전체 audit가 각각 종료 코드 0, 20/20 단계, 네이티브 585/585, WASM checks=6,587,669로 통과했습니다. 신규 13,080건이 이전 6,574,589건에 추가됐습니다. 신규 결과는 세 모드 모두 targets=3597/endpoints=3293/inactive=1308/rejected=4881/undecided=1입니다. 로그는 `/tmp/hwpjs-icc-power-nearest-{Debug,ReleaseSafe,ReleaseFast}.log`입니다.

ReleaseSafe·ReleaseFast의 실제 감사 산출물 직접 실행에서도 같은 신규 수치를 확인하고 미확정을 비활성으로 바꾸는 변형을 각각 ERR_ASSERTION으로 검출했습니다. 변경 Zig 포맷·JS 문법·diff 공백과 관련 문서 로컬 링크 4개도 확인했습니다.

최종 적대적 재검토에서는 목표 선행 검증, 공통 factory의 전체 정의역 검증, 닫힌 연결 출력 구간의 존재성, 값의 최근접 유일성과 입력 역상 유일성의 구분, 끝점과 같은 목표의 분수 보존, 확정 비교에 의한 조기 반환과 미확정 전파, 비활성과 전체 출력 부재의 구분을 확인했습니다. 결과 타입·선택 정책·WASM 직렬화·독립 oracle의 책임이 분리되어 있으며 이번 범위에서 추가 결함은 발견하지 않았습니다.

## 남은 범위

하위 후보와의 결합은 [전체 최근접 출력 선택](icc-parametric-nearest.md)에서 구현·검증 상태를 관리합니다. 최종 F.1(a) 역변환 입력 선택은 미완료입니다. 전체 ICC 역변환·PNG 픽셀 연결·HWP/HWPX 전체 문서 검증 완료를 의미하지 않습니다.

# 원본 표 셀의 여러 문단

원본 표의 행·열 변경은 비병합 직사각형 셀의 일반 문단 목록을 처리합니다. 파일 명령과 열린 세션은 형식별 구역 변환기를 공유합니다. 기존 셀의 문단 수·순서·본문·서식·ID는 보존하고 삭제한 셀의 전체 문단은 같은 Native 이력으로 복원합니다. 필드·중첩 개체·줄 캐시·보호 셀 등의 기존 거부 조건은 유지합니다.

## 삽입 정책

새 셀은 선택한 템플릿의 **첫 문단 서식을 사용한 빈 문단 하나**로 만듭니다. 후속 문단과 본문을 복제하지 않으며 새 문단 ID도 셀당 하나만 발급합니다. 이 정책은 문서 형식이 강제하는 편집 방식이라는 뜻이 아닙니다. 생존 셀의 여러 문단을 빈 문단 하나로 축약하지 않습니다.

HWP5는 모든 직접 문단과 본문·글자 모양 레코드를 검사합니다. 복제한 셀의 리스트 문단 수는 1이며, 첫 문단의 서식을 유지하면서 문자 수 상위 비트는 마지막 템플릿 문단의 원값을 승계합니다. 한컴의 [공식 revision 1.3 PDF](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf)는 문자 수에서 상위 비트를 분리하지만 그 의미를 설명하지 않습니다. 이를 새 명세 필드나 리스트 소유권 판정으로 해석하지 않습니다. 승인된 Noori HWP의 독립 CFB 관측에서는 표 문단 리스트 40개의 끝 문단만 이 비트가 켜져 있었으며, 여러 문단인 리스트 2개도 같은 패턴이었습니다. 단일 문단 셀의 기존 동작은 유지됩니다.

문자 수 0이며 TEXT 레코드가 없거나 payload가 빈 문단도 수용합니다. 원본의 레코드 부재와 빈 레코드를 구분해 보존하며, 이 경우 문자 모양은 위치 0의 한 항목만 허용합니다. 양수 문자 수인데 TEXT가 없거나 비어 있는 경우는 계속 거부합니다. 이는 표 편집의 제한된 입력 정책이며 공유 파서의 보존 정책을 변경하지 않습니다.

HWPX는 단일 subList 안의 모든 직접 p·plain run/t를 검사합니다. 새 셀의 첫 p 안에 있는 t 본문은 모두 비우고 후속 p의 전체 원문 범위를 제거합니다. 생존 셀의 p 원문은 그대로 보존합니다. 문단 목록 구조는 [한컴의 HWPX 본문 설명](https://tech.hancom.com/python-hwpx-parsing-2/)과 기존 namespace-aware 트리 계약을 참고합니다. 전체 XSD 적합성이나 한컴의 삽입 정책과의 동치를 보증하지 않습니다.

## 선택과 이력

커서 복원 정보는 같은 셀 안의 문단 순번을 사용합니다. 생존 셀의 문단 수·본문 순서와 새 관측의 소유자를 확인하고 선택 문단을 복원합니다. 선택한 셀이 삭제되면 검증된 인접 셀의 첫 문단 시작으로 이동합니다. 변경 전 노드·리스트·문단 번호를 새 관측에 그대로 재사용하지 않습니다. 기존 Native revision·token·Surface lease 검사와 입력 잠금 검증을 유지합니다.

## 처리 비용과 검증 범위

형식별 변환기는 직접 문단을 순서대로 검사하고 이미 정렬된 원문 변경 범위를 선형으로 조립합니다. JS의 선택 매핑은 Map·Set으로 문단과 중복을 색인합니다. 이 경계를 컨테이너 압축·XML 파서·전체 조판의 최악 복잡도 보장으로 확대하지 않습니다. 실제 파일·SDK·Canvas·배포 근거는 각각 구분해 기록합니다.

## 확인 결과와 남은 제한

`source-grid-multipara-r1/`의 새 엔진은 `202fc55283b670ea7c695ef3a326a0e6b8c86af3def7232c8e5bfab003699389`입니다. 너비 36,000인 표에 폭 18,000의 열을 추가하면 본문 너비 48,190을 넘어 54,000이 됩니다. 실제 브라우저에서 이 입력은 `PageFlowLimit`과 logical fallback을 보였습니다. 저장·Native 이력 검사가 통과해도 조판 성공으로 표시하지 않습니다. 너비 초과 표의 조판, 병합/중첩/필드/줄 캐시를 포함한 복합 셀의 격자 편집과 미적용 셀 서식·배경색 intent의 동시 편집은 이번 지원 범위에 포함하지 않습니다.

공개용 정적 후보 `cac6324f0f2ebe20d66f929a7e94d15d7f541743d75228cae24644d7de783264`에서 실제 브라우저의 Vanilla·React·Svelte × HWP5/HWPX 6조합이 통과했습니다. 각 조합의 네 명령에서 실제 마우스로 둘째 문단을 선택하고, 편집·저장·실행취소·다시실행·텍스트 입력·재열기 결과를 독립 파일 오라클로 확인했습니다. `task-e/browser-r8/{summary,results,cleanup}.json`이 근거이며 소유 브라우저의 종료도 확인했습니다. 입력은 셀당 3문단, 열 삽입 후에도 본문 폭 안에 들어가는 독립 합성 표입니다. 전수 문서나 폭 초과 표의 성공으로 확대하지 않습니다.

# JPEG progressive 스캔 이력

## 근거와 책임

[ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) G.1.1.1.1/G.1.1.1.2와 B.2.4를 참조합니다. 외부 코드를 추가하지 않았습니다.

- `progression.zig`: Frame 선언 순서의 최대 4개 성분 × 64개 계수에 마지막 Al을 저장합니다. 255는 아직 선언되지 않은 계수이며 Al=0과 구분됩니다. 입력은 기존 파서를 통과한 progressive Frame/Scan입니다. AC 이전에 해당 성분의 최초 DC가 있어야 합니다. 최초 밴드 재선언과 이전 Al에 맞지 않는 Ah를 거부합니다. 밴드 순서를 정렬하거나 최초 밴드 경계를 고정하지 않으므로 임의 순서·분할·병합을 계수별로 검사합니다. 전체 스캔 성공 시에만 이력을 반영합니다.
- `table_store.zig`의 `installQuantizationTracked`: 기존 DQT 설치에 변경 목적지 bit mask를 추가합니다. 최초 설치와 동일 precision/원값의 재설치는 변경이 아닙니다. 한 세그먼트에서 변경했다 복원해도 변경 이력을 남깁니다. 기존 void 설치 API는 이 함수를 재사용하며, 오류 시 슬롯도 mask도 부분 반영하지 않습니다.
- `progressive.zig`: 한 Huffman progressive Frame의 테이블 선택·계수 이력·Q 변경 이력·스캔 예산을 조립합니다. 산술/다른 프로세스는 명시적으로 거부합니다. 스캔 예산은 기본 65,536이며 조정할 수 있습니다. 실패한 스캔은 이력과 개수를 변경하지 않습니다.

코어는 할당하지 않습니다. Frame/테이블/반환 view가 사용하는 입력 버퍼는 수명 동안 불변이어야 합니다. 원문은 복사하거나 기본값으로 치환하지 않습니다.

## 양자화 테이블 수명

이미 스캔한 성분의 Q 목적지가 변경되면 해당 성분에 변경 사실을 남기고, 이후 그 성분의 스캔이 다시 등장할 때 `AlteredJpegProgressiveQuantization`을 반환합니다. 변경 후 원값을 되돌려도 이 사실은 사라지지 않습니다. 아직 한 번도 스캔하지 않은 성분에는 이전 사용 이력이 없으므로 새 정의를 사용할 수 있습니다. 같은 Q 목적지를 공유하는 다른 성분이 앞 성분의 마지막 스캔 이후 새 정의를 사용하는 경우를 전역 영구 잠금으로 거부하지 않습니다.

## 보고 범위와 남은 작업

보고서는 성공한 스캔 수와 계수 선언의 미등장/부분 정밀도/Al=0 개수를 반환합니다. 이는 실제 계수 값이나 픽셀을 복호화한 결과가 아닙니다. 호출자는 완전히 처리한 스캔 이벤트를 순서대로 전달해야 합니다. [파일 구조 검사](jpeg-structure.md)가 DRI/DNL/RST/EOI의 선언·마커 위치를 검사합니다. 엔트로피 완료·MCU 개수·심볼 의미·픽셀 복호화는 후속입니다. 보고서의 Al=0 개수만으로 JPEG 전체 유효성을 인증하지 않습니다. 제품 JS API와 HWP JPEG 미지원 집계는 변경하지 않았습니다.

## 검증 기록

- 새 네이티브 6개와 기존 JPEG 테스트 포함 세 모드 각각 35/35 통과. 64계수 × 초기 Al 0~13 × 보정 Ah 1~13, 임의 밴드 순서·분할·병합·실패 원자성, 동일 Q 재설치·변경 후 복원·공유 목적지, 다성분 후반 오류와 예산 복구를 포함합니다.
- 독립 JS Map 기반 이력과 mode 249 WASM 비교는 세 모드 각각 11,664건·오류 거부 10,825건 통과.
- 실제 HWP JPEG 참조 8건의 기존 선택 검사를 유지하고, 그중 progressive JPEG 1건(`noori.hwp`)에는 이력 검사를 추가해 세 모드에서 통과했습니다. 참고 `s1.jpg`의 기존 검사와 새 연결도 세 모드에서 통과했습니다. 픽셀 대조는 아닙니다.
- Debug/ReleaseSafe/ReleaseFast 전체 audit는 각각 20/20 단계·751/751 네이티브 테스트·7,034,040건 검사로 통과했습니다. 이는 전체 회귀 검사 합계이며 JPEG 복호화 및 전체 문서 구현 완료를 뜻하지 않습니다.

### 추가 적대적 검증

별도 소스 복사본 세 개에서 아래 결함을 각각 하나씩 주입했습니다. `zig test <copy>/src/root.zig --test-filter JPEG`를 Debug/ReleaseSafe/ReleaseFast로 실행했으며, 모든 변형이 각 모드에서 컴파일 성공 후 35개 중 2개 테스트에 의해 검출됐습니다.

- 이전 Al과 Ah 비교를 없애고 미등장 여부만 검사 → 잘못된 보정을 허용하여 `TestExpectedError`.
- 각 계수를 변경할 때마다 실제 이력에 부분 반영 → 뒤쪽 계수/성분 실패 이후 상태 보존 검사가 `TestExpectedEqual`.
- Q 변경 이력의 스캔 사용 거부 조건을 비활성화 → 변경 후 복원 및 성분 간 공유 사례가 `TestExpectedError`.

별도 mode 249 출력 변조는 오프셋 0/4/8/12/16/20/24/87/88/151의 첫 바이트를 각각 XOR 1로 바꾼 뒤 독립 JS 검사기를 실행합니다. 세 모드 각각 10종 모두 assertion으로 검출했습니다. 앞·뒤 계수와 두 번째 성분의 이력까지 포함하며, 소스 결함 검출과는 별도 결과입니다.

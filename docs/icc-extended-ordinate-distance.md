# ICC 확장 목표의 거리 비교

## 계약과 계산 폭

`power_ordinate_distance.compareWide(precision,value,r,target)`는 기존 출력 표현과 u256 유리수 후보 r의 u512 목표에 대한 거리를 비교합니다. lt/eq/gt 또는 정밀도 부족 null이며 실제 도달 여부·후보 선택·역함수 입력 정책은 결정하지 않습니다. 기존 [거리 비교](icc-ordinate-distance.md)와 같은 계약을 폭만 확장합니다.

유리수 출력은 공통 ordinate_distance.compareWide를 사용합니다. 차이 분자는 u768, 목표 분모를 약분한 뒤의 거리 교차 곱은 u1024입니다. 거듭제곱 출력은 r과 2*target-r 사이 닫힌 반사 구간에 속하는지 기존 임계값 비교기로 판정합니다. 반사 구간은 [0,1]로 클리핑하지 않습니다. 양 끝은 i770, 공통 분모는 u768이며 offset 적용은 signed 801비트·unsigned 784비트면 충분하므로 i1024/u1024에서 계산합니다.

## SSOT

ordinate_distance의 절댓값 차이·교차 곱, ordinate_distance_band의 원래 후보·반사값·분모, power_ordinate_distance의 안/밖/경계/미확정 판정은 각각 기존·확장 경로가 공유합니다. power_ordinate_rational_order.Of(768)는 기존 offset 적용을 사용하고 rational_power_order.Of(1024)의 정확 등식·방향성 경계에 연결합니다. 할당·파일 접근·실수 근사는 추가하지 않습니다.

직접 구성한 power 값은 원래 식이며 자동 클리핑하지 않습니다. 임계값 비교·거리 비교는 서로 다른 두 기호적 출력의 일반 거리 비교나 최근접 후보 선택 API가 아닙니다. 고정밀 최근접 출력 선택·전체 ICC 역변환·HWP 이미지 통합은 후속 범위입니다.

## 독립 검증과 wire

mode233은 기존 확장 출력 비교의 200바이트 입력 뒤 r의 n/d u256 BE 64바이트를 붙인 264바이트입니다. 출력 i32 LE는 -1/0/1/2(미확정)입니다. 기존 mode210과 폭별 probe를 공유하고 출력 표현·목표 입력은 기존 공통 parser를 재사용합니다.

독립 JS 기준은 정수 지수의 실제 출력 분수를 계산한 뒤 두 절댓값 거리를 교차 곱합니다. 제품의 반사 구간 방식을 복제하지 않습니다. 양/음/영 밑·지수·극단 offset, 최대 u512 목표·u256 후보 분모, 중점 양옆의 이웃 목표, 미확정·동률·잘림·패딩·잘못된 분수·오류 후 복구를 검사합니다. 기존 직접 결과는 comparisons=5,390/rejected=900/undecided=1, 확장은 5,453/996/1입니다.

확장 네이티브는 signed 770비트 반사 구간, 단위 범위 밖 반사값, 거리 동률·양 방향, 중점 양옆의 u512 이웃을 유리수/거듭제곱 두 경로로 검사하고 실제 미확정 반례·오류·극단 offset을 포함합니다. 전체 네이티브는 670/670으로 통과했습니다.

순서 반전·동률을 lt로 변경·미확정을 동률로 변경·목표 상위 비트 제거를 ERR_ASSERTION으로 검출했습니다. 임시 소스 복사본에서 반사식의 계수 2를 제거하자 세 모드 모두 확장 네이티브 4개가 전부 실패했습니다. 제품에는 변형을 남기지 않았습니다. 로그는 `/tmp/hwpjs-extended-distance-mutant-{Debug,ReleaseSafe,ReleaseFast}.log`입니다.

## 실제 ICC 확인

시스템 para TRC 15개의 type0/type3·양의 g/a·type3 내부 시작점·a+b=65536·시작 밑 (0,1)을 확인했습니다. 시작 출력이 type0에서는 0, type3에서는 (0,1), 마지막 출력이 1이라는 독립 기준으로 (r,target)=(0,0),(1,1),(0,1),(1,0)의 거리를 대조했습니다. 최대 u512 목표 분모를 사용한 120건이 일치했습니다. 실제 HWP 렌더링·전체 단조성·중간 목표의 최근접 검색 검사는 아니며 정규 audit 호출 수에 합산하지 않습니다.

## 최종 감사

Debug·ReleaseSafe·ReleaseFast 전체 audit는 모두 종료 코드 0, 20/20 단계, 네이티브 670/670, WASM checks=6,965,389로 통과했습니다. 이전 6,958,939에 신규 6,450회 호출이 추가됐습니다. 로그는 `/tmp/hwpjs-extended-distance-{Debug,ReleaseSafe,ReleaseFast}.log`입니다. ReleaseSafe·ReleaseFast 산출물의 기존·확장 직접 대조와 네 출력/입력 변형 검출도 동일하게 통과했습니다.

변경 Zig 포맷·JS 문법·diff 공백·문서 로컬 링크 3개를 확인했습니다. 최종 재검토에서는 목표·후보 검증 우선순위, 반사 구간의 비클리핑·부호·분모 양수, 정확한 동률과 미확정의 구분, offset 적용 폭, 유리수 거리 교차 곱 폭, 기존 경로·parser 재사용, 출력 초기화를 확인했습니다. 이번 범위에서 추가 결함은 발견하지 않았습니다. 고정밀 최근접 출력 선택·전체 ICC 역변환·전체 HWP/HWPX 문서 검증은 미완료입니다.

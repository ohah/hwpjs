# ICC 전체 parametric 곡선의 최근접 출력

## 계약과 책임

[u512 목표의 최근접 출력 선택](icc-extended-parametric-nearest.md)은 기존 흐름·후보 조합을 공유하며 큰 목표를 원래 폭으로 보존합니다.

`parametric_nearest.select(precision,curve,target)`는 선형·거듭제곱 두 분기의 클리핑 출력 합집합에서 목표 u128 분수에 가장 가까운 실제 출력값을 선택합니다. 전체 실수 정의역을 검증하며, 곡선의 단조성·비상수성이나 F.1 역변환 입력 선택은 별도 계약입니다. 비단조 곡선도 최근접 출력 자체는 정의될 수 있습니다.

결과는 아래처럼 구분합니다.

- undecided: 범위 또는 거리 비교를 현재 정밀도로 확정하지 못했습니다.
- unattained: 거리의 하한은 있으나 그 거리를 실현하는 출력값이 없습니다.
- selected: 하나의 실제 출력값입니다. rational은 정확한 u256 분수이고 power_endpoint는 상위 분기의 정확한 식·증거점을 유지합니다. 증거점은 우선 역변환 입력이 아닙니다.
- tie: 서로 다른 두 실제 출력값이 동률입니다. linear와 power_endpoint는 분기별 순서이며 숫자 크기순이 아닙니다. 임의 우선순위로 하나를 버리지 않습니다.

실제 전체 곡선의 출력은 비어 있지 않으므로 empty 결과는 없습니다. 상위 분기 비활성은 하위 분기로 처리합니다. 두 분기가 같은 출력값을 제공하면 중복을 제거하고 rational 하나로 반환합니다.

## 조립과 SSOT

공통 parametric_segments로 전체 정의역과 분기 계획을 먼저 검증합니다. 하위 출력은 linear_range가 만들고, rational_interval_nearest가 목표 투영 후보와 실제 도달 여부를 보존합니다. 기존 rational_range_nearest도 이 후보 생성기를 사용하며 전체 입력 목록을 먼저 검증하는 규칙은 유지합니다.

하위 분기에 목표가 실제로 있으면 거리가 0이므로 바로 선택합니다. 이때 상위 분기의 불필요한 정밀도 판정은 요구하지 않지만 전체 정의역 검증을 건너뛰지 않습니다. 상위 후보는 [상위 최근접 출력](icc-power-range-nearest.md)이 소유합니다.

parametric_nearest_candidates는 [정확한 거리 비교](icc-ordinate-distance.md)를 호출합니다. 하위 후보가 더 가까우나 열린 끝이어서 도달하지 못하면 unattained입니다. 같은 거리의 실제 상위 출력이 있다면 상위를 선택합니다. 두 실제 후보가 동률일 때 목표의 같은 쪽이면 같은 값이므로 중복 제거하고, 반대쪽이면 tie로 보존합니다. 미확정은 미도달과 혼동하지 않습니다. 타입·분기 조립·후보 결합·직렬화를 별도 파일로 나눕니다.

## 검증 진행

네이티브 신규 4개가 통과했습니다. 출력 `[0,1/2) ∪ {1}`의 목표 3/5는 unattained, 3/4는 상위 1입니다. `{0,1}`의 목표 1/2는 tie입니다. 두 분기의 같은 1/4 출력은 중복 제거합니다. 감소 선형 분기와 상위 비활성도 검사합니다.

type3 `[32768,0,32768,0,32768]`과 목표 11749380235262596085/16616132878186749607은 128에서 undecided, 512에서 상위 sqrt(1/2)를 선택합니다. 반면 `[32768,0,32768,65536,49152]`에서는 하위 분기가 그 목표를 포함하여 128에서도 정확한 목표를 선택합니다. 같은 입력의 상위 최근접 선택이 실제로 미확정임을 별도로 확인했습니다. 상위 밑을 음수로 바꾼 경우 하위 정확한 목표가 있어도 정의역 오류로 거부합니다.

테스트 mode211 입력은 precision u32 BE·목표 n/d u128 BE·para 태그입니다. 출력 status u32 LE는 0=unattained(4바이트), 1=undecided(4), 2=rational(68, n/d u256 LE), 3=power_endpoint(88, 공통 endpoint84), 4=tie(152, rational64+endpoint84)입니다. 실제 반환값만 직렬화하며 원본 계수에서 결과를 다시 계산하지 않습니다.

독립 JS oracle은 독립적으로 계산한 두 출력 구간을 기존 전체 유리수 구간 oracle에 전달합니다. 모든 끝점과 포함된 목표를 열거하고 거리 순으로 정렬하여 실제로 도달하는 최단 거리 값을 중복 제거합니다. 제품의 두 후보 조립 순서를 기대값 생성에 사용하지 않습니다. 반환 tie의 하위 값이 실제 하위 범위에 포함되는지, 상위 식·증거점·패딩이 맞는지도 검사합니다.

직접 Debug WASM은 selected=7725/ties=180/unattained=294/rejected=4882/undecided=1, 총 13,082건이 통과했습니다. 기존 유리수 최근접 1,482건과 전체 출력 범위 3,292건도 동일하게 통과했습니다. 동률 후보 하나를 버리기, unattained를 undecided로 바꾸기, undecided를 unattained로 바꾸기를 각각 ERR_ASSERTION으로 검출했습니다. 제품에는 변형을 남기지 않았습니다.

전체 세 모드 audit 결과는 아래 최종 확인 절을 기준으로 합니다.

별도 `/tmp` 소스 복사본에서 linearOnly가 attained를 무시하도록 바꿨습니다. Debug·ReleaseSafe·ReleaseFast 모두 `[0,1/2) ∪ {1}`의 목표 3/5에서 TestUnexpectedResult로 실패하여 열린 끝의 가짜 선택을 검출했습니다. 원본에는 변형을 적용하지 않았습니다.

## 실제 프로파일 대조

시스템 DCI(P3) RGB·Display P3·ITU-2020·ITU-709·ROMM RGB의 RGB TRC 15개에서 목표 0/1이 그대로 선택됨을 확인했습니다. type3 태그 12개에서는 추가로 하위 좌극한 `L/D=c*d/65536²`를 목표로 넣었습니다. 양의 지수·기울기, 내부 분기점, a+b=65536, N=a*d+b*65536과 L이 모두 (0,D)임을 먼저 확인했습니다.

g/65536=p/q를 기약화한 뒤 상위 시작값과 하위 좌극한의 순서는 BigInt로 `N^p*D^q`와 `L^q*D^p`를 비교하여 독립 판정했습니다. 상위 시작값이 더 큰 Display P3·ITU-2020의 6개 태그는 목표가 열린 하위 끝이므로 unattained를 반환했습니다. ITU-709·ROMM RGB의 6개 태그는 그 목표가 상위 출력 구간 안에 있어 정확한 목표를 반환했습니다. 총 42건이 통과했습니다.

이는 실제 고정소수점 태그의 전체 출력 합집합에 대한 읽기 전용 대조이며 정규 audit 호출 수에 합산하지 않습니다. ICC 역변환의 단조성 전제나 OS 엔진의 보정 정책·렌더링을 검증했다는 뜻은 아닙니다.

## 최종 확인

Debug·ReleaseSafe·ReleaseFast 전체 audit가 각각 종료 코드 0, 20/20 단계, 네이티브 593/593, WASM checks=6,607,042로 통과했습니다. 신규 13,082건이 이전 6,593,960건에 추가됐습니다. 신규 결과는 세 모드 모두 selected=7725/ties=180/unattained=294/rejected=4882/undecided=1입니다. 로그는 `/tmp/hwpjs-icc-parametric-nearest-{Debug,ReleaseSafe,ReleaseFast}.log`입니다.

ReleaseSafe·ReleaseFast의 실제 감사 산출물 직접 실행에서도 같은 신규 수치를 확인하고 동률 후보 하나를 버리는 변형을 각각 ERR_ASSERTION으로 검출했습니다. 변경 Zig 포맷·JS 문법·diff 공백과 관련 문서 로컬 링크 6개도 확인했습니다.

최종 적대적 재검토에서는 전체 정의역 검증 선행, 하위 정확한 목표의 정밀도 독립성, 열린 끝을 최단 거리 비교에서 제외하지 않는 규칙, 같은 거리의 실제 출력 우선, 동일 값 중복 제거와 서로 다른 동률 값 보존, 분기 비활성과 미도달·미확정의 구분, 증거점과 역변환 선택의 구분을 확인했습니다. 단일 유리수 구간 후보 생성기를 추출한 뒤에도 기존 다중 구간의 전체 입력 선행 검증이 유지됩니다. 이번 범위에서 추가 결함은 발견하지 않았습니다.

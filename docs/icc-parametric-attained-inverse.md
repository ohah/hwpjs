# ICC 도달 목표의 역변환 값 선택

## 명세와 범위

[ICC.1:2022 Annex F.1(a), PDF 115쪽](https://www.color.org/specifications/ICC.1-2022-05.pdf#page=115)을 다시 확인했습니다. 전체 정의역에서 비상수 단조인 곡선에 대해 평탄 역상이 전체 정의역 끝까지 포함하면 가장 작은 x, 그렇지 않으면 가장 큰 x를 선택합니다. 감소 곡선도 같은 x 기준이며 출력값의 증가/감소 방향에 따라 선택 규칙을 뒤집지 않습니다.

`parametric_attained_inverse.select(precision, curve, n, d)`는 **실제로 도달하는 목표값에 대한 F.1(a) 선택**입니다. normalized u128 목표를 먼저 검증하고 전체 곡선의 정의역·클리핑 후 단조성/상수성을 확인한 뒤 전체 역상 경계를 구합니다. 단일 목표에 해가 있더라도 전체 곡선이 상수면 ConstantIccCurve, 비단조면 NonMonotonicIccCurve를 반환합니다. 전체 정의역 오류도 전파합니다.

결과는 selected(정확한 유리수 또는 affine 기호근), missing_preimage(해 없음), undecided(검증·비교 정밀도 부족)입니다. 선택해야 할 최댓값/최솟값이 도달되지 않으면 UnattainedIccPreimageMaximum/Minimum 오류입니다. 명세 자체가 이 오류 이름을 정의한 것은 아니며 열린 구간 반례를 정확히 다루기 위한 구현 계약입니다.

F.1(b)의 최근접 출력 검색은 **아직 이 API에 포함되지 않습니다**. missing_preimage는 최근접 출력이 존재하지 않는다는 뜻도, 역변환을 완료했다는 뜻도 아닙니다. 범위 밖·점프 틈 모두 후속 처리가 필요합니다. 상한을 가장 가까운 실수 입력으로 반올림하거나 임의 fallback으로 반환하지 않습니다.

## SSOT와 책임

이 도달 목표 전용 API는 그대로 유지합니다. 후속 [전체 parametric 역변환](icc-parametric-inverse.md)에서 최근접 출력 검색·단조성 gate 공유·입력 선택 연결의 구현 및 검증 상태를 관리합니다. 아래의 F.1(b) 미구현 문장은 이 도달 목표 전용 단계의 이력입니다.

`preimage_choice_rule.zig`가 경계의 실제 포함 여부와 정의역 끝 여부로 선택할 쪽을 결정합니다. 기존 connected interval용 preimage_choice와 새 파라메트릭 경로가 공유합니다. 샘플 곡선의 최근접 목표 클램프는 기존 sampled_inverse가 소유하며 이 변경으로 제거하지 않습니다.

전체 단조성은 parametric_trend, 완전한 역상과 경계는 parametric_preimage_bounds가 소유합니다. 새로운 selector는 검증 순서와 결과 연결만 수행합니다. 기호근과 x=1의 동등성도 기존 정확한 근 대 유리수 비교를 사용하고 미확정을 동등/비동등으로 바꾸지 않습니다. 상한이 미도달이면 정의역 끝 예외를 적용하지 않습니다.

코어에 파일 접근·할당·부동소수점 계산은 없습니다. 제품 JS API는 변경하지 않았습니다. 테스트 mode202는 기존 36바이트 정밀도/목표 헤더 뒤 para 태그를 받습니다. 결과 status u32 LE는 0=missing_preimage, 1=undecided, 2=selected입니다. 앞의 두 결과는 4바이트, selected는 status와 기존 92바이트 경계 wire를 합친 96바이트이며 attained=true입니다. 경계 serializer를 icc-preimage-endpoint-wire.zig로 추출하여 mode201과 공유했고 기존 바이트 계약을 유지했습니다.

## 검증 진행

네이티브 562/562가 통과했습니다. 신규 4개 테스트는 증가/감소 곡선의 양쪽 평탄 구간, 열린 최대 해, 빈 틈, 정밀도별 미확정, 전체 상수·비단조·정의역 검증, 기호근 보존, terminal 단일점을 다룹니다.

독립 JS 기준은 g=1 곡선의 기울기 9개 × offset 9개 × 목표 4개를 네 정밀도로 반복하고, 정확한 정수 끝값으로 상수 여부를 판정합니다. 비상수 곡선의 해는 기존 독립 critical-cell 선형 기준으로 구성하여 선택을 대조합니다. type0..4 분기, 감소 곡선, 정의역 끝까지 닿는 평탄 구간, 큰 선형 좌표, 열린 끝점, 잘림·과잉·한도·잘못된 목표/정밀도·오류 후 복구도 검사합니다.

직접 Debug WASM 실행은 selected=422/missing=88/rejected=902/undecided=1로 통과했습니다. 총 1,413호출이며 기존 mode201도 comparisons=886/rejected=58/undecided=1로 유지됐습니다. 항상 상한 선택, 항상 하한 선택, 미확정을 해 없음으로 변경하는 유효한 출력 변형을 각각 ERR_ASSERTION으로 검출했습니다. 제품 파일에는 변형을 적용하지 않았습니다. 전체 세 모드 감사는 진행 중입니다.

비단조 오류를 가로채 기존 전체 역상의 알려진 해를 유효한 selected wire로 반환하는 변형도 ERR_ASSERTION으로 검출했습니다. 이는 단일 해의 존재가 전체 곡선 검증을 대신하지 못함을 검사합니다.

추가 수동 WASM 검사는 네 정밀도에서 8개 정확한 예제, 총 32건이 통과했습니다. type4 `[0,0,65536,65536,32768,-32768,0]`의 y=1/2→x=1/2 및 y=1/4→x=1/4, type3 `[-65536,65536,65536,0,0]`의 y=1/2,1,2/3→x=1,0,1/2, type0 g=32768의 y=1/2→x=1/4, type0 g=98304의 y=1/8→x=1/4, type3 `[131072,-65536,65536,0,0]`의 y=1/4→x=1/2입니다. g=0 상위가 평탄해도 전체 곡선이 비상수인 경우와 음의/비정수 지수를 확인하며 정규 audit 호출 수에는 합산하지 않습니다.

## 실제 ICC 태그와 독립 점프 증명

시스템 DCI(P3) RGB·Display P3·ITU-2020·ITU-709·ROMM RGB의 RGB TRC 태그 15개를 읽기 전용으로 확인했습니다. type0/type3, 양의 지수와 기울기, 내부 분기점, type3의 a+b=65536을 검사했습니다. type3에서 D=65536², N=a*d+b*65536, L=c*d로 두 분기 값을 나타내고, g/65536을 p/q로 약분한 뒤 `N^p*D^q−D^p*L^q`의 부호를 JavaScript BigInt로 정확히 계산했습니다. N/D와 L/D가 (0,1]에 있음을 확인했으므로 해당 점프에서는 클리핑이 부호를 바꾸지 않습니다.

Display P3·ITU-2020은 양수, ITU-709·ROMM RGB는 음수였습니다. 각 분기가 증가하더라도 후자의 하향 점프는 전체 비단조입니다. 목표 0/1에서 비상수 단조인 세 프로파일의 18건은 정확한 0/1 좌표를 선택했고, 하향 점프 두 프로파일의 12건은 NonMonotonicIccCurve로 거부했습니다. 특정 운영체제 색상 엔진도 같은 정책을 사용한다거나 프로파일 전체가 손상됐다는 주장은 아닙니다. 이 수동 30건은 정규 audit 호출 수에 합산하지 않습니다.

## 최종 감사와 적대적 재검토

Debug·ReleaseSafe·ReleaseFast 전체 audit가 각각 종료 코드 0, 20/20 단계, 네이티브 562/562, WASM checks=6,559,828로 통과했습니다. 신규 1,413건이 이전 6,558,415건에 추가됐습니다. 각 모드의 신규 결과는 selected=422/missing=88/rejected=902/undecided=1입니다. 로그는 `/tmp/hwpjs-icc-attained-inverse-{Debug,ReleaseSafe,ReleaseFast}.log`입니다. 앞의 진행 중 문장은 이력이며 최종 결과는 이 절을 기준으로 합니다.

ReleaseSafe·ReleaseFast 산출물 직접 실행도 같은 신규 수치로 통과했고 항상 상한을 선택하는 변형을 각각 검출했습니다. 변경 Zig 포맷·JS 문법·diff 공백·문서 로컬 링크 1개를 확인했습니다.

최종 재검토는 전체 목표/정의역/단조성 선행 검증, 비상수 조건, 미확정과 해 없음 구분, 열린 극값 오류, 감소 곡선에서도 x 기준 선택 유지, 기호근의 정확한 domain-end 판정, 공유 F.1(a) 규칙, 기존 sampled 경로와 mode201 wire 보존, 할당 이후 전체 출력 초기화를 확인했습니다. 이 범위에서 추가 결함은 발견하지 않았습니다. F.1(b) 최근접 출력 존재·검색·동률 처리, 전체 TRC 역변환 연결, 전체 HWP/HWPX 문서 검증은 아직 미완료입니다.

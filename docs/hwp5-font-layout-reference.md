# HWP5 글꼴 높이와 기존 기준 자료

## 책임과 수정 범위

`text-style.mjs`는 선언된 글자 크기의 px 변환을 소유합니다. HWP5에서 유효한 크기는 `height / 75`이며 일반 본문의 최소20px·1.25배 보정을 적용하지 않습니다. 크기 부재·미지원 값의 기존20px fallback과 HWPX 정책은 유지합니다. 이는 실제 글꼴 ascent/descent나 언어별 상대 크기 계산을 완료했다는 뜻이 아닙니다.

`layout.mjs`는 HWP5 documentBody의 각 줄 높이를 해당 줄의 측정값으로 집계합니다. UI용20px 초기값이나 이전 줄의 첫 글꼴 높이를 재사용하지 않습니다. 빈 줄·강제 개행은 현재 위치에서 명시적으로 측정합니다. 미지원 행간 fallback·입력 padding·대체 글꼴·실제 ink와 기준선은 별도이며, 단순 크기 변환으로 원본 줄바꿈이나 페이지 동치를 주장하지 않습니다.

## 실제 픽스쳐 대조

`font-height-reference.test.mjs`는 독립 CFB/레코드 리더로 `facename.hwp`13줄, `charshape.hwp`7줄, `linespacing.hwp`26줄을 읽습니다. 합계46줄에서 글자 모양의 선언 크기·저장된 줄 높이·짝지어진 기존 HTML의 height를 대조합니다. HTML의 mm 표시는 소수 두 자리이므로 허용 오차는0.0051mm입니다. 기존 HTML은 저장소의 기준 자료이며 이번 실행에서 한글을 실행해 새로 만든 결과가 아닙니다. HTML의 CSS line-height와 줄 상자의 height는 다른 값이므로 혼용하지 않습니다.

수정 전 세 실제 파일의 첫 줄은20px 대13.333333px로 실패했고, 수정 후46줄이 일치했습니다. 본문 흐름·작은 글꼴·첫 줄40px/다음 줄12px·빈 문단·개행·잘못된 측정값·원본 불변·HWPX/숫자 측정 fallback도 별도 검사합니다.

## 호환 옵션 커버리지

2026-10-17 레거시 fixture의 HWP48개를 독립 검사했습니다. 암호 플래그가 있는 `password-12345.hwp`1개는 해제 시도 전에 분리했고, 나머지47개 중12개는 호환 레코드가 없습니다.35개는 대상 프로그램0과 다섯 DWORD가 모두0인 레이아웃 호환 레코드를 가집니다. 부재와 명시0을 구분합니다. 비영 비트나 다른 대상 프로그램에 대한 완전한 동치 근거는 이 집합에 없습니다. RHWP/PDF·HWPX 자료의 추가 커버리지는 아직 이 수치에 포함하지 않습니다.

## 검증 제한

작업 트리의 관련5파일 집중검사32/32가 통과했습니다. 기존 미커밋 변경을 제외한 커밋 후보 스냅샷에서도 새7검사·기존 행간8검사·실제 Worker1검사가 합계16/16 통과했습니다. Worker는 앞서 빌드된 SHA256 `e006ec7ea337a5afd640e5447b147e0e95aac2b2209e0e604e040fdabc9ef5c4` 후보를 명시적으로 사용했으며 이번 JS 변경으로 WASM을 재빌드한 것은 아닙니다. 겹친 검사를 합쳐48개라고 집계하지 않습니다.

별도 확대 검사에서 HWPX 도형 높이 기대값, HWP5 page geometry 기대값 및 기본 WASM의 `Hwp5FieldSpansAbiUnavailable` 실패를 관측했습니다. 이번 두 제품 파일을 수정 전 HEAD로 대체한 실행에서도 각각 동일하게 재현됐습니다. 이를 이번 변경의 통과로 상쇄하거나 전체 suite 성공으로 보고하지 않습니다. 실제 브라우저·글꼴 파일 일치·전체 호환 옵션·픽셀/페이지 동치는 미완료입니다.

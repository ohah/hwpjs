# ICC v2 헤더 수치·미확정 영역

기준은 [ICC.1:2001-04 §5.3.1, §6.1, Annex A.1](https://www.color.org/specification/ICC.1-2001-04.pdf)입니다. `header_v2_values.inspect`는 파싱된 v2 헤더와 명시적 D50 비교 정책을 받습니다. v4 정책으로 자동 승격하거나 v4 ID를 해석하지 않습니다.

## 명세와 검사 경계

- 날짜 성분 범위는 기존 `date_time`을 공유합니다. 실제 달력 존재·시간대 진위까지 검사하는 것은 아닙니다.
- 렌더링 의도의 ICC 영역인 하위 16비트는 0~3을 검사합니다. 상위 16비트는 `intent_high_bits`로 보고합니다. v4의 상위 0 요구를 v2 규칙이라고 주장하지 않습니다.
- `header_bits`가 v2/v4 공통 플래그·속성의 비트 소유권을 정의합니다. 예약/미정의 비트의 허용 여부는 각 버전 검사기에 남겨 둡니다. v2의 `unassigned_icc_flags`·`unassigned_icc_attributes`는 해석 보류 값입니다.
- 84~127의 44바이트 전체가 v2 reserved tail입니다. 비영 바이트 수를 보고하며 첫 16바이트를 v4 프로파일 ID로 취급하지 않습니다. v2 표 9의 예약 설명과 v4 표의 명시적 0 요구는 구분합니다. 진단의 성공은 비영 reserved 값이 명세상 유효하다는 인증이 아닙니다.

v2는 D50 소수값을 명시하지만 v4 §7.2.16의 네 자리 반올림 문장은 없습니다. 그러므로 숫자 비교 방식을 호출자가 선택하도록 했습니다. `nearest_encoding`은 선언된 소수값에 가장 가까운 signed 16.16 정수(63190/65536/54061), `rounded_four_decimals`는 네 자리 반올림으로 동일 소수값이 되는 범위를 검사합니다. 둘은 애플리케이션의 명시적 비교 정책이며, 후자를 v2 명세의 의무 규칙으로 소급하지 않습니다. 향후 PNG 연결에서 임의 기본 정책을 선택하지 않습니다. D50 상수는 `pcs_illuminant` 한 곳에서 공유합니다.

이 API의 성공은 선택한 수치 검사와 진단 생성의 성공입니다. 미확정 영역을 숨기지 않으며 전체 헤더/프로파일 유효성을 보증하지 않습니다. 등록부·클래스별 추가 제약·필수 태그·내용·이미지 연결은 여전히 별도입니다.

# XML 이름·참조 토큰

[문자 입력](xml-input.md) · [선언·인코딩](xml-declaration.md)

## 범위

태그와 속성의 토큰 연결은 별도 [태그·속성 계약](xml-tags.md)이 소유합니다. 문서 전체 문맥 검증과 구분합니다.

XML 1.0의 Name과 Reference를 읽는 공통 토큰 계층입니다. 기준은 W3C Fifth Edition [§2.3 이름](https://www.w3.org/TR/2008/REC-xml-20081126/#sec-common-syn)과 [§4.1 문자·엔터티 참조](https://www.w3.org/TR/2008/REC-xml-20081126/#sec-references)입니다. 전체 태그·속성·namespace·DTD·문서의 well-formedness 검증은 아직 아닙니다.

## 책임과 SSOT

- `characters.zig`는 기존 Char와 NameStartChar/NameChar의 정확한 코드포인트 집합을 소유합니다. 이름 집합을 Unicode 일반 범주나 ASCII 정규식으로 대체하지 않습니다.
- `names.zig`는 Input에서 Name 하나만 소비하고 구분자는 남깁니다. 첫 문자와 후속 문자의 조건, 이름 바이트 한도를 검사합니다. 빈 이름이나 잘못된 첫 문자는 오류입니다.
- `references.zig`는 `&`부터 `;`까지 숫자·이름 참조 한 개를 검사합니다. 전체 참조 및 이름의 바이트 한도는 기본 각각 4096입니다. 세미콜론까지 전체 한도를 적용합니다.
- `text.zig`는 borrowed 인코딩 바이트와 ASCII 비교를 공유합니다. 기존 선언의 Value도 이 View의 alias로 바꾸어 동일 로직을 복제하지 않습니다. 선언의 기존 비교·수명 계약은 유지합니다.

모든 파싱은 메모리 할당이나 원본 쓰기 없이 수행합니다. 성공한 raw/이름은 입력을 빌리므로 입력 수명이 필요합니다. 오류 시 호출자의 offset과 문자 예산은 그대로이며 부분 참조를 반환하지 않습니다. Name parser는 구분자 앞에서 멈추므로 Name 성공이 전체 남은 문자열의 이름 적합성까지 뜻하지 않습니다.

## 이름과 namespace의 구분

콜론은 NameStartChar/NameChar에 포함됩니다. `:a:b`도 이 계층의 Name으로 읽히지만 namespace QName 검증을 통과한 것은 아닙니다. xml 예약 이름, PI target, prefix 바인딩, QName의 콜론 위치/개수는 후속 문맥 계층의 책임입니다. NFC 정규화나 Unicode 대소문자 접기는 하지 않습니다. U+EFFFF는 이름에 허용되지만 U+F0000은 일반 XML 문자로 허용되어도 이름에서는 제외됩니다.

## 참조 결과와 미해결 경계

결과 value는 `numeric`, `predefined`, `unresolved`로 구분합니다. 숫자 참조는 10진수 또는 소문자 x로 시작한 16진수이며 한 자리 이상과 세미콜론이 필요합니다. 선행 0은 허용하고 부호·공백·대문자 X는 허용하지 않습니다. 누적 값은 곱셈 전에 최대 코드포인트 한도를 검사하며, 최종 값은 기존 XML Char 검사로 확인합니다. 고립 서로게이트·NUL·U+FFFE/U+FFFF는 거부합니다.

`lt`, `gt`, `amp`, `apos`, `quot`만 대소문자 구별하여 기본 엔터티로 반환합니다. `&AMP;`나 `&custom;`은 이름 문법을 읽되 unresolved로 남깁니다. 이 결과는 선언된 유효 엔터티라는 뜻이 아닙니다. DTD 없는 문서 등의 미선언 엔터티 오류는 후속 문서 검증이 판단해야 하며 unresolved를 성공한 치환으로 취급하면 안 됩니다. 외부 파일·네트워크 조회, 일반 엔터티 확장/재귀, parameter entity는 수행하지 않습니다.

숫자 참조 `&#13;`의 결과는 CR입니다. literal 입력의 CRLF/CR → LF 처리에 다시 넣지 않습니다. 참조가 생성한 공백과 literal 속성 공백은 정규화 규칙이 다르므로 결과의 출처를 유지합니다. 실제 속성 값 정규화는 아직 미구현입니다.

참조가 생성한 `<`, `&`, 따옴표를 원본 마크업처럼 재파싱하지 않아야 합니다. 미해결 일반 엔터티의 replacement text 처리와 문자/기본 참조의 scalar 처리를 섞지 않습니다.

## 검증

네이티브 검사는 이름 범위의 양 끝과 제외 구간, 한글·비 BMP·결합 문자·콜론, 구분자 미소비, 숫자/기본/미해결 참조, CR 유지, 잘림·숫자 범위 초과·금지 문자·이름/참조 한도, 실패 원자성, UTF-16 양쪽 순서의 원본 위치·불변성을 확인합니다.

테스트 mode 120은 u32 코드포인트를 받아 이름 시작/후속 허용 비트를 반환합니다. mode 121은 kind u8(0=Name,1=Reference), encoding u8(0=UTF-8,1=UTF-16LE,2=UTF-16BE), 토큰/이름 바이트 한도 u32 두 개와 원문을 받습니다. 외부 limit은 전역 문자 예산입니다. 토큰 종류·해석 코드포인트·최종 offset·남은 예산·소비 raw 바이트를 대조합니다. 제품 JS API는 변경하지 않습니다.

독립 JS는 W3C 범위를 정규식으로 표현해 모든 Unicode 코드포인트와 범위 밖 값을 WASM과 비교합니다. 숫자 기대값은 BigInt로 계산합니다. UTF-8/UTF-16 양쪽의 정확·부족 한도, 긴 선행 0/이름, 잘린 접두부·UTF-16 참조, 오류 후 정상 재실행을 검사합니다. 이 파트는 토큰 단위 검사이며 실제 HWPML 전체 문서에서 참조 문맥을 검증했다고 주장하지 않습니다.

최종 집중 검증은 이름 분류 1,114,114개, 대표 정상 58개·거부 159개입니다. 추가로 BMP 전체를 10진수와 소문자 16진수로 생성해 정상 126,914개·거부 4,158개를 확인했습니다. 숫자 기대값·offset·남은 예산·raw 바이트를 대조하며 이 수치는 고유 기능 수가 아닙니다.

적대적 검토는 이름/Char/QName의 구분, 참조 문법/수치 누적과 금지 문자, 실패 원자성과 여러 한도, 독립 Unicode·BMP 대조, SSOT·미해결 문맥으로 나누었습니다. 긴 선행 0과 이름, 접두부 잘림, BMP 전체 숫자 참조 검사가 부족해 추가했습니다. 최종 검사에서 새 제품 결함을 발견하지 않았으며 외부 엔터티 해석을 완료로 보고하지 않습니다.

Debug 전체는 보강 전 테스트 구성의 2,941,418 checks였으며, 이후 같은 제품 로직의 Debug WASM에서 위 최종 집중 검증을 다시 통과했습니다. 최종 구성의 ReleaseSafe/ReleaseFast 전체는 각각 3,072,516 checks입니다. 기존 Node 47개·조사 22개·XML 외부 경계 6개도 통과했습니다. 기존 선언/인코딩/문자 입력 검사가 포함되므로 shared View 이동에 따른 회귀도 대조합니다.

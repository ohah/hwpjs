# Native 편집의 완료 판정

동기 Native 편집 ABI의 결과는 `js/native-edit-outcome.mjs`가 해석합니다. 원자 서식 API와 독립 텍스트 거래 후보가 이 함수를 공유합니다. 문서·이력·쓰기 권한은 기존 Native Session과 History가 계속 소유합니다.

| Native 코드 | 적용 상태                  | changed |
| ----------- | -------------------------- | ------- |
| 0           | 거부되어 적용하지 않음     | false   |
| 1           | 적용함                     | true    |
| 2           | 알려진 no-op               | false   |
| 3           | 복구 결과를 확정할 수 없음 | null    |

Primitive 결과를 받기 전 Native 호출이 trap하거나 유효하지 않은 코드를 반환하면 적용 여부는 unknown입니다. 입력 메모리를 준비하다 Native 호출 전에 실패한 경우에는 예외를 그대로 전달합니다.

코드를 받은 직후 완료 사실을 먼저 저장하고 오류 메시지를 읽습니다. 코드 0 뒤 진단 읽기에 실패해도 거부를 unknown으로 바꾸지 않습니다. 코드 3은 진단을 읽을 수 있어도 unknown입니다. 입력 메모리 정리 중 예외가 발생하면 이미 관측한 적용 사실과 Native 오류를 보존하고 `cleanupError`·`refreshRequired`를 전달합니다. 자동으로 편집을 재실행하지 않습니다. Runtime은 이 완료 사실을 유지하며 적용 뒤 화면 갱신 실패를 별도로 보고합니다.

## 확인 범위

기존 코드는 거부 결과를 받은 뒤 오류를 읽는 도중 예외가 나면 결과를 unknown으로 바꿨습니다. 진단 읽기 실패를 주입한 비교에서 이 경로를 재현했고, 공유 함수는 unapplied와 false를 유지합니다. 이는 실제 WASM 메모리 손상이나 일반 사용자 화면에서의 자연 발생 빈도를 측정한 결과가 아닙니다.

`node --test tools/tests/native-edit-outcome.test.mjs`는 네 코드·진단 실패·후처리 실패·호출 전 실패·trap·유효하지 않은 코드를 검사합니다. 동일한 공개 a524 WASM의 HWP5/HWPX 실제 원자 서식 API 15개를 별도로 대조해 정상 적용·단일 이력·원문 복원·독립 저장 검사를 통과했습니다. 새로운 독립 텍스트 API의 mock transport 검사와 실제 Native 서비스 완료, 브라우저 실행, 공개 배포는 서로 다른 증거입니다.

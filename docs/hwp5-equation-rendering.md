# HWP5 수식 조회와 Canvas 표시

HWP5 EQEDIT 원문의 조회와 화면 표시는 수식 스크립트의 편집·생성과 구분한다. `equation_sources.zig`는 실제 제어 링크와 현재 문단의 연장 제어를 대조하고, `equation_snapshot.zig`는 구역의 수식 원문과 현재 물리적 소유자를 함께 복사한 JSON을 만든다. 반환 버퍼는 호출자가 소유하며 Section 바이트를 빌리지 않는다. 이 조회는 저장 의도나 실행취소 항목을 만들지 않는다.

선택적 ABI는 `hwp5_edit_equation_sites`와 `hwp5_edit_equation_snapshot`이다. 기존 편집 출력 버퍼의 수명 규칙을 재사용한다. JS 어댑터의 `equationSnapshot(section, layout)`은 원시 UTF-16 단위·opaque 꼬리·현재 앵커를 보존한 독립 결과를 반환한다. `equationSource(section, node, layout)`은 그 결과에서 현재 물리 노드로 조회한다. 구형 엔진은 `supportsEquationSources() === false`이며 누락된 기능을 제공한다고 추측하지 않는다.

`version-only`와 `with-font`는 호출자가 명시한다. 버전이나 남은 바이트 수로 폰트 꼬리의 배치를 추측하지 않는다. 해석되지 않은 꼬리는 그대로 남기고, 잘못된 UTF-16은 원시 단위를 유지한 채 문자열을 `null`로 표시한다. 이를 복구한 텍스트로 저장하거나 수식으로 그리지 않는다.

`hwp5-equation-content.mjs`는 한 구역을 한 번 조회한다. 현재 원문 좌표에서 표시 좌표로의 변환은 `text-offsets.mjs`의 일괄 경로를 사용한다. 문단·수식 Map과 단조 증가하는 경계 커서로 조회·매핑 비용을 입력 수에 선형으로 제한한다. 보호 제어의 내부 좌표, 중복 소유자, 앵커와 맞지 않는 문단은 진단으로 남기며 일부분만 임의로 게시하지 않는다.

표시는 HWPX와 같은 수식 parser·측정 계획·Native 배치·Canvas painter를 사용한다. 원문 크기와 COLORREF 색을 적용하고, 미관측 글꼴은 명시적인 미리보기 글꼴 정책을 따른다. 원본 한/글의 폰트 지표·기준선·페이지 조판과의 동치를 뜻하지 않는다. 전체 문서와 현재 표시 구간의 실제 문단에만 앵커를 연결하며 화면 조회가 편집 권한을 발급하지 않는다.

## 현재 확인과 남은 검증

독립 합성 바이트에서 앵커·원문 단위·꼬리의 보존, 누락·중복 소유자의 거부와 할당 실패 정리를 검사했다. 실제 `latex.hwp` 편집 세션과 후보 WASM에서는 수식20개의 조회·배치, 조회 전후 저장 바이트·이력 불변, 저장 후 재열기 값을 확인했다. Node 배치 검사에서 사용한 글꼴 측정 대역과 공식 SDK로 빌드한 데모의 실제 Chromium 표시 검사는 별도 근거다.

## 새 수식 삽입

HWP5의 편집 가능한 일반 본문에 커서를 두고 **입력 → 수식**에서 스크립트와 개체 크기를 지정한다. 헤드리스에서는 현재 문단 선택에 `INSERT_EQUATION_COMMAND`를 호출한다. 수식 삽입은 한 번의 실행 취소로 되돌릴 수 있으며, 편집 후 재조판이 필요한 문서는 저장 시 줄 배치 변경을 명시적으로 허용해야 한다.

공개 SDK 빌드에서 기존 HWP5와 새 HWP5에 삽입한 수식의 저장·재열기, 실행 취소·다시 실행, 수식 원시 레코드와 비대상 스트림 보존을 확인했다. 로컬 브라우저에서는 새 문서에 `x over y`를 삽입하고 실행 취소·다시 실행한 후 내려받아 다시 열었다. 내려받은 파일에서 EQEDIT 레코드 한 개와 스크립트가 확인됐다. 이 결과는 검증한 후보의 근거이며 공개 배포 상태는 별도로 확인한다.

스크립트 변경, 수식 크기 자동 계산, 원본 글꼴·페이지 조판 동치는 후속 범위다. 기존 HWPX 편집 계약은 [수식 화면 연결](hwpx-equation-rendering.md)을 따른다.

## 현재 공개 번들의 새 문서 검증

소스 `370794258`의 공개 번들 manifest `34385392`와 WASM `9235b243`에서 실제 UI로 `x over y`를 한 번 삽입했다. Worker 문서의 수식 수는 생성 전0, 삽입1, 실행 취소0, 다시 실행1이며 실제 Canvas 표시도 사라졌다가 복원됐다. 내려받은 4096bytes에서 독립 CFB 검사로 EQEDIT 한 개와 정확 스크립트를 확인했다. 새 페이지의 로컬 파일 선택으로 같은 bytes를 다시 열었을 때 분수 한 개와 초기 이력0을 확인했다.

기본 저장은 `LayoutReflowRequired`로 거부됐다. 이 실패를 보존하고 UI의 줄 배치 변경 허용을 직접 선택한 뒤 저장했다. 따라서 이 근거는 기본 저장 성공이나 정식 재조판 완료를 뜻하지 않는다. 해당 앱 생성 파일을 `hwp5-equation-create.hwp` 예제 후보로 결속하며, 과거 b972 SDK·브라우저 근거와 현재 실행을 구분한다. 예제의 SHA256은 `ad090cb478e4e160e15d8d97e8c14b07e0d993fa533a993f48ea5b55158f58ef`이다.


## 기존 수식 내용 편집 후속

조회·생성과 별도로 [스크립트 편집 Native](hwp5-equation-script-edit.md)와 [Native 보관 lease ABI](hwp5-equation-script-edit-abi.md)를 격리 후보에서 준비한다. 기존 표시 snapshot과 구역별 Map 경로는 유지하며 새 capture를 inventory의 줄별 반복에 연결하지 않는다. 공용 SDK/UI와 실제 WASM의 추가 검증 완료를 뜻하지 않는다.

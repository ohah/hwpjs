# JPEG IDCT·샘플 복원 작업

IDCT·샘플 복원과 아래 범위의 검증을 구현했습니다. 제품 이미지 지원 완료가 아닙니다.

후속 [성분 평면 조립 작업](jpeg-sample-planes.md)은 별도 계약과 검증 기록으로 관리합니다.

## 책임과 계약

- `src/image/jpeg/idct.zig`: 역양자화된 row-major i64 계수 64개를 받아 중심 이동 전 f64 값 64개를 반환합니다. T.81 A.3.3의 수식을 두 축으로 분리하여 계산하며 할당·반올림·clamp는 하지 않습니다. DC만 있는 블록은 정확한 1/8 배율을 사용합니다.
- `sample_restoration.zig`: 8·12비트 정밀도만 받아 각각 128·2048을 더하고 가장 가까운 정수로 반올림한 뒤 유효 샘플 범위로 제한합니다. 정확한 반 정수는 양의 방향으로 반올림하는 구현 정책입니다. NaN·무한대는 거부하며 큰 유한 입력은 정수 변환 전에 제한합니다.
- 테스트용 mode 257은 i64 계수 입력에서 중심 이동 전 f64와 u16 샘플을, mode 258은 f64 입력에서 u16 샘플만 반환합니다. Mode 259는 기존 프레임 디코더와 역양자화를 연결하여 성분별 블록 샘플을 반환합니다. 제품 JS ABI에는 추가하지 않았습니다.

`tests/hwp5/jpeg-idct.mjs`는 두 축 분리나 제품 basis 표를 사용하지 않고 직접 2차원 합을 계산합니다. 부동소수점 대조 허용치는 `max(1e-12, 계수 절댓값 합 × 1e-14)`입니다. 이는 테스트 오차 예산이지 T.83 적합성 기준이 아닙니다. 샘플 반올림은 실제 반환된 f64로부터 정확히 대조하고, 독립 수식에서 얻은 샘플과의 차이도 별도로 집계합니다.

## 현재 실측

- Debug WASM: 비교 131,792건, 거부 1,922건 통과. 모든 주파수 위치, 양·음 impulse, DC -32768~32767, 8·12비트 샘플 범위와 반 정수 경계, 잘림·여분 바이트·한도·잘못된 정밀도·모든 위치의 비유한 값을 검사했습니다.
- 이 입력군의 중심 이동 전 최대 절대 오차는 `1.1920928955078125e-7`, 독립 수식과 복원 정수 샘플 차이는 0건입니다. 큰 impulse 입력을 포함한 합계이며 모든 가능한 계수의 동일성을 증명하지 않습니다.
- Debug JPEG 네이티브 테스트 76개 통과 기록이 있으며, 전체 네이티브 재실행도 792/792개 통과했습니다. 새 독립 검사를 정규 audit에 연결했습니다. 후속 프레임 대조·결함 주입과 세 모드 전체 audit 결과는 아래에 기록합니다.

### 프레임 연결과 적대적 검증 진행

- `tests/hwp5/jpeg-frame-samples.mjs`는 독립 프레임/역양자화 oracle의 정수 계수를 IDCT 직접 수식에 전달합니다. 제품 mode 256 결과를 기대 계수로 사용하지 않습니다. 헤더·성분·좌표·정밀도·모든 중심 값·샘플 위치를 확인하며 성분 블록의 검사 책임만 소유합니다.
- Debug에서 실제 HWP sequential JPEG 참조 7건의 20,089블록을 비교했습니다. 중심 값 최대 절대 오차는 `2.4158453015843406e-13`, 독립 수식과 정수 샘플 차이는 0건입니다. 참조 중 동일 이미지가 중복되므로 고유 이미지 7개라는 뜻은 아닙니다. Progressive 참조 1건은 보류했습니다.
- `reference/rhwp/samples/s1.jpg`의 1,197블록은 최대 절대 오차 `1.9895196601282805e-13`, 정수 샘플 차이 0건입니다.
- 합성 프레임 72건(스캔 분할·순서, 8/12비트, restart, DNL, Q 재정의) 및 출력 한도 거부 1건 통과. 기존 mode 254의 비교 196건·거부 166건도 통과했습니다. 실제 HWP의 프레임 샘플 검사를 정규 컨테이너 audit에 연결했습니다.
- Debug/ReleaseSafe/ReleaseFast에서 출력 변조 536건씩 모두 검출했습니다. 단일 블록의 64개 중심 값에 각각 1을 더하고 64개 샘플을 각각 XOR 1 했습니다. 3블록 프레임에서는 헤더 9개, 블록별 메타데이터 5개와 중심 값·샘플 각 64개를 개별 변조했습니다. f64의 최하위 비트까지 동일해야 한다는 검사가 아닙니다.
- 분리한 소스 복사본의 배율 누락·행렬 전치·반올림 누락·비유한 값 허용 변형은 Debug/ReleaseSafe/ReleaseFast 모두 컴파일 성공 뒤 테스트 실패로 검출했습니다(각 모드 5개 테스트 중 각각 2/2/2/1개 실패). 로그는 `/tmp/hwpjs-idct-mutants.1Go8nj/`에 있습니다.

### 릴리즈 모드 재검증

ReleaseSafe와 ReleaseFast의 독립 WASM도 별도 경로에 빌드하여 단일 블록 비교 131,792건·거부 1,922건, 합성 프레임 비교 72건·거부 1건, 실제 HWP 20,089블록과 별도 JPEG 1,197블록을 재검증했습니다. 위 Debug 결과와 동일한 최대 오차를 얻었고 정수 샘플 차이는 모두 0건입니다. 이 별도 실행은 정규 전체 audit 통과를 대신하지 않습니다.

별도 임의 계수 조사도 세 모드에서 수행했습니다. Xorshift32 초기값 `0x083dc701`, 이동 순서 13/17/5, 매 출력 unsigned 값의 `% 4097 - 2048`을 row-major 64개 계수로 사용했습니다. 10,000블록에서 12/8비트를 교대 적용했으며 세 모드 모두 최대 절대 오차 `4.547473508864641e-12`, 정수 샘플 차이 0건입니다. 이 별도 조사 횟수는 정규 audit 합계에 포함하지 않습니다.

Debug/ReleaseSafe/ReleaseFast 전체 audit는 각각 20/20 단계, 네이티브 792/792개, 총 7,516,092건 검사로 통과했습니다. 로그는 `/tmp/hwpjs-idct-{Debug,ReleaseSafe,ReleaseFast}-audit.log`에 있습니다. 이 합계는 전체 회귀 검사 수이며 전체 문서 구현 완료나 한글과의 픽셀 동일성을 뜻하지 않습니다.

## 미완료 경계

2026-09-09에 [ITU 공식 T.83 안내](https://www.itu.int/ITU-T/recommendations/rec.aspx?id=2635)를 확인했습니다. T.81 구현·압축 데이터의 적합성 시험을 별도 정의하고 시험 데이터를 포함한다고 안내하지만, 본문은 유료 제공으로 표시되어 있습니다. 해당 시험 원문과 데이터에 따른 적합성 검증은 아직 수행하지 않았으며 현재 수식 대조로 대체하지 않습니다.

부동소수점 합 순서가 다르면 반 정수 근처에서 샘플이 달라질 수 있습니다. 한글·libjpeg와 비트 단위 동일성 또는 T.83 정확도 적합성을 주장하지 않습니다. 성분 평면 조립·끝 블록 자르기·업샘플링·색 변환, progressive 계수 복호화와 HWP JPEG 지원 보고 연결은 후속 단계입니다. 반환한 블록 샘플을 완성된 RGB 이미지로 취급하지 않습니다.

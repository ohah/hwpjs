# 양식 입력 상자의 MaxLength

[관측 스키마](hwp5-form-schema.md) · [문서 진단](hwp5-form-document.md)

## 근거와 미확인 사항

한컴 [양식 개체 속성 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/view/workwindow/workwindow%28attribute%29.htm)은 MaxLength를 입력 상자의 최대 글자 수로 설명하며 -1을 무제한으로 정의합니다. 누락 시 기본값, 허용 상한, UTF-16 코드 유닛/Unicode scalar/자소 중 어떤 단위인지, 이미 저장된 Text가 설정을 초과할 때의 동작은 이 설명만으로 확정하지 않습니다.

실파일 `reference/rhwp/samples/form-01.hwp`·`form-02.hwp`의 편집 상자는 각각 `MaxLength:int:2147483647`, 빈 Text를 저장합니다. 이를 모든 파일의 기본값이나 무제한 sentinel이라고 일반화하지 않습니다.

rhwp `e8800c8de`의 HWP5 파서는 속성 원문을 문자열 맵에 보관하지만 `serializer/control.rs::prop_int`는 i32 변환 실패나 누락에 fallback을 사용합니다. 편집 상자의 MaxLength fallback은 2147483647입니다. 따라서 해당 작성 경로는 누락과 범위 초과 값을 같은 대체 수치로 작성할 수 있습니다. 이는 코드 대조 결과이며 이번 검사에서 rhwp 전체 serializer를 실행한 결과는 아닙니다. HWPX 작성기도 문자열 기본값 2147483647을 사용하지만 그 정책을 HWP5의 공식 기본값으로 가져오지 않습니다.

공개 HWP5 자료형 표의 INT32와 관측 속성 문법의 문자열 `int`가 동일한 저장 범위를 강제한다는 근거는 없습니다. 기존 문법은 임의 길이 십진 원문을 보존합니다. 이번 모듈도 i32/u32로 잘라내거나 큰 수를 정상 기본값으로 바꾸지 않습니다.

## 책임과 API

`body/form_max_length.inspectObserved(tree, schema_report, kind)`가 같은 변경되지 않은 속성 Tree·그 종류의 스키마 보고서를 받아 View를 반환합니다. 인식 경로는 기존 스키마가 소유하는 `EditSet/MaxLength` 하나이며 새 키 검색·숫자 문법 파서를 만들지 않습니다.

| state | 의미 |
|---|---|
| not_applicable | edit가 아닌 종류; 해당 위치를 읽지 않음 |
| missing | edit에서 인식된 경로가 없음 |
| unlimited | 명시적인 수치 -1 (선행 0 표기도 원문 보존) |
| nonnegative | 부호 없는 비음수 십진 원문; 지원 상한까지 검증했다는 뜻이 아님 |
| deferred | -0 및 -1 이외의 음수; 오류·기본값으로 치환하지 않음 |

View.raw는 missing/not_applicable이면 null, 나머지는 원래 Property.value를 빌립니다. View와 비교 함수는 할당하거나 원문을 변경하지 않습니다. Tree 노드 배열은 해제해도 되지만 raw를 쓰는 동안 원본 속성 입력은 유지해야 합니다. 직접 조작한 View/Tree의 유효성을 복구하는 API가 아닙니다.

`View.compareCount(count: u64)`는 nonnegative 원문에 대해서만 **count와 저장 수치 사이의 수학적 대소 관계**를 반환합니다. 그 외 상태는 null입니다. 저장 수치가 u64를 넘으면 모든 u64 count보다 크므로 lt를 반환하며, 중간 오버플로를 숫자 0이나 최댓값으로 포화시키지 않습니다. 선행 0은 비교 값만 같고 raw는 달라질 수 있습니다.

이 비교는 실제 사용자 입력 허용 여부가 아닙니다. 문자 단위를 선택하지 않고 기존 Text를 자르거나 거부하지도 않습니다. nonnegative 0이라는 분류만으로 원본 프로그램의 편집 동작을 확정하지 않습니다. 스키마의 잘못된 자료형·중복, 원시 숫자 문법 오류는 기존 파서 오류를 그대로 반환합니다.

문서의 `SectionReport.forms`는 max_length_missing/unlimited/nonnegative/deferred 네 수치만 추가로 집계합니다. 다른 양식 종류는 이 네 개에 포함하지 않습니다. 숫자 값이나 borrowed raw를 구역 보고서에 남기지 않으므로 임시 속성 Tree/CFB 수명을 늘리지 않습니다. 양식 미선택 모드와 ViewText의 기존 미해석 경계도 그대로입니다.

## 검증 구성

테스트 mode 112 입력은 kind u32·비교 count u64·관측 UTF-16 속성입니다. 출력은 state u32·비교 결과 u32(없음 0, lt 1, eq 2, gt 3)·raw 바이트 길이 u32(부재 FFFFFFFF)와 raw입니다. 테스트 전용이며 제품 JS ABI 변경은 아닙니다.

독립 JS oracle은 기존 독립 스키마 경로를 통해 원문을 찾고 BigInt와 부호 표기를 이용해 기대값을 구합니다. 여섯 종류·20가지 누락/숫자·여섯 비교 수를 교차 검사합니다. i32/u32/u64 경계, 매우 큰 양/음수, 긴 선행 0, 음수 0, 미지 하위 트리, 잘못된 자료형·중복·숫자 문법과 오류 후 복구를 포함합니다.

두 실파일의 편집 상자마다 MaxLength 아홉 값을 변조하고 Text에 ASCII·비 BMP·한글·CRLF를 넣습니다. typed view의 원문/상태와 문서·재압축한 메모리 CFB의 전체 보고서, 네 개의 독립 고정 카운터, 양식 선택/미선택을 대조합니다. 입력 단위의 원본 프로그램 대조를 대신하는 검사는 아니며, 저장 Text를 임의로 제한하지 않는 현재 계약을 검사합니다. 디스크 표본은 쓰지 않습니다.

네이티브 검사는 Tree 해제 뒤 원본 입력을 빌린 View의 수명, 임의 길이 수치 비교, 부재/비대상/잘못된 경로와 원문 보존을 확인합니다. 기존 문서 전역 예산·할당 실패 주입과 다중 구역 진단 검사도 유지합니다.

새 네 수치의 위치 편향도 독립적으로 검사합니다. 각 실파일에서 구역 0은 비음수, 새 구역 1은 무제한으로 구성하고 입력을 1→0으로 전달합니다. 두 구역의 네 필드를 각각 고정 기대값과 비교하고, 입력 순서를 뒤집어도 전체 보고서가 같은지 확인합니다. DocInfo 구역 수와 Section1을 반영한 메모리 CFB에서도 같은 구역별 진단을 검사합니다.

## 적대적 재검토

- 명세/레퍼런스: rhwp의 작성기 fallback을 공식 기본값으로 보지 않았습니다. nonnegative 진단과 프로그램 허용 상한 검증을 구분합니다.
- 수치 경계: u64를 넘는 저장 수치는 모든 u64 count보다 큽니다. 비교 중 오버플로가 나면 lt인 이유가 이 단조성에 있으며 값 자체를 포화시키지 않습니다. 음수는 이 비교 경로에 들어오지 않습니다.
- 수명/SSOT: 숫자 문법과 경로는 기존 Property/Schema가, MaxLength 분류와 수학적 비교는 새 모듈이 소유합니다. 문서 계층은 상태를 집계할 뿐 다시 해석하지 않습니다. Tree 해제 후의 raw는 살아 있는 원본 입력을 빌리며, 구역 보고서에는 포인터가 남지 않습니다.
- 독립 대조/위치: 제품의 분류 로직을 가져오지 않는 BigInt 기대값과 raw 전체를 대조합니다. 실파일의 값 변조 외에 서로 다른 상태를 가진 두 구역·역순 입력·CFB의 Section1 추가 검사를 보강했습니다.
- 변경 없는 경로: 양식 미선택, 다른 양식 종류, 기존 FollowContext/TriState, 저장 Text를 임의로 잘라내지 않는 경계를 함께 검사합니다. 문자 수 계산 단위의 원본 프로그램 실측을 대신했다고 주장하지 않습니다.

최초 Debug 전체 실행은 다중 구역 위치 검사 보강 전 구성이어서 해당 프로세스를 의도적으로 중단했습니다. `/tmp/hwpjs-form-max-length-debug.log`의 종료 실패는 이 중단 결과이며 제품 결함이나 최종 통과 기록으로 집계하지 않습니다. 보강한 테스트 구성으로 최종 실행을 분리했습니다.

## 남은 범위

다른 버전과 원본 프로그램에서 허용하는 MaxLength 상한·누락 기본값·문자 계산 단위·입력/스크립트 변경 동작의 실측이 필요합니다. 이 수치 뷰를 전체 입력 상자의 의미·편집·렌더링 구현 완료로 해석하지 않습니다.

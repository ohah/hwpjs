# 문서 정보와 이미지 도구

CLI와 MCP는 같은 파일 호스트와 Native 문서 기능을 호출합니다. 문서 전체 JSON 변환이나 별도 파서를 추가하지 않습니다. 설치·사용법은 공개 문서의 CLI·MCP 가이드가 안내하며, 플랫폼별 기능 제공 원칙은 [플랫폼 계약](platform-compatibility.md)을 따릅니다.

## 책임과 수명

- `packages/cli/src/inspect-document.mjs`는 문서 바이트·SHA·포맷을 대조하고 Native에서 관측한 메타데이터를 반환합니다. `observed`, `unknown`, `unsupported`를 구분하며, 문서 열기 성공을 암호화 부재나 전체 편집 가능 여부로 해석하지 않습니다. 자체 문서 세션은 성공·실패 모두 닫습니다.
- `packages/cli/src/document-images.mjs`는 빌린 SDK에서 구역별 그림 참조를 열거하고 이미지 바이트를 복사합니다. `close()`는 자체 캐시만 해제하며 SDK 수명은 호출자가 소유합니다. 목록과 반환 바이트는 내부 저장소와 분리합니다.
- `arguments.mjs`, `main.mjs`, `files.mjs`는 명령 검증·결과 보고·파일 접근을 담당합니다. MCP 도구는 같은 명령 처리 경로를 사용하며 문서 해석을 복제하지 않습니다.

현재 이미지 목록의 범위는 **구역 본문의 그림 참조**입니다. 배경 브러시·바탕쪽·미참조 이진 자원을 전수 열거하는 기능과 구분하고, 출력에 이 범위를 표시합니다. 이미지 형식 식별은 시그니처와 일부 헤더 관측이며 픽셀 유효성 검사가 아닙니다. 인식하지 못한 내장 그림도 원본 바이트를 `.bin`으로 보존할 수 있습니다. 외부 링크는 내려받지 않습니다.

## 추출과 결과 보고

CLI의 `extract-images`는 새 디렉터리에 생성한 파일명으로 저장합니다. 단건을 선택할 때는 목록의 그림 ID와 같은 원문의 SHA가 필요합니다. MCP의 `extract_document_image`는 ID·SHA와 새 출력 파일 경로를 받습니다. 문서 파일이나 기존 출력은 덮어쓰지 않으며 경로에 포함된 심볼릭 링크를 거부합니다. 임의의 동시 경로 교체까지 방어하는 `openat` 기반 구현이라는 주장은 하지 않습니다.

추출 도중 일부 파일이 저장된 뒤 실패하면 저장 사실·위치·개수를 보고하고 실패 상태를 반환합니다. 빈 출력 디렉터리가 남을 수도 있습니다. 기존 경로로 재시도해 파일을 덮어쓰지 않습니다. 출력 스트림 자체가 끊기면 사용자에게 전달되었다고 보장할 수 없습니다.

한도는 참조 4,096개, 이미지 한 개 8MiB, 캐시에 보관하는 고유 바이트와 호스트가 저장하는 전체 바이트 각각 32MiB입니다. HWPX의 현재 Native API는 JS 검사 전에 최대 64MiB의 바이트를 만들 수 있으므로, JS의 8MiB 제한을 사전 할당 상한으로 설명하지 않습니다. Native 파싱 전체의 선형 시간이나 프로세스 전체 메모리 상한도 보장하지 않습니다.

많은 그림과 긴 출력 경로가 결합되면 파일 저장 후 결과 목록이 보고 한도를 초과하는 오류가 확인됐습니다. 예상 파일 경로·SHA·개수에 필요한 보고 공간을 저장 전에 검사하도록 수정했습니다. 저장 후 진단 생성이 실패하는 경우에는 저장 위치·개수와 세부 목록 생략 여부를 제한된 대체 보고에 남깁니다. 전체 목록을 조용히 잘라 성공으로 처리하지 않습니다.

## 확인한 결과와 범위

실제 Noori HWP5·HWPX에서 각각 그림 네 개를 추출해 SDK의 원본 바이트와 비교했고, 두 포맷 사이에서도 네 이미지의 SHA가 일치했습니다. 읽기 작업 뒤 문서를 저장한 전체 바이트도 원본과 같았습니다. 실제 CLI·MCP에서는 원문 SHA 불일치·기존 출력 거부·단건 추출과 읽기·편집·재열기를 별도로 확인했습니다.

합성 경계 검사에서는 유효한 경로 구성 요소를 사용한 긴 경로와 참조 4,096개의 조합이 이미지 읽기·저장 전에 거부되는 것을 확인했습니다. 저장 후 경고가 커지는 경우와 오류 출력 실패도 확인했습니다. 이 결과를 모든 문서·모든 자원의 추출 또는 RN 실제 실행의 증거로 확대하지 않습니다. 검증 자료는 `zig-out/verification/cli-info-r1/`, `cli-images-r1/`, `cli-info-images-r1/`에 보존합니다.

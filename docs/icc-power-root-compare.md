# ICC 거듭제곱 근과 정확한 좌표의 비교

## 범위와 반환값

[기호적 실근](icc-power-level.md)을 실제 밑 좌표와 비교합니다. 기반 식은 [ICC.1:2022 Table 68](https://www.color.org/specifications/ICC.1-2022-05.pdf)의 거듭제곱 분기입니다. 근이나 좌표를 f64로 바꾸지 않습니다.

`power_root_compare.compare(precision, root, n, d)`는 근과 정확한 signed i128/u128 좌표 n/d의 순서를 반환합니다. d=0은 오류입니다. `.lt/.eq/.gt`는 증명된 순서이고 `null`은 선택 정밀도로 판정하지 못했다는 뜻입니다. null을 같음, 범위 밖, 근 부재로 바꾸면 안 됩니다. 호출자가 더 높은 정밀도로 재시도하거나 미확정을 전파해야 합니다.

`at(precision, root, a, b, x)`는 정규화 u64 Fraction x를 검증하고 원본 signed 16.16 a/b로 `(a*x+b)/65536`을 정확히 만든 뒤 비교합니다. **밑 변수의 근과 밑 좌표의 순서**이며, x 좌표 순서나 활성 구간 포함 판정 그 자체가 아닙니다. a의 부호, a=0, 열린/닫힌 끝점, 클리핑 분할·전체 단조성·역변환은 후속 계층의 책임으로 남습니다.

정밀도는 컴파일 시 128/256/512/1024 유효 정수 비트 중 선택합니다. 최대 정밀도로 모든 가능한 입력이 반드시 분리된다는 보장은 아직 증명하지 않았습니다. 미확정은 잘못된 파라미터라는 뜻도 아닙니다. 유효 곡선 전체의 무조건 판정 완료나 전체 문서 기능 완료를 주장하지 않습니다.

## 책임과 증명

- `power_level.Radical.validate`: 생성 계약인 1..4294967295의 radicand 분자, ±65536의 역지수 분자, 1..2147483648의 분모를 검증합니다. 외부 구성 값도 부호만 보고 조기 반환하기 전에 검사합니다.
- `integer_power`: 정수 거듭제곱이 지정 한계 이하이면 정확한 값을, 초과하면 null을 반환합니다. 양의 정수의 완전 거듭제곱근은 이 비교를 사용한 이진 탐색으로 구합니다. 정수 곱의 빈 곱 항등값과 실수 0^0 정의역 정책은 다릅니다. 실근 생성기가 0^0을 먼저 제외합니다.
- `radical_equality`: 양수 크기의 정확한 등식을 검사합니다. 기약분수 A/B와 서로소 지수 p/q에 대해 `(A/B)^(p/q)`가 유리수이려면 A와 B가 각각 완전 q제곱이어야 합니다. 소인수 지수가 q로 나누어져야 한다는 조건으로 증명할 수 있습니다. 완전근을 구한 뒤 p제곱을 기약 좌표 분자·분모 한계 안에서만 계산합니다. 한계 초과는 동등하지 않음의 정확한 증거입니다.
- `positive_bounds`: 양수 유리수의 정수 유효숫자·이진 지수 상/하한을 소유합니다. 나눗셈의 몫/나머지와 곱의 버린 하위 비트로 하한은 아래쪽, 상한은 위쪽으로 반올림합니다. 거듭제곱은 반복 제곱으로 최대 32개 지수 비트를 순회합니다. 양수 곱의 순서 보존으로 매 단계 참값을 감쌉니다.
- `power_root_compare`: 영점·부호·정확한 등식 검사를 먼저 하고 나머지 크기 비교를 상/하한 연산으로 조립합니다. 음수 근의 크기 순서는 마지막에 뒤집습니다. 서로 겹치지 않는 구간에서만 부등식을 반환합니다.

근 크기가 `(N/65536)^(±65536/q)`일 때 양의 지수에서는 `(N/65536)^65536`과 `(|n|/d)^q`를 비교합니다. 음의 지수에서는 첫 비율을 뒤집습니다. 양수에 대한 q제곱의 엄격한 증가 성질로 원래 순서가 보존됩니다. 동등성은 구간의 겹침 여부로 추정하지 않습니다.

정규화 유효숫자는 선택 비트 폭을 채우므로 끝점의 이진 지수, 같은 지수일 때 유효숫자 순으로 정확히 비교할 수 있습니다. 곱은 두 배 폭 정수에 들어갑니다. 상향 올림이 유효숫자 최대값을 넘으면 2의 거듭제곱으로 정확히 재정규화합니다. 초기 분수 스케일은 입력 비트 길이로 정하며 두 배 폭을 넘지 않습니다.

좌표 절댓값은 i128 최솟값까지 u128로 보존합니다. at의 분자·분모 중간값은 각각 i128/u128 안에 들어갑니다. 유효 입력의 이진 지수 크기는 128비트 좌표와 최대 2³¹ 지수에서 대략 2³⁸ 규모로 i64보다 작으며, 합·차에도 checked 연산을 사용합니다. 거대한 거듭제곱 정수를 전개하지 않고 고정 크기 값 연산만 사용하며 할당하지 않습니다.

## 검증 계약

네이티브 검사는 정수 한계·완전근, 1/3의 정확한 양/음 역근, 약분 전 좌표, 영점, 지수 극값, i128 최솟값, 잘못 구성한 근/좌표와 Pell 반례를 포함합니다. 별도 `positive_bounds_tests`는 n,d=1..17, 지수 0..7의 모든 2,312개 조합에서 두 끝점이 정확한 u256 유리수 거듭제곱을 감싸는지 검사합니다.

테스트 WASM mode183 입력은 precision u32 BE, g/offset/target i32 BE, root index u32 BE, n i128 BE, d u128 BE의 52바이트입니다. mode184는 같은 첫 20바이트 다음 a/b i32 BE, x 분자/분모 u64 BE의 44바이트입니다. all_nonzero는 NonIsolatedIccPowerRoot, 범위 밖 index는 InvalidIccPowerRootIndex입니다. 결과 i32 LE는 −1/0/+1의 정확한 순서 또는 2의 미확정입니다. 제품 JS API에는 노출하지 않습니다.

독립 JS 검사는 작은 기약 지수의 **전체 BigInt 거듭제곱과 교차 곱을 직접 전개**합니다. 제품의 상/하한 연산을 재사용하지 않으며, 밑 부호의 허용 목록만 기존 독립 해 집합 테스트에서 공유합니다. 비정수·음의 지수, 128비트 좌표, 결정적 난수 1,000개, a/b 극값과 u64 좌표, 비이진 유리수 등식, 잘림·과잉·자원 제한·오류 후 정상 호출을 검사합니다. 전개가 비현실적으로 큰 극값 지수는 좌표 1과의 비교를 우변 원값의 순서로 독립 확인합니다.

### 정밀도 부족과 승격

근 √(1/2)와 아래 좌표들을 비교합니다. 정확한 순서는 BigInt의 2n²−d²로 확인합니다.

| n/d | 2n²−d² | 128비트 비교 | 512비트 비교 |
|---|---:|---|---|
| 66992092050551637663438906713182313772 / 94741125149636933417873079920900017937 | −1 | 미확정 | 근이 좌표보다 큼 |
| 161733217200188571081311986634082331709 / 228725309250740208744750893347264645481 | +1 | 미확정 | 근이 좌표보다 작음 |

이 두 미확정을 정상 결과로 검사합니다. 미확정을 같음으로 바꾸는 임시 반환값 변형은 독립 검사가 ERR_ASSERTION으로 검출했습니다. 앞 단계의 u64 Pell 좌표 두 개도 at(256)에서 올바르게 구분하며 f64 순서 역전 경로를 사용하지 않습니다.

## 실행 기록

네이티브 최종 추가 테스트는 499/499, 5/5 단계로 통과했습니다. 직접 WASM 대조는 비교 2,983건·예상 오류 거부 1,117건·의도된 미확정 2건으로 통과했습니다.

초기 전체 Debug 실행 `/tmp/hwpjs-icc-root-compare-Debug.log`는 JS 기대값 −0과 제품 정수 결과 0의 strictEqual 차이로 실패했습니다(18/20 단계, 당시 네이티브 498/498). 정수 비교 wire에는 음의 0이 없으므로 독립 기대값의 부호 곱/반전을 0으로 정규화했습니다. 제품 비교 코드는 이 실패를 이유로 변경하지 않았습니다. 직접 대조와 추가 상/하한·입력 경계 테스트 후 최종 세 모드 감사를 순차 실행합니다.

최종 로그는 `/tmp/hwpjs-icc-root-compare-Debug-final.log`, `/tmp/hwpjs-icc-root-compare-ReleaseSafe-final.log`, `/tmp/hwpjs-icc-root-compare-ReleaseFast-final.log`입니다. 완료 결과를 확인하기 전에는 최종 전체 감사 통과로 표시하지 않습니다.

최종 Debug 로그는 20/20 단계·499/499 네이티브 테스트·WASM 검사 6,378,352건으로 통과했습니다. 신규 결과는 비교 2,983건·거부 1,117건·미확정 2건입니다.

추가 수동 적대적 검증에서는 ±1 근과 128비트 한계 주변의 좌표를 비교했습니다. n=2¹²⁷−1 또는 −2¹²⁷, d=2¹²⁷−2..2¹²⁷+1, 극값·양/음·정수/비정수 지수와 256/512/1024비트 정밀도를 조합하여 132건을 확인했습니다. 정확한 ±d−n의 부호와 모두 일치했습니다. 이 수동 건수는 정규 감사에 합산하지 않습니다.

ReleaseFast 산출물 직접 대조도 비교 2,983건·거부 1,117건·미확정 2건으로 통과했습니다. 시스템 ICC para TRC 태그 15개(type0/type3)의 실제 g/a/b와 활성 거듭제곱 구간 시작·중간·끝 좌표를 사용하여 0/1 밑 근 비교 90건을 추가 확인했습니다. 이 태그들의 거듭제곱 출력 오프셋은 0이므로 밑 근은 정확히 0/1이며, 독립 정수식 target*d−a*n−b*d의 부호와 모두 일치했습니다. 파일은 읽기만 했으며 수동 건수를 정규 감사에 합산하지 않았습니다. 픽셀 색상 일치나 전체 곡선의 단조성 검증은 아닙니다.

### 최종 확인

세 모드 순차 감사는 종료 코드 0으로 완료했습니다. 위 최종 로그 세 파일 모두 20/20 단계·499/499 네이티브 테스트·WASM 검사 6,378,352건을 기록합니다. 앞의 실행 중 문장은 진행 이력이며 최종 결과는 이 절이 소유합니다.

반올림 방향·올림 후 재정규화, 양수 곱의 포함 관계, 정확한 등식의 완전근 조건, 음수 크기 순서 반전, 최소 i128 절댓값, 배열/입력 경계와 미확정 전파를 재검토했습니다. 해당 범위에서 추가 결함은 발견하지 않았습니다. 포맷·변경 JS 문법·로컬 문서 링크·diff 공백 검사도 통과했습니다. 미확정 입력의 완전 판정, 활성 구간 포함·클리핑 분할, 전체 문서 기능은 여전히 후속 범위입니다.

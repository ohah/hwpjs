# HWP5 각주·미주 원문 표식 위치

[본문 계약](hwp5-body-contracts.md) · [자동 번호 관계](hwp5-note-number-links.md)

## 현재 계약

각주 `fn  `와 미주 `en  `는 문단 텍스트의 확장 제어 토큰(코드 17)과 같은 문단의 `HWPTAG_CTRL_HEADER`가 순서대로 짝지어집니다. `control_links.Links`가 이미 문단·텍스트·컨트롤 노드 인덱스, 원본 UTF-16 코드 유닛 시작 위치, 토큰/헤더 ID와 일치 종류를 소유합니다. 새 주석 전용 파서나 번호별 전역 ID 맵을 만들지 않습니다. `control_type_validation`은 해당 ID의 코드 17을 확인합니다. `note_validation`은 컨트롤의 직접 리스트를, [자동 번호 관계](hwp5-note-number-links.md)는 그 리스트의 번호 컨트롤을 별도로 확인합니다.

`start_unit`은 해당 문단의 원본 `PARA_TEXT`에서의 UTF-16 코드 유닛 오프셋입니다. 파일 전체의 바이트 오프셋, 화면 좌표, 주석 번호, 편집 가능한 커서 위치가 아닙니다. 같은 문단에 각주·미주가 여러 개 있어도 각 표식은 발생 순서대로 서로 다른 컨트롤 헤더를 가리킵니다. 중첩 문단의 표식을 바깥 문단의 것으로 취급하지 않습니다. 원문 위치를 문서 모델의 주석 객체/저장 가능한 참조로 승격하는 것은 후속 책임입니다.

## 명세·실파일 대조

[한컴 공식 HWP 5.0 명세 revision 1.3](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.3.pdf)의 제어코드 표 6과 컨트롤 ID 표 127에 맞춰 `fn  `·`en  `와 코드 17만 주석 표식으로 간주합니다. 로컬 명세 요약 4.3.10.4의 `foot`는 꼬리말 ID라서 각주 별칭으로 사용하지 않습니다. `fn  `·`en  `의 공백과 대소문자를 보존합니다.

2026-09-27 독립 원시 Section 레코드와 테스트용 WASM `Links` 출력을 대조했습니다. 추적된 `footnote-endnote.hwp`에는 표식 4건, 로컬 `reference/rhwp/samples`의 `footnote-01.hwp`에는 9건, `endnote-01.hwp`에는 6건, `footnote-tbox-01.hwp`에는 2건이 있습니다. 21건 모두 코드 17·정확한 동일 ID로 연결되며, 문단·텍스트·컨트롤 노드 인덱스와 UTF-16 시작 위치를 `tests/hwp5/note-source-sites.mjs`의 파일별 고정 기대값과 대조합니다. 추적 파일은 기본 HWP5 audit, 뒤의 세 파일은 로컬 레퍼런스가 있을 때의 선택 검사입니다. 선택 파일이 없으면 검증 완료로 세지 않고 기존 audit의 `skipped`에 남습니다.

합성 반례는 같은 문단의 반복 ID 두 건을 발생 순서대로 짝짓고, 표식 앞 한 코드 유닛 삽입 시 위치 변화가 고정 기대값을 깨는지 확인합니다. 중첩 주석 문단은 바깥 문단과 별도 위치를 가지며 `foot` 꼬리말을 주석으로 세지 않습니다. 잘못된 ID·코드, 빠진 헤더·빠진 토큰은 거부하고 정상 입력으로 복구됩니다. 이 검사는 네 실파일과 합성 입력의 **원문 표식 연결**만 증명합니다. 화면 조판·번호 순서·본문 주석 텍스트 편집·저장과 모든 HWP 버전의 호환성을 증명하지 않습니다.

ReleaseSafe `zig build hwp5-audit -Doptimize=ReleaseSafe` 재검증에서 8,905,855회 검사와 추적 HWP 48개 처리가 통과했습니다. 변경된 JS 세 파일의 구문 검사와 `git diff --check`도 통과했습니다. 이 수치는 지원 기능 비율이나 전체 문서 검증률이 아닙니다.

# ICC 전체 parametric 출력 범위

## 계약과 책임

`src/image/icc/parametric_range.zig`의 build는 전체 클리핑 출력 집합을 하위 선형 분기의 WideInterval과 상위 거듭제곱 분기의 Range의 합집합으로 반환합니다. 두 출력 구간은 입력 분기와 달리 겹치거나 순서가 뒤집히거나 떨어질 수 있습니다. 따라서 전체를 하나의 닫힌 구간으로 합치거나 정렬하지 않습니다.

먼저 [거듭제곱 출력 범위](icc-power-range.md)를 통해 전체 실수 정의역을 검사합니다. 미확정이면 부분 선형 결과도 노출하지 않습니다. 기존 parametric_segments의 분기 정책과 [선형 출력 범위](icc-linear-range.md)를 재사용하며 임계점·클리핑·계수 매핑 규칙을 복제하지 않습니다. 결과 타입은 parametric_range_types에 분리합니다.

원래 선형 입력의 열린 끝은 출력이 상수거나 클리핑 평탄부인 경우 닫힐 수 있습니다. 이 규칙은 linear_range가 소유합니다. 거듭제곱 출력은 정확한 식과 증거점을 유지합니다. 증거점은 역변환에서 우선 선택해야 하는 입력이라는 뜻이 아닙니다.

예를 들어 type4 `[65536,0,0,65536,32768,65536,0]`의 출력은 `[0,1/2)`와 `{1}`입니다. 중간 틈을 채우지 않습니다. `[65536,65536,0,131072,32768,0,0]`는 `[0,1)`와 `[1/2,1]` 두 기여를 그대로 유지합니다. 상위 비활성, 시작점 0, 마지막 단일점도 기존 분기 정책을 따릅니다.

## 독립 검증

네이티브 테스트는 틈·상수 단계·겹침·마지막 단일점·비활성 분기·전체 정의역 오류를 검사합니다. 테스트 mode207은 precision u32 BE와 para 태그를 입력받습니다. 미확정은 4바이트 0, 확정은 status=1 뒤 선형 범위 공통 136바이트와 거듭제곱 범위 공통 wire를 붙입니다. 상위 비활성이면 총 144바이트, 활성이면 312바이트입니다. serializer는 입력으로 분기를 재계산하지 않고 실제 조립 결과만 직렬화합니다.

`tests/hwp5/icc-parametric-range.mjs`는 독립 정의역 oracle로 선형 입력 구간을 만들고, 독립 BigInt 선형 출력 기준과 비교합니다. 상위 출력은 기존 독립 후보점 열거·정확한 거듭제곱 계산 기준을 공유합니다. 기대값 생성에 제품 모듈을 사용하지 않습니다. 서로 다른 c/e/f 값으로 필드 위치 혼동도 검사합니다.

Debug WASM 직접 실행에서 정상 범위 2,063건과 오류 거부 1,229건, 총 3,292건이 통과했습니다. 기존 상위 범위 3,342건도 동일하게 통과했습니다. 선형 분기 삭제·상위 분기 삭제·열린 선형 끝 닫기 변형은 각각 ERR_ASSERTION으로 검출했습니다. 제품 코드에는 변형을 남기지 않았습니다.

전체 build의 미확정을 실제로 발생시키는 입력은 이번 테스트에 포함하지 못했습니다. 점 helper의 정밀도 반례와 전체 조립의 미확정 테스트를 동일시하지 않습니다.

네이티브 전체 실행은 578/578 테스트가 통과했습니다. 변경 Zig 포맷, JS 문법, diff 공백과 관련 문서 로컬 링크 3개도 확인했습니다.

## 실제 프로파일 대조와 재검토

시스템 DCI(P3) RGB·Display P3·ITU-2020·ITU-709·ROMM RGB의 RGB TRC 태그 15개를 읽기 전용으로 검사했습니다. type0은 선형 기여 부재와 출력 0/1을 확인했습니다. type3은 g/a/c>0, 0<d<65536, a+b=65536을 확인한 뒤 선형 출력 `[0,c*d/65536²)`와 상위 하한의 입력 d/65536, affine 밑 `(a*d+b*65536)/65536²`, 원본 지수·offset=0, 상위 출력 1을 정수 교차곱으로 대조했습니다. 15개 모두 통과했으며 수동 검사는 정규 audit 호출 수에 합산하지 않습니다. 근삿값·OS 색변환 결과나 HWP 렌더링 비교를 주장하지 않습니다.

조립 코드 재검토에서는 전체 정의역 검증 선행, 미확정의 부분 결과 비노출, 입력 분기의 순서와 출력 구간 순서의 구분, 상수 출력의 끝점 포함, 증거점과 역변환 선택의 구분을 확인했습니다. 공통 serializer 추출 후 기존 mode205/206 독립 테스트 결과도 유지됐습니다. 출력 할당 전 임시 power 버퍼는 defer로 해제하고 할당된 결과 바이트는 전부 초기화합니다.

## 최종 전체 감사

Debug·ReleaseSafe·ReleaseFast 전체 audit가 각각 종료 코드 0, 20/20 단계, 네이티브 578/578, WASM checks=6,572,764로 통과했습니다. 이전 6,569,472건에 신규 3,292건이 추가됐습니다. 각 모드 신규 결과는 ranges=2063/rejected=1229입니다. 로그는 `/tmp/hwpjs-icc-parametric-range-{Debug,ReleaseSafe,ReleaseFast}.log`입니다.

ReleaseSafe·ReleaseFast의 실제 감사 산출물을 직접 실행해 같은 신규 수치를 확인하고, 열린 선형 끝을 닫는 변형을 각각 ERR_ASSERTION으로 검출했습니다. 공유 serializer와 독립 oracle 추출을 포함한 전체 회귀이며 제품 JS API는 바뀌지 않았습니다.

## 남은 범위

서로 다른 기호적 출력값의 거리 비교, 최근접 출력의 존재·동률 처리 및 F.1(a) 연결은 미구현입니다. 전체 ICC 역변환, PNG 픽셀 연결, HWP/HWPX 문서 기능 완료를 의미하지 않습니다.

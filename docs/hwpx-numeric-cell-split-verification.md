# 숫자 셀 분할의 독립 검증

## 범위와 단일 출처

실제 `chart.hwpx`의 SUM/AVG 범위 수식과 plain 셀을 검증합니다. 일반 수식 엔진·모든 선택 분기·전체 픽스쳐/브라우저/조판 검증이 아닙니다. 후보는 [필드 문단 병합 수정](hwpx-formatted-field-merge-regression.md)의 `formatted-original-field-merge/bin/hwpjs.wasm` SHA256 `7f310f37d2900794df5aeb2ec2b8df4c95e61f8b49b6e477a6209fadd2e74d26`이며 기본 제품을 교체하지 않았습니다.

문단 분할 XML·생성 ID의 양수/유일성·비대상 ZIP 대조는 기존 `hwpx-resplit-save-oracle.py`가 소유합니다. 새 `hwpx-sum-split-oracle.py`는 이 구조 검사기의 programmatic expected-transform 경계로 예상 XML만 갱신합니다. 실제 출력의 결과값을 기대 산술에 사용하지 않습니다. 수식 참조 문법은 기존 독립 fixture 검사기에서 재사용하고, Decimal 계산은 원본/예상 분할 셀에서 각각 수행합니다. 변경된 결과에만 dirty·LastResult·Command·정확히 연결된 본문을 반영하고 다른 내용은 전체 XML 비교에서 유지합니다. 이 도구는 관측한 변경 결과의 `%g`/`%g,`만 지원하며 다른 변경 표시 형식은 거부합니다.

SUM은 첫 직접 문단의 숫자를 읽으며 이후 문단을 연결하거나 나중 숫자를 검색하지 않습니다. 빈 문자열·잘못된 숫자 문법은 SUM의 숫자 목록에서 제외합니다. ASCII 정수/그룹/소수 문법은 독립 정규식으로 판정하고 AVG는 여러 문단·잘못된 숫자를 거부합니다. 컨트롤은 모든 문단에서 확인해 이후 문단에 숨은 컨트롤도 조용히 무시하지 않습니다. 일반 식·중첩 표/병합 셀은 이 oracle의 지원 증거로 확대하지 않습니다.

## 실측과 적대적 검증

최종 보강 뒤 실행5/5·exit0·skip0(24170.718708ms)은 두 숫자 분할 회귀·SUM→AVG 참조 변조를 추가한 inventory·수식 구조 세션·참조 셀 이력 검사를 포함합니다. 첫 결과를 잘못된 문단 연결 값67.5로 변조하는 반례도 양 Python 모드에서 거부했습니다. 앞선157경계 전체 실행과 이 집중 실행의 범위/수를 합산하지 않습니다.

최초11.2의0/1/2/3/4 경계는 모두 성공했습니다. 끝4 경계는 수식 결과가 같아 순수 분할 oracle로 일치했고, 앞·중간은 SUM 결과가 바뀌어 순수 구조 oracle가 의도대로 거부했습니다. 이 실패를 허용 목록으로 숨기지 않고 산술 expected-transform을 추가했습니다.

`formula-numeric-split-editor.test.mjs`의 끝 분할은11.2/100/0 각각을 검사한1/1·exit0·skip0(7160.381583ms)이었습니다. 후속 산술 테스트는 같은 세 값의 총11경계를 추가했습니다. 두 테스트2/2·exit0·skip0(19659.147375ms)는 양 Python 모드의 전체 XML/ZIP·잘못된 분할 위치 기대·변경/비변경 수식의 일관된 잘못된 결과/캐시 변조·undo/redo·거부 뒤 redo 보존·재열기·입력 메모리/디스크 불변을 확인합니다. 이후 첫 변조 값은 문자열999 대신 잘못된 문단 연결 결과67.5로 강화했습니다. 이를 앞선 실행에 소급하지 않습니다.

독립 Python 단위 검사2개는 일반/`-O` 모두 통과했습니다. 첫 빈 문단 뒤의 숫자 검색 금지·문단 연결 금지·잘못된 trailing dot/분리 소수·ASCII 숫자 문법·그룹 소수·뒤 문단 컨트롤 거부를 포함합니다.

기존 세 실패는 전체 숫자 셀 분할 거부 기대가 오래된 것이었습니다. fixture inventory가 수식 참조에서 SUM 전용 의존 셀과 AVG 등 strict 의존 셀을 독립 분류하도록 보강했습니다. 기존157경계를 모두 실행해108 SUM 분할 성공을 산술/전체 XML 양 Python 모드로 대조하고,49 strict 의존/수식 내부 거부에서 원문/기존 redo 보존을 확인했습니다. 수정된 세 검사와 inventory 검사4/4·exit0·skip0(111399.888083ms)입니다. 구조66개 전체·공개 suite 전체 완료를 의미하지 않습니다. 최신 전체 native gate·기본 WASM/외부 데모 승격 및 runtime/관련 공개 회귀의 커밋은 남습니다.

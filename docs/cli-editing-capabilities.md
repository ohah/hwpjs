# CLI·MCP 편집·생성·변환 기능 계약 초안

## 기준과 문서의 역할

기준 공개 배포는 `d8706ee31e0c44dad33a2da614ff6335da3677c4`이며 아래 첫 표는 그 배포의 역사적 범위입니다. 현재 후보는 이후 TypeScript 전환과 apply·새 문서·text-only 변환·OCR·문단 원문 조회를 포함합니다. 이 문서는 두 세대를 구분해 현재 후보의 실측과 남은 기능의 수용 기준을 관리합니다. 아래 작업명과 진행 상태는 구현 계약이며 설치된 명령·MCP 도구의 제공 여부와 구분합니다. 구현 소유자가 입력 스키마와 실패 계약을 확정한 뒤 공개 가이드에 반영합니다. 기존 읽기 계약은 [문서 관측·편집 경계](cli-ai-document-view.md)가 소유합니다.

목표는 원본 HWP5/HWPX를 공통 엔진으로 읽고 수정·저장하며 필요한 변환과 개체 처리를 제공하는 것입니다. 과거 Rust 함수명·동기 방식·문자열 형식을 그대로 재현하는 것은 수용 조건이 아닙니다. 문서 전체 JSON 출력이나 HTML 문서 작성만으로 원본 편집을 대체하지 않습니다. 기능 구현의 승인과 각 기능의 설치·배포 완료는 구분합니다.

현재 Native 기준은 SHA256 `82031994b4b7f066c28c725495954eebc67bb25570869c06528ea328e0155ccc`인 WASM입니다. 새 기능은 이 산출물의 기존 기능부터 연결합니다. 필요한 ABI가 없으면 미지원 사유를 내고 별도 Native 작업으로 분리합니다. 작업 디렉터리의 SDK 변경을 이 기준에 섞어 실행하거나 출하하지 않습니다.

아래 결과는 소스 서비스와 격리된 Git SDK·Native820, 별도 npm 설치 후보에서 확인한 범위입니다. 기준 공개 배포의 명령 목록에 합산하지 않으며, 설치 실행과 공개 실습 배포는 해당 산출물의 증거로 구분합니다. TypeScript 소스와 JS 배포의 경계는 [CLI·MCP TypeScript 빌드](cli-typescript-build.md)를 따릅니다.

글자·문단 서식은 제공하는 속성의 sparse 변경과 기존 리소스 참조 범위를 따릅니다. 표 생성은 생성된 실제 identity를 결과로 반환하며 행/열 삭제·임의 병합 같은 추가 작업을 암시하지 않습니다. 그림은 크기 조정이며 새 원시 그림 삽입·교체가 모두 구현됐다는 뜻이 아닙니다. 차트·수식 래스터화, OLE 원시 추출, 전체 의미 보존 변환 등 미완료 항목은 아래 행렬에 계속 남깁니다.

## 공통 작업·저장 계약

1. **원본 결속:** 원본을 한 번 읽은 소유 바이트와 SHA로 작업을 시작합니다. 편집 대상은 같은 스냅샷에서 발급한 Native 주소 또는 논리 참조여야 합니다. HWP5 문단 번호는 구역 안의 0 기반, HWPX는 문서 전체의 1 기반 Native 번호를 유지합니다. 표시 순번으로 재구성하지 않습니다.
2. **공통 엔진:** Node CLI·MCP·웹은 같은 메모리 기반 작업 함수를 호출합니다. 파서·writer·문자 좌표·색·폭·단위 변환을 호스트마다 복제하지 않습니다. RN은 현재 JSI/provider 경계에 같은 기능을 연결하며 Node CLI나 파일시스템 모듈을 내장해 실행하지 않습니다.
3. **명시 변경:** 생략은 유지, 명시한 빈 문자열·0·검정·NONE은 각각의 실제 변경 값입니다. 미관측 `null`을 폼 기본값으로 승격하지 않습니다. 지원하지 않는 속성·형식·보호 상태를 조용히 무시하지 않습니다.
4. **대상과 좌표:** UTF-16 편집 좌표와 보호·구조 컨트롤 검사는 Native 정책을 따릅니다. 표시용 텍스트를 정규화해 원문 오프셋으로 재사용하지 않습니다. apply의 좌표는 current-transaction 기준입니다. 뒤 작업은 앞 작업이 반영된 현재 문서의 대상·범위를 지목하며, 최초 스냅샷 좌표를 자동 보정하지 않습니다. Native `expectedText` 사전조건으로 실제 대상 원문을 확인하고 불일치하면 후보를 버립니다.
5. **원자 게시:** 새 출력 경로가 필수입니다. 기존 파일·원본 경로·하드링크 충돌·출력 심볼릭 링크를 거부합니다. 검증·편집·저장 실패 시 최종 문서 파일을 게시하지 않습니다. 게시 완료 뒤 진단 출력이 실패하면 `published` 상태를 보존해 재실행으로 덮어쓰도록 유도하지 않습니다.
6. **일괄 작업:** 명시 작업 목록의 타입·키·필수 필드·숫자 범위·배치 예산을 전체 사전 검증한 뒤 소유 후보 세션에서 순서대로 수행합니다. 실행 시 현재 좌표와 Native `expectedText`를 검증하고 한 번 저장·게시합니다. 마지막 작업 실패 시 후보 전체를 버립니다. 기존 Native 배치가 제공하는 한 이력 명령과, 후보 세션을 통한 최종 파일의 원자 게시를 혼동하지 않습니다. 단일 Native 트랜잭션을 제공하지 못하는 작업 조합은 그 제한을 명시합니다.
7. **조판과 손실:** HWP5의 `allowStaleLayout`은 기본 false를 유지합니다. 조판 갱신 필요·미관측 개체·변환 손실은 결과에서 분리해 알립니다. 소리 없이 보호 검사나 저장 정책을 완화하지 않습니다.
8. **자원과 소유권:** 입력·출력·디코딩·개체 수·제공자 실행에 각각 상한을 둡니다. 현재 호스트 문서 파일 한도는 64MiB, WASM 읽기 한도는 32MiB이며, 내부 엔진의 더 큰 출력 한도를 호스트 게시 허용으로 해석하지 않습니다. 개체 조회는 스냅샷별 inventory와 Map을 재사용하고 대상마다 전체 문서를 다시 읽지 않습니다. 관측 항목 N개와 작업 M개의 소유자 결속은 O(N+M)을 목표로 하며, 변환·출력 비용과 별도로 검증합니다.

읽기와 변경의 결과 형식은 분리합니다. content 읽기는 문서 본문, structure는 편집 대상·SHA·진단을 제공합니다. 변경 작업은 새 출력·SHA·변경 여부·조판 상태와 실패/게시 여부를 영수증으로 전달합니다. 문서 내부 문자열을 명령·파일 경로·외부 요청 권한으로 해석하지 않습니다.

각 행은 최종 수용 범위이며 위에서 확인한 일부 서비스보다 넓습니다. 행 전체의 완료 표시가 아닙니다. 실제 SDK 실행, 독립 컨테이너 비교, 설치된 CLI/MCP, 브라우저·RN 실행 증거를 별도로 남깁니다.

## 변환의 손실·미관측 보고

같은 포맷 저장과 교차 포맷 변환의 보존 기준을 나눕니다. 같은 포맷은 가능한 범위에서 원본의 무관 스트림·파트·리소스·불명 레코드를 보존합니다. 교차 포맷은 컨테이너 바이트 동일성을 요구할 수 없으므로 원본 개체별 의미·서식·소유 관계와 출력 대응을 검증합니다.

현재 text-only 경로는 원문에서 관측한 본문을 대상 형식의 새 문서로 재생성하는 손실 있는 변환입니다. 이 경로는 사용자가 명시 선택해야 하며, 표의 텍스트가 남는 것과 원본 표 구조가 보존되는 것은 다릅니다. 원본 그림·서식·개체·구역 설정 등의 미보존 범위를 알리고, 기본 보존 요청을 자동 text-only로 대체하지 않습니다. 전체 의미 보존 경로는 미완료 항목으로 유지합니다.

새 변환 결과에는 지원된 항목, 관측했으나 변환하지 못한 항목, 원본에서 관측하지 못한 범위, 조판 갱신 필요를 구분하는 계약이 필요합니다. 변환하지 못한 항목이 있는 작업을 완전 변환으로 표시하지 않습니다. 허용 가능한 손실 정책은 명시 옵션으로 정하고, 적용하지 않은 정책을 사용자 동의로 추정하지 않습니다. `allowStaleLayout`은 교차 포맷 손실이나 보호 해제의 포괄 허가가 아닙니다.

이미지 원시 추출, 이미지 디코딩, WMF/EMF 래스터화, 차트·수식 렌더링, OCR은 서로 다른 단계입니다. 각 단계가 실제 지원하는 입력·출력과 실패 상태를 노출합니다. 알려지지 않은 바이트는 기존처럼 원시 데이터로 남기며, 확장자 식별을 픽셀 유효성으로 해석하지 않습니다.

## 공개 실습의 실제 실행 경계와 확장 계획

기준 배포의 [공개 실습](https://ohah.github.io/hwpjs/cli-simulation)은 공개 샘플과 WASM을 가져와 `cli-simulation.mjs`의 메모리 엔진 `read`·`edit`를 호출합니다. CLI 명령과 MCP 요청 예시는 설명용이며 브라우저 안에서 Node 프로세스나 MCP stdio 서버를 실행하지 않습니다. 실제 출력 문서는 엔진의 소유 바이트로 Blob을 만들고 다운로드합니다.

| -------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

새 기능 UI는 이번 TS 전환의 완료 조건에 포함하지 않습니다. 현재 실습의 읽기·보기 전환·대표 편집 동작은 유지하고, apply/create/convert/OCR 연결은 서비스 동결·실물 검증 뒤 후속으로 진행합니다.

업로드를 추가하면 샘플 읽기와 같은 바이트·형식·크기·취소 경계를 사용합니다. 경로 입력만으로 사용자의 임의 파일을 읽는 것처럼 꾸미지 않습니다. 새 다운로드는 파일명뿐 아니라 실제 바이트 SHA·형식·원본 결속을 표시합니다. 이전 스냅샷에서 만든 결과를 새 입력의 결과로 남기지 않습니다.

향후 브라우저 수용 검사는 실제 DOM 라벨을 통해 조작하고, 실행 index·route·동적 엔진·원본·WASM의 HTTP 핀과 실제 WASM 호출·다운로드를 관측합니다. 제품 API·모델 주입으로 성공 상태를 만들지 않습니다. 소유 세션은 실패해도 finally 종료하고 잔류를 확인합니다. 정적 가이드의 설명 확인과 실제 도구/제공자 실행을 같은 증거로 계산하지 않습니다.

## 실제 검증 자료와 출시 판정

### 저장과 대상 결속

HWP5는 독립 CFB/레코드 해석으로 대상 문단·리스트 헤더·리소스 참조·DocInfo/폰트와 비대상 스트림을 대조합니다. HWPX는 Python 표준 ZIP/XML 등 별도 해석기로 정확한 대상·전체 XML 의미·비대상 파트·리소스·필요한 메타데이터를 확인합니다. 구조 변경은 예상한 대상 참조 변경과 조판 캐시 정책을 독립 기대값으로 표현합니다. 제품 reader로 다시 읽는 것만으로 보존을 입증하지 않습니다.

각 비교기는 실제 올바른 저장 결과를 받아들이고, 잘못된 대상·내용·폭·색·참조 또는 무관 파트가 달라진 결과를 거부해야 합니다. 원본 SHA는 작업 전후 같아야 하고, 새 출력은 다시 열어 관측 값과 편집 가능성을 확인합니다. no-op·실패·취소·마지막 대상 오류·지원 밖 객체·출력 충돌·게시 후 진단 오류도 결과에 포함합니다.

### 자료 범위

실물 기본 자료는 허용된 Noori HWP5/HWPX입니다. HWP5 원본 SHA256은 `b18be0217a5d9f81e587705edc0c514cdd11e6314bbe434f17d256aa21b75a7f`, HWPX는 `6ee9014f23650987803481e7aa51b3b2201f91f549dccfe34880469621d62aab`입니다. 이 두 문서에 없는 차트·수식·OLE·복잡한 구조·OCR 대상은 독립 소유 합성 문서 또는 별도로 허용된 실물로 검증하고 원본/파생 자료를 구분합니다. Noori에 없는 기능을 통과로 추정하지 않습니다.

## 2026-11-08 초안 작성의 확인 범위

이 초안은 기준 커밋의 CLI 명령·MCP 연결·메모리 엔진·새 출력 호스트와 SDK 연결 지점, 기존 Native820 export 자료, 공개 실습 소스를 읽어 작성했습니다. SDK 작업본에 별도 변경이 있으므로 기준 HEAD 소스와 구분했습니다. 초안 작성 자체로 새 기능 실행·Native 컴파일·패키지 빌드·OCR 제공자 실행·새 브라우저 검사를 수행하지 않았습니다. 이후 별도 TS 서비스 검사의 확인 결과는 아래 후속 기록과 구분합니다.

## 2026-11-08 서비스·TS 확인의 근거

apply 서비스의 격리 실행에서는 두 형식의 정확 교체·no-op·사전조건 거부·마지막 Native 작업 실패·현재 좌표의 분할/병합·여러 문단 교체·글자/문단 서식·셀 크기/스타일·그림 크기·표 생성을 확인했습니다. 실제 저장·재열기 결과와 실패 시 입력 불변을 남겼으며, 이는 공개 설치 완료나 모든 원본의 편집 가능성을 뜻하지 않습니다.

create/convert는 빈 문서·문자열 초기화와 양방향 text-only 변환의 실제 출력, HWP5 구역/단 접두사, 빈 문단·Unicode와 비대상 컨테이너 보존을 독립 CFB/XML 비교로 검사했습니다. TS 이식 후 선택한 출력 바이트가 이전 검사 산출물과 같음을 확인한 범위에서 그 독립 비교 근거를 재사용합니다. 손실 있는 변환을 전체 문서 의미 보존으로 승격하지 않습니다.

읽기 TS 전환의 소유 단위·실습 전송 검사는 Node24 기본 stripping에서 통과했고, 별도 strict 검사를 수행했습니다. 후속 격리 실행에서 두 형식의 실제 text/Markdown 본문은 최종 기존 CLI stdout과 같았으며, 문단 조회는 실제 Native getter와 JSON 원문이 일치했습니다. 신규 설치 패키지·MCP 프로토콜·공개 브라우저·RN 기기 결과는 이 소스 검사로 대체하지 않습니다.

OCR의 기존 실제 Vision 실행과 제공자 부재 거부는 보존합니다. 결과 문자열은 해당 이미지·제공자·언어의 관측이며 보편적인 인식 정확도나 실제 Tesseract 인식의 근거가 아닙니다. 실제 로컬 제공자를 정적 공개 웹에서 실행했다고 표시하지 않습니다.

설치된 정규 JS 후보의 후속 검사에서는 CLI 생성·문단 조회·apply·양방향 text-only 변환·읽기·기본 변환 거부와 공식 MCP 클라이언트의 12도구/새 서비스 호출을 확인했습니다. OCR은 없는 실행 파일 거부를 확인했으며 실제 Tesseract 인식 완료를 뜻하지 않습니다. 기존 fixture 19검사와 새로운 설치 서비스 2검사는 별도 코호트로 보존합니다. 공개 실습의 새 작업 UI·RN 기기·새 Native 기능의 완료 근거로 합산하지 않습니다.

# JFIF 8비트 색 변환

## 계약과 공식 근거

[ITU-T T.871](https://www.itu.int/rec/T-REC-T.871-201105-I/en) 7절의 공식 PDF에서 양방향 변환, `floor(x + 0.5)` 반올림 및 0~255 제한을 확인했습니다. `src/image/jpeg/jfif_colour.zig`는 정수 Y/Cb/Cr 또는 R/G/B 한 샘플의 변환만 소유합니다. 파일 형식 판단, 메타데이터 우선순위, 업샘플링, 메모리 할당은 하지 않습니다.

- `toRgb(y, cb, cr)`: full-range 8비트 JFIF 성분을 RGB로 변환합니다.
- `fromRgb(r, g, b)`: RGB를 full-range 8비트 JFIF 성분으로 변환합니다. 인코더 전체의 구현을 뜻하지 않습니다.
- `grayscale(y)`: 단일 Y를 R/G/B에 그대로 복제합니다.

공식 본식의 유리수 계수를 i64 정수 분수로 계산합니다. 분모는 1000, 1772, 1402, 587000이며, 모든 u8 입력에서 중간값은 i64 범위 안입니다. 공통 `quantize`가 반올림 후 clamp를 소유합니다. 문서의 네 자리 근사 계수로 바꾸지 않습니다. 입력 타입 자체가 범위를 제한하며 음수·NaN·12비트 샘플을 임의 보정하는 진입점이 아닙니다.

색 값은 양자화·범위 제한 때문에 양방향 왕복 시 항상 원본과 같지 않습니다. JFIF 색 좌표와 sRGB/ICC 관리 결과를 동일시하지 않으며, Exif/Adobe/ICC 메타데이터가 있는 임의 JPEG에 자동 적용하지 않습니다. 해당 의미 판단과 [JFIF 배치 검사](jpeg-jfif-layout.md), 성분 평면 조립은 별도입니다. 색 변환 완료는 실제 HWP의 RGB 렌더링 완료나 한글/libjpeg와의 픽셀 일치 보장이 아닙니다.

## 독립 검증

JPEG 네이티브 100/100개가 통과했습니다. 회색축 256개, 중성 chroma, 원색, 양수 half tie와 clamp를 검사하고, 첫 성분이 0/1/127/128/254/255인 전체 두 성분 격자를 양방향으로 확인했습니다. 네이티브 기대값은 합쳐진 정수 계수가 아닌 공식 소수 수식의 독립 평가입니다.

테스트용 mode 266/267은 RGB 방향/YCbCr 방향의 packed u8 triple 배열, mode 268은 grayscale u8 배열을 받아 결과를 반환합니다. triple 잘림과 출력 한도를 검사하며 계수·반올림은 제품 코어를 호출합니다. 제품 JS API는 변경하지 않습니다.

`tests/hwp5/jpeg-jfif-colour.mjs`는 각 방향의 모든 256³ 입력을 65,536개 단위 배치로 대조합니다. Debug에서 비교 516건·거부 11건, 양방향 총 33,554,432개 triple과 회색값 256개가 통과했습니다. 비교 건수와 triple 수를 구분합니다. 빈 입력, 1/2/4/5바이트 잘림 및 출력 한도도 포함합니다.

독립 JS/네이티브 소수식의 `1e-9` 여유는 유리수의 정확한 half tie에서 발생하는 이진 부동소수점 오차만 해소합니다. 가장 가까운 비-tie 간격은 적어도 1/587000이므로 이 여유보다 큽니다. 추가 일회성 JS BigInt 분수 대조에서는 부동소수점 없이 같은 전체 33,554,432개 입력을 Debug WASM과 비교하여 일치했습니다. BigInt 쪽은 분자를 2배해 반올림하고, 제품은 분모 절반을 더한 뒤 floor 나눗셈을 사용합니다.

세 모드 별도 소스 복사본 `/tmp/hwpjs-jfif-colour-mutants.HOMvGb/`에서 G 계수 419198→419000, Cb 중심 128→127, half 반올림 제거, 최대값 255→254를 각각 주입했습니다. 모두 컴파일 후 테스트 실패로 검출했습니다. 각 모드에서 세 테스트 중 계수 변형은 1개, 나머지는 2개 실패했습니다. Debug 출력 2,304바이트의 개별 XOR 1 변조도 모두 검출했습니다.

ReleaseSafe와 ReleaseFast의 별도 WASM에서도 각각 비교 516건·거부 11건, 총 33,554,432개 triple과 회색값 256개가 통과했습니다. BigInt 전체 입력 대조와 출력 2,304바이트 개별 변조 검출도 두 릴리즈 모드에서 반복해 통과했습니다.

실제 HWP의 JPEG 참조 8건은 세 모드에서 기존 성분 평면 회귀를 다시 확인했습니다. Sequential 참조 7건의 19개 평면·1,237,819개 샘플이 독립 결과와 일치했고 progressive 참조 1건은 픽셀 복호화를 보류했습니다. 이 실측은 새 색 변환을 파일 전체 RGB 출력에 연결했다는 뜻이 아닙니다.

전체 회귀 검사를 Debug → ReleaseSafe → ReleaseFast 순서로 완료했습니다. 각 모드 모두 20/20 단계, 네이티브 816/816개, checks 7,656,891건이 통과했습니다. 로그는 `/tmp/hwpjs-jfif-colour-{Debug,ReleaseSafe,ReleaseFast}-audit.log`에 남겼습니다. 검사 수는 포맷 전체 지원률이나 모든 디코더와의 픽셀 일치를 뜻하지 않습니다.

SSOT 검토에서 변환 계수와 정수 반올림·clamp가 `jfif_colour.zig` 한 곳에 있고, 테스트용 배치 직렬화·입력 길이 검사는 별도 probe가 담당하는 것을 확인했습니다. 독립 소수식 및 BigInt 분수식은 제품 구현에서 기대 출력을 생성하지 않습니다. 업샘플링 및 실제 파일의 RGB 출력 연결은 후속 단계입니다.

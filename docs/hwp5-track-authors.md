# HWP5 변경 추적 작성자

[DocInfo 계약](hwp5-docinfo-contracts.md)

## 확인된 범위와 근거

- 명세 `legacy/rust/.claude/skills/hwp-spec/3-2-2-문서-정보.md` 표 4는 변경 추적 작성자를 가변 길이, 레벨 1로 정의합니다.
- `4-2-문서-정보의-데이터-레코드.md` 표 13의 `HWPTAG_BEGIN+81`이 작성자 태그 97의 근거입니다.
- `4-2-2-아이디-매핑-헤더.md` 표 16은 슬롯 17을 변경 추적 사용자 개수로 정의합니다(5.0.3.2 이상). 버전상 기대 슬롯 수와 실제 payload에 존재하는 슬롯 수는 다릅니다.
- 레거시 `legacy/rust/crates/hwp-core/src/document/docinfo/track_change_author.rs`도 상세 구조가 명세에 없다고 명시하며 raw bytes만 복사합니다. 이름·색상·작성자 ID의 배치를 확정하는 근거로 사용하지 않습니다.

## 책임과 SSOT

`docinfo/reader.zig`의 태그 97 정의와 레벨 검사가 단일 출처입니다. 레벨 1만 허용하고 다른 레벨은 `InvalidDocInfoLevel`입니다. 실패한 iterator 호출은 위치를 진행시키지 않습니다.

payload는 계속 `Value.unknown`이며 framing의 입력 슬라이스로 빌립니다. 별도 복사·문자열 디코딩·최소 길이 추측을 하지 않습니다. 참조 보고서의 `unknown_records`에서도 제외하지 않습니다. 원문 뷰가 있다는 사실은 문서 무손실 저장을 구현했다는 뜻이 아닙니다.

`docinfo/resources.zig`가 실제 작성자 레코드 수를 집계합니다. `validateKnownCounts()`는 실제 슬롯 17이 있을 때만 비교합니다. 음수는 `NegativeMappingCount`, 불일치는 `ResourceCountMismatch`입니다. 슬롯 부재(null)는 0개 선언이 아니며 버전 번호로 슬롯을 보충하지 않습니다. 선언 개수에 비례하는 메모리 할당은 없습니다.

선택적 슬롯 비교는 메모 모양과 공유하는 `validateOptionalCount()`가 소유합니다. 기존 BinData/글꼴 전용 `validate()`의 범위는 바꾸지 않습니다. 참조 검증과 decoded/CFB 문서 검증은 기존 `validateKnownCounts()` 호출을 통해 동일한 검사를 받습니다.

## 실제 표본과 적대적 검증

참조 표본의 `.hwp` 경로 536개 중 디코딩 가능한 DocInfo 430개를 조사했을 때 작성자 레코드는 5개였고 모두 레벨 1이었습니다. 슬롯 17이 없는 문서는 147개였으며, 슬롯이 있는 나머지 문서에서는 작성자 개수 불일치를 발견하지 못했습니다. CFB/스트림 접근 실패 및 암호화·배포용 제외 106개는 이 통계의 검증 대상이 아닙니다. 이는 430개 전체 문서의 모든 기능이 유효하다는 검증이 아닙니다. Node의 `inflateRawSync`와 독립 `documentRecords` 순회로도 같은 통계를 재확인했습니다.

`tests/hwp5/track-author.mjs`는 다음 원본에서 작성자 수·payload 길이·매핑 값과 참조 검증 성공을 회귀 검사합니다.

| 표본 | 작성자 수 | payload 길이 |
|---|---:|---|
| `issue5169_viewtext_changetracking.hwp` | 4 | 18, 18, 20, 20 |
| `task2070/1130000-201900011_D0150004-1-002_2017년기준 시장구조조사.hwp` | 1 | 24 |

합성 테스트는 네 버전, 일반/확장 레코드 헤더, 0/1/18바이트 미해석 payload, 잘못된 레벨 0/2/1023, 슬롯 부재와 -1/0/1/2/INT32_MAX를 구분합니다. 빈 payload 허용은 상세 구조의 유효성 판정이 아니라 미해석 원문 전달 경계입니다.

실제 변경 추적 표본에서는 선언 개수 변조, 작성자 삭제·중복, 레벨 변조를 참조 검증·decoded 문서·재압축한 CFB 문서 세 경로에 투입합니다. 오류 후 같은 인스턴스에서 원본 문서 결과가 복구되는지도 비교합니다. 디스크의 표본은 수정하지 않습니다.

네이티브 `src/hwp5/docinfo/track_author_tests.zig`는 실패 재호출의 원자성, unknown payload 보존, 실제 슬롯 유무, 음수·최댓값 및 작성자 없는 0개 선언을 검사합니다. 실행은 [세 빌드 모드 감사 명령](development-commands.md#세-빌드-모드-회귀-검증)을 따릅니다.

Debug → ReleaseSafe → ReleaseFast 순차 감사는 모두 성공했습니다. 각 모드에서 네이티브 255/255, Node 47/47, HWP5 WASM 검사 1,372,281회를 통과했습니다. 작성자 전용 합성 결과는 정상 32건·거부 88건, 실제 문서 변조 거부는 세 경로 합계 30건입니다. 원문과 오류 후 복구 비교는 별도로 포함됩니다. 포맷·JS 구문·diff 공백 검사 및 주제 문서 링크도 확인했습니다. 검사 횟수는 미해석 필드의 구현 완성도를 뜻하지 않습니다.

## 남은 범위

작성자 payload 필드 해석, 작성자 ID 참조 연결, 변경 적용·취소·편집·저장은 미완료입니다. 변경 추적 내용/정보 레코드(태그 96/32)와 매핑 슬롯 16의 경계 검증은 [별도 계약](hwp5-track-changes.md)이 소유합니다. 이번 개수·레벨 검사를 변경 추적 전체 지원으로 해석하지 않습니다.

# ICC 문자열의 명시적 IANA 비교

## 계약

`mluc_selection.Options.matching`의 기본값은 `raw`입니다. 호출자가 `iana_direct`를 선택한 경우에만 공통 `text.bcp47_alpha2_match.matches`를 사용합니다. [IANA 이력 조회](bcp47-alpha2-history.md)의 등록 목록·직접 Preferred-Value를 재사용하며 별도 동의어 표를 만들지 않습니다.

동일한 원시 두 바이트는 등록 여부와 무관하게 같습니다. 서로 다른 입력은 양쪽 모두 등록된 경우에만 직접 권장 값을 한 번 적용하고 대소문자를 무시해 비교합니다. 이는 코드의 유효성 검사가 아니며 전체 태그 canonicalization·재귀 대체·ISO 전체 동의어 지원도 아닙니다. sh→sr, AN→CW, UK→GB 같은 임의 대체를 하지 않고 bh의 세 글자 권장 값 bih를 bi로 자르지 않습니다.

선택의 순위는 [기존 선택 계약](icc-localized-selection.md)을 유지합니다. 이 모드의 exact는 정책상 언어·지역 일치이며 원시 바이트 동일성을 뜻하지 않습니다. 앞선 동등 코드와 뒤의 원시 동일 코드가 동률이면 앞선 레코드가 선택됩니다. 원문을 변경하지 않으며 locale_deferred·unicode_deferred는 true입니다.

## 검증 진행

2026-09-08 네이티브 검사 5/5 단계·466/466 테스트가 통과했습니다. 직접 권장 코드의 대칭 비교, 미등록 원시 동일성, 대소문자, 모호한 대체 거부, 지역 후보의 후반 위치, 파일 순서 동률과 자원 한도를 검사했습니다.

WASM mode170은 동일 probe에 비교 정책만 전달하고 mode167의 기존 원시 비교를 유지합니다. 명시적 기대 결과, 64개 위치 이동, 확장 stride·홀수 offset·잘림·한도·실패 후 복구 검사를 정규 감사에 연결했습니다. 직접 실행과 세 모드 전체 감사 결과는 아래에 기록합니다.

WASM 직접 실행에서 정상 비교 210건·오류 거부 49건이 통과했습니다. 별도 수동 검사에서는 언어 5쌍과 지역 6쌍의 직접 권장 관계를 교차해 양방향·대소문자 조합과 원시 모드 비적용을 240건 대조했습니다. 이 수동 검사 수는 정규 감사에 합산하지 않습니다.

공식 [RFC 5646 §3.1.7](https://www.rfc-editor.org/rfc/rfc5646.html#section-3.1.7)을 다시 확인한 적대적 검토에서 생성기의 기존 결함을 발견했습니다. extlang 이외의 Preferred-Value 레코드는 Deprecated가 필수인데 언어·지역의 날짜 없는 권장 값을 승인했습니다. 원본 추출과 테이블 생성 양쪽에 같은 조건을 추가하고, 잘못된 정상 테스트를 거부 테스트로 수정했습니다. 고정 스냅샷 데이터 변경은 필요하지 않습니다. 이전 감사 결과를 이 수정본의 완료 근거로 사용하지 않습니다.

같은 RFC는 지역 권장 값이 역사적 원본과 정확히 같은 의미가 아닐 수 있다고 설명합니다. 따라서 이 opt-in 정책의 일치는 국가의 역사적 동일성 보증이 아니며, 기본 원본 비교와 보류 플래그를 유지합니다. 등록부의 연결된 권장 값 갱신 규칙과 전체 canonicalization 검증은 별도 남은 범위입니다.

날짜 필수 관계 수정 후 생성기 정상 4건·거부 48건과 파생 파일 8개 일치 검사가 통과했습니다. 원본 추출과 테이블 생성이 validateDeprecation을 재사용하여 날짜·필수 관계를 한 곳에서 검사합니다.

추가 수동 WASM 적대적 비교 913,952건이 통과했습니다. 영문 두 글자 소문자 조합 676개 사이의 모든 쌍을 language/region 각각 대조하고 오른쪽 코드의 절반은 대문자로 변형했습니다. 독립 기대값은 원본 JSON 범위·이력에서 계산하며 Zig 고정 폭 테이블이나 제품 비교 함수를 사용하지 않습니다. 모든 256진 두 바이트 쌍의 전수 검사는 아니며 수동 검사 수는 정규 감사에 더하지 않습니다.

최초 Debug 전체 감사는 `/tmp/hwpjs-icc-iana-Debug-first.log`에서 종료 코드 0, 20/20 단계·466/466 네이티브 테스트·WASM 5,036,248개 검사로 통과했습니다. 해당 실행은 생성기 수정 전 모듈을 로드해 정상 5건·거부 44건을 보고했으므로 날짜 필수 관계 수정본의 전체 감사 근거로 사용하지 않습니다.

수정본 Debug·ReleaseSafe·ReleaseFast 전체 감사가 `/tmp/hwpjs-icc-iana-{Debug,ReleaseSafe,ReleaseFast}-final.log`에서 각각 종료 코드 0, 20/20 단계·466/466 네이티브 테스트·WASM 5,036,248개 검사로 통과했습니다. 세 모드 모두 수정된 생성기 정상 4건·거부 48건을 보고했습니다.

ReleaseSafe WASM의 추가 수동 한도 검사 3건이 통과했습니다. 레코드 100,000개·선호 32개에서 마지막 선호와 마지막 레코드의 권장 코드 일치, 같은 언어 fallback, 레코드 100,001개의 한도 거부를 확인했습니다. 이 수동 검사 수는 정규 감사에 합산하지 않습니다.

최종 적대적 검토에서 원시 기본값, 선택 순위와 보류 플래그, 정적 이력 문자열 수명, probe 할당 해제, 공통 등록·날짜 규칙 재사용을 확인했습니다. 수정 후 이번 범위의 추가 결함은 발견하지 못했습니다. Zig 포맷·변경 JS 구문·diff 공백과 관련 문서의 로컬 링크 6개 검사도 통과했습니다. ISO 전체 동의어·전체 프로파일 의미 검증·HWPX 통합·렌더링 완료를 뜻하지 않습니다.

# HWP5 원본 표 격자 후보

`src/hwp5/edit/source_table_grid.zig`는 명시된 원본 Section의 TABLE 레코드와 예상 행·열 수를 받아 새 구역 바이트만 반환하는 private 후보입니다. 세션·이력·WASM에는 아직 연결하지 않았습니다. 파일 컨테이너 저장은 아래 private 어댑터에서 별도로 검증합니다. 생성 표의 웹 명령 지원과 구분합니다.

공식 HWP5 revision1.2의 표75/79/80과 기존 프로젝트 framing/tree/list-group 모듈을 사용합니다. ListHeader는 spec6/observed8을 호출자가 명시하며 길이나 버전으로 추측하지 않습니다. 전체 문서의 새 문단 ID 발급은 호출자 책임이고 후보는 현재 구역 내 충돌·중복·0값을 추가 거부합니다. 현재 레코드 번호와 예상 크기는 내용 지문이나 영구 identity가 아닙니다.

현재 지원 후보는 최상위 본문의 절대 크기·간격0인 직사각형 표입니다. 주소는 행 우선 완전 격자이며 span은1×1이어야 합니다. 각 열 폭·행 높이는 해당 축에서 일정한 양수이고 합계는 표 공통 크기와 같아야 합니다. 셀은 한 문단, plain UTF16 본문과 글자 모양 레코드만 허용합니다. 줄 캐시·변경추적 병합 문단·필드·캡션·중첩 표·미해석 셀/표 확장·유효 구역은 거부합니다. 각주/도형 안 소유자 등 다른 문맥도 현재 거부합니다.

원본 표 정책은 생존 셀의 폭·높이·본문·서식을 유지하는 것입니다. 삽입은 앞선 행/열(처음 위치에서는 첫 행/열)의 크기와 기본 문단/글자 모양을 사용해 빈 셀을 만들고 합계 크기를 늘립니다. 삭제는 제거한 축 크기만큼 합계를 줄입니다. 새 문단에는 새 ID를 쓰고 기존 본문·문단 ID는 보존합니다. 이 정책은 생성 표의 고정 총 폭 재분배와 구분하며, 한컴 UI가 요구하는 공식 삽입 정책이라는 주장은 아닙니다.

준비 중 원본을 수정하지 않으며 실패/OOM 시 후보와 arena를 해제합니다. 비대상 앞뒤 레코드는 원시 바이트로 보존하고 결과를 tree/list-group으로 다시 검사한 뒤 반환합니다. 원본 줄/페이지 조판 캐시 갱신, HWP5 파일 저장의 reflow 동의와 문서 전체 ID 선택은 향후 상위 거래가 소유해야 합니다.

집중 검사는 두 명시 ListHeader 형식에서 네 action의 앞/중간/끝 매핑·생존 본문/서식·비대상 원문, ID/대상/크기·위험 구조 거부와 OOM 원자성을 검사합니다. OOM은 공통 `src/testing/allocation_failures.zig`를 사용해 일반 resize 성공 경로와 resize를 거부한 결정적 allocate/copy 실패 경로를 구분합니다. std Arena의 기회적 backing resize 때문에 단순 주입 실행 수가 달라지는 초기 실패 기록을 보존합니다. 이는 원본 변경이나 누수의 재현이라는 뜻은 아닙니다.

실행 명령은 [개발·검증 명령](development-commands.md), 공통 좌표 매핑과 공개 생성 표의 범위는 [격자 계약](created-table-grid-edit.md)을 따릅니다. 타 구현 소스/역분석 결과를 새로 열람하지 않았으며 엄격한 클린룸 인증을 주장하지 않습니다.

## 파일 단위 후보

`src/hwp5/edit/source_table_grid_file.zig`의 `transform`은 DocInfo와 모든 구역의 문단 ID를 한 번 색인하고 새 ID를 발급한 뒤 대상 구역만 교체한 새 CFB를 반환합니다. 명시된 spec6/observed8 정책을 유지하며 보정이 필요한 CFB와 변경 이력·서명 문서는 거부합니다. 비대상 스트림 바이트와 디렉터리 메타데이터를 검사합니다. 컨테이너 내부 섹터 배치까지 동일하다는 의미는 아닙니다.

삽입 후 해제 바이트·레코드 총량이 입력보다 커질 때 한도를 우회하는 반례를 재현했습니다. 출력 준비 전 비대상 예산을 예약하고, 후보 합계와 엄격한 재개방 뒤 합계를 다시 검사하도록 수정했습니다. 입력 932바이트·43레코드가 행 삽입 후 1,102바이트·51레코드로 늘어나는 경우의 거부와 정확한 한도 수용을 함께 확인했습니다.

ReleaseSafe 집중 검사 11개는 합성 compressed/raw 입력, 네 명령, OOM·원본 불변성, 예산 증가·경계, 메타데이터 변조 거부와 기존 브라우저가 저장한 단순 표의 재열기를 포함합니다. 실제 브라우저에서 원본 표를 편집한 증거는 아니며 공개 SDK·CLI 연결과 복합 표 지원은 남아 있습니다. 실행과 필수 픽스처 환경변수는 [개발 명령](development-commands.md)의 파일 단위 표 격자 후보를 따릅니다.

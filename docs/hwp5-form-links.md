# 양식 텍스트 토큰·컨트롤 연결

[양식 조립](hwp5-form-controls.md) · [본문 계약](hwp5-body-contracts.md)

## 관측 근거와 범위

명세 3.2.3 표 6과 4.3.6은 확장 제어문자와 컨트롤 헤더를 정의합니다. 양식의 `form` ID를 코드 11에 대응시키는 규칙은 공식 대응표에 새로 기입하지 않고 명시적 관측 경로에서만 적용합니다.

`reference/rhwp/samples/form-01.hwp`·`form-02.hwp`의 BodyText/Section0에서 양식 10개는 모두 코드 11, 토큰 ID와 헤더 ID 모두 `form`입니다. 두 파일 모두 첫 문단에는 `secd`·`cold` 토큰이 앞서 있어 양식 토큰 시작 위치가 16 UTF-16 유닛이고, 나머지 네 양식은 각 문단의 위치 0입니다. 연결된 컨트롤 노드는 12·21·30·39·48, 텍스트 노드는 1·18·27·36·45입니다. 토큰의 ID 뒤 8바이트는 현재 모두 0이지만 주소·instance ID로 해석하거나 0을 필수 조건으로 강제하지 않습니다.

rhwp 로컬 `e8800c8de`의 `src/serializer/body_text.rs`도 `Control::Form`을 `(0x000B, CTRL_FORM)`으로 작성합니다. 이는 실파일 관측을 보강하지만, 다른 구현의 작성 규칙 자체를 공식 명세로 취급하지 않습니다.

이 표본은 HWP 5.0.3.0 두 파일에 대한 근거입니다. 모든 버전이나 양식 타입의 표현을 증명하지 않으며, 원본 프로그램으로 생성한 다른 버전·비 BMP 속성 표본의 대조는 별도로 남아 있습니다.

## API·SSOT

`hwp5.form_links.collectObservedUnits(allocator, tree, options)`는 변경되지 않은 `body_tree.Tree.parse` 결과를 받습니다. 결과 `forms`는 기존 양식 조립 Report이고, `links[i]`는 `forms.forms[i]`와 대응하는 기존 `control_links.Link`의 값 복사입니다.

- 공통 속성·envelope·속성 Tree와 공유 양식 예산은 `form_control`에 위임합니다. 옵션은 그대로 전달합니다.
- 문단별 직접 자식 수집, 텍스트 토큰의 파싱, 등장 순서·ID 일치·누락·중복 검사는 `control_links.Links.build`에 위임합니다. 같은 Tree의 모든 컨트롤을 연결하므로 양식 이외의 컨트롤에서 연결 오류가 나도 실패합니다.
- 양식의 관측 제어코드 11은 `form_links.observed_code` 한곳에 둡니다. 다른 확장 코드이면 `FormControlCodeMismatch`입니다. 일반 제어코드 대응표와 기본 문서의 deferred 분류는 바꾸지 않습니다.
- 양식 결과는 컨트롤 노드 순서입니다. 일반 Links는 문단별 순서라서 바깥 문단의 뒤쪽 형제가 중첩 문단의 컨트롤보다 먼저 나올 수 있습니다. 두 배열을 같은 순서로 가정하지 않고 각 양식 연결을 컨트롤 노드 번호의 이진 검색으로 대응시킵니다. ID를 전역 키로 삼지 않아 반복되는 `form`도 각각 유지합니다.

양식이 F개, 전체 노드가 N개, 텍스트 바이트가 T개일 때 기존 조립·연결 순회와 양식당 검색으로 O(N + T + F log F), 여기에 기존 속성 파싱 비용이 추가됩니다. 양식마다 전체 노드나 링크를 반복 검색하지 않습니다. 같은 Tree에서 생성한 두 결과만 내부에서 사용하므로 각 헤더의 유일한 연결을 전제로 하며, 임의의 다른 Tree에서 가져온 결과를 합치는 API는 제공하지 않습니다.

## 소유권·실패·미검증 경계

Report가 Form 배열·속성 노드 배열·양식 Link 배열을 소유합니다. 작업 중 전체 Link 배열은 결과를 복사한 뒤 해제합니다. 오류 때도 이미 생성한 양식 결과와 임시·최종 링크 배열을 해제하고 부분 결과를 반환하지 않습니다. `deinit(allocator)`은 최초 할당자와 함께 호출합니다.

결과의 문자열·꼬리는 원본 Section 바이트를 빌립니다. 본문 Tree 노드 배열은 먼저 해제할 수 있지만 원본 Section은 결과 사용이 끝날 때까지 유지해야 합니다. Link의 start_unit은 원본 문단 텍스트 기준 UTF-16 유닛 위치이며, 삭제 투영이나 Unicode scalar 위치로 바꾸지 않습니다.

옵션의 max_forms·속성 바이트/노드/깊이 예산은 양식 조립과 같습니다. 전체 링크 메타데이터는 양식만이 아니라 전체 Tree의 컨트롤 수에 비례하므로 양식 수 제한만으로 전체 메모리를 제한한다고 해석하면 안 됩니다. Tree 생성의 레코드·입력 제한도 적용해야 합니다.

토큰과 헤더의 연결은 다른 컨트롤의 코드 적합성·payload 의미 검증과 별개입니다. 양식 타입별 키·자료형·기본값·리소스 참조, instance ID 유일성, 문단 글자 수·레이아웃 검증, 렌더링·편집·저장 성공도 보장하지 않습니다. 기본 document/container 경로에 자동 연결하거나 공개 JS API를 변경하지 않았습니다.

## 검증

테스트 전용 mode 107은 버전 u32 뒤의 decoded Section을 받아 양식 순서대로 32바이트 행을 반환합니다: 양식 배열 인덱스, 문단/텍스트/컨트롤 노드, 시작 유닛, 코드, 토큰 ID, 헤더 ID. 기존 독립 JS `controlLinkEvidence`의 부모·토큰 수집을 공유하여 원시 바이트 전체를 대조합니다. 제품 연결 결과를 기대값 생성에 사용하지 않습니다.

합성 정상 28건·거부 22건은 빈 입력, 텍스트 뒤에 오는 헤더와 그 반대 순서, 반복 ID, 중첩 문단과 바깥 형제의 순서 역전, 선두 미지 노드, 비 BMP 텍스트/인라인 탭 이후 위치, 토큰 부가정보의 비영값, 다른 컨트롤과의 혼합, 코드 11 이외의 확장 코드 12종, 누락·중복·ID 불일치·인라인 대체·종료 코드 불일치·양식 payload 누락/중복을 포함합니다. 오류 후 정상 입력을 다시 검사합니다.

실파일은 두 파일의 양식 5개씩을 모두 대조하고, 각 토큰의 코드·ID·누락 변조를 파일당 15건 거부합니다. 선두 미지 레코드를 삽입한 결과도 재계산한 노드 번호와 대조합니다. 원본 파일은 수정하지 않습니다.

일반 타입 검사 mode 16도 두 원본에서 각각 checked 3·deferred 5·observed 0임을 별도 실행으로 확인했습니다. 양식 연결 성공을 기본 타입 검사 성공으로 바꾸지 않았습니다.

네이티브 검사는 12개 양식의 정상 경로와 마지막 양식의 코드 오류 경로에서 모든 할당 실패를 주입합니다. 입력 바이트의 불변성과 Tree 노드 해제 후 결과 접근도 검사합니다.

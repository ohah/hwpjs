# 원본 표 행 편집의 캐시와 원문 보존

행·열 명령의 선택·세션·이력은 [live 계약](source-table-grid-live-edit.md), 파일 단위 참조와 저장은 [파일 API](source-table-grid-file-api.md)가 소유합니다. 이 문서는 원본 셀 확장·문단 ID·파생 줄 배치 캐시의 추가 입장 조건만 설명합니다. 캐시를 사용해 누락된 내용 높이나 글자 폭을 추정하지 않습니다.

## HWP5 관측 확장과 새 빈 문단

명시 observed8 셀의 13바이트 확장은 정확한 버전 5.0.3.0·5.1.0.1에서만 행 삽입·삭제에 허용합니다. 기존 공용 파서의 관측 폭이 셀 폭과 같고 marker가 0이며 뒤 8바이트가 모두 0이어야 합니다. 꼬리는 원시 보존하며 새 의미를 부여하거나 폭·높이 보정에 사용하지 않습니다. 다른 버전·길이·값·열 편집의 이 확장은 거부합니다. 이름 있는 셀 등의 더 긴 확장 지원을 뜻하지 않습니다.

새 SOURCE-grid 셀의 빈 문단은 알려진 한 단위의 암시적 종결자를 사용하며 CR만 담은 TEXT 레코드를 새로 만들지 않습니다. 원본 생존 문단의 TEXT 부재와 원문은 그대로 유지합니다. 이 전용 writer는 일반 본문 Enter·생성 표·셀 나누기의 직렬화 계약을 변경하지 않습니다. 향후 공통화할 때에도 원본 원시 복사와 새 문단 작성은 구분해야 합니다.

## 문단 ID와 현재 대상

기존 HWPX 문단의 중복·0·부재 ID를 일괄 손상으로 판정하거나 재번호하지 않습니다. 기존 값은 원문대로 유지하고 새 문단에만 문서 전체 기존 값과 충돌하지 않는 ID를 발급합니다. 템플릿에 ID 속성이 없으면 신규 문단 조각에만 기존 scalar upsert를 적용합니다.

물질화 전후 대상 표는 Native의 실제 구역·트리·물리 소유 경로와 같은 종류의 형제 순서로 확인합니다. 외부 p@id·텍스트·호출자가 낸 숫자를 영속 권한으로 삼지 않습니다. Core token·현재 selection lease·Native 바인딩 검사도 계속 필요합니다.

## 알려진 캐시의 제거 경계

지원 격자의 기하를 바꾸면 영향 구역의 알려진 줄 배치 캐시를 제거합니다. HWP5는 선언·실제 line segment 수, 문자 수 상한·순서·치수·알려진 flags를 확인합니다. HWPX는 필수 수치·단조로운 textpos·치수·알려진 flags와 배열/세그먼트의 속성·자식을 검사합니다. HWPX textpos를 현재 본문의 anchor로 사용하거나 본문 길이와 일치한다고 보증하지 않습니다. 알려진 파생 캐시를 통째로 제거하는 정책이며 실제 내용 높이 계산 근거로 삼지 않습니다.

제거할 캐시에는 물리 소유권이 필요합니다. HWPX는 구역 직속 문단 또는 paragraph/run/table/row/cell/subList/paragraph 경로를 namespace와 함께 확인하며 깊이는 64 이내입니다. foreign wrapper·미지 owner·switch/case·잘못 배치된 알려진 요소 아래의 HP 캐시는 전체 거래를 `UnsupportedSourceLineCache`로 거부합니다. HP 캐시가 없는 opaque 원문과 다른 namespace의 배열은 그대로 보존합니다. 알려지지 않은 캐시 속성·자식은 제거 대상으로 보정하지 않습니다.

HWP5도 루트 문단 또는 알려진 tbl 제어 아래 셀 문단의 물리 조상을 확인합니다. 알 수 없는 제어 아래의 캐시는 빈 레코드라도 제거하지 않습니다. 상위 표 입장 검사에서 먼저 거부되는 경우와 캐시 writer 자체의 소유권 거부는 별도로 검사합니다.

이 확장은 행·열 격자 경로에 한정됩니다. 기존 엄격한 셀 나누기·병합·캡션 경로에 캐시 허용을 전파하지 않습니다. 일반 다중 문단의 실제 내용 높이·모든 span·모든 복합 표와 조판 동치는 아직 완료 범위가 아닙니다.

## 검증 경계

누리 두 형식의 첫 표에서 삽입과 원래 내용이 있는 행의 삭제를 구분합니다. undo는 제거한 원문·서식을 복원하며, 삽입 뒤 새 행을 삭제한 결과와 원본의 차이에는 허용된 파생 캐시 제거가 남을 수 있습니다. 이를 원본 전체 바이트 동일성으로 표시하지 않습니다. 실제 CLI·MCP의 새 파일과 재열기, 독립 CFB/XML 전체 대상 구역·비대상 stream/part, 일반 Python과 -O 및 틀린 기대 결과의 거부를 대조합니다. 공개 Canvas·서버 배포 증거는 별도로 확인합니다.

적대적 검증에서는 대상 밖 foreign wrapper 안의 HP 캐시가 삭제되는 실패를 재현했습니다. 수정 후 같은 입력은 원문과 이력이 변하지 않은 채 명시적으로 거부됩니다. 정상 행 편집의 성공만으로 미지 원문 보존을 주장하지 않습니다.

## 배포 엔진에서 확인한 누리 표별 범위

Native `ac652edc…`와 같은 후보에서 빌드한 공개 SDK로 누리 HWP5/HWPX의 원본 표 5개를 각각 조사했습니다. 삽입은 index 1, 삭제는 index 0을 사용한 표본이며 모든 위치·임의 문서의 지원을 뜻하지 않습니다. 아래 표 번호는 문서 안 원본 표 순서입니다.

| 표 | 원본 행×열 | 두 형식의 행 편집 | HWP5 열 편집 | HWPX 열 편집 |
| --- | --- | --- | --- | --- |
| 1 | 3×4 | 삽입·삭제 성공 | 관측 확장의 폭 변경 미지원 | 삽입·삭제 성공 |
| 2 | 1×1 | 삽입 성공; 마지막 행 삭제 거절 | 삽입 미지원; 마지막 열 삭제 거절 | 삽입 성공; 마지막 열 삭제 거절 |
| 3 | 1×2 | 삽입 미지원; 마지막 행 삭제 거절 | 삽입·삭제 미지원 | 삽입·삭제 미지원 |
| 4 | 1×3 | 삽입 성공; 마지막 행 삭제 거절 | 삽입·삭제 미지원 | 삽입·삭제 성공 |
| 5 | 8×3 | 삽입·삭제 미지원 | 삽입·삭제 미지원 | 삽입·삭제 미지원 |

마지막 행·열 삭제는 `InvalidSourceTableGridBounds`로 Core에서 거부됩니다. 남은 축을 0으로 만드는 명령과 아직 지원하지 않는 구조를 같은 실패로 집계하지 않습니다. 원본 표 3·5는 HWP5에서 `UnsupportedSourceTableGrid`, HWPX에서 `UnsupportedSourceTableStructure`로 거절됐습니다. 이 오류 이름만으로 세부 원인을 단정하지 않습니다.

40개 표본 중 성공 13개는 undo/redo·저장·재열기의 동일 SHA를 확인했습니다. Core 범위 거절 8개와 Native 구조 거절 19개는 원문·이력 revision 불변을 확인했습니다. 이 추가 조사는 SDK 경로이며 실제 Canvas와 독립 CFB/XML 증거는 앞 절의 범위로 구분합니다. 재현 도구와 원시 결과는 `zig-out/verification/grid-forms-main-integration-r1/noori-all-tables-main-r1/`에 보존합니다.

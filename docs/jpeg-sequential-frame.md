# JPEG sequential 프레임 연결 작업

Huffman sequential 프레임의 계수 복호화와 성분 포함 검증을 구현했습니다. 반환 블록의 양자화 테이블 보존과 역양자화 진행 현황은 [역양자화 작업](jpeg-dequantization.md)이 소유합니다. 픽셀 복호화나 제품 JS 공개 API 연결은 포함하지 않습니다.

## 근거와 책임

[ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf)의 3.1.116, 4.10, B.2와 기존 [스캔 복호화](jpeg-sequential-scan.md) 계약을 참조합니다. Sequential에서는 각 성분이 정확히 한 스캔에 포함되어야 합니다. 한 스캔 내부의 성분 순서와 여러 스캔 사이의 순서는 구분합니다.

- `sequential_coverage.zig`: 프레임 선언 순서로 255개까지의 성분 포함 여부를 추적합니다. 한 스캔의 일부 성분이 기존 스캔과 겹치면 전체 변경을 취소합니다. 마지막에는 누락을 검사합니다. 파싱된 동일 프레임/스캔을 요구하며, 헤더 포함 여부만 검사하므로 entropy 복호화 성공을 뜻하지 않습니다. Progressive는 이 규칙의 대상이 아닙니다.
- `sequential_frame.zig`: Huffman sequential 이미지 전체의 마커·활성 테이블·스캔 디코더를 조립합니다. 먼저 기존 구조 검사로 마커 순서와 첫 스캔 뒤 DNL의 최종 높이를 확정합니다. SOF 마커 분류는 기존 구조 모듈의 함수를 공유합니다. 각 스캔 시작 전에 중복을 확인하고, 스캔의 계수와 마지막 패딩 검사가 성공한 뒤에만 coverage를 반영합니다. EOI에서 전체 성분이 완료됐는지 확인합니다.

입력·테이블 바이트는 불변 상태로 빌리며 코어는 할당하지 않습니다. 블록 개수 한도는 스캔마다 초기화하지 않고 프레임 전체에 적용합니다. 구조·재시작 한도는 기존 구조 옵션을 단일 출처로 사용합니다. `next`의 오류는 해당 호출 시작 상태로 되돌리며, 앞서 반환한 블록을 취소하지 않습니다. 같은 호출에서 앞 스캔을 끝낸 뒤 다음 스캔/EOI 검사에 실패했다면 그 호출의 coverage 변경도 반영하지 않습니다.

`next`가 EOI까지 검사하고 null을 반환해야 `complete`입니다. APP/COM/DAC 내용 의미, 색 변환, 역양자화·IDCT와 픽셀은 아직 인증하지 않습니다. 기본적으로 trailing bytes를 거부하며 명시적으로 허용한 경우 구조 보고서에 개수를 보존합니다. 테스트 전용 mode 254는 프레임 필드·완료 스캔/블록/RST 수·소비 바이트와 전체 블록을 반환하고 출력 길이에도 한도를 적용합니다.

## 검증 현황

- 신규 네이티브 5개와 기존 JPEG 검사 포함 Debug/ReleaseSafe/ReleaseFast 각각 66/66 통과.
- 여러 스캔의 성분 순서 변경, 겹친 부분 집합의 원자성, 255개 성분, 누락·중복·패딩 실패의 원자성, DNL 높이 확정, 여러 스캔에 걸친 블록 예산을 확인했습니다.
- Debug WASM에서 동일한 3성분 이미지를 한 스캔 또는 순서가 다른 세 단일 성분 스캔으로 구성했습니다. 각각 27블록이며 RST는 8/24개입니다. 모든 계수·성분·좌표와 프레임 헤더 결과가 독립 JS 스캔 oracle을 조합한 기대값과 일치했습니다.

- 세 모드 각각 mode 254 독립 비교 196건·거부 166건 통과. 성분 분할/스캔 순서, 8/12비트, DNL, Ri=0/1/2/7, 테이블 재정의, 잘림·전역 예산·trailing 정책을 포함합니다. 255개 성분의 완전한 프레임과 중간 DC 코딩 테이블을 변경 후 복원하는 사례도 확인했습니다. JS는 기존 독립 스캔 oracle과 성분 ID Set으로 프레임 기대값을 구성하며 네이티브의 프레임 위치별 coverage와 대조합니다.
- 세 모드에서 실제 HWP의 sequential JPEG 7건·총 20,089블록·RST 10개를 프레임 단위로 대조했습니다. Progressive 1건은 이 디코더에서 명시적으로 제외합니다. `reference/rhwp/samples/s1.jpg`도 세 모드에서 1,197블록·RST 18개를 확인했습니다. 픽셀 대조는 아닙니다.
- 27블록·3스캔·RST 24개의 합성 프레임 출력에서 모든 32비트 필드 1,845곳을 각각 XOR 1로 변조해 세 모드 독립 대조에서 전부 검출했습니다.
- 별도 4성분 분할 조사: 성분 0~3을 기존 그룹에 추가하거나 새 단일 그룹으로 각 스캔 위치에 삽입해 순서 있는 분할 75개를 생성했습니다. 각 스캔 내부는 프레임 선언 순서를 유지합니다. 폭 17·높이 9·sampling `[34,17,17,17]`에서 8/12비트, Ri=0/1/3, DNL 유무를 조합한 900건이 세 모드 모두 일치했습니다. `jpegFrameFixture`와 `jpegFrameActual`로 수행한 이 별도 조사 수치는 정규 audit 합계에 포함하지 않습니다.

### 소스 결함 주입

별도 소스 복사본의 결함 4종을 Debug/ReleaseSafe/ReleaseFast에서 각각 실행했습니다. 모든 변형은 컴파일 성공 후 네이티브 테스트 실패로 검출했습니다.

- 성분 중복 거부 제거: 각 모드 66개 중 2개 실패.
- 마지막 성분 누락 검사 제거: 각 모드 2개 실패.
- 블록 예산을 스캔마다 원래 한도로 초기화: 각 모드 1개 실패.
- 프레임 `next` 오류 시 부분 상태 반영: 각 모드 2개 실패.

Debug/ReleaseSafe/ReleaseFast 전체 audit는 각각 20/20 단계, 네이티브 782/782 테스트, 총 7,315,173건 검사로 통과했습니다. 전체 회귀 합계이며 픽셀 동일성이나 전체 문서 구현 완료를 뜻하지 않습니다.

# 현재 문서의 셀 모양 복사

[공식 모양 복사 도움말](https://help.hancom.com/hoffice/multi/ko_kr/hwp/format/quick_format/quick_format.htm)은 표 안에서 셀 속성·선 종류·배경을 기억하고 대상 블록에 같은 명령으로 적용하는 동작을 설명한다. 이 기능은 기존 모양 복사 명령의 셀 모양만 연결하며 새 최상위 메뉴·우클릭 항목·단축키를 추가하지 않는다.

원본 표 셀 안에 일반 커서를 두고 모양 복사를 실행한다. 셀 테두리·셀 배경·셀 대각선 중 실제 확인 가능한 항목을 직접 체크하고 복사한다. 대상 셀의 글자 블록 또는 F5 단일/사각 셀 블록을 고르고 같은 명령을 다시 실행한다. 현재 문서의 원본 셀만 대상으로 한다.

지원되는 테두리는 네 변의 종류·굵기·색이 모두 확인되고 동일한 경우다. 각 변이 다른 테두리, 미확인 선·굵기·색은 복사하지 않는다. 대각선은 확인된 none/rising/falling/cross와 선 속성만 전달하며 기존 가는 두 줄의 0.50mm 제한을 유지한다.

배경은 확인된 없음·단색·무늬·두 원본 색의 선형 그라데이션을 지원한다. 그림·다중 색/미확인 메타데이터·복합 채우기는 복사하지 않는다. HWPX의 non-none 채우기는 대상 채우기도 확인 가능한 경우에만 허용한다. 기존 Native879는 배경이 없는 대상에 새 브러시를 만들 때 alpha를 명시할 수 없어 현재의 확인 계약을 만족하지 못한다. 이 경우 대상 배경 복사를 거부하며 기본 alpha를 추측하지 않는다. 배경 없음 복사는 별도로 지원한다.

선택 항목은 기존 table-cell-appearance-port와 Native cell-styles batch로 한 번에 적용한다. 셀별 setter 반복·서식 리소스 ID 통째 복사·UI 문서 모델은 사용하지 않는다. 변경된 batch는 한 Native 이력이며 같은 값은 no-op으로 기존 redo를 보존한다. 저장·재열기와 undo/redo는 Native/SDK가 소유한다.

F5 셀 블록에서 편집 메뉴의 진입점과 모양 복사 버튼으로 이동할 때는 기존 Surface의 셀 블록 포커스 계약을 재사용한다. 편집 메뉴 전체나 다른 명령에는 유지 권한을 주지 않는다. 이는 대상 편집 권한을 추가하지 않으며 실제 적용 시의 현재 문서·선택·lease·읽기 전용 검사를 그대로 거친다. 이 경로의 Node 제어 검사와 실제 브라우저 재검증은 구분한다.

Core의 planCellAppearanceSelection은 기존 canonical 셀 소유자·사각 범위 검증과 현재 batch capability를 재사용한다. F5가 제공한 목록은 선택 의도일 뿐 편집 권한이 아니다. Core/Native의 문서·owner·readonly·보호·이력·대기열 검사를 유지한다. 보호 상태가 현재 DTO에 보이면 미리 거부하고, Native879가 투영하지 않는 보호 비트는 최종 Native admission이 거부한다. resource ID나 화면상의 셀이 편집 권한을 대신하지 않는다.

복사 값은 소유된 불변 스칼라 복제본이며 문서 세대가 바뀌면 폐기한다. 원본 모달과 적용 대기의 state/선택 ABA, 폐기, 셀 블록 lease 변경, busy, composition/key229는 쓰기 전에 재검사한다. 늦은 응답은 다른 선택·문서에 복원을 강제하지 않는다. 선택 복원도 기존 Core 선택 발급 경로를 쓴다.

원본 Noori HWP5와 명시적인 opaque 채우기를 넣은 자체 HWPX fixture에서 Native879 실제 적용·저장·이력 검사를 구분한다. 원본 HWPX의 absent-alpha 제한과 실제 protect="1" 거부도 별도 검사한다. Node DOM/제어 callback 검사는 브라우저의 F5·focus·OS IME·공식 외형 동치의 증거가 아니다. 실제 GUI 검증은 별도다.

전체 글자·문단·스타일·셀 속성(안 여백·세로 정렬·제목 셀 등), 비대칭 테두리, 모든 배경 조합, 본문과 셀 결합 거래, 생성/중첩 셀, 문서 간 복사 목표는 그대로 남는다. 현재의 실제 지원 필드를 전체 모양 복사 완료로 표시하지 않는다.

## 등록 메뉴로 포커스가 도착한 뒤의 강조

실제 브라우저573 후보에서는 F5 논리 선택1이 유지돼도 Edit summary에 포커스가 도착한 뒤 강조0이 남았습니다. 같은 코드가 실제 로드된 SDK/공개 asset에 존재했고, blur 중 activeElement가 body인 상태로 paint한 뒤 허용 focusin이 다시 그리지 않는 순서를 통제 재현했습니다. 현재 보존 블록과 등록 소유권이 같고 focusin의 실제 activeElement가 event.target일 때만 paint를 한 번 더 요청합니다. pointerdown·다른 대상·소유권 소멸·이미 바뀐 블록은 강조 허가를 얻지 않습니다. 저장·쓰기 admission이나 동의는 변경하지 않습니다.

해당 통제 회귀31은 실제 Surface/브라우저31 성공이 아닙니다. 새 source/SDK/public artifact로 만든 별도 manifest에서 실제 GUI를 다시 확인해야 하며, 기존573 실패를 지우거나 GUI 통과로 대체하지 않습니다.

# HWPX 그림 이미지 바이트 검사

선택 section·마스터페이지의 직접 `hp:pic/hc:img`가 [OPF 항목으로 해결된 뒤](hwpx-picture-image-links.md), `picture_image_payloads.zig`가 내장 항목의 실제 ZIP 바이트를 검사합니다. ZIP 해제·길이/CRC, 정확한 manifest `href` 대조, 고유 항목 중복 제거, 형식 시그니처와 MIME 진단, PNG/JPEG/BMP/GIF/WMF/TIFF/PCX/[SVG XML 구조](hwpx-svg-image-payloads.md) 검사, 합계 자원 한도는 `image_payloads.zig` 한 곳이 소유합니다. [브러시 이미지 바이트 검사](hwpx-fill-brush-image-payloads.md)도 같은 코어를 호출합니다. 그림 래퍼는 기존 OPF ID 해결 함수를 다시 호출해 사이트의 absent/empty/embedded/external/missing 상태와 항목 인덱스가 정규화 ID에 실제로 대응하는지 확인합니다. 조작된 상태로 내장 payload 검사를 우회할 수 없습니다. 내장 대상의 반복 참조는 한 번만 해제하며 `Target.references`로 보존합니다.

`Document.inspectPictureImagePayloads()`와 `inspectMasterPagePictureImagePayloads()`는 각각 원문 링크·payload 검사를 개별 실행하고, `inspectKnown()`은 두 보고서를 독립 소유합니다. 외부 URL·빈 값·부재·미해결 ID는 읽지 않고 `non_embedded_sites`에만 셉니다. 각 보고서는 기본적으로 고유 대상 10만 개, 엔트리 64MiB, 인코딩 합계 512MiB, PNG 복원 바이트 256MiB, PCX RLE 출력 256MiB 및 GIF 인덱스/코드/프레임 합계 한도를 적용합니다. 한도와 ZIP CRC 오류·메모리 부족은 함수 오류이며, 이미지 내부 형식 오류는 대상별 `inspection_error` 진단입니다. `inspectKnown()` 성공은 모든 대상이 유효한 이미지라는 뜻이 아닙니다.

PNG는 픽셀/스캔라인, JPEG는 마커·엔트로피 **경계**, BMP는 파일·DIB·픽셀 영역 **구조**, GIF는 프레임 인덱스까지 검사합니다. WMF는 Placeable key 또는 표준 META_HEADER의 type·header-size 서두로 판별하고 [공통 WMF 헤더·레코드 검사기](wmf-header.md)로 헤더 크기·체크섬과 종단 META_EOF까지의 framing만 검사합니다. Placeable은 공식 `specified` 크기 정책과 EOF 뒤 추가 0 WORD를 허용하지 않는 기본값을 명시적으로 사용합니다. TIFF는 [공통 TIFF 구조 검사기](tiff-structure.md)로 헤더·IFD·필드·strip/tile 바이트 범위만 검사합니다. PCX는 [공통 RLE 경계 검사기](pcx-structure.md)로 헤더·출력 길이·선택적 팔레트 꼬리만 검사합니다. 오류는 대상별 `inspection_error`로 남기고 다른 형식으로 재분류하지 않습니다. JPEG 계수·색상 복원, BMP 픽셀 복호화, GIF 합성·색 관리, WMF 개별 명령 의미·렌더링, TIFF 압축 해제·픽셀, PCX 픽셀·색상과 화면 렌더링은 포함되지 않습니다. 현재 검사기가 인식하지 않는 시그니처는 `unknown_formats`이며 정상 이미지 판정이 아닙니다. ZIP 내부 길이/CRC가 맞아도 PNG 내부 CRC가 틀릴 수 있으므로 두 층을 분리합니다.

## 독립 실측과 남은 범위

`python3 tools/hwpx-fill-brush-image-oracle.py --picture-payloads`는 Python ZIP/OPF/XML에서 직접 `pic/img`를 독립 선택하고, 사이트별 내장 여부·고유 manifest 항목·ZIP 바이트 시그니처·선언 MIME·PNG 청크 CRC·WMF framing·TIFF 구조·PCX RLE·SVG XML 루트를 조사합니다. 로컬 HWPX 484개에서 ZIP 거부 6개·암호화 2개를 제외한 476개 문서의 section 그림 사이트는 1993건이며, 내장 1945건이 고유 OPF 대상 1513개를 가리킵니다. 내장 대상의 인코딩 바이트 합계는 1,513,489,451바이트입니다. 현재 시그니처별로 PNG 441, JPEG 344, BMP 677, GIF 19, WMF 23, TIFF 6, PCX 1, SVG 2개이며 MIME 불일치는 106개입니다. SVG 두 건의 깊이와 비표준 MIME은 [SVG 계약](hwpx-svg-image-payloads.md)에 기록합니다. 외부 7건과 빈 ID 41건은 읽지 않았습니다. 61개 선택 마스터페이지에는 그림 사이트 35건·고유 JPEG 대상 9개·인코딩 바이트 1,096,713개가 있습니다. 고유 대상 합계는 *보고서별*이므로 section과 master에서 같은 OPF item을 가리키면 각 보고서에서 한 번씩 셉니다.

`Target.media_matches=null`은 형식 미지원으로 MIME 대조 자체가 불가능하다는 뜻이며 실제 불일치(false)와 분리합니다. SVG 두 건은 구조 검사에 통과하지만 선언 `image/svg`가 등록형 `image/svg+xml`과 달라 false로 남습니다. TIFF 6개는 구조 범위에서 모두 통과했지만 LZW를 포함한 압축·픽셀 의미는 검증하지 않았습니다. PCX 1개도 RLE 길이까지 검사했으며 픽셀·색상 의미는 검증하지 않았습니다. WMF 23개 중 표준 헤더 21개·Placeable 2개이며 독립 strict framing에서는 3개가 실패합니다. 표준 1개는 선언 전체 크기와 실제 길이가 다르고, Placeable 2개는 크기 필드 0입니다. 이것을 자동 보정하거나 모두 손상 파일이라고 단정하지 않습니다. 독립 PNG 청크 조사에서 내부 오류 대상 최소 29개가 관측됐습니다. 실제 제품의 형식 내부 진단은 PNG 이외 형식의 미지원 변형도 포함할 수 있으므로 이 수치를 전체 `inspection_failures`의 정확한 기대값으로 사용하지 않습니다. 브러시와 그림 사이의 공통 OPF 항목을 합쳐 문서 전체에서 한 번만 검사하는 API는 아직 없고, 이 바이트 검사는 그림의 배치·자르기·회전·렌더링·편집·저장 또는 HWPX 전체 XSD/의미 유효성을 보증하지 않습니다.

전용 테스트는 중복 참조, 외부/빈/부재/미해결 건너뛰기, MIME 불일치·unknown, ZIP CRC와 PNG 내부 CRC의 서로 다른 오류 경로, WMF 표준·Placeable 헤더 및 크기·record·checksum 반례, 위조된 사이트 ID·상태, 정확한 대상/바이트/PNG 한도, 모든 할당 실패, Git 추적 그림 HWPX, section과 master의 분리된 Known 조립을 검사합니다. ReleaseFast 8개 실파일 shard는 독립 조사기의 사이트·고유 대상·형식·MIME 불일치·인코딩 바이트 및 WMF 내부 실패 수와 대조합니다. 재현 명령은 [개발·검증 명령](development-commands.md)을 따릅니다.

2026-09-25 이전 그림 파트 기준 전용 테스트는 Debug·ReleaseSafe·ReleaseFast 각각 8/8, 기존 공통 코어 브러시 테스트는 각 모드 9/9 통과했습니다. 독립 oracle 자체 반례와 8개 ReleaseFast 실파일 shard도 통과했고, 전체 Debug `zig build test --summary all`은 종료 코드 0·5/5 단계·2,456/2,456 테스트를 통과했습니다. ReleaseSafe 제품 빌드·CFB 비교 47/47·전체 audit도 각각 종료 코드 0입니다. 전체 빌드와 audit 출력에는 `failed command` 러너 문구가 섞였으나 빌드 최종 요약과 프로세스 종료 상태는 성공입니다. 성공한 `inspectKnown()`도 대상별 내부 형식 오류·미지원 형식·MIME 불일치 진단이 0이라는 뜻은 아닙니다.

WMF 확장 재검증: 독립 Python ZIP/XML/바이트 조사와 자체 반례가 통과했고, Zig ReleaseFast 실파일 shard 0~7이 모두 통과했습니다. WMF의 shard별 고유 대상은 0/0/6/0/0/13/0/4개, 내부 framing 실패는 0/0/2/0/0/0/0/1개로 일치했습니다. 전용 그림 테스트는 Debug·ReleaseSafe·ReleaseFast 각각 9/9, 공유 코어 브러시 테스트는 Debug 9/9입니다. 최종 소스의 전체 Debug `zig build test --summary all`은 종료 코드 0·5/5 단계·2,457/2,457 테스트를 통과했고, ReleaseSafe 제품 빌드와 전체 감사도 종료 코드 0이었습니다. 출력의 `failed command` 문구는 이 최종 종료 상태를 대체하지 않습니다. 적대적 검토에서 새 형식을 브러시 조사기가 무조건 거부하던 경로를 별도 카운터로 고쳤고, 선언 MIME만 보고 WMF로 분류하거나 실패 바이트를 `unknown`으로 숨기지 않음을 재확인했습니다. 이 검증은 WMF 헤더·record framing까지만 뒷받침합니다.

TIFF 확장 검증: 독립 ZIP/XML/구조 조사에서 여섯 대상이 모두 구조 검사에 통과했고, Zig ReleaseFast 실파일 shard 0~7이 형식·MIME·바이트·TIFF 오류 0건을 대조했습니다. 전용 그림 테스트는 Debug·ReleaseSafe·ReleaseFast 각각 10/10, [TIFF 구조 계약](tiff-structure.md)의 필터는 각각 6/6 통과했습니다. 최종 전체 Debug 테스트는 종료 코드 0·5/5 단계·2,462/2,462, ReleaseSafe 제품 빌드와 전체 감사도 종료 코드 0입니다. 당시 미지원 형식은 SVG 2개와 PCX 1개였으며, TIFF 구조 성공을 LZW·픽셀·색상 의미의 검증 완료로 읽지 않습니다.

PCX 확장 당시: [PCX 헤더·RLE 경계 검사](pcx-structure.md)를 공통 이미지 계층에 추가했습니다. 당시 선택 그림 1,513개 중 PNG 441, JPEG 344, BMP 677, GIF 19, WMF 23, TIFF 6, PCX 1개를 시그니처로 인식했고 SVG 2개는 아직 미지원이었습니다. PCX 1개는 독립 조사에서 RLE 출력 길이가 일치하며, 픽셀/색상·렌더링을 검증한 것은 아닙니다. PCX 해제 길이의 개별·보고서 합계 한도와 대상별 `inspection_error`를 유지합니다. 위의 과거 TIFF 파트 수치는 당시 검증 기록이며, 해당 PCX 파트의 최종 검증 결과는 [PCX 계약](pcx-structure.md)에 따릅니다.

최종 PCX 파트에서는 Debug·ReleaseSafe·ReleaseFast 그림 전용 테스트가 각각 12/12, PCX 구조 테스트가 각각 5/5 통과했습니다. 독립 Python 반례·실파일 조사와 ReleaseFast known shard 0~7도 통과했으며, 전체 Debug는 종료 코드 0·2,468/2,468, ReleaseSafe 제품 빌드는 5/5 단계로, ReleaseSafe 전체 감사도 종료 코드 0으로 통과했습니다. 형식 내부 오류의 대상별 진단과 전체 문서 의미 검증은 여전히 별개입니다.

# XML 태그·속성 토큰

[이름·참조](xml-names-references.md) · [문자 입력](xml-input.md)

## 범위와 출처

태그 하나의 시작/종료/빈 요소 문법과 속성 이름·값을 검사합니다. W3C XML 1.0 Fifth Edition [§3.1](https://www.w3.org/TR/2008/REC-xml-20081126/#sec-starttags)의 STag/ETag/EmptyElemTag/Attribute와 [§3.3.3](https://www.w3.org/TR/2008/REC-xml-20081126/#AVNormalize)의 CDATA 방식 속성 정규화를 기준으로 합니다.

**전체 XML 문서 검증기는 아닙니다.** 시작/종료 이름의 짝, 중첩/루트 개수, namespace 확장 이름, DTD·일반 엔터티 의미는 후속 단계입니다. `<x/></x>`도 두 태그를 각각 읽을 수 있으나 유효한 문서라는 뜻은 아닙니다. 태그 뒤 NUL 등 미소비 본문도 이번 호출의 검증 범위에 포함하지 않습니다.

## 책임과 소유권

- `tags.zig`: 태그 종류·이름·속성 순서·동일 이름 중복 검사, 속성 배열과 임시 이름 집합의 수명, 전체 태그 원자적 반환을 소유합니다. 속성 배열은 allocator로 할당하며 Tag.deinit으로 해제합니다. raw/이름/값 문자열은 입력을 빌립니다.
- `tag_cursor.zig`: 태그와 내부 속성·참조가 공유하는 바이트 예산, 공백·구분자·기존 이름/참조 파서 연결을 소유합니다. 글로벌 문자 예산은 기존 Input 그대로 사용합니다.
- `attribute_value.zig`: 두 따옴표의 경계, literal `<` 금지, 속성 값의 Part 순회와 정규화/미해결 진단을 소유합니다. 태그 파서가 값 문법을 다시 구현하지 않습니다.
- `characters.whitespace`: 선언·태그·속성 정규화에서 XML 공백 집합을 공유합니다. 일반 Unicode 공백 분류로 대체하지 않습니다.

태그 전체가 성공하고 속성 배열 소유권 이전까지 완료된 뒤에만 Input을 갱신합니다. 잘림·구문 오류·중복·한도·할당 실패는 호출자의 offset/남은 문자 예산을 바꾸거나 부분 Tag를 반환하지 않습니다. 임시 이름 집합과 속성 배열을 실패 경로에서도 해제합니다.

속성 이름은 같은 strict 인코딩 안에서 raw 바이트로 중복을 검사합니다. UTF-8의 비최단 표기나 고립 UTF-16을 이미 거부하므로 같은 코드포인트 열은 같은 바이트입니다. 대소문자나 NFC 정규화는 적용하지 않습니다. `a`/`A`, `é`/결합 문자 표기는 서로 다른 이름입니다. `p:x`/`q:x`가 같은 namespace로 확장되는 중복은 아직 별도 검사하지 않습니다.

## 값과 참조

Value.raw는 양쪽 따옴표를 포함한 원문이며 text는 그 안의 borrowed View입니다. Value.iterator는 같은 값 파싱 로직으로 Part를 반환합니다. literal 공백·탭·줄바꿈은 공백으로 정규화하고 숫자 참조의 TAB/LF/CR은 그대로 둡니다. U+0085·U+2028은 XML 1.0 공백으로 치환하지 않습니다. 태그 구문에서 NBSP를 공백처럼 받지 않습니다.

Part는 literal 또는 기존 Reference입니다. `&quot;`가 만든 따옴표는 속성을 닫지 않고, `&lt;`/`&#60;` 결과를 마크업으로 재해석하지 않습니다. 서로 다른 따옴표나 `>`·`/`는 속성 안의 literal 문자로 읽을 수 있습니다.

Stats.scalars는 해석된 scalar 수, references는 원시 참조 수, unresolved는 미해결 이름 참조 수입니다. 미해결 참조는 scalar 수에서 제외하고 Part에 이름을 보존합니다. **unresolved가 있으면 완성된 정규화 문자열이나 유효한 속성이라고 주장하지 않습니다.** DTD 선언·일반 엔터티의 replacement text·외부 엔터티 금지·비 CDATA 타입의 공백 압축 등 의미 검증은 남아 있습니다. 외부 조회·엔터티 확장은 수행하지 않습니다.

Value.iterator는 별도 읽기 전용 순회이며 원래 문서 Input의 예산을 재차감하지 않습니다. 저장된 참조 옵션과 값의 바이트 길이 안에서 읽고, 값의 수명 동안 원본 바이트는 유지되어야 합니다.

## 한도

기본값은 태그 64 KiB, 요소/속성 이름 4096바이트, 속성 4096개, 참조 65,536개입니다. 참조 토큰/참조 이름은 기존 Options의 각 4096바이트 한도를 별도로 적용합니다. 태그 바이트 예산은 이름·공백·등호·따옴표·참조·닫는 구분자 모두 포함합니다. 참조 개수는 모든 속성이 공유합니다. 이름/참조 한도는 남은 태그 바이트 한도보다 커질 수 없습니다.

여기서 속성/참조 개수는 태그 단위입니다. 후속 문서 순회는 문서 전체 예산을 별도로 전달·차감해야 합니다. Input의 글로벌 문자 한도는 현재 태그 전후에 유지합니다. 입력 offset이 0이 아닌 경우에도 태그 시작 기준 바이트 예산을 적용합니다.

## 실측과 적대적 검증

독립 JS 기준은 기존 이름·참조 기준을 공유하고 별도 태그/속성 문법과 정규화를 구현합니다. mode 122는 encoding u8, 태그/이름/속성/참조/참조 바이트/참조 이름 한도 u32 여섯 값, 원문을 받습니다. 외부 limit은 문자 예산입니다. 태그 raw·이름·종류·offset·남은 예산·속성 원문·정규화된 Part와 미해결 참조를 바이트 단위로 대조합니다. 제품 JS ABI는 바꾸지 않습니다.

정상 1,377건·거부 5,871건의 최종 집중 검증을 통과했습니다. 0~255 코드포인트와 두 따옴표를 세 인코딩으로 조합하고, NEL/줄 구분자·NBSP·한글/비 BMP·결합 문자·NFC 구별, 모든 잘림 위치, 정확/부족 한도, 중복/구분자 오류, 오류 후 정상 재실행을 확인했습니다. 네이티브에서는 모든 할당 실패와 마지막 중복 속성 오류에서 메모리 해제·입력 상태 보존을 검사합니다.

적대적 재검토는 태그/값의 구분자 경계, literal/참조 정규화, 중복 이름/namespace 범위, 여러 예산/비영점 offset/할당 실패, SSOT·독립 기준·실측 범위로 나누었습니다. 비영점 offset의 정확/부족 태그 한도와 문자·따옴표 조합을 보강했습니다. 최종 검사에서 추가 제품 결함은 발견하지 못했습니다.

실파일 treatise sample.hwp의 이력 XML 다섯 payload에서는 **첫 루트 태그만** 검사했습니다. VersionLog0은 20바이트 빈 요소 태그, 나머지 VersionLog는 각 18바이트 시작 태그이며 속성이 없습니다. HistoryLastDoc의 루트 시작 태그는 112바이트·속성 3개입니다. 이 결과를 나머지 XML의 중첩/문서 검증 성공으로 확대하지 않습니다.

별도 수동 확인에서는 literal 공백/TAB/CRLF와 숫자 TAB/LF/CR·기본 엔터티가 섞인 속성 값을 xmllint로 읽었습니다. UTF-8·UTF-16LE·UTF-16BE 모두 기대 scalar 열과 일치했습니다. 기본 audit에 외부 도구 의존성을 추가하지 않았습니다.

## 실행 기록

Debug → ReleaseSafe → ReleaseFast 전체 audit는 각각 17/17 단계·네이티브 322/322이 통과했습니다. Debug 전체는 테스트 보강 전 3,072,864 checks였으며, 이후 최종 네이티브 Debug 322/322과 최종 WASM 집중 검증(정상 1,377·거부 5,871)을 별도로 통과했습니다. 제품 태그 처리 로직은 보강 중 변경하지 않았습니다. 최종 구성의 ReleaseSafe/ReleaseFast 전체는 각각 3,081,141 checks입니다. 기존 Node 47개·조사 22개·XML 외부 경계 6개도 통과했습니다.

전체 로그는 `/tmp/hwpjs-xml-tag-{debug,safe,fast}.log`, 최종 네이티브 Debug 로그는 `/tmp/hwpjs-xml-tag-native-debug-final.log`입니다. 최종 Debug 집중 검증은 `.zig-cache/o/a241cce4617671d2a5e9c87809883736/hwp5-probe.wasm`에서 수행했습니다. 캐시가 없어도 audit 재빌드로 최종 검사를 실행합니다. 포맷·변경 JS 문법·diff 검사와 변경 문서의 로컬 링크 19개 존재 확인도 통과했습니다.

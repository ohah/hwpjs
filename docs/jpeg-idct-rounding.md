# JPEG IDCT의 정확한 상쇄·반올림 경계

이 문서는 [IDCT·샘플 복원](jpeg-idct.md)의 반 정수 경계 수정과 근거를 소유합니다. Progressive·순차 샘플 경로가 같은 구현을 사용합니다. 프레임/평면 조립과 실제 파일 전체 회귀 상태는 [progressive 샘플 평면](jpeg-progressive-samples.md)에 있습니다.

## 재현한 두 원인

수정 전 `reference/rhwp/samples/images/moogung.jpg`의 785,000샘플 중 53개에서 제품과 독립 직접 2차원 IDCT 수식의 정수 샘플이 1만큼 달랐습니다. 세 모드에서 같은 차이를 확인했습니다. 계수 프레임 wire·샘플 헤더·progression/levels는 일치했고, 개별 블록 mode 257의 샘플은 평면 mode 282와 일치했습니다. 차이 위치의 두 f64 계산 사이 최대 차이는 `4.263256414560601e-14`였습니다.

- 역양자화된 row-major 계수 `0:420, 1:-6, 8:-6`과 나머지 0, 블록 `(x=5,y=2)`에서 AC 두 항이 정확히 상쇄됩니다. 중심값은 52.5, 8비트 샘플은 181이어야 하지만 제품의 `52.49999999999998`은 180이 됐습니다.
- 계수 `0:-300, 1:-6, 8:-6`의 같은 위치는 중심값 -37.5, 샘플 91이 맞지만 독립 JS 수식의 `-37.500000000000014`는 90이 됐습니다.
- 이미 정확하게 표현된 f64에도 별도 문제가 있었습니다. 0.5 바로 아래 인접 f64에 128을 먼저 더하면 마지막 비트가 사라져 샘플이 129가 됐습니다. 이 입력의 올바른 샘플은 128입니다. -0.5 바로 아래와 12비트에서도 같은 종류의 문제를 재현했습니다.

53개 차이 위치를 정수 다항식으로 다시 계산하여 모두 정확한 반 정수임을 확인했습니다. 이 위치들 중 제품 반올림 오류는 42개, 독립 JS 오류는 11개였습니다. 이는 차이가 난 위치의 분류이며 나머지 모든 위치의 수학적 정확도를 당시 증명했다는 뜻은 아닙니다.

## 제품 책임과 정확한 상쇄

`idct_rational.zig`는 [T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) A.3.3의 수식에 곱을 합으로 바꾸는 항등식을 적용합니다. DC의 정규화 인자는 cos(π/4), 나머지는 원래 위치·주파수의 cosine으로 표현할 수 있습니다. 두 인자의 곱은 `(cos(a+b)+cos(a-b))/2`이므로 각 항의 최종 배율은 1/8입니다.

각도는 π/16 단위의 정수입니다. 주기·대칭·부호와 cos(π/2)=0을 사용해 cos(kπ/16), k=0..7의 여덟 계수로 축약하고 i128로 합칩니다. 이 여덟 기저는 유리수 위에서 선형 독립입니다. 비상수 계수가 전부 정확히 0일 때만 상수 계수/8을 반환하며, 그렇지 않으면 null입니다. 반 정수까지의 거리나 epsilon으로 상쇄를 추측하지 않습니다. 최대 128개의 signed i64 기여분을 합하므로 i128 중간값은 넘치지 않습니다. 위치는 내부 8×8 반복문이 공급합니다.

`idct.zig`는 기존 분리형 f64 계산을 유지하되 위 함수가 증명한 유리수 결과를 사용합니다. DC-only의 기존 빠른 경로도 유지합니다. 큰 유리수의 f64 변환 자체는 반올림될 수 있지만 유효 8/12비트 샘플 범위의 정확한 1/8 값은 그대로 표현됩니다. 비유리수 결과의 f64 근사나 임의로 큰 입력의 모든 반올림 정확성을 새로 보증하는 것은 아닙니다.

`sample_restoration.zig`는 범위 검사를 먼저 한 뒤 centered의 정수 부분과 소수 부분으로 가장 가까운 정수를 결정하고, 마지막에 정수 level을 더합니다. 정확한 반 정수는 양의 방향입니다. 이미지 포맷·정밀도에 따라 보정 상수를 다르게 더하지 않으며, IDCT에 샘플 clamp 책임을 넣지 않습니다.

## 독립 검증과 실패를 검출하는 검사

`tests/hwp5/jpeg-idct-rational.mjs`는 제품의 여덟 cosine 기저를 복사하지 않습니다. z=exp(iπ/16)로 두고 각 cosine을 `(z^k+z^-k)/2`로 바꿔 네 단항식을 전개합니다. `z^16=-1`로 16항 다항식을 BigInt로 축약하고 16으로 나눕니다. 비상수 항이 전부 0일 때만 유리수입니다. 일반 값은 기존 직접 2차원 f64 수식이 계산합니다. 독립 샘플 반올림은 level을 더하기 전에 `floor(value)+0.5`와 비교합니다.

AC 정확한 상쇄·4번 주파수의 정확한 부호 패턴·마지막 비트 유실의 세 네이티브 테스트를 수정 전에 실행해 모두 실패함을 확인했습니다. 비유리수 거부와 i64 최댓값/최솟값 조합의 i128 합 검사도 추가했습니다. 수정 후 IDCT/샘플 복원 테스트는 세 모드 각각 9/9 통과했습니다.

세 모드의 독립 WASM IDCT 비교는 각각 132,172건, 오류 거부 1,922건이며 최대 f64 오차는 `1.1920928955078125e-7`, 독립 정수 샘플 차이는 0건입니다. 기존 입력군에 더해 서로 반대인 주파수 쌍의 대각/반대각 상쇄, 4번 수평·수직·혼합 주파수, 8/12비트 모든 샘플 구간의 반 정수 바로 아래·정확히 같은 값·바로 위 인접 f64를 검사합니다. 큰 impulse까지 포함한 오차 합계이며 T.83 기준과 동일시하지 않습니다.

별도 밀집 상쇄 조사 1,024블록도 세 모드에서 통과했습니다. Xorshift32 seed `0x083dc701`, 이동 13/17/5, unsigned `%4097-2048`을 사용합니다. 각 주파수 쌍 u>v에 대해 반대편 계수를 대각 또는 반대각에서 정확히 상쇄되도록 구성하고, DC는 `(n%250)*8-996`, 8/12비트를 교대합니다. 각 블록의 대각 또는 반대각 8개 중심값을 정확한 DC/8과 직접 비교했습니다. 전체 64개 값의 독립 수식 대조 최대 오차는 `3.183231456205249e-12`, 정수 샘플 차이는 0건입니다. 이 별도 조사는 정규 audit 합계에 더하지 않습니다.

별도 WASM 큰 정수 조사 32블록도 세 모드에서 통과했습니다. row-major 위치 0/4/32/36의 각 계수를 i64 최소/최대로 바꾼 16조합을 8/12비트에서 검사했습니다. 4번 주파수의 수동 부호 패턴으로 BigInt 분자를 합산한 기대값과 64개 중심값·샘플을 직접 비교했습니다. 큰 항이 상쇄되어 -0.25 또는 0 같은 작은 값이 되는 경우도 포함하며, 제품 i128 합과 독립 BigInt 합의 WASM 경계를 확인합니다. 이 별도 조사도 정규 audit 합계에 더하지 않습니다.

격리 경로 `/tmp/hwpjs-progressive-samples-mutants.F4NKTH/`의 유리수 복원 제거·cosine 부호 처리 손상·level 먼저 더하기 소스 변형은 세 모드에서 모두 컴파일 후 실패했습니다. 9개 테스트 중 각각 2/4/1개가 실패했습니다. 독립 JS 쪽의 유리수 복원 제거·이전 반올림 수식 복귀도 세 모드에서 각각 AssertionError로 검출했습니다. 실제 제품/독립 검증 파일에는 이 변형을 반영하지 않았습니다.

한글/libjpeg와 픽셀 동일성, 모든 비유리수 입력에서의 정확한 반올림, 공식 T.83 시험 통과를 주장하지 않습니다. 이번 수정의 실제 파일 전체 대조·정규 전체 회귀 결과는 [샘플 평면 검증](jpeg-progressive-samples.md)이 소유합니다.

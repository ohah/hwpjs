# 추적 픽스쳐 편집 지원 전수 기준

전체 픽스쳐의 파싱·편집과 rhwp 형태의 Canvas 편집 UI가 목표입니다. 단순 문단 일부에서 입력이 성공했다고 전체 목표가 달성된 것으로 보지 않습니다. HWPX도 목표에서 제외하지 않습니다.

## 최신 전수 실측

2026-10-02 현재 HWP5 전수 prefix 이력 검사는 [HWP5 편집 이력](hwp5-edit-history.md), HWPX 전수 편집/이력 검사는 [HWPX 편집 이력](hwpx-edit-history.md)이 최신 수치·거부 분류·검증 범위를 소유합니다. 두 포맷 모두 공개 편집/저장 및 Canvas 이력에 연결됐습니다. 아래 2026-10-01 ‘HWPX 미연결’은 당시 단계의 기록이며 현재 상태가 아닙니다. 전체 픽스처의 임의 위치·모든 명령·완전 조판 지원은 여전히 미완료입니다.

2026-10-01 root 문단 간 하이퍼링크 거래 연결 후 같은 93개 추적 파일에서 HWP5 prefix 삽입 1481회 중 1433회가 저장·독립 텍스트/비본문 스트림 대조·재열기에 성공했습니다. 44개 HWP는 모든 문단 삽입 성공, chart 1개는 참조 숫자 셀에 비숫자를 넣는 InvalidFormulaNumber 48회가 남습니다. HWP5 미리보기 거부 3개는 유지됩니다. 후속 [HWPX 공개 읽기](hwpx-text-api.md) 연결로 HWPX 44개가 텍스트 이벤트/읽기 전용 Canvas projection에 성공하고 암호화 1개는 EncryptedDocument로 거부됩니다. HWPX 편집/저장은 45개 모두 아직 미연결입니다. 아래 기준선은 이전 단계 기록이며 현재 지원 수치가 아닙니다. 이 실측은 임의 편집·서식·조판·문서 전체 선택·실행 취소의 완료 증명이 아닙니다.

## 검사 책임과 증명 범위

`tools/hwp5-edit-corpus-audit.mjs`는 Git 추적 파일 중 `fixtures/` 아래의 HWP/HWPX를 전수 열거합니다. 성공하는 파일명 목록을 따로 유지하지 않습니다. HWP5는 공개 미리보기와 실제 편집 API를 열고, 모든 문단의 시작에 `검증😀`을 삽입합니다. 무변경 명령으로 편집 가능성을 대신 검사하지 않습니다. 원본 파일에는 쓰지 않습니다.

`tools/hwp5-edit-corpus-lib.mjs`는 목록 필터·실제 명령 실행·독립 텍스트 대조만 담당합니다. 편집 허용 규칙·문단 모델·직렬화를 다시 구현하지 않습니다. CFB.js가 저장된 컨테이너를 열고 Node zlib와 기존 독립 레코드 oracle이 모든 문단의 원시 UTF-16 바이트를 대조합니다. 거부 명령의 문단 값 유지, 모든 비본문 스트림의 payload 보존, 변경 후 기본 저장의 재조판 거부도 검사합니다. 전부 거부된 파일은 원본 전체 바이트가 동일한지도 확인합니다. 저장 출력을 새 제품 편집 세션으로 다시 열어 모든 문단 바이트를 재대조합니다.

이는 글자 모양·범위 이동·본문의 모든 비텍스트 레코드·실제 페이지/표 배치·한컴 GUI·브라우저 입력의 증명이 아닙니다. 해당 검증은 각 주제 계약의 독립 검사와 실제 E2E가 계속 필요합니다. `textAndUnselectedStreamsVerified`는 그 제한된 증명만 뜻합니다. 거부나 공개 API 미연결은 지원 완료로 집계하지 않습니다. `verification_failed`가 있으면 명령이 실패 종료합니다. 정상 종료만으로 전체 지원을 주장하지 않습니다.

최신 HWP5 도구의 HWPX `hwpx_edit_audited_separately`는 별도 [HWPX 전수 편집 도구](development-commands.md)의 검사 대상이라는 뜻이며 미구현을 의미하지 않습니다. 과거 `hwpx_public_parser_editor_not_connected`는 당시 공개 API 미연결 분류였습니다. 암호화/배포용 문서도 현재 거부 사실을 따로 남기며 조용히 검사 목록에서 빼지 않습니다.

## 2026-10-01 최초 기준선

현재 제품 WASM에서 추적 픽스쳐 93개(HWP 48개·HWPX 45개)를 조사했습니다. HWP 45개는 미리보기와 편집 세션이 열렸지만 문서별 모든 문단 편집은 어느 파일도 완료되지 않았습니다. 실제 1,481문단에 명령을 시도해 269문단에서 삽입·저장 후 텍스트 대조가 성공했습니다. 미리보기 거부 3개는 `distribution.hwp`·`viewtext.hwp`의 `UnsupportedDistribution`, `password-12345.hwp`의 `UnsupportedEncryption`입니다.

거부 명령은 중첩 문단 792건, 제어 포함 텍스트 158건, 구역 내 다른 컨트롤 158건, 표/리스트 구조 80건, 텍스트 레코드 부재 24건입니다. 복합 문단은 먼저 발생한 오류 하나로 집계하므로 이것이 독립적인 미구현 기능 수는 아닙니다.

사용자가 확인한 `software.hwp`는 101문단 중 성공 0건입니다. 중첩 79건, 제어 포함 4건, 구역 내 다른 컨트롤 제한 18건을 확인했습니다. 문서 제목은 표 셀에 있으며 LIST_HEADER의 자식이 아니라 같은 표 컨트롤 아래의 형제 문단입니다. 셀 소유 관계는 원래 Tree와 별개인 기존 `list_groups` 계약을 따라야 합니다. parent 값만으로 셀을 추정하거나 중첩 제한만 삭제해서 해결됐다고 보지 않습니다.

단위 반례는 무시된 성공 명령, 거부 중 값 변경, 스트림 누락/손상, 잘못된 문단 텍스트와 섹션 누락을 검출합니다. 실행 명령은 [개발·검증 명령](development-commands.md)이 소유합니다.

## 중첩 문단 연결 직후 기준선

[중첩 목록 편집](hwp5-nested-text-edit.md) 연결 후 같은 1,481문단 중 712개가 삽입·저장 대조에 성공했습니다. 26파일은 일부 성공, 19파일은 전부 거부이며 3개의 미리보기 거부와 HWPX 45개의 공개 연결 미구현은 그대로입니다. software는 101문단 중 70개 성공입니다. 남은 전체 거부는 제어 포함 228건·텍스트 부재 383건·구역 컨트롤 정책 157건·미지원 중첩 소유 1건입니다. 이전에 먼저 걸리던 중첩 제한이 제거되면서 뒤의 거부 이유가 드러났으며, 새로운 파일 손상을 발견했다는 뜻은 아닙니다. 전체 목표는 계속 미완료입니다.

## 남은 완료 게이트

[기존 빈 문단 연결](hwp5-empty-text-edit.md) 직후 실측은 1,481문단 중 1,095개 성공이었습니다. 당시 32파일 일부 성공·13파일 전부 거부·3파일 미리보기 거부이며 HWPX 45개는 공개 연결 미구현이었습니다. software는 당시 101문단 중 93개 성공·제어 포함 8개 거부였습니다. 최신 수치는 문서 첫머리를 따르며 일반 저장·원본 조판 완료를 뜻하지 않습니다.

- 표 셀·텍스트 상자·주석·머리말/꼬리말과 제어 포함 문단의 소유권/위치 보존 편집.
- 새 문단 생성, 문단 분할/병합, 문서 범위 선택. 실행 취소/다시 실행은 두 포맷의 현행 이력 계약에 연결됐으며 구조 편집 지원을 뜻하지 않습니다. 기존 빈 문단의 제한적 입력은 위 별도 계약을 따릅니다.
- 두 포맷의 편집 모델·저장 계약 확장과 임의 위치·미지원 명령 검증. HWPX 공개 읽기·편집·저장은 연결됐으나 전체 의미 모델 완성은 아닙니다.
- rhwp의 셀 경로·명령 이력·조판 갱신 책임을 참고한 Canvas UI 및 실제 픽스쳐 E2E.
- 저장 후 서식·비텍스트 본문·표/페이지 조판·외부 프로그램 대조. 암호/배포용 문서는 권한 및 포맷 정책에 맞는 지원 상태를 명시적으로 검증.

이 게이트들은 전수 검사 도구가 추가된 것만으로 완료되지 않습니다.

# HWP5 행간과 Canvas 이동량

## 책임과 원값

공개 문단 모양은 구형·신형 원값을 보존합니다. 표시·입력 폼의 선택은 `paragraph-spacing-source.mjs`가 소유합니다. 정상 신형 종류0에 구형 쌍이 있으면 그 쌍을 선택하며, 잘못된 신형 값은 이 분기로 숨기지 않습니다. 명시적0·부재·미확정 종류를 구분합니다.

native 편집의 선택은 `paragraph_spacing_values.zig`, byte patch는 기존 payload writer가 소유합니다. 비례 행간 변경은 구형·신형 쌍을 함께 갱신해 저장 재열기 때 이전 값이 선택되지 않게 합니다. 무관한 비트·tail·레코드는 보존합니다. wire/API의 원시 scalar 계약은 유지합니다.

## 산술

`hwp5-line-spacing.mjs`는 정수 단위의 추가 간격과 이동량만 소유합니다. H는 줄 높이, B는 비례 간격의 별도 기준 높이, P는 백분율, D는 해석된 거리입니다.

- 비례 추가 간격: `4 × R(trunc(B / 4), P - 100, 100)`.
- 고정: `D - H`. 추가 여백: `D`. 최소: `max(0, D - H)`.
- 기본 이동량: H + 추가 간격. 추가 간격은 음수일 수 있습니다.

R은 signed64 곱과 가까운 정수 반올림이며 동점은0에서 멀어집니다. JS는 BigInt 중간값과 signed i32 결과 범위를 검사합니다. 고정·여백·최소의 짝수 원값은 절반 거리입니다. 홀수는 상대 단위이며 명시적 `relativeBase`가 없으면 계산하지 않습니다.

`paragraph-geometry.mjs`는 px와 정수 단위 경계입니다. 현재 일반 Canvas는 상대 단위의 문서/호환 기준을 공급하지 않으므로 해당 값·미확정 입력에는 기존 미리보기 높이를 유지합니다. 브라우저 측정의 양자화가 한글 글꼴 측정 동치라는 뜻은 아닙니다. HWPX 표시 projection의 `spacingFormat: "hwpx"`는 HWP5 전용 단위/반올림을 차단합니다.

`row.height`는 이동량, `rowVisualHeight`는 글자·입력 영역입니다. 화면 culling·hit 검사는 후자를 사용합니다. 도형은 이동0에서도 문자 진행·행 예산과 ink overflow를 검사합니다. compact 도형은 후행 간격을 ink에 포함하지 않습니다. 인라인 HWP5 개체는 H/B를 분리하고 음수 간격을 개체 높이로 다시 clamp하지 않습니다. HWPX의 기존 인라인 정책은 유지합니다.

## 적대적 검증 5회

1. 정수·단위·경계 검토: 4단위 반올림과0%·작은 고정값을 검사했습니다. oracle의 signed0 및 실제 픽스쳐에 없는 최소 종류를 잘못 기대한 부분을 바로잡았습니다.
2. 입력·SSOT 검토: malformed 신형/부재/0/범위/미확정 종류/상대 단위를 검사하고 표시·폼의 중복 선택을 제거했습니다. 기존 UI·기하36/36이 통과했습니다.
3. 배치·선택 검토: compact 도형에서 후행 행간까지 ink로 예약한 회귀를 수정하고 다단·도형·혼합 개체60/60이 통과했습니다.
4. 실제 저장 검토: 45 HWP/266참조 리소스의 행간 편집1,007건과 독립 DocInfo/CFB 원문·저장·이력, HWPX 백분율 편집을 검사했습니다. native Debug/ReleaseSafe 집중검사 각각8/8에 명시0 재열기·no-op·byte-exact undo가 포함됩니다.
5. 음성 대조·재검토: 캡처한 산술8개 대조와 정수 단계 제거·거리 두 배·최소 높이 clamp의3개 변조 구별이 통과했습니다. 실제 인라인 경로의 잔여 clamp도 수정하고 회귀를 추가했습니다. 최종 선택75개 중73개는 통합 실행에서 통과했고2개는 ENOSPC로 중단됐습니다. 소스/후보 변경 없이 해당 HWPX2파일을 다시 실행해3/3 통과했습니다. 겹친1개를 더해76개라고 계산하지 않으며,75개 대상 모두 통과 결과가 확보됐지만 단일 통합 실행75/75와는 구분합니다.

별도 기존 `paragraph-format-worker.test.mjs`는 undo 전체 응답 비교에서 셀 주소 epoch4를2로 기대해 실패합니다. 이전 후보에서도 동일하게 재현했으며 해당 기존 파일은 수정하지 않았습니다. 새 `line-spacing-worker.test.mjs`는 실제 Worker의0%·표시·텍스트 불변·undo·잘못된 명령 뒤 redo를 검사합니다. 선택 회귀와 기존 실패를 합쳐 전체 suite 통과라고 부르지 않습니다.

ReleaseSafe 후보: `/tmp/hwpjs-spacing-build/bin/hwpjs.wasm`, SHA256 `83e90291b9067b4255ba298a3d9a6eba79cbe1fc5be239ef690cee369a50d589`. 전체 root/CI·브라우저 E2E·데모 배포·모든 글꼴/개체/격자/호환 옵션의 픽셀 동치는 검증하지 않았습니다. 디스크 부족으로 중단된 실행은 통과 수에 포함하지 않습니다.

# HWPX section 직접 문자 콘텐츠 순회

`SectionTree.visitContent(allocator, visitor)`는 [section 원문·요소 인덱스](hwpx-section-tree.md)의 소유 XML을 공통 XML 파서로 다시 순회하며, 각 CharData·CDATA 조각과 그 **직접 부모 요소 인덱스**를 원문 순서대로 콜백에 전달합니다. 별도 텍스트 노드 배열을 보관하지 않습니다. 요소 인덱스·확장된 이름·시작/끝 태그 위치·부모 관계가 재파싱 결과와 일치하지 않으면 오류로 반환합니다. 형제 연결 목록 전체를 다시 검증하는 API는 아닙니다.

`SectionTree.visitOrdered(allocator, visitor)`는 같은 단일 재파싱 경로에서 요소 시작·끝, 빈 요소, 직접 문자·CDATA를 **서로 섞인 원래 XML 순서**로 전달합니다. 이벤트의 요소 번호는 기존 인덱스 번호이고, 문자 이벤트는 직접 부모 번호를 갖습니다. 빈 태그는 `empty_element` 한 번만 전달하며 `<x></x>`처럼 명시적 쌍은 시작·끝 두 번 전달합니다. 미지원 요소도 건너뛰지 않습니다. `visitContent`는 이 순회에서 문자 이벤트만 필터링하므로 XML 해독 규칙을 따로 구현하지 않습니다. 콜백 실패 전의 이벤트는 이미 전달될 수 있으므로 호출자가 부분 모델을 폐기해야 합니다.

같은 재생기는 [header 원문 트리](hwpx-header-tree.md)에도 적용됩니다. header의 전체 요소·순서 실측은 그 문서가 소유하며 이 문서의 section 수치와 합쳐 지원률로 세지 않습니다.

이벤트의 `value.raw`는 `SectionTree.source`를 빌리며 CDATA 경계 표시(`<![CDATA[`/`]]>`)는 제외합니다. 콜백 밖에서도 트리가 살아 있는 동안 원문 조각은 사용할 수 있습니다. `value.toUtf8(allocator, max_bytes)`는 문자 참조와 XML 줄바꿈을 공통 규칙으로 정규화한 별도 버퍼를 돌려주며 호출자가 해제합니다. 문서 ZIP과 원본 입력 바이트를 해제한 뒤에도 트리를 소유하는 동안 순회할 수 있습니다. 콜백이 오류를 반환하면 이미 전달된 앞부분 이벤트는 취소되지 않으며 재호출은 처음부터 다시 시작합니다.

`hp:t`만 골라 표시 텍스트라고 주장하지 않습니다. 스크립트·도형·표·확장 요소 안의 문자도 원래 부모에 연결하고, 자식 요소를 사이에 둔 양쪽 문자 조각의 순서를 유지합니다. XML 루트 밖의 공백, 주석, 처리 지시문과 CDATA 구분 기호는 콘텐츠 이벤트가 아닙니다. CDATA와 일반 CharData의 종류는 보존하지만 둘을 합친 의미 해석, 조건부 분기 선택, 렌더링, 편집·저장은 후속 계층입니다. 기존 [section 텍스트 이벤트](hwpx-section-text.md)의 `hp:t` 중심 분류·진단도 이 API가 대체하지 않습니다.

## 검증

합성 테스트는 중첩 부모 인덱스, 자식 전후의 문자 순서, 문자 참조와 CDATA의 별도 종류, UTF-16 양 바이트 순서, ZIP 해제 후 트리 수명, 콜백 실패 뒤 재시도, 바뀐 인덱스 span 거부 및 모든 할당 실패 경로를 확인합니다. 선택 실파일 대조는 [개발·검증 명령](development-commands.md)의 8개 shard를 각각 별도 프로세스로 실행합니다. 독립 Python Expat 파서는 각 요소의 직접 문자·CDATA를 UTF-8로 합쳐 요소별 길이·바이트를 순서대로 SHA-256에 넣고, section 해시를 shard별로 합산합니다. 이는 모든 요소의 직접 문자 값 대조이며 개별 파서의 콜백 분할, 주석·처리 지시문, 화면상 읽기 순서나 모델 저장 동치 검사는 아닙니다.

로컬 corpus의 HWPX 484개 중 ZIP 종료 레코드가 없는 6개·암호화 2개를 제외한 476개 문서, 544개 section, 2,174,716개 요소를 대조했습니다. Zig와 독립 Expat의 직접 콘텐츠 해시는 8개 shard 모두 일치했습니다. oracle은 DTD·외부 엔터티를 거부하며, 실패를 빈 콘텐츠로 바꾸지 않습니다. 큰 마지막 shard는 한때 높은 메모리 사용량을 보였으므로 corpus 전부를 한 프로세스로 실행한 결과라고 주장하지 않습니다. 기본 테스트는 2,164/2,164개, Debug·ReleaseSafe·ReleaseFast 섹션 트리 전용 테스트는 각 10/10개, ReleaseSafe WASM 빌드와 기존 JS 비교는 47/47개가 통과했습니다. 이 기본 검사에는 선택 실파일 shard가 포함되지 않습니다.

순서형 이벤트의 독립 검증에서는 Expat의 시작·끝 요소와 **요소 경계 사이에서 합친 직접 문자**를 section별 SHA-256으로 기록하고, 각 shard에서 순서 독립적으로 합산합니다. Zig의 빈 태그 이벤트는 해시에서 시작+끝으로 확장하고 문자 참조·CDATA의 콜백 분할은 경계 사이에서 합칩니다. 이 해시는 앞의 요소별 직접 콘텐츠 해시와 달리, 자식 요소 앞뒤에서 문자가 이동하면 달라집니다. 주석·처리 지시문, 개별 콜백 분할, 표시/편집 의미의 동치는 검증 대상이 아닙니다.

2026-09-24 적대적 검증에서는 직접 콘텐츠 합계가 같은 `A<x/>B`와 `AB<x/>`의 순서 해시가 달라지는 반례를 Zig·Python 양쪽에서 확인했습니다. 요소 이름·부모·원문 span 변조, 빈 태그와 명시적 빈 쌍의 구분, 콜백 중단 뒤 재시도, 모든 할당 실패 지점도 테스트했습니다. 기본 테스트 2,169개와 섹션 트리 Debug·ReleaseSafe·ReleaseFast 각 13개, ReleaseSafe 제품 WASM 빌드 및 Debug `zig build audit --summary all`이 통과했습니다. 로컬 476문서·544섹션·2,174,716개 요소를 8개 독립 프로세스로 다시 검사해 모든 shard의 요소 수·기존 직접 콘텐츠 해시·새 순서 해시가 독립 Python 결과와 일치했습니다. 이는 HWPX 전체 스키마·문서 모델 지원률이 아닙니다.

`zig fmt --check build.zig src`, `git diff --check`, Debug `zig build audit --summary all`도 통과했습니다. 전체 audit는 기존 HWP5·CFB 등 다른 영역까지 실행하지만 이 결과가 HWPX 의미 모델·편집·저장 완성을 뜻하지는 않습니다.

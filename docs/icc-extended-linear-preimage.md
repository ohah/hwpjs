# ICC 512비트 목표값의 선형 역상

## 계약과 책임

`linear_preimage.solveWide(linear, n, d)`는 한 선형 분기에서 clip((a*x+b)/65536)=n/d인 모든 x를 u1024 분수 끝점의 ExtendedInterval 또는 null로 반환합니다. 입력 목표는 u512, 원래 활성 구간은 u64 분수와 포함 플래그입니다. null은 실제 역상 부재이며 최근접 값을 뜻하지 않습니다.

기존 [u128 선형 역상](icc-linear-preimage.md)과 solveFor가 목표 검증·상수·교점·클리핑 반구간 조립을 공유합니다. 잘못된 원래 구간을 먼저 거부하는 기존 오류 순서를 유지합니다. numerator=(65536*n−b*d), denominator=a*d의 부호를 맞춘 뒤, 내부 목표는 단일점과 활성 구간의 교집합을 구합니다. 0/1은 기울기 방향에 맞는 반구간을 교차시킵니다. 교점이 [0,1] 밖이면 시작점에서 전체/부재를 판정합니다.

교점 중간값은 i1024이며 |numerator|<2^544, |denominator|<2^543입니다. 시작점 비교는 원래 u64 좌표를 사용하므로 교차 곱의 크기도 2^608 미만입니다. 어떤 단계에서도 목표나 좌표를 u512 이하로 자르지 않습니다. 코어는 할당하지 않습니다.

`fraction.Normalized(1024)`가 검증·u2048 교차 곱 비교를 소유하며 Zig 진입점 image.icc.fraction에서 공통 분수 API에 접근할 수 있습니다. `unit_interval.ExtendedInterval`은 기존 Of의 구간 검증·동일 경계 AND·교집합 규칙을 재사용합니다. extend/widen은 공통 승격 함수를 사용해 원래 포함 플래그를 보존합니다. 기존 Interval/solve와 JS 제품 API는 유지합니다.

## 실수 변환에서 재현한 기존 문제

새 폭의 명시적 근사 변환을 검증하는 중, 기존 Normalized(256/512).toFloat()를 실제로 호출한 최소 네이티브 테스트가 현재 macOS Zig 0.16 LLVM에서 `LLVM ERROR: unsupported library call operation`으로 종료되는 것을 각각 재현했습니다. 재현용 복사본은 `/tmp/hwpjs-extended-linear-mutant.4XLsD5/icc`에 두었고 제품 소스에서 직접 오류를 주입하지 않았습니다.

bits>128의 근사 변환은 분자/분모를 각각 상위 53비트의 u64와 이진 지수로 분리한 뒤, 지원되는 정수의 f64 변환과 ldexp를 사용하도록 수정했습니다. 두 값을 동일한 폭만큼 잘라 작은 분자를 0으로 만들지 않으며, 최대 u1024를 곧바로 f64로 변환해 무한대가 되는 경우도 피합니다. 0·1·작은 양수 비율을 보존하는 **손실 가능한 근사 API**이지 정확한 비교나 올바르게 반올림된 결과의 보증은 아닙니다. 역상·구간 비교는 이 변환을 호출하지 않습니다. 64/128비트 기존 변환은 그대로입니다.

## 독립 검증

테스트 mode226 입력은 u64 시작/끝 n/d 네 값, flags u32, a/b i32, 목표 n/d u512의 172바이트 BE입니다. 출력은 존재/flags u32와 시작/끝 n/d u1024 네 값의 520바이트 LE이며 null은 전부 0입니다. 기존 mode193 probe와 구간 serializer를 폭별로 공유합니다.

JS 기준은 입력 선형 식의 목표·0·1 임계점 및 사이 구간을 직접 계산하는 기존 독립 기준을 사용합니다. 제품의 반구간 교집합 함수를 기대값으로 가져오지 않습니다. i32 계수 극값, 음의 기울기·상수·열린 단일점, u512 최대 분모와 이웃, 고정 seed 128개 넓은 목표, 잘림·한도·잘못된 구간·오류 후 복구를 검사했습니다. 직접 결과는 comparisons=804, empty=1,971, rejected=1,062입니다. 기존 선형/선택 경로도 1,947/5,110/2,655, chosen=1,337, unattained=674로 통과했습니다.

mode227은 폭 u32 BE+n/d의 정확한 길이를 받고, 256/512/1024비트의 toFloat를 실제 WASM에서 호출해 f64 LE 8바이트를 반환합니다. JS는 반환 IEEE 754 비트를 정확한 BigInt 분수로 복원한 뒤 원래 n/d와 교차 곱하여 표본의 상대 오차≤2^-48을 검사합니다. 제품의 스케일링 계산을 재사용하지 않습니다. 정상 비교 211건과 오류 거부 473건이 통과했으며 모든 정상 반환의 유한성·[0,1] 범위와 양수 보존을 확인했습니다.

## 적대적 검사와 보강

포함 플래그를 모두 닫기, 분자를 0으로 만들기, 분모를 0으로 만들기, 결과 분모의 상위 512비트를 버리기를 각각 ERR_ASSERTION으로 검출했습니다. 변환 결과를 NaN 또는 작은 비율에서 0으로 바꾸는 두 추가 변형도 검출했습니다.

임시 복사본 `/tmp/hwpjs-extended-linear-cross-mutant.M9N4h8/icc`에서 u2048 교차 곱을 u1024로 줄인 소스 변형은 처음 Debug/Safe의 오버플로 검사에 걸렸지만 Fast 테스트는 놓쳤습니다. h=2^1023에서 h/(h+1)>(h−1)/h인 쌍을 추가하여, 교차 곱의 wrap이 반드시 순서를 뒤집는 경우를 검사했습니다. 보강 후 Fast도 예상 gt 대신 lt로 실패했고 정상 제품은 세 모드 모두 신규 5/5 통과했습니다. 초기 예비 감사는 이 보강과 변환 수정을 모두 포함하지 않으므로 최종 결과로 사용하지 않습니다.

실제 시스템 ICC 하위 선형 태그 12개에서 원시 c/d로 [0,d/65536)을 만들고 시작·중간·제외된 끝점의 출력 목표를 정확히 계산했습니다. 목표 분자/분모에 같은 큰 정수를 곱해 u512 범위로 확대한 뒤, 한 점 역상 또는 null을 독립 교차 곱으로 확인한 36건이 일치했습니다. 읽기 전용 수동 검사로 audit 횟수에 합산하지 않으며 전체 프로파일 변환/렌더링 일치 검증이 아닙니다.

## 최종 회귀 결과

수정·보강된 최종 Debug/ReleaseSafe/ReleaseFast audit는 모두 종료 코드 0, 20/20 단계, 네이티브 643/643, WASM checks=6,938,874로 통과했습니다. 이전 6,934,353에 선형 3,837회와 변환 684회, 합계 4,521회 호출이 추가됐습니다. 로그는 `/tmp/hwpjs-extended-linear-{Debug,ReleaseSafe,ReleaseFast}-final.log`이며 임시 로컬 산출물입니다. 중간 상태의 예비 Debug와 중단한 예비 Safe 로그는 최종 결과로 사용하지 않습니다.

Safe/Fast 최종 audit WASM의 직접 대조에서도 신규·기존 선형 검사와 변환 검사 수가 일치했고 출력 변형 6종을 검출했습니다. 교차 곱 폭 축소는 네이티브에서 Debug/Safe 오버플로와 보강 후 Fast 대소 오판으로 검출했습니다. 로컬 문서 링크 7개, Zig 포맷·JS 문법·diff 공백 검사도 확인했습니다.

# 플랫폼별 기능 대응과 API 이전

목표는 Node·Web·CLI·React Native에서 필요한 **읽기·편집·저장·변환·이미지 기능을 공통 엔진과 일관된 API로 제공하는 것**입니다. Rust 버전의 함수명·옵션·반환 형태·동기 호출 방식·모듈 형식·최소 Node 버전을 그대로 복제하는 것은 구현 목표나 필수 검증 기준이 아닙니다. 새 API로 이전할 때에는 기능의 대응 관계와 제한을 명시합니다.

원문 무결성, 안전한 저장, 누락과 미지원의 가시화, 플랫폼별 실제 검증은 계속 필요합니다. 문서 전체 JSON 출력은 요구 범위에서 제외하지만, 메타데이터 조회나 이미지 반환·추출 기능까지 제외하는 뜻은 아닙니다. 현재 `@ohah/hwpjs@0.1.0`은 공개 npm 패키지이며 인증 없는 새 소비자의 실제 설치까지 확인했습니다. 공개 설치가 다른 플랫폼의 기능 검증을 대신하지는 않습니다.

## 네 플랫폼의 현재 기능 대응

| 플랫폼       | 현재 제공하는 경로                                                                                                                          | 확인한 범위                                                                                                                                                                                   | 남은 기능·검증                                                                                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node         | 공개 `@ohah/hwpjs@0.1.0`의 `createEditor`·runtime·공개 타입 선언과 공통 문서 처리 계층                                                      | 격리 패키지의 엄격한 소비자 타입 검사와 HWP5/HWPX 읽기·텍스트 편집·새 파일 저장. 공개 설치 파일 110개의 일치도 확인                                                                           | 소스 내부 함수가 모두 공개 API인 것은 아님. HTML·원본 조판 변환과 모든 형식/개체의 지원 완료로 안내하지 않음                                                                      |
| Web          | 편집기와 문서 시뮬레이션이 공통 엔진을 사용하며 브라우저에서 읽기·편집·다운로드 수행                                                        | 두 형식의 실제 읽기·편집·다운로드와 독립 CFB/XML 저장 검사                                                                                                                                    | 문서 변환과 이미지 조회·추출의 실제 브라우저 경로는 별도 검증. 로컬 Node CLI나 stdio MCP를 실행하는 기능이 아님                                                                   |
| CLI/MCP      | 공개 `hwpjs`·`hwpjs-mcp`: 읽기·배치·정보/개체 조회·이미지 추출·문단 조회·편집·apply 14종·생성·명시 text-only 변환·로컬 OCR 연결. MCP 12도구 | 공개 레지스트리에서 인증 없이 새로 설치한 CLI의 도움말·HWPX 생성·Noori HWP5 편집/재열기와 독립 CFB/XML 검사. 실제 MCP 버전 `0.1.0`·12도구 목록 확인. 앞선 설치/소스 검사는 기능별 범위로 구분 | 표 전체 삭제·이미지 삽입/교체·전체 의미 보존 변환 미지원. 빈 문서에서 누리 전체 재생성 미완료. OCR은 외부 제공자·언어 데이터 필요, 공개 설치에서 OCR 양성을 새로 검증한 것은 아님 |
| React Native | 공개 JavaScript provider·controller·runtime/context와 별도 Canvas 연결 경계                                                                 | 공개 선언과 DOM 의존성 없는 소비자 타입 검사                                                                                                                                                  | 실제 iOS/Android 읽기·편집·저장·변환·이미지 검증 완료가 아님. 기기에 연결된 Native 구현과 기능 경로를 별도로 검증해야 함                                                          |

현재 증거는 제한된 문서와 동작에 대한 결과입니다. 모든 문서·버전·서식의 지원 완료를 뜻하지 않으며, 한 플랫폼의 실행 결과를 다른 플랫폼의 실제 지원으로 대신하지 않습니다.

## 기능별 이전 안내

- 읽기: CLI의 `read INPUT --format text|markdown`은 기본적으로 문서 내용을 표시하며, 정확한 Native 문단 ID·원본 SHA·진단 상세는 `--view structure`로 조회합니다. `read --format markdown`은 논리 읽기 뷰이며, 기존 `toMarkdown` 문서 변환기와 같은 기능이라고 안내하지 않습니다.
- 편집·저장: `edit`에는 읽기 결과의 Native ID와 원본 SHA, 찾을 문자열·대체 문자열·새 출력 경로를 전달합니다. 원본과 기존 출력 파일을 덮어쓰지 않습니다. HWP5의 오래된 조판 정보가 남는 편집은 명시적으로 허용해야 합니다. Node·Web·React Native의 호스트 연결도 원문 식별과 저장 안전성의 같은 기준을 따라야 합니다.
- 메타데이터: 기존 `fileHeader`의 동일한 이름이나 JSON 문자열 반환을 복제할 필요는 없습니다. 새 `info`·`get_document_info` 경로에서 실제 관측값과 미관측·미지원 상태를 구분합니다. 열기 성공만으로 보안 상태나 전체 편집 가능 여부를 단정하지 않습니다.
- 이미지: 공개 `images`·`list_document_images`는 원본 SHA에 연결된 이미지 ID와 상태를 제공합니다. CLI의 `extract-images --output NEWDIR`는 새 디렉터리에, MCP의 `extract_document_image`는 선택한 ID와 SHA 또는 본문의 이미지 참조를 받아 새 파일에 원시 바이트를 저장합니다. 현재 수집 범위는 구역의 그림 참조이며 바탕쪽 그림·이미지 채우기·참조되지 않은 리소스는 제외됩니다. 형식 미인식 데이터는 `.bin`으로 보존하고 이미지 변환이나 픽셀 유효성을 보장하지 않습니다.
- 변환: `convert`·`convert_document`는 명시한 text-only 정책에서 관측 본문 문단·빈줄·Unicode를 HWP5↔HWPX로 이관하며, 서식·표 구조·그림 등 손실을 보고합니다. 기본 정책은 거부이며 전체 보존으로 자동 대체하지 않습니다. HTML·문서 변환용 Markdown과 이미지 포함 방식은 필요한 기능 범위로 남아 있습니다. 기존 옵션과 반환 객체를 그대로 복제할 필요는 없지만, 읽기 뷰나 이미지 자리표시자만으로 변환 기능을 제공했다고 계산하지 않습니다. 아직 없는 기능을 새 API의 지원 목록에 넣지 않습니다.
- 실행 환경: 공개 `0.1.0`의 Node 요구 조건은 `>=24.20.0`이며 모듈은 `ESM`입니다. 기존 `CommonJS` 로더나 동기 함수를 사용하던 호출자는 새 진입점·비동기 수명·오류 처리에 맞춰 이전합니다. 이전 Node 최소 버전이나 호출 형태의 동일성은 필수 기준이 아니며, 실제 지원 환경은 새 API에 맞춰 명시하고 검증합니다.

## 검증 증거를 읽는 기준

기존 Rust 사전 빌드로 Noori HWP5의 HTML·Markdown 변환과 이미지 반환을 실제 확인했습니다. 같은 로컬 바이너리에서 일부 공개 선언과 실제 함수가 일치하지 않는 점도 기록했습니다. 이 과거 결과는 변경하지 않으며, 새 API가 Rust의 모든 동작을 복제해야 한다는 규칙으로 사용하지 않습니다.

공개 레지스트리 설치 검사, 같은 CLI 바이트의 앞선 설치 검사, 기능별 CLI/MCP 소스 검사, 브라우저의 독립 저장 검사, React Native 타입 검사는 각각 다른 범위의 증거입니다. 공개 설치 검사에서 MCP는 초기화 버전과 12도구 목록을 확인했으며 모든 도구 호출을 다시 실행하지 않았습니다. 후속 이미지 출력 예산 검사 역시 합성 파일시스템·수집기를 사용한 경계 검사이며, 실제 대량 파일 저장이나 새 설치 패키지의 검증으로 확대하지 않습니다.

남은 작업은 함수·옵션의 1:1 복제가 아니라, 위 기능의 플랫폼별 누락을 구현하고 새 API의 사용법·지원 환경·제한을 공개하며 실제 실행 경로를 확인하는 것입니다. 과거 비교표와 동등성 감사는 당시 상태의 증거로 보존하고, 현재 구현 목표는 이 문서의 기능 대응 기준을 따릅니다.

## Rust rc.10과 공개 0.1.0 비교

비교 기준은 npm의 실제 `@ohah/hwpjs@0.1.0-rc.10`과 `@ohah/hwpjs@0.1.0`입니다. rc.10의 배포 파일 66개와 대응 Git 태그를 확인하고, 현재 공개 설치본의 110개 파일을 고정했습니다. 개발 중인 초기 셀 본문 일괄 삽입·표 전체 삭제·이미지 바이너리 교체·용량 후처리 후보를 공개 0.1.0의 기능으로 계산하지 않습니다.

### 공개 함수와 기능의 대응

| rc.10의 함수·기능 | 공개 0.1.0의 대응 | 해석 |
| --- | --- | --- |
| `fileHeader(data)` | CLI `info`, MCP `get_document_info`, 공개 editor/runtime의 관측 | 목적을 나누어 제공하며 같은 함수명·JSON 문자열 반환의 호환 API는 없음 |
| `toMarkdown(data, options)` | CLI `read --format markdown`, `read-many`, 별도 이미지 조회·추출 | AI용 논리 읽기 뷰. 기존 `{ markdown, images }` 및 base64/blob·HTML 옵션을 보존하는 변환기의 동등 구현은 아님 |
| `toHtml(data, options)` | 대응 HTML 변환 API 없음 | Canvas 뷰어는 제공하지만 HTML 문자열·CSS·이미지 파일을 내보내는 기존 기능의 해결 또는 동등 지원으로 계산하지 않음 |
| `toJson(data)` | 전체 문서 JSON 출력은 현재 요구 범위에서 제외 | `read --view structure`의 편집용 좌표·진단은 원래 전체 AST 출력과 다름 |
| 기존 `to-html`·`to-markdown`·`to-json`·`batch` CLI 이름 | 새 `read`·`read-many`·`info`·`images`·`extract-images` 등 | 이전 명령은 호환 별칭이 아님. 단순 이름 변경과 의미·옵션 차이를 구분해야 함 |
| HWP 읽기·단방향 변환 | HWP5·HWPX 읽기와 선택·명령·편집·저장 | 지원하는 문서·개체 경계에서 기능 확장. 전체 조판·변환 동치 완료는 아님 |

rc.10은 네 공개 변환/정보 함수를 실제 Native에서 확인했습니다. 새 root의 32개 export에는 상수·클래스·도우미도 포함되므로 이를 32개 문서 처리 기능으로 세지 않습니다. WASM export 14개에서 446개로 바뀐 수치도 ABI 분할 방식이 달라 기능 수나 구현 완성도 비율로 사용하지 않습니다.

새 공개 API는 `createEditor`로 만든 editor의 `load`, `createDocument`, `setSelection`, `dispatchCommand`, `save`, `undo`, `redo`, `queryFormatting`, `getFormattingCapabilities`, 상태·업데이트·오류·명령 콜백과 `dispose` 수명을 제공합니다. 공개 CLI에는 조건부 텍스트 편집과 `apply` 14종, 새 문서 작성, 명시적 text-only 형식 변환, 이미지 자원 도구와 OCR 연결이 있고, MCP는 같은 파일 호스트를 쓰는 12도구입니다. 표 생성·셀 크기와 서식·기존 그림 크기 변경은 제공하지만 표 전체 삭제·그림 삽입과 바이너리 교체는 이 버전에 없습니다.

웹은 공통 WASM과 Worker를 사용하며 Vanilla·React·Svelte를 공개 subpath로 제공합니다. 공개 0.1.0을 실제 설치하고 같은 두 자산만 배치한 각 프레임워크에서 누리 HWP5/HWPX를 여는 여섯 경우를 확인했습니다. 이는 첫 화면 Canvas·Worker 종료 검증이며 전체 페이지 조판·IME·모든 편집의 검증을 대신하지 않습니다. Node는 최소 24.20.0과 ESM으로 바뀌었고, React Native는 새 provider·Canvas 통합 경계와 기기 검증을 별도로 확인해야 합니다.

### 같은 실제 파일 91개의 읽기 결과

2026-11-08 공개 예제 목록 101항목을 원문 SHA로 중복 제거해 91개 파일을 대조했습니다. rc.10은 실제 macOS arm64 Native의 `toMarkdown`, 0.1.0은 공개 CLI `read`와 원본 `82031994…` WASM을 사용했습니다. HWP3와 보호된 파일은 대상에서 제외했고 원본은 변경하지 않았습니다.

| 결과 | HWP5 | HWPX | 합계 |
| --- | ---: | ---: | ---: |
| 양쪽 읽기 성공 | 44 | 0 | 44 |
| 이전 거부·현재 성공 | 1 | 44 | 45 |
| 이전 성공·현재 기본 CLI 거부 | 2 | 0 | 2 |
| 양쪽 거부·실행 중단 | 0 | 0 | 0 |

HWPX 44개는 rc.10이 ZIP 입력을 CFB로 해석하다 거부했고 새 파서에서 읽혔습니다. `latex.hwp`는 rc.10의 EqEdit 레코드 해석 오류로 문서 전체가 거부됐지만 새 CLI는 본문과 미분류 개체 표시를 반환했습니다. 이를 수식 표시·편집 완료로 확대하지 않습니다. 양쪽 성공 44개도 Markdown 변환 결과와 논리 읽기 뷰의 계약이 달라 출력 동치로 판정하지 않았습니다.

`distribution.hwp`와 `viewtext.hwp`는 rc.10에서 읽혔으나 현재 기본 CLI가 `UnsupportedDistribution`으로 거부합니다. 기본 CLI의 지원 누락으로 남기며, Native의 명시적 배포 문서 관측 정책이나 다른 플랫폼 경로까지 미지원이라고 일반화하지 않습니다. 예제 집합의 성공 수는 모든 HWP 버전·손상·암호 문서에 대한 지원율이 아닙니다.

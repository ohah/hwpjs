# 플랫폼별 기능 대응과 API 이전

목표는 Node·Web·CLI·React Native에서 필요한 **읽기·편집·저장·변환·이미지 기능을 공통 엔진과 일관된 API로 제공하는 것**입니다. Rust 버전의 함수명·옵션·반환 형태·동기 호출 방식·모듈 형식·최소 Node 버전을 그대로 복제하는 것은 구현 목표나 필수 검증 기준이 아닙니다. 새 API로 이전할 때에는 기능의 대응 관계와 제한을 명시합니다.

원문 무결성, 안전한 저장, 누락과 미지원의 가시화, 플랫폼별 실제 검증은 계속 필요합니다. 문서 전체 JSON 출력은 요구 범위에서 제외하지만, 메타데이터 조회나 이미지 반환·추출 기능까지 제외하는 뜻은 아닙니다. npm 게시 자체는 수행하지 않습니다.

## 네 플랫폼의 현재 기능 대응

| 플랫폼       | 현재 제공하는 경로                                                                                                                | 확인한 범위                                                                                                                                                                                        | 남은 기능·검증                                                                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node         | `createEditor`와 읽기·편집·저장에 필요한 실행 환경을 연결합니다. CLI의 바이트 기반 엔진도 같은 문서 처리 계층을 사용합니다.       | 격리된 패키지의 설치·엄격한 소비자 타입 검사와 Node에서 실행한 HWP5/HWPX 읽기·텍스트 편집·새 파일 저장을 확인했습니다.                                                                             | HTML·문서 변환용 Markdown API와 이미지 기능의 최종 공개 패키지 제공 범위는 별도 확인이 필요합니다. 소스 내부 함수가 존재한다는 이유로 공개 API라고 안내하지 않습니다. |
| Web          | 편집기와 문서 시뮬레이션이 공통 문서 처리 엔진을 사용합니다. 시뮬레이션은 브라우저에서 읽기·편집·다운로드를 수행합니다.           | 두 형식의 실제 읽기·편집·다운로드와 독립 CFB/XML 저장 결과를 확인했습니다.                                                                                                                         | 문서 변환과 이미지 조회·추출의 실제 브라우저 경로는 미검증입니다. 브라우저가 로컬 Node CLI나 stdio MCP 서버를 실행하는 것은 아닙니다.                                 |
| CLI          | `read`·`edit`와 별도 `hwpjs-mcp` 진입점이 있습니다. 후속 소스에 `info`·`images`·`extract-images` 및 대응 MCP 도구를 연결했습니다. | 기존 설치 패키지의 두 형식 읽기·편집·저장을 확인했습니다. 후속 메타데이터·이미지 명령은 두 형식의 실제 Native 연동 증거가 있으며, 출력 예산 수정은 새 소스 고정본의 독립 집중 검사로 확인했습니다. | 후속 기능이 포함된 새 배포 패키지의 검증은 기존 설치 패키지 증거와 구분합니다. HTML·문서 변환용 Markdown 및 디렉터리 배치 변환은 현재 제공 완료로 안내하지 않습니다.  |
| React Native | 제공자·제어기·실행 환경·문맥 연결 API와 별도 Canvas 진입점이 있습니다.                                                            | 공개 선언과 DOM 의존성 없는 소비자 타입 검사는 통과했습니다.                                                                                                                                       | 이 증거만으로 실제 iOS/Android의 읽기·편집·저장·변환·이미지 기능이 확인된 것은 아닙니다. 기기에서 연결된 Native 구현과 플랫폼별 기능 경로를 따로 검증해야 합니다.     |

현재 증거는 제한된 문서와 동작에 대한 결과입니다. 모든 문서·버전·서식의 지원 완료를 뜻하지 않으며, 한 플랫폼의 실행 결과를 다른 플랫폼의 실제 지원으로 대신하지 않습니다.

## 기능별 이전 안내

- 읽기: CLI는 `read INPUT --format text|markdown`으로 계층과 정확한 Native 문단 ID, 원본 SHA를 표시합니다. `read --format markdown`은 논리 읽기 뷰이며, 기존 `toMarkdown` 문서 변환기와 같은 기능이라고 안내하지 않습니다.
- 편집·저장: `edit`에는 읽기 결과의 Native ID와 원본 SHA, 찾을 문자열·대체 문자열·새 출력 경로를 전달합니다. 원본과 기존 출력 파일을 덮어쓰지 않습니다. HWP5의 오래된 조판 정보가 남는 편집은 명시적으로 허용해야 합니다. Node·Web·React Native의 호스트 연결도 원문 식별과 저장 안전성의 같은 기준을 따라야 합니다.
- 메타데이터: 기존 `fileHeader`의 동일한 이름이나 JSON 문자열 반환을 복제할 필요는 없습니다. 새 `info`·`get_document_info` 경로에서 실제 관측값과 미관측·미지원 상태를 구분합니다. 열기 성공만으로 보안 상태나 전체 편집 가능 여부를 단정하지 않습니다.
- 이미지: 후속 `images`·`list_document_images`는 원본 SHA에 연결된 이미지 ID와 상태를 제공합니다. CLI의 `extract-images --output NEWDIR`는 새 디렉터리에, MCP의 `extract_document_image`는 선택한 ID와 SHA를 받아 새 파일에 원시 바이트를 저장합니다. 현재 수집 범위는 구역의 그림 참조이며 바탕쪽 그림·이미지 채우기·참조되지 않은 리소스는 제외됩니다. 형식 미인식 데이터는 `.bin`으로 보존하고 이미지 변환이나 픽셀 유효성을 보장하지 않습니다.
- 변환: HTML·문서 변환용 Markdown과 이미지 포함 방식은 필요한 기능 범위로 남아 있습니다. 기존 옵션과 반환 객체를 그대로 복제할 필요는 없지만, 읽기 뷰나 이미지 자리표시자만으로 변환 기능을 제공했다고 계산하지 않습니다. 아직 없는 기능을 새 API의 지원 목록에 넣지 않습니다.
- 실행 환경: 현재 후보의 Node 요구 조건은 `>=24.20.0`이며 모듈은 `ESM`입니다. 기존 `CommonJS` 로더나 동기 함수를 사용하던 호출자는 새 진입점·비동기 수명·오류 처리에 맞춰 이전합니다. 이전 Node 최소 버전이나 호출 형태의 동일성은 필수 기준이 아니며, 실제 지원 환경은 새 API에 맞춰 명시하고 검증합니다.

## 검증 증거를 읽는 기준

기존 Rust 사전 빌드로 Noori HWP5의 HTML·Markdown 변환과 이미지 반환을 실제 확인했습니다. 같은 로컬 바이너리에서 일부 공개 선언과 실제 함수가 일치하지 않는 점도 기록했습니다. 이 과거 결과는 변경하지 않으며, 새 API가 Rust의 모든 동작을 복제해야 한다는 규칙으로 사용하지 않습니다.

현재 패키지의 설치 검사, 후속 CLI/MCP 소스 검사, 브라우저의 독립 저장 검사, React Native 타입 검사는 각각 다른 범위의 증거입니다. 후속 이미지 출력 예산 검사 역시 합성 파일시스템·수집기를 사용한 경계 검사이며, 실제 대량 파일 저장이나 새 설치 패키지의 검증으로 확대하지 않습니다.

남은 작업은 함수·옵션의 1:1 복제가 아니라, 위 기능의 플랫폼별 누락을 구현하고 새 API의 사용법·지원 환경·제한을 공개하며 실제 실행 경로를 확인하는 것입니다. 과거 비교표와 동등성 감사는 당시 상태의 증거로 보존하고, 현재 구현 목표는 이 문서의 기능 대응 기준을 따릅니다.

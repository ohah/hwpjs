# GIF 블록·LZW·색인 프레임 복호화

## 범위와 책임

`src/image/gif/document.zig`의 decode는 GIF87a/89a 파일의 블록을 순회하고 각 이미지의 top-down u8 색인 평면을 반환합니다. [PrvImage 조사](hwp5-preview-image-evidence.md)에서 확인한 GIF 입력을 실제로 복호화하는 코어입니다. HWP 컨테이너 연결의 현재 범위와 검증은 [PrvImage 검사](hwp5-preview-image.md)가 소유합니다. 제품 JS 공개 API에는 아직 연결하지 않았습니다.

참조는 [CompuServe GIF89a 원문(W3C 보관)](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)의 본문·부록입니다. GIF 형식과 GIF 서비스 마크의 원 권리자는 CompuServe Incorporated입니다. 외부 구현 코드는 이식하지 않았으며 GPL/LGPL 의존성을 추가하지 않았습니다.

- header: 버전·논리 화면 원값·전역/지역 팔레트 바이트 수의 공통 계산.
- sub_blocks: 길이 접두사와 0 종료자의 경계·공유 하위 블록 한도·빌린 iterator.
- blocks: 이미지/제어/주석/응용/일반 텍스트 블록, 고정 길이, 제어의 적용 범위와 파일 종료. 실패한 next는 모든 순회 상태를 유지합니다.
- code_bits: 하위 블록을 넘는 LSB-first 코드 읽기. 블록 경계에서 비트를 버리지 않습니다.
- lzw: 고정 4,096칸 prefix/suffix 사전·역순 스택과 호출자 sink. 스트림 저장·프레임 배치는 소유하지 않습니다.
- raster: 출력 한도 선검사·색인 범위·인터레이스 행 배치·정확한 픽셀 수. 소유한 색인 버퍼의 해제 책임.
- document: 프레임 배열과 전체 프레임/픽셀/코드 예산의 조립. 일반 텍스트·응용 확장은 진단으로 남깁니다.

테스트 fixture와 네이티브 테스트는 각각 fixtures.zig와 tests.zig로 분리합니다. 독립 JS는 전체 문자열 사전과 비트 위치를 사용하며 Zig prefix/suffix 스택을 복제하지 않습니다. 인터레이스 기대 행은 행 번호의 순위로 정렬해 구합니다.

## 소유권·선택·미지원 경계

Document는 프레임 배열과 각 색인 평면을 소유합니다. 헤더/팔레트/압축 데이터/프레임 원문은 입력 바이트를 빌리므로 Document보다 입력을 먼저 해제하면 안 됩니다. 각 프레임의 색인 버퍼는 별도로 할당합니다. 문서 중간 오류와 프레임 내부 오류 모두 이미 할당한 배열을 정리합니다. 이 단계에서 CFB 해제 이후에도 모든 원문 view가 유효하다고 주장하지 않습니다.

기본 한도는 파일 64 MiB, 블록 100,000개, 비어 있지 않은 하위 블록 1,000,000개, 프레임 10,000개, 전체 색인 픽셀 256 Mi개, 전체 LZW 코드 256 Mi개입니다. 파일 종료자도 블록 한도에 포함하고 각 프레임의 Clear/EOI도 코드 예산에 포함합니다. 프레임마다 전역 한도를 새로 주지 않습니다. 팔레트·descriptor는 입력을 빌리며 사전은 고정 크기입니다. 이 한도들을 합산 peak-memory 상한이라고 표현하지 않습니다.

초기 Clear의 부재는 보존·보고합니다. 코드 폭 3~12비트, KwKwK, 폭 증가, Clear에 의한 재설정과 사전이 찬 뒤 Clear 없이 유지되는 경우를 처리합니다. EOI가 없는 입력과 EOI 뒤 추가 데이터 바이트를 거부하되 마지막 바이트의 사용하지 않은 비트값을 0으로 강제하지 않습니다. 픽셀 수는 선언된 폭×높이와 정확히 같아야 합니다. 0 크기는 자동으로 1로 보정하지 않으며, 이미지가 없는 팔레트 전용 스트림도 처리합니다.

지역 팔레트는 해당 이미지에만 적용하고 다음 프레임은 전역 팔레트를 다시 선택합니다. 두 팔레트가 모두 없으면 색인을 보존하고 colors_resolved=false/unresolved_color_frames로 보고합니다. 검정·흰색 팔레트를 만들어 넣지 않습니다. 팔레트가 있으면 출력 색인 범위를 검사합니다. colors_resolved는 색상표 선택·범위의 증거이며 색 관리·전체 색 의미 검증이 아닙니다.

제어는 주석/응용 확장을 넘어 다음 이미지 또는 일반 텍스트에 적용됩니다. 중복 제어와 적용 대상 없이 끝난 제어는 오류입니다. GIF87a에 89a 전용 확장·필드를 넣으면 InvalidGifVersionFeature, 미지 버전/확장은 별도 미지원 오류입니다. 예약 비트는 검사하지만 disposal 4~7은 원값과 reserved_disposals 진단으로 보존합니다.

일반 텍스트의 격자·문자·색상 의미와 글꼴 선택, 응용 확장의 반복 횟수·기타 프로토콜, 배경색·종횡비 적용, 투명도/배치/disposal의 캔버스 합성, 재생/입력 대기는 미구현입니다. 이들의 블록 경계를 읽었다고 의미 검증·렌더링을 완료했다고 바꾸지 않으며 rendering_deferred는 항상 true입니다. 텍스트/응용 원문은 blocks.Iterator에서 조회할 수 있고, Document는 그 개수만 집계합니다.

## 검증 경계와 실측

테스트 전용 WASM mode 295는 trailing u8 뒤 파일/블록/하위 블록/프레임/픽셀/코드 한도 u32 여섯 개를 받습니다(25바이트). 출력은 문서 20개 u32(80바이트)와 전역 팔레트, 프레임별 18개 u32(72바이트)와 지역 팔레트·색인 바이트입니다. 기존 probe 형식이나 제품 ABI를 바꾸지 않았습니다. probe limit은 직렬화 크기이며 실제 크기를 선계산해 검사합니다.

Debug/ReleaseSafe/ReleaseFast의 네이티브 GIF 필터는 root 포함 11/11개를 통과했습니다. 모든 파일 접두부, sub-block cursor 원자성, 제어 적용, 팔레트 부재, KwKwK, 초기 Clear 부재, height 1~33 인터레이스, 10,000리터럴/12비트 사전 유지, 반복 프레임 공유 예산, 모든 할당 실패와 명시적 오류 경로 할당 회계를 검사합니다.

세 WASM 모드 각각 정상 비교 283·의도한 오류 94건을 통과했습니다. seed 1195984437의 4,000건 변형에서 승인 889/거부 3,111/정상 입력 재검사 63건이며 trap은 0입니다. 오류 종류를 확인하므로 WASM trap이나 JS 오류를 파서의 정상 거부에 포함하지 않습니다. 네 종류 출력의 779바이트를 각각 XOR 1로 변형한 검사와 첫 정상 오류의 RuntimeError 주입을 세 모드에서 모두 검출했습니다.

앞선 PrvImage 조사 범위의 GIF89a 133개(고유 바이트열 110개)를 세 모드에서 독립 JS와 대조했습니다. 모두 단일 프레임이며 색인 픽셀 5,884,250개가 일치했습니다. 기본 fixture 14개/619,500픽셀은 정규 HWP audit에서도 별도로 검사하고 파일·프레임 수를 고정 검증해 실파일 경로가 빠지지 않게 했습니다. 암호화/배포용 문서라도 이 검사는 raw PrvImage만 검사하며 문서 전체 지원으로 세지 않습니다.

추가로 macOS ImageIO를 제3 구현으로 사용했습니다. GIF 133개와 생성 입력 30개(40,733픽셀)의 팔레트 기반 픽셀을 ImageIO의 unscaled RGBA와 바이트 대조했습니다. 생성 입력은 색상 팔레트·작은 인터레이스 높이·모든 코드 폭 전환·가득 찬 사전·Clear 재설정·KwKwK·투명 색인을 포함합니다. 이 비교는 원점에 놓인 단일 프레임과 명시적 팔레트에 한정하며, 애니메이션 캔버스 일치로 확대하지 않습니다. Swift oracle과 JS 비교기는 테스트 전용이며 [개발 명령](development-commands.md)에 별도로 안내합니다.

첫 오류 fixture는 EOI 누락보다 패딩에서 생성된 추가 픽셀 오류가 먼저 발생했습니다. 입력을 분리하여 MissingGifEndCode와 ExcessGifPixels를 따로 검사했습니다. 네이티브 제어 테스트는 명시적인 null 검사를 추가해 ReleaseFast의 unchecked optional unwrap에 검출을 의존하지 않도록 보강했습니다. 이들은 테스트 보강이며 제품 결함으로 세지 않습니다.

격리 소스에서 코드 폭 증가 제거·사전이 찰 때 자동 Clear·인터레이스 무시·팔레트 색인 검사 제거·프레임 내부 오류의 색인 누수·문서 오류의 이전 프레임 누수·주석에서 제어 소실·전체 픽셀 한도 재사용·전체 코드 한도 재사용·파일 꼬리 무시의 10종을 검사했습니다. 보강한 테스트로 세 모드 모두 각 11개 테스트를 실제 실행했고, 실패 수는 순서대로 1/1/1/1/1/2/1/1/1/1개였습니다. 두 누수 변형은 ReleaseFast에서도 expected 0, found 1을 확인했습니다. 컴파일 실패는 검출 수에 포함하지 않았습니다. 근거는 `/tmp/hwpjs-gif-mutants.NRXigB/`의 `*-{Debug,ReleaseSafe,ReleaseFast}-v2.log`입니다.

관련 문서 4개의 로컬 링크 63개와 변경 코드의 포맷·구문·diff 검사를 확인했습니다. 전체 audit를 Debug → ReleaseSafe → ReleaseFast 순서로 실행하여 각 모드 23/23 단계·954/954 네이티브 테스트·7,839,634개 HWP/WASM 검사를 통과했습니다. 실행 셸 종료 코드 0을 확인했으며 로그는 `/tmp/hwpjs-gif-{Debug,ReleaseSafe,ReleaseFast}-audit.log`입니다.

최종 `zig build test --summary all`은 5/5 단계·954/954 테스트, `zig build -Doptimize=ReleaseSafe --summary all`은 5/5 단계로 모두 종료 코드 0입니다. GIF 전부·PrvImage 통합·전체 HWP 문서 검증 완료를 선언하지 않습니다.

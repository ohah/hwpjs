# HWPX 차트 현재값의 혼합 편집 검증

## 계약과 책임

계열 이름과 숫자/문자열 포인트는 서로 다른 주소·명령을 쓰지만 native `chart_resources`의 같은 소유 리소스에 보관한다. JS 조회 결과와 폼 초안은 저장 SSOT가 아니다. 한 종류를 수정한 뒤 다른 종류를 수정해도 앞선 값·비대상 XML·OLE 사본이 보존되어야 한다. 같은 값 요청과 잘못된 입력은 현재 이력 및 남은 redo를 지우지 않아야 한다.

`tests/hwpx/chart-mixed-current-values.test.mjs`는 기존 public adapter와 `hwpx-chart-session-oracle.py`를 재사용한다. 별도 제품 파서나 기대값용 저장기를 만들지 않는다. 원본에서부터 매 단계 직전의 저장본을 독립 oracle의 기준으로 사용하므로 두 번째 변경이 첫 변경을 지우는 경우도 검출한다.

## 2026-10-18 실측

main `601e0091` 기반으로 격리한 차트 native 통합 트리 `764aee5c68e10f05bcd32d6335398d269b9643e4`의 ReleaseSafe WASM 빌드는 5/5 단계 통과했다. SHA256은 `43395302660c8b0ee2178b6b894ebe840dce2fec8802d6822eabe3631e9d0b02`이며 이전 후보 `891fe0a1cb560083251ac50130505dc2dabac57f6ebeaf37f90bc226e76a676a`의 export 327개 이름·종류를 모두 유지한다. 이 정적 검사를 signature·전체 동작 동치로 해석하지 않는다.

새 빌드에서 혼합 편집 선언 1/1, 실패·skip 0(18,805.87ms)이다. RHWP issue6037의 직접 계열 이름 10개 각각에 계열→숫자→문자열 및 문자열→숫자→계열 두 순서를 적용해 거래 20건·변경 상태 60개를 확인했다. 매 단계 모든 이름/포인트 조회·이전 조회 불변·같은 값 요청·잘못된 숫자와 고립 서로게이트 거부를 대조한다. 전체 undo/redo의 저장 바이트, undo 뒤 같은 값 요청의 redo 유지, 최종 재열기·변경 없는 재저장·원본 파일 불변도 확인한다.

Python 일반/-O의 독립 XML/ZIP/OLE 대조 120회와 잘못된 기대값 반례 120회를 실행한다. 최초 검사 설정은 이력 8개×checkpoint 32MiB가 ABI의 128MiB 예약 한도를 넘어 `LimitExceeded`로 거부됐다. 제품 한도를 완화하지 않고 8×16MiB로 검사를 수정했다. 이는 제품 결함 수정이 아니다.

이전 후보 `891fe0a1cb560083251ac50130505dc2dabac57f6ebeaf37f90bc226e76a676a`에서도 같은 혼합 검사 1/1·실패/skip 0(18,922.86ms)이다. 두 후보의 서로 다른 결과 파일을 비교했다는 뜻은 아니며 각 후보에서 같은 독립 oracle·내부 모든 상태 검사를 실행했다.

참조 파일 부재는 명시적 skip이며 성공으로 세지 않는다. 이 검사는 두 편집 순서의 원본 보존을 확인하지만 모든 임의 명령 순서·전체 OOM·브라우저 입력·원본 차트 그림/조판을 증명하지 않는다. native 전체 gate와 기본 WASM 승격은 별도 미완료 항목이다. 실행 명령은 [개발·검증 명령](development-commands.md)이 소유한다.

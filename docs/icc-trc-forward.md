# TRC 순방향 평가 통합

## 계약

`trc_forward.evaluate(curve, x)`는 `trc_tag.Curve`와 정규화된 u64 Fraction을 입력받습니다. identity·gamma·samples·parametric 분기를 연결하며 파싱, 판본별 허용 타입 검사, 프로파일 계산 모델 검증은 기존 계층의 책임으로 유지합니다. 이미 파싱한 Curve를 직접 받으므로 헤더와 판본 일치를 재검증하지 않습니다.

출력 Result는 exact(Fraction)와 approximate(f64)를 구분합니다. identity는 약분 없이 입력 분수를 그대로 반환하고 samples는 기존 [샘플 보간](icc-sampled-forward.md)을 재사용합니다. gamma·parametric은 [수치 평가](icc-analytic-forward.md)를 재사용하며 분수를 f64로 변환한 뒤 계산합니다. 수치적으로 정확히 표현되는 결과도 analytic 경로에서는 approximate입니다. f64 변환 때문에 서로 다른 큰 분수가 동일한 입력값으로 반올림될 수 있으므로 임의 정밀도나 정확한 분기 보존을 보증하지 않습니다.

`fraction.zig`가 분모 0·분자 범위 검사와 명시적인 toFloat 변환을 소유합니다. 샘플 보간도 같은 검사를 호출하며 기존 오류 이름을 유지합니다. 샘플 계산의 분모 상한은 샘플 평가기에만 적용합니다. identity는 u64 최대 분모도 보존하고, 샘플 계산에서 상한을 넘으면 오류를 그대로 전달합니다. 표본을 f64로 변환해 이 제한을 숨기지 않습니다.

평가 함수는 Parsed를 변경하지 않으며 semantics_deferred는 계속 true입니다. 한 점의 평가 성공은 곡선 전체의 단조성·연속성·역함수·필수 태그·행렬 연결·PCS·렌더링 성공을 뜻하지 않습니다. 전체 색상 변환과 제품 JS API 연결은 미구현입니다. 할당하지 않고, 샘플 입력은 평가 중 변경하면 안 되며 반환 결과는 입력 포인터를 보유하지 않습니다.

## 검증 진행

2026-09-08 네이티브 전체 테스트가 5/5 단계, 446/446로 통과했습니다. 신규 테스트는 identity의 약분 없는 보존·u64 상한, 정확/근사 출력 구분, 샘플 분모 제한과 의미 보류 유지입니다. 공유 분수 검사 변경 후 기존 순방향·역방향 테스트도 포함합니다.

WASM mode161/162는 각각 v2_2001/v4_2022 정책으로 파싱한 뒤 같은 평가기를 호출합니다. 네 채널, identity·감마·샘플·para, v2 para 거부, 잘못된 분수·미지원 이름·잘림·한도·복구를 독립 JS 기준으로 검사합니다. 정확 출력은 BigInt 교차 곱, identity는 분자·분모 원형까지 비교하고, analytic은 별도 수식과 절대 오차 2e−12로 비교합니다. 분기 결과와 channel·semantics_deferred·예약 출력 영역도 검사합니다.

새 Debug WASM에서 독립 통합 테스트를 직접 실행해 비교 118건·예상 오류 거부 96건이 통과했습니다. 정규 전체 감사 완료와는 구분합니다.

macOS 기본 프로파일 11개의 TRC 태그 29개에서 입력 j/16(j=0…16)을 적용한 493건을 실제 major에 맞춘 mode161/162와 독립 JS 기준으로 대조했습니다. 채널·의미 보류·정확/근사 분기와 결과가 일치했습니다. 확인한 종류는 gamma·samples·para0·para3이며 identity·para1/2/4의 실파일 근거는 아닙니다. 파일은 읽기 전용으로 사용하고 복제하지 않았으며 공유 데이터는 태그별로 셌습니다. 수동 결과는 자동 감사 수에 더하지 않고 전체 색상 변환·렌더링 증거로 확대하지 않습니다.

Debug·ReleaseSafe·ReleaseFast 전체 감사가 각각 종료 코드 0, 20/20 단계, 네이티브 446/446, 신규 비교 118건·오류 거부 96건으로 통과했습니다. HWP5 감사 검사는 각 4,765,231건이며 반복·변형을 포함한 검사 수이지 지원율이 아닙니다. 로그는 `/tmp/hwpjs-icc-trc-forward-{Debug,ReleaseSafe,ReleaseFast}-final.log`입니다.

최종 적대적 검토에서는 기존 샘플 입력 검사와 오류 이름의 유지, 순방향·역방향 Fraction 별칭의 동일 타입 유지, 정확 경로의 f64 변환 부재와 비할당 결과를 확인했습니다. u64 최대를 M이라 할 때 (M−1)/M과 M/M을 실제 WASM에 입력해 identity가 두 원형을 구분해 반환하고 gamma=1 경로는 둘 다 근사값 1로 반환함을 재현했습니다. 따라서 문서의 analytic 입력 반올림 제한은 실측된 제한이며, 이를 정확 계산이나 동일한 분기 보존으로 표현하지 않습니다. 포맷·JS 문법·diff 공백 검사도 통과했습니다.

# ISO 639 두 글자 코드 조회

## 근거와 원본 확보

[ISO의 데이터베이스 안내](https://standards.iso.org/iso/639/ed-2/en/Access%20to%20the%20databases%20of%20the%20ISO%20639%20Language%20Code.pdf)는 Set 1의 관리 기관을 Infoterm, 공개 호스트를 Library of Congress로 안내합니다. ICC 기술 노트의 두 글자 코드 요구를 확인하기 위해 [LoC 코드 목록](https://www.loc.gov/standards/iso639-2/php/code_list.php)의 ISO 639-1 열을 조사했습니다.

2026-09-08 웹 조회 도구가 반환한 공식 목록의 표 행 12~558 전체(547줄)를 여러 구간으로 수집하고 누락된 줄 번호가 없는지, 겹치는 구간의 내용이 같은지 확인했습니다. 두 글자 열만 추출·중복 제거·정렬한 결과는 183개입니다. 이는 LoC 페이지에 표시된 마지막 갱신일 2026-01-15의 목록입니다. 세 글자 B/T 별칭 행은 같은 두 글자 코드로 중복 집계하지 않습니다. 언어명과 전체 HTML은 저장하지 않았습니다.

데이터의 단일 출처는 `src/text/iso639/alpha2.txt`, 출처·날짜·수집 방식은 `source.json`입니다. 원문 HTTP 요청은 403이었으므로 원문 바이트 SHA-256은 null로 기록합니다. 웹 조회본을 직접 다운로드한 원문이나 오늘 갱신된 목록이라고 주장하지 않습니다. 브라우저에서도 ISO OBP의 보안 확인 화면을 확인했으며 인증 우회·로그인·구매는 하지 않았습니다.

## 조회 계약

`text.iso639.inspect([2]u8)`는 소문자 ASCII 두 글자에 대해 고정 목록의 포함 여부를 이진 검색합니다. 상태는 listed, known_deprecated, not_listed, invalid_syntax로 구분합니다. 대소문자 보정이나 과거 코드를 자동 치환하지 않습니다. not_listed는 이 스냅샷의 목록에 없다는 뜻이지 모든 과거 문서에서 무효라는 뜻이 아닙니다. listed도 현재 시점의 온라인 등록 유효성을 실시간 보증하지 않습니다. `provenance_json`으로 고정 출처 정보를 제공합니다.

[LoC 변경 기록](https://www.loc.gov/standards/iso639-2/php/code_changes.php)에서 직접 확인한 두 항목만 `history.zig`에 보관합니다. bh는 2021-05-25 폐기됐고 권장 식별자는 세 글자 bih입니다. mo는 2008-11-03 폐기됐고 권장 두 글자 식별자는 ro입니다. 특히 이 변경 기록은 기존 mo 사용을 무효로 취급하지 않는다고 설명합니다. preferred는 원문 길이를 유지하는 정적 힌트이며, 두 글자 mluc 필드로 자르거나 문서 바이트를 바꾸지 않습니다.

모든 결과에서 history_complete=false입니다. 기존 IANA 스냅샷의 두 글자 코드 190개와 대조하면 bh/in/iw/ji/jw/mo/sh의 7개가 LoC 183개 목록에 없습니다. IANA 등록부를 현행 ISO 목록으로 대신 쓰지 않습니다. bh/mo 외 항목의 역사와 동의 관계를 이 조회기에서 확정하지 않았습니다. 국가 코드·판본별 유효성·동의 코드 기반 문자열 선택·ICC 전체 locale 의미 검증은 아직 남아 있으며 기존 mluc_selection의 원시 비교와 보류 플래그를 바꾸지 않습니다.

후속 [출처별 이력 대조](iso639-history-evidence.md)에서는 IANA 원본의 동일 해시와 7개 코드의 세부 필드를 확인했습니다. bh/mo의 폐기 날짜 차이와 sh의 단일 대체 코드 부재를 기록하며, 이를 제품의 ISO 이력으로 자동 병합하지 않습니다.

## 책임과 검증

공통 언어 코드 조회는 `src/text/iso639/`에 두고 ICC 태그 구조·문자열 선택·UTF-16 해석을 섞지 않습니다. 데이터 표의 고정 3바이트 행·ASCII·정렬·중복은 컴파일 시 검사합니다. 최초 검증에서 정렬 확인의 기본 comptime 분기 한도 1,000 초과를 확인해 이 검증 블록에 한정하여 10,000으로 늘렸습니다. 런타임 입력 한도를 완화한 것이 아닙니다. 조회는 할당·파일 접근·네트워크 없이 수행하고 반환 문자열은 정적 데이터입니다.

수정 후 Debug 네이티브 검사가 5/5 단계·460/460으로 통과했습니다. 모든 65,536개 바이트 쌍에 대해 제품의 이진 검색과 별도의 선형 문자열 포함 검사를 대조합니다. 대문자·NUL·비ASCII, listed 183개, 권장 코드의 길이·날짜, 미확정 별칭에 임의 힌트를 만들지 않는 점을 검사합니다.

WASM mode168과 JS 독립 Set 조회를 정규 감사에 연결했습니다. JS도 출처 JSON의 개수와 표의 소문자·정렬·중복을 확인합니다. 모든 두 바이트 입력의 상태/권장 코드/날짜/이력 불완전 플래그, 잘못된 길이, 한도, 실패 후 복구를 비교합니다. Debug WASM 직접 실행에서 비교 65,537건·오류 거부 4건이 통과했습니다. 모든 두 바이트 조합의 상태 분포는 listed 183·known_deprecated 2·not_listed 491·invalid_syntax 64,860개였습니다.

고정 표 파일은 549바이트이고 투영 결과 SHA-256은 `646d6b21a18544f9542fdc6e03bcb0b9f415f9746444b06bab15f2d580b051b7`입니다. 원본 HTTP 바이트의 해시가 아닙니다. 실제 IANA 스냅샷과의 집합 차이를 Node로 다시 계산해 위 7개와 일치하고 LoC에만 있는 코드는 없음을 확인했습니다.

macOS 프로파일 6개(ACESCG Linear, DCI(P3) RGB, Display P3, ITU-2020, ITU-709, ROMM RGB)의 desc/cprt 12태그·12레코드 언어 코드를 읽기 전용으로 추출해 WASM 결과와 JS 조회를 대조했습니다. 모두 일치했고 관측된 언어는 en 한 종류입니다. 한국어 등 다른 언어의 실파일 검증, 국가 코드나 표시 결과의 검증으로 확대하지 않습니다. 시스템 파일은 복제하지 않았고 수동 대조는 정규 감사 수에 더하지 않습니다.

Debug 전체 감사는 `/tmp/hwpjs-iso639-Debug-first.log`에서 종료 코드 0, 20/20 단계·460/460 네이티브 테스트·WASM 4,904,909개 검사로 통과했습니다. 제품 코드와 테스트는 해당 감사 시작 후 변경하지 않았습니다. ReleaseSafe·ReleaseFast 전체 감사도 `/tmp/hwpjs-iso639-{ReleaseSafe,ReleaseFast}-final.log`에서 각각 종료 코드 0, 20/20 단계·460/460 네이티브 테스트·WASM 4,904,909개 검사로 통과했습니다. 신규 비교 65,537건·오류 거부 4건과 상태 분포도 세 모드에서 일치했습니다. 이번 고정 목록 조회의 추가 결함은 최종 적대적 검토에서 발견하지 못했으나, 공개 JS 문서 API나 ICC locale 검증 완료로 승격하지 않습니다.

추가 적대적 검증에서 제품 lookup/history/source 파일을 임시 폴더 `/tmp/hwpjs-iso639-guards.KjXuWU`에 복사하고 표만 변형해 컴파일 단계의 거부를 실측했습니다. 정상 두 행은 네이티브 1/1 테스트로 통과했고, 중복·역순·대문자·잘못된 구분자·짧은 행 5개는 각각 의도한 진단으로 컴파일에 실패했습니다. 실제 제품 표는 변경하지 않았습니다. 이 수동 검사는 정규 감사 수에 더하지 않습니다. 최종 코드 검토에서는 고정 2바이트 입력·정적 반환 힌트·이력 불완전 표시·조회/선택 정책 분리를 확인했고, 포맷·JS 구문·diff 공백 검사도 통과했습니다.

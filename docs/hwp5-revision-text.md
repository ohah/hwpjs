# 관측 변경 추적 묶음 텍스트 조립

[병합 소유권](hwp5-revision-groups.md) · [문단 바이트 변환](hwp5-revision-projection.md) · [원본 대조](hwp5-merged-line-cache.md)

## API와 책임

`hwp5.revision_text.collectObserved(allocator, tree, index, options)`는 같은 변경되지 않은 Tree에서 생성한 병합 Index를 받아 묶음별 UTF-16 바이트와 문단별 대응 위치를 반환합니다. 병합 표식·흐름 소유권·삭제 종류를 재해석하지 않고 기존 인덱스와 `revision_projection.projectObserved`를 사용합니다. 임의로 조작한 Tree/Index를 복구하는 API가 아닙니다.

문단 직접 자식과 중복은 `paragraph_children.collect`, 선언된 글자 모양·줄·범위 개수는 `Metadata.validateCounts`, 범위 위치는 기존 변환기가 재사용하는 `Range.validateBounds`가 소유합니다. `Metadata.validate`도 같은 개수 함수를 사용하므로 기존 전체 메타데이터 검사의 오류 조건은 바뀌지 않습니다. 이 조립 경로에서는 리소스 ID·줄 시작 위치·필드 참조 전체를 검사하지 않습니다.

기본 부재 텍스트 정책은 reject입니다. 명시적인 `options.paragraph.missing_text=.observed_cr`만 관측 CR 후보를 사용합니다. 값과 제한의 세부 의미는 문단 변환 계약이 소유합니다. 기본 문서/컨테이너 ViewText 검사와 제품 JS API에 자동으로 연결하지 않습니다.

## 결과 소유권과 좌표

Report는 Group/Member 배열과 모든 결과 텍스트를 소유하며 `deinit`으로 해제합니다. 입력 Tree·인덱스·원시 파일을 해제한 뒤에도 결과 바이트와 scalar 정보를 사용할 수 있습니다. 원본 노드 번호는 출처 식별자이며 Tree를 해제한 후 그 번호로 원문에 접근할 수 있다는 뜻은 아닙니다.

Group은 선두 노드·흐름·문단 수·선언 유닛 합·결과 text를 보존합니다. 빈 결과를 가진 묶음도 삭제하지 않습니다. Member는 원본 문단 노드·묶음 인덱스·원본/결과 문단 길이 및 두 시작 위치를 가집니다.

- `source_start`: 해당 묶음의 **선언 길이 기준** 원본 문단 시작(u64).
- `projected_start`: 해당 묶음의 **변환 후 UTF-16 코드 유닛 기준** 문단 시작(u64).

같은 묶음의 문단이 중첩 문단 때문에 배열에서 떨어져 있어도 group_index와 결과 시작 위치로 정확히 배치합니다. 원본과 결과의 문단 길이가 다를 수 있으므로 두 시작 위치 차이를 모든 문자에 적용하는 선형 변환은 불가능합니다. **문단 내부 삭제 구간·임의 문자·줄 캐시 좌표의 매핑은 아직 제공하지 않습니다.** 원시 코드 유닛 출력의 토큰/Unicode/저장 가능성 제한은 기존 문단 변환 계약과 같습니다.

## 공유 예산과 실패 정리

기본 전체 입력 텍스트 64MiB·전체 출력 64MiB·전체 범위 100,000개를 모든 문단이 공유합니다. 각 문단에는 `min(문단별 한도, 전체 남은 예산)`을 전달합니다. 문단마다 예산을 초기화하지 않으며 원본이 없는 명시적 CR 후보도 입력 2바이트를 소비합니다. 범위 예산은 종류와 무관한 실제 범위 개수입니다. 전체 한도를 키워도 더 작은 문단별 제한은 유지됩니다.

변환된 문단 조각을 임시 보유하고 묶음별 정확한 크기를 계산한 뒤 결과 버퍼를 할당합니다. 큰 선언 유닛 합으로 버퍼를 만들지 않습니다. 복사 중 문단 조각과 최종 묶음 텍스트가 함께 존재할 수 있어 텍스트 payload 메모리의 정점은 출력 합의 약 두 배이고, 별도로 배열·할당자·Tree/Index 메모리가 필요합니다. payload 한도를 전체 프로세스 메모리 상한으로 설명하지 않습니다. 정렬된 범위 처리 외 조립은 노드/문단/묶음 수 및 복사 바이트에 선형입니다.

오류가 나면 이미 변환한 조각·부분 결과 텍스트·두 보고서 배열을 모두 해제하고 부분 성공 Report를 반환하지 않습니다. Index/Tree는 호출자가 계속 소유하며 입력을 변경하지 않습니다.

## 실제 검증

테스트 mode 102는 버전·세 전체 한도·CR 정책과 decoded Section을 받아 기존 Tree/Groups/Flows/Index 및 조립 코어를 호출합니다. 보고서에는 개수·소비 예산, 각 묶음의 원문 출처와 텍스트, 문단별 두 좌표가 들어갑니다. 제품 공개 ABI와 구분합니다.

`revision-text.mjs`는 기존 독립 병합 oracle과 코드 유닛 마스크를 공유해 **전체 보고서 바이트**를 대조합니다. 같은 병합 판단을 새 테스트에 다시 복제하지 않습니다. 실제 결과는 다음과 같습니다. 입력 바이트에는 부재 텍스트의 명시적 CR 후보가 포함됩니다.

| 문서·스트림 | 문단 / 묶음 | 입력 바이트 | 출력 바이트 | 범위 |
|---|---:|---:|---:|---:|
| issue5169 BodyText | 228 / 228 | 7,200 | 7,200 | 0 |
| issue5169 ViewText | 590 / 524 | 20,634 | 16,514 | 702 |
| task2070 BodyText | 53,448 / 53,448 | 810,642 | 810,642 | 0 |
| task2070 ViewText | 53,448 / 53,448 | 810,674 | 810,674 | 1 |

issue5169의 루트 99묶음 결과는 원본 BodyText 루트 99문단과 순서·바이트가 같습니다. 하지만 ViewText 전체 524묶음이 BodyText 전체 228문단으로 변환된 것은 아니며 중첩 개체 구조·모양까지 같은 문서로 변환한 것도 아닙니다.

합성 검사는 중첩 흐름의 비연속 문단 조립, 문단 사이 공유 예산, 세 종류 메타데이터 개수와 늦은 오류, 부재 정책, 빈 입력/빈 텍스트/전체 삭제, 미지 레코드로 인한 노드 위치 이동을 검사합니다. 실파일의 세 정확한 전체 예산과 한 단위 부족, 오류 뒤 보고서 복구를 확인합니다. 네이티브 테스트는 입력·Tree·Index를 먼저 해제한 후 출력 소유권을 확인하고 성공·늦은 출력 한도 오류의 모든 할당 실패를 검사합니다. 문서와 스냅샷은 수정하지 않습니다.

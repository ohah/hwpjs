# 넓은 ICC 기호근의 정확한 순서

## 계약과 책임

`normalized_root_order.compare`는 같은 인코딩의 역지수 p/q를 가진 두 기호근을 정확히 비교합니다. 양수 radicand n/d의 교차곱을 u512로 계산하므로 u256 최대 입력의 곱도 손실 없이 보존합니다. 양의 지수는 크기 순서를 유지하고 음의 지수는 뒤집습니다. 음수 근이면 다시 뒤집습니다. 근의 실제 거듭제곱이나 부동소수점 근사는 계산하지 않습니다.

두 비영 근의 p/q가 다르면 부호가 달라도 IncompatibleIccPowerRoots입니다. 서로 다른 지수의 일반 대수적 수 비교는 범위 밖입니다. 0은 모든 유효한 근과 비교할 수 있지만 양쪽 입력 검증보다 먼저 반환하지 않습니다. inAffine은 기울기가 음수이면 순서를 뒤집고 0이면 NonIsolatedIccAffineRoot를 먼저 반환합니다. 같은 affine 변환을 공유하는 두 근에만 적용합니다.

기존 power_root_order는 power_level.widen을 통해 이 비교를 재사용합니다. widen은 기존 분자 한도 4294967295를 검증한 뒤 고정 분모 65536을 명시하는 무손실 변환입니다. 기존 근 대 유리수 비교도 이 어댑터를 공유합니다. 기존 입력 한도를 넓히거나 오류 계약을 바꾸지 않습니다.

이 모듈은 내부 비교 기반입니다. 전체 역상의 최솟값·최댓값 조립, 열린 끝점의 실제 도달 여부, F.1 선택과 최근접 출력 판정은 아직 구현 범위에 포함하지 않습니다.

## 검증

네이티브 552/552가 통과했습니다. 신규 테스트는 전체 폭의 인접 분수 (M−1)/M과 (M−2)/(M−1), 동치 분수, 부호·역지수·최소 i32 기울기, 잘못된 분자·분모·지수, 부호 조기 반환 방지, 기존 분자 한도 보존을 검사합니다. 여기서 M=2²⁵⁶−1이며 첫 분수의 교차곱이 정확히 1 더 큽니다. 이 사례는 하위 비트 손실이나 부동소수점 비교로 동등 처리하는 결함을 겨냥합니다.

분자·분모 1..8의 모든 쌍과 부호·역지수 조합 16,384건도 작은 정수의 정확한 분수 순서와 대조합니다. 신규 테스트는 네이티브 검사이며 새 WASM 공개 API나 probe 모드를 추가하지 않았습니다.

임시 소스 복사본에서 음의 지수 반전을 제거하는 변형과, 교차곱을 비교하기 전 하위 128비트를 버리는 변형을 각각 실행했습니다. 두 경우 모두 신규 테스트 3개 중 2개가 실패하며 종료 코드 1로 검출됐습니다. 제품 파일에는 변형을 적용하지 않았습니다. 로컬 재현 로그는 `/tmp/hwpjs-wide-order-mutation-{sign,bits}.log`이며 임시 파일입니다.

## 최종 감사

Debug·ReleaseSafe·ReleaseFast 전체 audit가 각각 종료 코드 0, 20/20 단계, 네이티브 552/552, WASM checks=6,557,470으로 통과했습니다. 기존 WASM 경로를 공통화했으며 신규 probe 호출은 없으므로 WASM 건수는 이전과 같습니다. 로그는 `/tmp/hwpjs-icc-wide-order-{Debug,ReleaseSafe,ReleaseFast}.log`입니다.

신규 네이티브 테스트 3개를 ReleaseSafe·ReleaseFast에서 별도로 실행해 모두 통과했습니다. 하위 비트 손실 변형은 두 Release 모드에서도 각각 2개 실패로 검출됐습니다. Zig 포맷·diff 공백·변경 문서 로컬 링크 3개를 확인했습니다. 적대적 재검토는 입력 검증 선행, 기존 범위와 오류 유지, 최대 교차곱 폭, 음의 지수·음수 근·음의 affine 기울기 반전, 0 기울기 오류를 대상으로 했고 추가 결함은 발견하지 않았습니다. 전체 문서 검증이나 역변환 완성을 주장하지 않습니다.

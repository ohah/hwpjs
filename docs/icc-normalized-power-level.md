# ICC 정규화 목표값의 거듭제곱 기호근

## 범위

`normalized_power_level.solve(g, offset, n, d)`는 정규화 u128 목표값 n/d에 대해 `z^(g/65536)+offset/65536=n/d`의 정확한 실수 **밑 변수 z** 해를 보존합니다. [기존 signed 16.16 수준 해](icc-power-level.md)와 달리 목표값을 i32로 재양자화하지 않습니다. [선형 분기의 u128 역상 입력](icc-linear-preimage.md)과 같은 목표값 폭을 다루기 위한 준비 단계입니다.

이 결과는 아직 x 좌표·활성 구간의 역상·출력 클리핑 후 역상·선형/거듭제곱 합집합이 아닙니다. a=0인 상수 밑과 근의 위치는 [활성 구간 위치](icc-normalized-root-locations.md)가 [넓은 근의 좌표 비교](icc-normalized-root-compare.md)를 사용해 처리합니다. y=0/1 클리핑 평탄 구간과 전체 역상 선택은 후속 범위입니다. 새 넓은 Root를 기존 좁은 power_root_compare에 축소해서 전달하지 않습니다.

## 표현과 정확성

먼저 공통 정규화 분수 검증으로 d=0과 n>d를 거부합니다. 부호 있는 목표 차이 `N=65536*n-offset*d`와 양의 분모 `D=65536*d`를 i256/u256으로 계산합니다. 32비트 계수와 u128 목표 입력에서 |N|<2^160, D<2^144이므로 손실 없이 들어갑니다.

반환값은 all_nonzero 또는 최대 두 Root의 finite 배열입니다. all_nonzero는 g=0이고 N/D=1일 때의 모든 **0이 아닌 실수 밑**이며 모든 x가 해라는 뜻은 아닙니다. finite의 count=0은 해 부재입니다. Root.zero는 영점이며, 비영 근은 부호와 양수 크기 `(numerator/denominator)^(exponent_numerator/exponent_denominator)`를 담습니다. numerator=|N|, denominator=D, 역지수 분자는 ±65536, 양의 분모는 abs(g)입니다. 두 근이면 양수·음수 순서이고 x 좌표순 정렬은 아닙니다. count 밖 배열은 읽지 않습니다.

실제 거듭제곱이나 f64 계산을 하지 않으므로 √(1/3) 같은 무리수를 그대로 표현합니다. 목표값이 정규화됐다고 밑 근이나 radicand가 [0,1]에 있다고 가정하지 않습니다. 타입 자체의 Radical.validate는 양의 u256 radicand 성분과 유효한 역지수 필드를 검사하며, 특정 원본 곡선의 해임이나 활성 범위 포함을 인증하지 않습니다.

u128을 넘는 성분은 단순히 약분하지 않아서 생기는 현상만이 아닙니다. d=2^128−1, n=floor(d/2), offset=1이면 생성 N/D가 서로소인데도 분자·분모 모두 u128보다 큽니다. 이를 u128이나 기존 고정 분모로 좁힐 수 없습니다.

## SSOT와 기존 경로

power_level_shape가 g=0·영점·우변 부호·정수 지수 홀짝에 따른 근의 부호/개수와 역지수 생성을 소유합니다. 기존 power_level과 새 normalized_power_level은 입력 표현을 이 공통 판정에 맞추고 각 Root 레이아웃으로 옮기는 어댑터입니다. fixed16_exponent의 지수 분류도 계속 공유합니다.

공통 Reciprocal.validate가 ±65536 분자와 1..2147483648 분모의 검증을 소유합니다. @abs(g)의 unsigned 결과를 사용해 i32 최솟값의 역지수 분모도 보존합니다. 공통 shape 함수의 양의 분모 전제는 기존 경로의 상수 65536과 새 경로의 선행 목표값 검증이 보장합니다. 출력은 고정 크기이고 코어는 할당·입력 변경을 하지 않습니다.

기존 power_level의 공개 타입·20바이트 테스트 Root wire·결과 순서·오류 계약은 유지합니다. 기존 원시 입력의 target-offset 범위는 계속 i64 안에 있습니다. 기존 비교·위치·클리핑·전체 방향 경로가 이 공통화의 회귀 검사 대상입니다.

## 검증

네이티브 검사는 √(1/3)의 두 부호, 음의 지수와 음수 우변, 비정수 지수의 음수 밑 제외, 영점·음의 지수, g=0에서 정확한 값 및 u128 분자 ±1 이웃, 서로소의 넓은 radicand, i32 극값 지수/오프셋, 잘못된 목표값·근 필드를 포함합니다.

독립 JS 기준은 BigInt 유리수로 목표 차이를 계산하고, 원래 정수 지수의 홀짝과 우변 부호로 전체 실근 부호 집합을 확인합니다. 각 반환 radicand의 정확한 비율·양의 분모·역지수 필드·zero 슬롯을 검사합니다. 새 제품 shape 결과를 기대값으로 사용하지 않습니다. 고정 seed 512개 u128 목표값, 최대 분모와 g=0의 인접 값, 잘림·과잉·크기 제한·오류 후 복구를 포함합니다. 기존/새 어댑터의 175쌍(350회 호출) 대조는 호환성 근거이며 공통 shape의 독립 검증으로 세지 않습니다.

WASM mode195는 g/offset i32 BE와 n/d u128 BE의 40바이트를 입력받습니다. 출력은 kind u32 LE(0 finite, 1 all_nonzero)·count u32 LE 다음 Root당 76바이트입니다. sign i32, numerator/denominator u256, 역지수 분자 i32·분모 u32 순서이며 zero 슬롯은 전체 0입니다. 최대 출력은 160바이트입니다. 제품 JS API에는 노출하지 않습니다.

## 실행 기록

공통화 후 기존 네이티브 526개가 통과했습니다. 신규 Debug WASM 직접 대조는 comparisons=1412, rejected=45, roots=1198, bridges=350으로 통과했습니다. roots는 반환 근 구조 개수이고 추가 호출 수가 아닙니다. 넓은 radicand 분모를 u128로 자르는 임시 반환값 변형을 ERR_ASSERTION으로 검출했습니다. 제품에는 변형을 남기지 않았습니다.

추가 오류 주입에서는 정규화 목표값을 16.16 격자로 내림 양자화하는 변형, g=0의 목표값 이웃을 정확한 all_nonzero 해로 바꾸는 변형을 각각 ERR_ASSERTION으로 검출했습니다. 형식상 유효한 기호식이어도 원래 목표값의 해가 아니면 통과하지 않습니다.

실제 시스템 ICC para TRC 태그 15개(type0/type3)에서 원시 g를 읽어 정규화 목표값 다섯 종류를 적용했습니다. 해당 유형의 상위 오프셋은 0이므로 radicand 비율을 목표 n/d와 직접 대조하고 역지수 분모가 원시 g인지 확인했습니다. 75건이 일치했습니다. 읽기 전용 수동 검사이며 정규 감사 수에 합산하지 않습니다. 실제 x 역상·활성 구간·클리핑이나 전체 프로파일 역변환 검증은 아닙니다.

## 최종 회귀·적대적 검증

Debug·ReleaseSafe·ReleaseFast 전체 audit가 각각 20/20 단계, 네이티브 530/530, WASM checks=6,519,806으로 통과했습니다. 로컬 실행 로그는 `/tmp/hwpjs-icc-normalized-power-level-{Debug,ReleaseSafe,ReleaseFast}.log`이며 임시 파일이므로 영구 산출물은 아닙니다. 세 모드 모두 신규 결과는 comparisons=1412, rejected=45, roots=1198, bridges=350입니다.

ReleaseFast 산출물을 직접 인스턴스화한 재검사도 같은 결과였습니다. 두 근 중 음의 근을 제거하고 출력 길이·count까지 맞추는 임시 반환값 변형을 ERR_ASSERTION으로 검출했습니다. 단순 wire 일관성이 아니라 근 집합의 완전성을 검사하는 근거이며 제품 파일에는 변형을 남기지 않았습니다.

최종 코드 검토에서는 목표값 선행 검증, i256/u256 연산 폭, i32 최솟값의 unsigned 절댓값, count 안에서만 초기화된 슬롯 접근, 공통 부호/개수 판정과 표현 어댑터의 책임 분리를 확인했습니다. 이 검증은 본 모듈과 기존 경로의 회귀 범위에 한정되며, 넓은 근의 좌표 비교·활성 구간 연결이나 전체 ICC 역변환 완료를 뜻하지 않습니다.

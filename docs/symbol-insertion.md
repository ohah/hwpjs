# 문자표와 기호 삽입

문자표는 범주별 기호를 고르거나 넣을 문자를 입력하는 독립 모달입니다. 기호 버튼은 선택만 바꿉니다. `넣기`를 누르거나 그 버튼에서 Enter를 누르면 현재 문서에 한 번 삽입합니다.

## 선택과 입력

문자표를 열 때 관측한 선택 대상과 버전을 사용합니다. 삽입은 기존 `SPLICE_TEXT_COMMAND` 한 개로 요청하며 별도 문서 모델이나 이력을 만들지 않습니다. 입력 위치나 문서가 바뀌면 이전 선택을 재사용하지 않습니다. 읽기 전용·보호 구간·지원하지 않는 원본 대상은 기존 core/Native 검증 결과에 따라 거부합니다.

조합 문자와 astral 문자를 지원하며 짝이 맞지 않는 UTF-16 서로게이트, 제어 문자, 빈 입력은 거부합니다. 한 번에 최대 64 UTF-16 단위를 받습니다. 글꼴에 없는 기호까지 표시할 수 있다는 뜻은 아닙니다. 표준 문자열 유효성 API가 없는 환경에서는 넣기를 비활성화합니다.

Tab과 Shift+Tab은 모달 안에서 이동합니다. Escape와 취소는 편집하지 않고 창을 닫습니다. 정상 삽입 뒤에는 검증된 최신 caret으로 복귀합니다. 실제 열린 창의 문서가 유지되는 경우에만 포커스를 반환합니다. 조합 중 Enter/Escape나 중복 클릭으로 명령을 추가 접수하지 않습니다.

## 삽입 결과와 커서 복원

Native에서 삽입이 반영된 뒤 커서 복원만 실패할 수 있습니다. 이 경우 삽입 완료와 위치 확인 필요를 따로 알리고 창을 닫습니다. 이를 미반영 실패로 표시하거나 같은 삽입을 자동 재시도하지 않습니다. 새 사용자 선택이나 다른 문서의 위치를 덮어쓰지 않습니다. 반영 후 snapshot 확인이 필요한 상태도 일반 거부와 구분합니다.

## 저장과 검증 범위

HWP5와 HWPX의 실제 Canvas에서 조합·astral 기호 삽입, undo/redo, 편집본 저장과 재열기를 검증했습니다. HWP5는 편집 뒤 `LayoutReflowRequired`로 기본 저장이 거부될 수 있습니다. 필요한 경우 기존 저장 정책의 명시적 `allowStaleLayout` 선택을 사용하며, 문자표가 이를 자동으로 허용하지 않습니다.

단위 테스트의 editor/DOM 모의 계약과 실제 Native/Canvas 검증은 다른 근거입니다. IME 검사는 합성 이벤트의 조합·229 차단 범위이며 OS IME 실입력 검증은 아닙니다. 모든 문서·보호 영역·기호·브라우저나 한컴 문자표 전체와의 동등성을 뜻하지 않습니다. 공개 번들 배포와 npm 발행은 소스 지원과 별도로 확인합니다.

[헤드리스 API 범위](headless-api-coverage.md)와 [개발·검증 명령](development-commands.md)을 함께 참고합니다.

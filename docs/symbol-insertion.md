# 문자표와 기호 삽입

문자표는 범주별 기호를 고르거나 넣을 문자를 입력하는 독립 모달입니다. 입력 buffer는 빈 값으로 시작하며 기호 버튼을 누르면 현재 buffer 끝에 그 기호를 누적합니다. 현재 선택한 기호 표시는 buffer와 별도로 유지합니다. `넣기`를 누르거나 그 버튼에서 Enter를 누르면 현재 문서에 한 번 삽입합니다.

## 선택과 입력

문자표를 열 때 관측한 선택 대상과 버전을 사용합니다. 삽입은 기존 `SPLICE_TEXT_COMMAND` 한 개로 요청하며 별도 문서 모델이나 이력을 만들지 않습니다. 입력 위치나 문서가 바뀌면 이전 선택을 재사용하지 않습니다. 읽기 전용·보호 구간·지원하지 않는 원본 대상은 기존 core/Native 검증 결과에 따라 거부합니다.

조합 문자와 astral 문자를 지원하며 짝이 맞지 않는 UTF-16 서로게이트, 제어 문자, 빈 입력은 거부합니다. 한 번에 최대 64 UTF-16 단위를 받습니다. 누적 결과가 상한을 넘거나 유효하지 않으면 기존 buffer를 보존하고 오류를 표시합니다. 입력 문자를 직접 편집할 수도 있습니다. 글꼴에 없는 기호까지 표시할 수 있다는 뜻은 아닙니다. 표준 문자열 유효성 API가 없는 환경에서는 넣기를 비활성화합니다.

Tab과 Shift+Tab은 모달 안에서 이동합니다. Escape와 취소는 편집하지 않고 창을 닫습니다. 정상 삽입 뒤에는 검증된 최신 caret으로 복귀합니다. 실제 열린 창의 문서가 유지되는 경우에만 포커스를 반환합니다. 조합 중 Enter/Escape나 중복 클릭으로 명령을 추가 접수하지 않습니다.

## 삽입 결과와 커서 복원

Native에서 삽입이 반영된 뒤 커서 복원만 실패할 수 있습니다. 이 경우 삽입 완료와 위치 확인 필요를 따로 알리고 창을 닫습니다. 이를 미반영 실패로 표시하거나 같은 삽입을 자동 재시도하지 않습니다. 새 사용자 선택이나 다른 문서의 위치를 덮어쓰지 않습니다. 반영 후 snapshot 확인이 필요한 상태도 일반 거부와 구분합니다.

## 누적 입력과 화면 배치 후보

현재 후보는 최대 780px 폭의 대화상자에서 범주 선택 영역과 문자 선택 영역을 분리하고 좁은 화면에서는 재배치합니다. 범주 이름과 순서는 공식 reference의 16범주를 반영합니다. 문자 집합은 자체 선정한 Unicode17 데이터 1621항목·1615고유값이며 기존 43개를 보존합니다. 공식 글리프 집합 전체와 동등하다는 뜻은 아닙니다. 최근 문자 목록과 격자 키보드 탐색은 제공하지 않습니다. 공식 reference의 전체 DOM 16범주·초기 가시15 및 빈 buffer→※→※※·넣기 뒤 창 닫힘과 본문 삽입 관측은 별도 비교 근거입니다. 범주 명칭·순서와 누적 동작을 반영해도 공식 전체 문자표·글리프·배치·최근 문자 기능과 동등하다고 주장하지 않습니다. 후속 HWP5의 실제 폭·포커스·Canvas 확인은 아래 한정 검증과 구분합니다.

이전 source hardening의 실제 Core 경계 1건을 포함한 집중 40건은 별도 근거입니다. 16범주 후속 후보는 46건 통과·lint/format/선택 strict 오류0이며, 기존 대조는 37통과·명시3실패·module error1로 같은46건의 일대일 대조가 아닙니다. 두 세대의 시험 수를 합산하지 않습니다. 안정적인 범주 ID는 private Map으로 조회하고 선택한 범주의 최대261항목만 그립니다. Unicode 고지 주석만 바꾼 후속 소스는 실행 코드 동일이며, 최종 minified JS의 전체 고지 보존은 아직 별도 빌드 확인 대상입니다. 실제 Core 사용을 Native·Worker·브라우저 실행으로 확대하지 않습니다. 읽기 전용·stale·UTF-16·조합 중 중복 요청 거부와 한 번의 기존 splice 위임을 유지하며, 아래 기존 Canvas 성공을 이 새 누적 UI 후보의 검증으로 승계하지 않습니다.

## 저장과 검증 범위

HWP5와 HWPX의 실제 Canvas에서 조합·astral 기호 삽입, undo/redo, 편집본 저장과 재열기를 검증했습니다. HWP5는 편집 뒤 `LayoutReflowRequired`로 기본 저장이 거부될 수 있습니다. 필요한 경우 기존 저장 정책의 명시적 `allowStaleLayout` 선택을 사용하며, 문자표가 이를 자동으로 허용하지 않습니다.

단위 테스트의 editor/DOM 모의 계약과 실제 Native/Canvas 검증은 다른 근거입니다. IME 검사는 합성 이벤트의 조합·229 차단 범위이며 OS IME 실입력 검증은 아닙니다. 모든 문서·보호 영역·기호·브라우저나 한컴 문자표 전체와의 동등성을 뜻하지 않습니다. 공개 번들 배포와 npm 발행은 소스 지원과 별도로 확인합니다.

[헤드리스 API 범위](headless-api-coverage.md)와 [개발·검증 명령](development-commands.md)을 함께 참고합니다.

## 현재 누적 UI 후보의 HWP5 검증

B1 r4에서 빈 buffer의 ※ 두 번 누적으로 ※※를 만들고 넣기 한 번, 실제 painted caret2→4, undo 한 번의 원문 proxy SHA·caret2, redo 한 번의 삽입 proxy SHA·caret4와 focus를 확인했습니다. 취소 전후 문서 proxy도 불변이었습니다. 이는 문서 전체 저장 bytes나 Native 이력 수 직접 관측과 다릅니다.

HX B2 초기 두 시도는 disk preflight 중단으로 Chrome0·Native0이며 따로 보존합니다. 후속 한 cohort에서는 텍스트99→※※ 삽입101→undo99→redo101과 proxy SHA, painted caret2→4→2→4·focus·취소 불변·16ID·기본 bounds를 확인했습니다. 복원은 해당 UI proxy 관측이며 저장 파일 전체 바이트 검증이 아닙니다.

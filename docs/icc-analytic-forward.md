# ICC 감마·파라메트릭 순방향 평가

## 계약과 현재 범위

[ICC.1:2022 §10.6·§10.18 Table 68](https://www.color.org/specifications/ICC.1-2022-05.pdf)을 기준으로 `gamma_forward`는 u8Fixed8 감마, `parametric_forward`는 기존 파서의 s15Fixed16 파라미터와 함수 0–4를 평가합니다. 원시 파서의 계약은 변경하지 않습니다. 입력은 유한한 f64의 [0,1]이며 출력은 [0,1]로 제한합니다. 이는 특정 입력의 수치 평가이며 곡선 전체 정의역·단조성·연속성·역함수·프로파일 유효성을 보증하지 않습니다. 제품 색상 변환·TRC 통합·identity dispatch는 아직 남아 있습니다.

`curve_math`가 좌표 검사·실수 거듭제곱 정책·출력 제한을 공유합니다. 각 계산 함수는 ReleaseFast에서도 strict float 모드를 명시합니다. 타입별 분기와 고정소수점 변환은 전용 평가기가 소유하며 파라미터 개수는 원시 파서의 Function.count를 재사용합니다. 없는 파라미터 슬롯은 읽지 않습니다.

0^0과 0의 음수 거듭제곱은 계산 정책상 UndefinedIccCurvePower로 반환합니다. 0^0의 정책은 명세가 정한 숫자 결과라고 주장하지 않습니다. 음수 밑과 비정수 지수도 오류이며, 정수 지수는 계산할 수 있습니다. type1/2의 a=0은 임계값 정의 불가 오류입니다. 선택되지 않은 분기의 거듭제곱은 실행하지 않습니다. 매우 큰 유한 거듭제곱의 부동소수점 오버플로는 출력 범위 제한으로 처리하며 NaN은 오류입니다. 임의 정밀도·비트 단위 동일성은 보증하지 않습니다.

## 진행 중인 검증

2026-09-07 초기 네이티브 전체 테스트가 441/441로 통과했고, 신규 3개 테스트는 별도 ReleaseSafe·ReleaseFast에서도 통과했습니다. 감마 인코딩 전체의 양 끝점, 각 함수의 분기와 서로 다른 e/f, clipping, 잘못된 좌표, 비활성 분기, 정의되지 않는 거듭제곱을 검사했습니다. 이 수치는 아래 경계 수정 이전 결과입니다.

적대적 검토에서 a=49/65536, b=−1/65536, x=1/49의 f64 표현을 사용하면 별도로 반올림한 임계값 −b/a와 a*x+b 부호가 불일치하는 문제를 재현했습니다. type1/2는 융합 곱셈·덧셈으로 계산한 동일 affine 항의 부호와 a의 부호로 분기를 선택하도록 수정했습니다. 해당 x가 정확한 1/49보다 작은 경우의 회귀 테스트를 추가했습니다.

추가 검토에서는 최소 양의 f64를 a=±1/65536에 곱하면 평가 전에 0으로 언더플로되는 문제를 재현했습니다. affine 항을 인코딩 단위로 유지해 음수 부호를 먼저 검사합니다. 스케일 변환 결과가 subnormal이면 log2를 이용한 거듭제곱으로 평가해 조기 정밀도 손실을 피합니다. g=1/2의 음수 밑 오류와 양수 밑의 2^-545 결과를 네이티브·WASM 회귀 입력으로 추가했습니다. 이 처리는 임의 정밀도 계산이나 모든 입력의 상대 오차 보증이 아닙니다.

테스트 WASM mode159/160과 독립 JS 수식 대조를 정규 감사에 연결했습니다. 허용 절대 오차는 2e−12이며 감마 전체 값·파라메트릭 각 함수의 1/1024 격자, 잘림·NaN·무한대·한도·복구를 검사합니다. subnormal 제곱근은 절대 오차 허용이 아니라 정확한 2^-545 값과 비교합니다. `/tmp/hwpjs-icc-analytic-Debug-first.log`의 최초 전체 감사는 20/20 단계, 441/441로 통과했지만 경계 수정 전에 시작했으므로 최종 수정본의 통과 근거로 사용하지 않습니다.

수정된 Debug WASM으로 macOS 기본 ICC 프로파일 9개(ACESCG Linear, AdobeRGB1998, DCI(P3) RGB, Display P3, Generic Gray, Generic RGB, ITU-2020, ITU-709, ROMM RGB)를 읽기 전용으로 조사했습니다. 감마·para 태그 25개에서 129개 입력씩 3,225건이 독립 JS 수식과 일치했고 최대 절대 차이는 1.1102230246251565e−16이었습니다. 확인한 함수는 gamma·type0·type3이며 type1·2·4의 실파일 근거는 아닙니다. 공유 데이터는 태그별로 셌고 파일을 복제하지 않았습니다. 전체 프로파일 유효성·색상 변환·렌더링 검증과 구분하며 자동 감사 수에 더하지 않습니다.

수정본 Debug·ReleaseSafe·ReleaseFast 전체 감사가 각각 종료 코드 0, 20/20 단계, 네이티브 443/443, HWP5 감사 검사 4,765,017건으로 통과했습니다. 신규 독립 비교 201,738건·오류 거부 62건도 세 모드 모두 통과했습니다. 로그는 `/tmp/hwpjs-icc-analytic-{Debug,ReleaseSafe,ReleaseFast}-final.log`입니다. 최종 재검토에서 파라미터 개수의 단일 정의, 미사용 슬롯을 읽지 않는 처리, 파싱·계산 책임 분리와 strict float 모드를 확인했습니다. 포맷·JS 문법·diff 공백 검사도 통과했습니다. 검사 건수는 반복 입력을 포함하며 지원율이 아닙니다.

최종 검토에서는 고정 seed 15379의 LCG(1664525·1013904223, u32)로 20,000개 추가 WASM 입력을 생성했습니다. 함수 j%5, 파라미터 raw=((다음 난수%17)−8)×16384, x=(다음 난수%17)/16을 순서대로 사용했습니다. 독립 JS Table 68 분기·실수 거듭제곱 정책과 비교해 정상 15,878건·정의 불가 오류 4,122건이 일치했습니다. 음수 a·음수 지수·비정수 지수·0 임계값을 포함하며 이는 수동 추가 검사로 자동 감사 수에 합산하지 않습니다.

# ICC 정규화 기호근의 넓은 좌표 비교

## 계약

`normalized_power_root_compare.compare(precision, root, n, d)`는 [정규화 거듭제곱 근](icc-normalized-power-level.md)과 signed i256/u256 밑 좌표 n/d를 비교합니다. d=0 또는 잘못 구성된 비영 근은 부호 조기 반환 전에 거부합니다. 결과는 증명된 lt/eq/gt 또는 선택 정밀도에서 미확정인 null입니다. null을 같음이나 근 부재로 바꾸지 않습니다.

`at`은 기존 u64 정규화 x를 공통 affine_value로 정확한 밑 좌표로 바꿉니다. x 좌표순 정렬, 활성 구간 포함 판정, 넓은 x 분수, 출력 클리핑 역상·전체 역변환은 아직 이 계층이 처리하지 않습니다.

## SSOT와 계산

integer_power.Of(128/256)가 bounded power와 완전 정수근 알고리즘을 공유합니다. 기존 u128 함수는 Of(128) 어댑터로 유지합니다. q≥정수 폭이면 1 이외의 양의 완전 q제곱은 표현할 수 없습니다. 이진 탐색은 midpoint의 checked 거듭제곱과 목표 상한으로 비교하며 초과를 wrap 값으로 처리하지 않습니다.

rational_power_equality.Of(128/256)는 밑·지수·목표를 각각 약분한 뒤 완전근과 bounded power를 사용합니다. 양수 입력과 양의 p/q는 호출자의 선행 검증 계약이고 Debug assertion으로 표시합니다. 입력 폭만 바뀌며 동등성 알고리즘을 복제하지 않습니다.

근의 절댓값이 (A/B)^(±65536/q)이면 음의 역지수에서 A/B를 뒤집습니다. 정확한 동등성을 먼저 검사하고, 나머지는 [공통 상하한](icc-wide-positive-bounds.md)으로 (A/B)^65536과 (|n|/d)^q를 감싸서 분리된 경우만 대소를 반환합니다. 음수 근은 최종 대소를 뒤집습니다. i256 최솟값의 절댓값도 u256으로 보존합니다. 최대 입력과 u32 지수에서 이진 지수는 i64 범위보다 충분히 작고 공통 계층의 checked 연산을 유지합니다.

기존 power_root_compare는 이전의 더 좁은 Root 계약을 먼저 검사한 다음 분모 65536의 넓은 표현으로 승격합니다. 기존 i128/u128 입력·오류·반환 형식은 유지하고 비교 알고리즘을 넓은 계층에서 공유합니다. 제품 JS API는 변경하지 않습니다.

## 검증 진행

완전근 검사는 u128 최댓값의 제곱과 ±1 이웃, 2^255의 255제곱근, 256비트 한계·빈 곱·영 입력을 포함합니다. 분수 검사는 128비트를 넘는 제곱 및 200비트 공통 인수를 가진 약분, 정수 지수 극값을 확인합니다. 작은 양수 조합 38,416건은 독립 반복 곱으로 A^p D^q = B^p N^q를 직접 비교합니다.

넓은 근 비교 검사는 큰 유리수 제곱근의 정확한 등식·인접 좌표, 역수·음수 근, i256 최솟값, 생성 radicand가 u128보다 큰 정규화 목표값, Pell 좌표의 128비트 미확정과 512비트 분리, 잘못된 피연산자 검증 순서를 포함합니다. 전체 모드 감사·WASM 신규 입력 대조·적대적 검증 결과는 아래에 구분합니다.

## WASM 독립 대조

테스트 전용 mode196 입력은 144바이트 BE입니다: precision u32, sign i32(0 영점, ±1 비영 근), radicand n/d u256 두 개, 역지수 분자 i32·분모 u32, 좌표 n i256·d u256 순서입니다. 영점의 radicand·역지수 72바이트는 모두 0이어야 합니다. 출력 i32 LE는 −1/0/+1의 증명된 대소 또는 2의 미확정입니다. 크기 제한·정확한 길이·sign·precision을 검사하고 코어 판정 후에만 결과를 할당합니다.

독립 JS는 작은 기약 지수에서 전체 BigInt 거듭제곱과 교차 곱을 전개합니다. 제품의 완전근 탐색이나 상하한 알고리즘을 기대값 계산에 사용하지 않습니다. 256비트 radicand 극값, ±부호·역수, signed 좌표 극값, 고정 seed 난수 256개, 네 정밀도의 등식, 잘림 144종·과잉·한도·잘못된 필드·오류 후 정상 호출을 검사합니다.

Debug 산출물 직접 검사는 comparisons=1810, rejected=155, undecided=1로 통과했습니다. 미확정 2를 등식 0으로 바꾸는 변형과 정확한 등식 0을 미확정 2로 바꾸는 변형은 각각 ERR_ASSERTION으로 검출했습니다. 출력 복사본에만 적용했고 제품 파일에는 오류를 남기지 않았습니다. ReleaseSafe·ReleaseFast 산출물도 같은 신규 직접 검사 수로 통과했고, 각 산출물에서 미확정을 등식으로 바꾸는 변형을 검출했습니다. 직접 검사는 전체 감사 완료와 구분합니다.

추가 오류 주입에서는 비영 radicand 분자의 상위 128비트를 지워 좁은 값으로 바꾸는 입력 복사본 변형, 음수 근의 증명된 비등식 결과를 반대로 바꾸는 출력 복사본 변형을 각각 ERR_ASSERTION으로 검출했습니다. 단순 성공 여부가 아니라 정확한 크기·부호 순서를 검사하는 근거입니다. 제품 코드는 변경하지 않았습니다.

Debug·ReleaseSafe·ReleaseFast 전체 audit는 각각 20/20 단계, 네이티브 537/537, WASM checks=6,521,772로 통과했습니다. 신규 comparisons/rejected/undecided의 합계 1,966건이 이전 checks=6,519,806에 추가됐습니다. 로컬 로그는 `/tmp/hwpjs-icc-normalized-root-compare-{Debug,ReleaseSafe,ReleaseFast}.log`이며 임시 파일입니다. 변경 문서의 로컬 링크 15개와 Zig 포맷·JS 문법·diff 공백 검사도 통과했습니다.

최종 재검토에서는 양수·유효 역지수 전제의 검증 순서, 256비트 완전근 탐색의 종료·오버플로 경계, 기약 지수 동등성, 부호·역수 처리, 미확정 전파, 기존 좁은 Root 선행 검증 및 입력 승격을 확인했습니다. 해당 범위에서 추가 결함을 발견하지 않았습니다. 활성 구간 위치 판정과 전체 역변환은 아직 미완료입니다.

# HWPX 문서 끼워 넣기

웹 편집기에서 **파일 → 문서 끼워 넣기**를 열고 HWPX 파일을 고르면 현재 본문 캐럿 위치에 삽입합니다. Core에서는 `getDocumentInsertionCapabilities()`로 가용성을 조회하고 `INSERT_DOCUMENT_COMMAND`로 같은 작업을 실행합니다. 삽입할 문서의 글자 모양, 문단 모양과 문단 스타일은 대상 문서의 ID와 충돌할 수 있어 참조를 재매핑합니다. 삽입한 결과를 재열고 저장 가능한 상태임을 검사한 뒤 하나의 이력 항목으로 게시합니다.

SDK와 Runtime은 적용 전 세션, 이력 revision, 변경 serial을 검사합니다. 이전 상태로 실행 취소한 경우에도 오래된 삽입 요청은 거부됩니다. 실행 취소·다시 실행은 삽입 경계 양쪽의 원본과 세션을 복원합니다. 비활성 세션이 점유하는 메모리는 기존 이력 예산에 포함됩니다.

현재 엔진의 가져오기 범위는 Core 응답의 `sourceProfile`에 표시됩니다.

- `single-section-ordinary-body`는 설정이 호환되는 단일 구역 HWPX의 일반 본문과 서식 자원을 받습니다. 종전 WASM capability 응답 v1의 범위입니다.
- `single-section-body-with-inline-static-tables`는 같은 범위에 본문 줄 안의 정적 표를 추가합니다. WASM capability 응답 v2가 이 값을 명시합니다. 표·셀·셀 영역의 테두리와 채우기, 셀 문단·글자 서식 참조를 재매핑하며, 기존 대상 표와 리소스 ID를 보존합니다.

두 프로필 모두 삽입 위치는 일반 본문 문단의 캐럿입니다. 현재 프로필은 엔진이 시도할 수 있는 범위를 나타내며 파일의 실제 호환성은 적용 시 검사합니다. 중첩·떠 있는 표, 그림, 필드, 보호 문서, 외부 리소스, 호환되지 않는 구역 설정은 파일 전체를 적용 전에 거부합니다. 이 범위에서 교차 형식 삽입은 지원하지 않습니다.

새 SDK는 응답 v1과 v2를 모두 읽습니다. v2를 내보내는 WASM은 v2를 해석하는 SDK 및 Worker와 함께 배포합니다.

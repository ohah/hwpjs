# 표가 있는 HWP5 각주의 연속 페이지

단일 구역·단일단에서 긴 텍스트와 빈 페이지에 들어가는 표 하나가 섞인 각주를 측정 단위로 분할합니다. 텍스트는 완전한 측정 행에서 나누고 표는 셀을 포함한 원자 블록으로 옮깁니다. 다른 plain 각주와의 순서·본문 하단 예약은 공통 `footnote-continuation-engine.mjs`가 소유합니다. plain validator를 느슨하게 만들어 표를 텍스트로 취급하지 않습니다.

## 소유권과 거부 경계

`mixed-footnote-continuation.mjs`는 표시 geometry만 다룹니다. 원본 표의 section/tableNode/listNode와 생성 표의 identity/row/column을 구분하고 Native 참조를 발급하지 않습니다. 각 행·box·번호 prefix가 정확히 한 단위에 속하는지 Map/Set으로 검사합니다. 셀과 표 경계, 실제 clip, 유한 좌표와 음수가 아닌 폭은 기존 사각형 검증 함수를 공유합니다. 합법적인 0폭과 폭 없는 gap을 NaN·음수 폭과 구분합니다.

표 자체의 높이가 빈 페이지를 넘거나, 셀 병합·그림·변환·다단·keepNext 제약 등 현재 단위 계약 밖인 경우 기존 거부 또는 fallback을 유지합니다. 여러 혼합 각주나 여러 표의 일반 분할, 셀 내부 쪽 나눔, 모든 원본 한글 조판 동치는 지원 완료가 아닙니다. 일반 host 행의 기존 오른쪽 clip 의미를 셀의 완전 포함 조건으로 바꾸지 않습니다.

공통 계획기는 기존 참조 잠금·물리 배치 검사·행/쪽/재조판 상한을 유지합니다. 표시 분할이 원본 편집이나 저장 모델을 수정하지 않습니다. 인덱스 검증은 입력 단위·행·box·prefix·셀 수에 선형적인 방문과 평균 Map/Set 조회를 사용하지만, 반복 본문 재조판과 fragment trial을 포함한 전체 알고리즘의 O(n)은 아직 입증되지 않았습니다.

## 예약 높이 인덱스

`footnote-allocation-index.mjs`의 단일 Map 항목이 페이지별 fragment 배열과 합계를 소유합니다. 내부 plain·mixed adapter가 새로 만든 표시 fragment는 append할 때 높이를 한 번 더하고, 예약 조회는 평균 O(1)로 합계를 읽습니다. 초기값 0부터 같은 순서로 더하며 overhead와 각주 사이 간격은 기존 조회 식의 위치에 남깁니다. 별도 편집 모델이나 Native 원본 캐시를 만들지 않습니다.

외부 custom adapter의 높이 변경·getter·예외 관측은 기존 reduce 경로로 유지합니다. 내부 소유 높이의 최적화를 외부 입력까지 자동 적용하지 않습니다. fragment 32개·본문 128행의 순수 대조에서 예약 조회 8,480회는 그대로였고, 합산용 높이 방문은 135,664회에서 append 시 32회로, append 배열 복사는 496개 원소 방문에서 0으로 줄었습니다. 이 계수는 trial 배치·반복 재조판 비용이나 브라우저 속도 개선을 증명하지 않습니다.

정규 예약 인덱스 회귀 12개는 독립 reduce의 Float64 비트·512개 prefix·극단값, overhead와 간격의 연산 위치, 페이지 분리, 높이 읽기 횟수, custom 변이·getter·예외 순서 및 공통 계획기 내부/외부 경로를 검사합니다. 개선 반영 뒤 실제 작업 트리에서 기존 102개와 함께 114개가 실패·skip 없이 통과했습니다. 과거 진단 engine 사본이나 로컬 검증 폴더를 정규 테스트가 읽지 않습니다.

## trial 출력 생성 생략

`note-body-page-layout.mjs`가 같은 동기 호출에서 새로 측정한 plain·mixed 표시 자료에만 직접 수치 trial을 선택합니다. 공통 각주 영역 계산식과 검증 순서는 유지하고, 시험 배치에서는 최종 표시용 행·box·번호 prefix 객체의 생성을 생략합니다. 최종 배치에는 기존 객체 출력을 사용합니다. raw/custom adapter는 기본적으로 기존 물질화 경로를 사용하며, 이 내부 옵션은 외부 입력의 권한을 인증하는 브랜드가 아닙니다.

정규 회귀는 원 영역 계산을 고정한 테스트 전용 대조 함수, getter·Proxy·속성 순서·예외·Float64 경계, 현재 계획기의 물질화/직접 경로 및 실제 측정 생성 경로를 검사합니다. 기존 114개와 신규 21개를 합친 135개가 정규 소스 후보에서 실패·skip 없이 통과했습니다. 기존 원본 계획기와 비교한 별도 135개 실행은 보존하며 두 실행 수를 누적하지 않습니다.

fragment 32개·각 16행의 순수 모형을 ABBA 순서로 8개 프로세스에서 측정한 함수 중앙값의 중앙값은 1.4890ms에서 1.3228ms로 줄었습니다. RSS 범위는 겹치며 이 값은 브라우저 입력 지연이나 전체 문서의 개선율이 아닙니다. 행 방문 8,448회와 O(F²H) 반복 비용은 남습니다. 객체의 key 삭제를 반복하는 앞선 후보는 약 3.6배 느려 채택하지 않았습니다.

## 2026-10-30 검증

정규 테스트 전용 JSON은 허용 원본의 기존 d849 Native 실행에서 얻은 생성 표 상태와 저장 후 원본 표 상태입니다. 정확한 `currentReference` 키만 제거했고, 제거된 키 외 전체 레이아웃·coverage 동등성을 비교했습니다. 출처·원본/정규 SHA·명시한 세 편집은 `tests/hwp5/fixtures/mixed-note-table/provenance.json`이 소유합니다. 이 데이터로 편집 권한을 발급하지 않습니다.

실제 작업 트리에서 기존 plain 70개와 혼합·기록·기본 투영 동등성 32개, 총 102개가 실패·skip 없이 통과했습니다. 고정 8px 진단에서는 두 상태가 각각 3페이지·92/93행·표 1개이며, 실제 Chrome 글꼴 측정과 Canvas에서는 각각 2페이지·67/68행·표 1개였습니다. 측정 방식이 다른 결과를 같은 페이지 수로 주장하지 않습니다. 실제 Canvas의 처음·표·마지막 위치와 현재 paint를 확인했고 표와 마지막 각주 텍스트의 스크린샷도 확인했습니다. 소유 브라우저와 임시 서버는 종료했습니다.

별도 독립 MIT CFB/raw-record oracle 10개는 기존 저장본의 전체 대상 Section, 9개 스트림 집합과 비대상 바이트, 컨테이너 metadata, undo 원본 바이트를 검사했습니다. 기대값은 저장 결과가 아닌 원본과 명시 편집 요청에서 구성하며 변조 반례 8종을 거부했습니다. 이 저장 검사는 새 Native 빌드나 Canvas 안의 실시간 편집 검사가 아닙니다.

회귀와 Canvas는 고정된 표시 소스 후보를 사용했습니다. 소스 반영·공개 번들 배포·사설 서버 교체는 별도 단계이며 npm·RN·모든 혼합 문서 지원으로 확대하지 않습니다. 명시 실행 명령은 [개발·검증 명령](development-commands.md)의 각주 절을 따릅니다.

후속 정규 앱 QA에서도 기본 Worker 경로로 Noori HWP5/HWPX와 기존 저장본 `edited.hwp`를 실제 파일 입력으로 열었습니다. 저장본은 표의 `CELL_TEXT`와 원본에 대응하는 테두리 없는 배치, 두 번째 쪽 하단의 계속 문구·구분선·두 번째 각주를 확인했습니다. 첫 검사의 scrollTop1000에서는 그 하단이 화면 밖이었고, scrollTop=scrollMax1842 후속 검사로 확인했습니다. 미확인 기록은 보존하며 렌더링 실패로 확정하지 않습니다. 소유 브라우저를 종료했고 이 앱 검사는 새 편집·저장이나 한컴 픽셀 동치의 증거가 아닙니다.

## 공개·사설 데모 반영

공개 데모 manifest `f4d7b84cbb9f2c3a6171b1605a3171a1d8426dee0628797e91e1f34436e76ec8`의 138개 payload를 실제 HTTP 응답의 크기·SHA로 대조했습니다. 공개 브라우저에서 Noori와 기존 저장본을 열고 마지막 페이지의 계속 문구를 확인했습니다. 호환 정적 파일 11개는 유지했습니다.

사설 데모는 같은 Worker·WASM과 표시 코드를 사용하는 manifest `4835744ec138cfa60f4ddcef3f86f94105361030c07b19b9b8e6d4c091435b3b`로 운영 전환했습니다. 설치 경로의 정규 bundle 검증, 예제 117개 목록, Noori 두 형식 열기와 저장본의 실제 마지막 스크롤 위치를 QA에서 확인했습니다. 전환 후 외부 접속 경로에서도 manifest·Worker·WASM·허용 Noori 원본의 HTTP 200과 SHA, 목록 117개를 확인했습니다. 예제 목록 전체를 모두 열었다는 뜻은 아닙니다. 기존 release는 롤백용으로 보존했고 임시 QA 서버 두 개와 소유 검증 브라우저는 종료했습니다. 새 SDK·Native 빌드나 npm 배포는 수행하지 않았습니다.

# 프로젝트 문서 검증 현황

검증 대상은 Git이 추적하는 현재 프로젝트의 Markdown 문서입니다. `legacy/`와 `reference/`는 이전 구현·외부 참고 자료이므로 이 집계에서 제외하고, 별도로 인용할 때 해당 부분을 확인합니다. 현재 작업 트리에서 삭제 상태인 `lint-rules.md`는 사용자의 변경을 보존하며 `missing`으로 표시합니다. 존재하지 않는 파일을 임의로 복구하거나 검증 완료로 세지 않습니다.

`tools/docs-audit-status.mjs`가 추적 대상·현재 내용 해시가 일치하는 검증 완료 파일·미검증·변경 후 재검증 필요·작업 트리 누락·새 미추적 문서를 구분합니다. 실행 방법은 [개발·검증 명령](development-commands.md)이 소유합니다. 완료 게이트는 **목록/해시 관점의** 검사일 뿐입니다. 검증 완료 목록의 단일 출처는 `tools/docs-audit-reviewed.json`이며, 문서가 바뀌면 해당 항목은 자동으로 `stale`이 됩니다. 이 수치는 제품 구현률이 아닙니다.

파일을 완료 목록에 넣기 전에는 링크/실제 경로, 현재 코드와의 계약 일치, 명령의 실행 가능성과 적용 범위, 실파일·명세 근거 및 미지원 경계를 확인합니다. 링크 검사나 테스트 성공만으로 해당 파일을 완료 처리하지 않습니다. 전체 완료 판단에는 목록 게이트 외에 문서끼리의 모순, 누락된 요구 사항, 대표 실파일과 오류 경로를 다시 보는 최종 적대적 검증이 필요합니다.

기존 문서의 과거 테스트 기록은 이 목록에 자동 소급하지 않습니다. 이 목록의 비율은 새 기준에 따라 **현재 내용 전체를 다시 검증한 파일의 비율**이며, 이전 구현 진행률이나 과거 검증 작업량의 추정치가 아닙니다.

2026-09-27 기준 첫 완료 파일은 [HWP5 각주·미주 원문 표식 위치](hwp5-note-source-sites.md)입니다. 해당 주제의 공식 명세·제품 코드·원시 레코드 대조와 반례, 감사 테스트 결과는 그 문서에 둡니다. [프로젝트 구조](project-structure.md)는 HWPX XML 트리·section·WMF/EMF 범위 표현을 교정했으나 파일 전체의 검증 완료로 세지 않습니다. 새 현황 문서까지 포함해 현재 존재하는 프로젝트 Markdown 560개에서 일반 인라인 로컬 링크 2,518개의 대상 파일이 모두 존재했습니다. 작업 트리에서 삭제된 `lint-rules.md`는 이 링크 검사에서 제외됩니다. 참조형 링크·앵커·외부 URL·문서 내용의 옳음까지 증명하는 검사는 아닙니다.

진입점 [AGENTS.md](../AGENTS.md)는 링크 대상과 인덱스 전용 책임을, [커밋 규칙](../commit-rules.md)은 프로젝트 규칙·실제 빌드 명령·레거시 규칙 경로와의 일치를 확인해 완료 목록에 넣었습니다. [README](../README.md)도 빌드·공개 JS API·두 실행 예제를 확인했습니다. Node에서는 추적 HWP fixture의 `/BodyText/Section0`이 `Buffer` 402바이트였고, 실제 Chromium에서는 HTTP로 받은 WASM/fixture의 strict 읽기 후 `/FileHeader`가 값 256개의 배열이었습니다. README의 `sample.hwp`는 사용자가 제공할 입력 예시이므로 검사에는 같은 저장소의 추적 fixture를 사용했습니다.

`docs/project-rules.md`는 실제 모듈·레거시 명세 경로, 진입점/상세 문서의 소유권, 현 커밋·검증 명령과 충돌하지 않는지 확인해 완료 목록에 넣었습니다. 구현 원칙은 정책이지 모든 HWP/HWPX 기능이 이를 이미 충족했다는 선언으로 읽지 않습니다.

HWPX 주석의 `hwpx-note-sites.md`·`hwpx-note-bodies.md`·`hwpx-note-number-links.md`·`hwpx-note-text.md`는 공식 한컴 모델/구조 설명, 현 Zig 소유권·수명 경계, 세 빌드 모드의 주석 계열 27개 테스트, 네 독립 오라클의 일반/최적화 변이 검사, 476개 허용 실파일의 파일별 대조와 단독/known 경로를 확인해 완료 목록에 넣었습니다. known-inspections도 8개 shard를 **별도 프로세스**로 재실행해 각각 통과했으며 합계는 허용 476개·ZIP 거부 6개·암호화 2개·section 544개였습니다. 이 공통 실측의 제품 코드 기준은 `2570e219`, 로컬 rhwp 샘플 리비전은 `e8800c8de`이고 샘플 변경은 없었습니다. 각 주제의 현재 재현값과 미지원 범위는 해당 문서가 소유합니다. `docs/development-commands.md`는 1차 정적 조사에서 추출한 85개 경로가 존재하고 인용 필터 156개 중 155개가 테스트 이름과 대응했으며 나머지 하나는 명시적 `<이름>` 자리표시자였습니다. 이 조사는 모든 명령의 실행 성공 검증이 아니므로 명령 문서 전체는 아직 완료로 세지 않습니다.

HWPX 번호 컨트롤과 단 설정 문서도 한컴 고정 버전 모델의 필드·열거형, 현재 검사기의 소유 경계, 세 모드의 집중 테스트, 독립 오라클 자체검사 및 허용 476개 파일별 결과, 실파일 단독/known 경로를 다시 확인해 완료 목록에 넣었습니다. 기준 제품 코드 `752ca0d2`는 이전 known-inspections 8개 shard가 통과한 코드 `2570e219`에서 문서만 변경된 상태이고, 로컬 rhwp 샘플은 `e8800c8de`입니다. 이 재사용 증거는 보고서 조립 경로에 한정하며 번호 계산·단 조판·저장 기능을 입증하지 않습니다.

HWPX 필드 마커와 인라인 문자열 컨트롤 문서도 공식 필드·자식 모델, 현재 코드의 namespace·링크·직접 텍스트 경계, 세 모드의 집중 테스트, 독립 오라클 자체검사와 476개 허용 파일의 파일별 결과, 양성 실파일의 단독/known 경로를 확인해 완료 목록에 넣었습니다. 필드 마커의 모델 밖 속성 11개는 별도 ZIP/XML 집계로 모두 `fieldBegin/@metaTag`임을 확인했습니다. 이 묶음의 제품 코드 기준은 `855b891c`이며 이전 known-inspections 8개 shard의 코드 기준 `2570e219` 이후 제품 코드는 변경되지 않았습니다. 기능별 미지원 범위는 각 주제 문서가 소유합니다.

HWPX section `metaTag`와 파라미터 목록 문서도 공식 모델·현재 선택/소유 경계·세 모드 집중 테스트·독립 오라클의 자체검사와 허용 476개 파일별 대조·실파일 known 연결을 확인해 완료 목록에 넣었습니다. `metaTag` 양성 네 파일의 부모·개별 텍스트 길이와 파라미터 목록의 양성 파일 수·스칼라 바이트·자식 종류별 수치도 별도 XML 집계로 재확인했습니다. 기준 제품 코드 `23831fd0`는 이전 known-inspections의 `2570e219` 이후 문서만 바뀐 상태이며, 로컬 rhwp 샘플 리비전은 `e8800c8de`입니다. 값의 제품 의미·렌더링·저장 지원까지 완료했다는 뜻은 아닙니다.

HWPX 수식 원문·도형 자식·`shapeComment`·caption의 네 문서도 한컴 고정 버전 모델, 현재 수식/도형/공통 caption 책임, 세 모드 집중 테스트, 독립 수식 오라클의 변이·476개 파일별 대조, 주석·caption 합성 고정 해시를 재확인해 완료 목록에 넣었습니다. 별도 ZIP/XML 인벤토리로 도형 자식 종류·속성값 총계와 주석 길이·속성·하위 요소 분포를 확인했습니다. corpus의 수식 caption은 0개여서 이 경로의 실파일 값 검증으로 세지 않습니다. 기준 제품 코드 `b085d347`는 기존 known-inspections 8개 shard의 `2570e219` 이후 문서만 바뀐 상태입니다. 수식 문법·조판·편집·저장은 미지원 경계로 유지합니다.

ParaListType 속성과 표 shape 문서도 고정 버전 공식 필드·현재 호출자 연결·공유 판독 코드·합성 반례, 마스터페이지/표 독립 ZIP/XML 오라클의 현재 실파일 집계와 기존 known-inspections 비교 범위를 확인해 완료 목록에 넣었습니다. ParaList 문서의 오래된 호출자/후속 문구는 각주·미주 및 표·수식 caption 연결을 포함하도록 교정했고, 마스터페이지 수치를 다른 호출자 경로로 일반화하지 않았습니다. 제품 코드 기준 `905c870b`는 기존 8개 shard 실행 기준 `2570e219` 이후 문서만 바뀐 상태입니다. 실제 레이아웃·편집·저장은 여전히 범위 밖입니다.

표 셀의 직접 `subList`, 표 자체 속성, 표 안쪽 여백·셀 구역의 세 문서도 고정 버전 모델·현재 소유 코드·세 모드 집중 테스트·독립 표 오라클의 자체 반례와 476개 허용 실파일 집계를 대조해 완료 목록에 넣었습니다. 셀별 목록 누락·중복, 표 ID 0의 미해결 참조, 여백의 음수·상위 비트 여부를 총계와 분리해 확인했습니다. 기존 known-inspections 8개 shard는 제품 코드가 변경되지 않아 이전 결과만 재사용했고 이번 묶음에서 재실행하지 않았습니다. 셀 본문 의미·표 레이아웃·편집·저장은 완료 범위가 아닙니다.

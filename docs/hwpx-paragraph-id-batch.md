# 신규 셀 문단 ID의 일괄 계획

## 외부 생성 ID 검증

`validateAdditional`은 호출자가 제공한 신규 셀 문단 ID들을 동일한 원본/현재 생성 inventory에 대조합니다. 양의 u32·원본 충돌·기존 생성 충돌·이번 입력 중복과 전체 문단 예산을 검사합니다. `next`/`nextMany`의 수집기를 공유하고 예약이나 문서 변경을 수행하지 않습니다. 2026-10-11 ReleaseSafe 집중2/2(root 포함)·exit0은 원본 중복/동일값 어휘/유효 넓은 ID 보존, zero/세 종류 충돌/예산 거부, 모든 할당 실패와 후속 할당 결과 불변을 확인했습니다. 아직 Session 생성 거래가 이 검증기를 호출하지 않으므로 공개 삽입의 문서 전체 충돌 방지가 완료된 것은 아닙니다.

후속 생성 거래 연결과 source-part 수집 모듈의 현재 이름·검증 범위는 [생성 표 문서 참조 검증](hwpx-created-table-validation.md)을 따릅니다. 기존 ID 파서나 ZIP 탐색 정책을 복제하지 않습니다.

최종 별도 prefix `/tmp/hwpjs-paragraph-id-batch-20261011`의 ReleaseSafe build도 exit0입니다. 후보에는 기존 작업 트리 변경이 포함되므로 깨끗한 게시 소스 검증/기본 제품 승격으로 해석하지 않습니다.

2026-10-11 최종 root 집중 ReleaseSafe 실행6/6·exit0은 root 진입, 기존 HWP5 ID2검사, HWPX 기존/새 ID2검사와 실제 root/nested 문단 분할 XML 재열기1검사입니다. fmt/diff도 exit0입니다. 신규 표 생성 검사가 아니라 기존 분할 경로와 ID 정책 회귀이며 전체 최신 native gate 완료로 계수하지 않습니다. 기본 WASM은 변경하지 않습니다.

`paragraph_instance_ids.nextMany`는 전달된 모든 원본 part와 현재 생성 문단 ID를 한 번 수집하고 요청 수만큼 최소 빈 양수 u32 ID를 오름차순으로 반환합니다. 호출자는 반환 배열을 해제합니다. 기존 단일 `next`도 같은 원본/생성 ID 수집과 빈 값 판정을 사용하며 정책을 복제하지 않습니다.

원본0·중복·ID 부재·u32보다 큰 유효 정수는 그대로 보존합니다. 생성 ID의0·원본 충돌·생성끼리 중복은 거부합니다. 예산은 원본 문단 수(중복·ID 부재 포함)와 현재 생성 문단 수, 이번 요청 수를 함께 계산합니다. 빈 요청도 원본/생성 ID를 검사하되 새 문단 공간은 예약하지 않습니다.

함수는 읽기 전용 계획이며 전역 예약이나 Session 변경이 아닙니다. 같은 입력을 반복하면 같은 ID를 반환합니다. 다음 거래는 이미 생성된 모든 문단과 신규 셀의 문단 ID를 generated 입력에 포함해야 합니다. 아직 확정되지 않은 두 계획을 동시에 commit하면 충돌할 수 있으므로 Session 거래가 하나의 현재 모델에 원자적으로 반영해야 합니다. 모든 section/master-page 등 source part 제공은 호출자의 책임이며 이 함수 자체가 ZIP을 탐색하지 않습니다. 표 instance_id·현재 object identity의 할당기는 별도 namespace 책임입니다.

검사는 희소 원본·동일 값의 다른 정수 어휘·원본 중복/0/큰 ID·현재 생성 값의 처리, 일괄/연속 단일 결과 대조·반복/다음 계획·정확 예산과 초과·빈 요청의 중복 거부·모든 할당 실패·생성 입력 불변을 포함합니다. 원본 보존/생성 정책을 완화하지 않습니다. 실제 신규 표의 Session/Checkpoint/저장/공개 UI 연결은 아직 없습니다.

# ICC 곡선의 임계점 분할과 구간별 방향

## 현재 범위

[ICC.1:2022 Table 68·Annex F.1](https://www.color.org/specifications/ICC.1-2022-05.pdf)의 후속 단조성/역변환을 위해 원본 분기를 세분화합니다. 선형 분기는 0/1 클리핑 경계까지 정확하게 나누고 최종 클리핑된 방향을 기록합니다. 이 문서의 거듭제곱 분할은 밑 영점에서 나누고 **클리핑 전** 방향만 기록합니다. 거듭제곱의 클리핑 경계·최종 구간은 [별도 조립 계층](icc-power-clipping.md)이 소유합니다. 분기 간 점프 비교, 전체 상수성·단조성·역상 판정은 아직 미완료입니다.

## 책임과 정확 산술

- Fraction.order는 공통 정규화 분수 검사와 u128 교차 곱 비교를 소유합니다. unit_interval의 순서·포함 검사와 새 분할/정렬이 재사용합니다.
- interval_split은 입력 구간을 cut에서 나누며 실제로 포함된 cut은 오른쪽에 배정합니다. 바깥 끝점의 포함 여부는 보존합니다. cut이 닫힌 끝점과 같으면 오른쪽은 닫힌 한 점 구간이며, 열린 끝점과 같으면 오른쪽은 없습니다. 시작점 이하/끝점 초과의 cut도 빈 구간 객체 대신 optional 부재로 표현합니다.
- affine_root의 unrestricted는 인코딩된 slope*x+offset=target의 근을 부호 있는 분자·양의 분모로 구하며, solve는 이를 [0,1]로 제한합니다. 기울기 0은 고립된 근이 없어 null입니다. i32 계수 차이와 부호 전환은 i64에서 처리합니다. 기존 type1/2 분기점도 unrestricted를 재사용하고, 그 호출 계층에서 기울기 0을 UndefinedIccCurveThreshold로 해석합니다.
- linear_clip은 target=0/65536의 근을 정렬하고 최대 3개 구간을 만듭니다. 각 구간은 zero/affine/one과 constant/increasing/decreasing을 가집니다. 기울기 0의 내부 상수는 affine+constant이며, 한 점 구간은 방향 constant입니다.
- power_partition은 기존 분기 조립기의 전체 실수 정의역 검사를 거쳐 밑 영점에서 최대 2개 구간으로 나눕니다. 계수·지수·오프셋을 보존하며 양/음의 밑과 정수 지수의 홀짝에 따라 클리핑 전 방향을 계산합니다. 비활성 거듭제곱은 count=0입니다.

구간 내부의 부호/클리핑 종류는 양 끝 분수의 mediant로 판정합니다. 서로 다른 끝점이면 mediant는 구간 내부에 있으며 각 구간에는 이미 제거한 영점/클리핑 근 외에 방향·종류를 바꾸는 임계점이 없습니다. 이는 임의 격자 샘플링으로 전체 유효성을 추정하는 방식과 다릅니다. 분자·분모 합은 i128에서 계산하여 u64 최대값의 합도 보존합니다. 합은 2^65 미만, affine 중간값의 절댓값은 2^97 미만이므로 i128에 들어갑니다. Fraction 교차 곱은 2^128 미만이며 부동소수점·허용 오차·약분을 필요로 하지 않습니다.

전역 검증을 마친 거듭제곱 분기의 음수 밑은 정수 지수에 한정됩니다. 구간별 방향은 a·g의 부호와 음수 밑에서의 g−1 홀짝으로 결정합니다. g=0·a=0·한 점 구간은 constant입니다. 오프셋 때문에 클리핑 후 상수가 되는 경우에도 이 **원래 방향**을 최종 방향으로 바꾸지 않습니다. 실제 최종 분류는 별도 후속 계층의 책임입니다.

거듭제곱의 클리핑 근은 일반적으로 무리수일 수 있습니다. 이번 모듈은 정확한 유리수로 표현되는 선형 클리핑 근과 affine 밑 영점만 처리합니다. 나머지 근을 Fraction으로 강제 반올림하지 않으며 후속 대수적 경계 표현/확정 비교가 필요합니다. 이는 목표에서 해당 근을 제외한다는 의미가 아닙니다.

[거듭제곱 경계의 기호적 실근](icc-power-level.md)은 밑 변수에서의 해 집합을 보존하는 후속 계층입니다. 활성 x 구간의 클리핑 분할로 연결하는 작업은 아직 남아 있습니다.

클리핑 경계는 오른쪽 구간에 속하지만 왼쪽 식과 값이 같습니다. 예를 들어 감소하는 affine 구간의 시작점에 y=1이 포함될 수 있습니다. 이후 역상 계산은 flat 종류 구간만 찾지 말고 인접 affine/거듭제곱 구간의 경계 역상도 합쳐야 합니다. 그렇지 않으면 인위적인 분할로 달성 가능한 평탄 끝점을 잃게 됩니다.

분할 결과는 고정 크기 값 배열(count 이내만 초기화)이며 할당하지 않고 입력을 변경하지 않습니다. 외부에서 구성한 선형 구간은 공통 Interval.validate를 먼저 거칩니다. 거듭제곱 분할은 Curve를 받아 기존 정의역 검사와 원본 분기 조립을 재사용합니다.

power_partition.Result.source는 분할 전 원본 Power를 보존하며 비활성 분기에서는 null입니다. [클리핑 구간 조립](icc-power-clipping.md)이 이를 전달받아 계수와 원래 활성 범위를 다시 추정하지 않습니다.

## 검증 기록

네이티브 실행은 종료 코드 0, 5/5 단계·491/491 테스트로 통과했습니다. 네 가지 열린/닫힌 끝점 조합에서 9개 cut·17개 질의의 소유권/전체 구간 보존을 검사했습니다. 최대 u64 분수, 닫힌 끝점의 한 점 구간, 상승/하강 선형 클리핑, 내부 상수, 짝수/홀수 거듭제곱, 클리핑 전 방향 보존과 정의역 오류를 포함합니다.

WASM mode181은 para payload를 받아 선형/거듭제곱 구간 개수 u32 두 개와 각 64바이트 슬롯을 반환합니다. 슬롯은 기존 40바이트 구간 표현, kind u32, direction u32, 원본 계수 i32 네 개입니다. kind 0/1/2는 zero/affine/one, 3은 클리핑 전 power이며 direction 0/1/2는 constant/increasing/decreasing입니다. 선형 계수는 slope/offset/0/0, power는 a/b/g/offset입니다. 최대 출력은 328바이트입니다. 기존 mode180과 구간 직렬화를 icc-interval-wire에서 공유하며 기존 wire 형식은 유지합니다.

독립 JS 기대값은 임계점 목록을 정렬·중복 제거하여 구간을 만들고 제품의 반복 split을 호출하지 않습니다. 부호/클리핑 종류에는 산술평균을 사용하여 제품 mediant와 산술 경로를 달리합니다. 정수 지수의 방향은 구간 내부 두 점의 거듭제곱 값을 BigInt 분수로 직접 비교합니다. 비정수 지수의 방향은 검증된 비음수 밑에서 거듭제곱의 증가/감소 성질을 사용합니다. 기존 분수 정규화와 정의역 임계점 기준은 각각의 기존 테스트 모듈에서 export해 재사용했습니다.

Debug WASM 직접 실행은 신규 비교 7,861건·예상 오류 거부 4,157건으로 통과했습니다. 공통 직렬화 추출 후 기존 구간 조립 검사도 비교 3,016건·거부 1,377건으로 통과했습니다. 전체 감사 결과는 종료 후 기록합니다.

최종 경계 검토에서 선형 계수 c의 i32 최솟값·최댓값 조합과 최대 u64 분모의 mediant 사례를 정규 테스트에 추가했습니다. 확장 전 Debug 감사는 완료됐지만 최신 테스트의 근거로 사용하지 않고 세 모드를 다시 실행합니다. 제품 코드는 이 추가로 변경하지 않았습니다.

확장된 Debug WASM 직접 대조는 비교 13,101건·예상 오류 거부 6,917건으로 통과했습니다. 확장 전 전체 Debug 로그 `/tmp/hwpjs-icc-partition-Debug.log`는 종료 코드 0, 20/20 단계·491/491·WASM 5,709,895건이었으며 최신 최종 검사 수와 구분합니다.

시스템 ICC para TRC 태그 15개(type0/type3)를 읽기 전용으로 검사했습니다. type0은 선형 분기 없이 한 개의 증가 power 구간, type3은 열린 하위 끝점을 갖는 증가 affine 구간과 증가 power 구간을 반환했습니다. 원본 g/c 계수도 일치했습니다. 기존 조사에서 일부 프로파일의 하향 점프를 확인했으므로 이 결과를 전체 곡선의 단조성 통과로 확대하지 않습니다. 공유 payload의 고유 개수나 type1/2/4의 실파일 증거는 아니며, 수동 검사 수는 정규 감사에 합산하지 않았습니다. 파일은 복사·수정하지 않았습니다.

테스트 민감도 조사에서 음수 밑·짝수 지수의 방향 보정을 생략하는 임시 반환값 변형을 적용했고 독립 비교가 ERR_ASSERTION으로 검출했습니다. 제품 코드에는 변형을 남기지 않았습니다. 최대 분모 테스트는 분모 합이 u64에서 래핑되면 내부 상수 1/2이 zero로 잘못 분류되는 사례도 추가하여 ReleaseFast의 래핑 결함을 놓치지 않도록 했습니다.

SSOT 최종 검토에서는 기존 type1/2 분기점과 새 affine 근의 부호 정규화 계산 중복을 제거했습니다. unrestricted를 공통 소유자로 두고 각 호출 계층의 정의역/오류 정책은 유지했습니다. 이 변경 전 감사 결과를 최종 상태의 근거로 대신하지 않고 공통화 이후 모드별 전체 검사를 확인합니다.

공통화 이후 ReleaseFast 바이너리에서 분할 13,101/6,917건, 정의역 5,262/4,381건, 기존 구간 조립 3,016/1,377건의 비교/거부를 직접 재확인했습니다. 전체 ReleaseFast 감사 `/tmp/hwpjs-icc-partition-ReleaseFast-final.log`도 종료 코드 0, 20/20 단계·491/491·WASM 5,717,895건으로 통과했습니다. 이 모드는 공통화 및 최종 극값 단언을 반영한 뒤 빌드됐습니다. 이전 상태로 실행됐던 Debug·ReleaseSafe는 `-ssot.log`로 재실행합니다.

추가 수동 실측에서는 type4 raw [−2147483648,−2147483648,−2147483648,0,0,0,0]을 확인했습니다. x=1/4와 3/4의 기존 f64 점 계산은 모두 언더플로로 0이었지만 분할 결과는 원래 함수의 감소 방향과 극값 계수를 보존했습니다. 정확한 실수 함수는 (−32768x−32768)^−32768로 이 구간에서 양수·감소이며 클리핑 범위 안에 있습니다. 같은 반올림 결과를 상수성 근거로 사용하지 않는 사례입니다. 수동 검사 수는 정규 감사에 합산하지 않습니다.

### 최종 확인

공통화 이후 Debug·ReleaseSafe 감사도 완료했습니다. `/tmp/hwpjs-icc-partition-Debug-ssot.log`, `/tmp/hwpjs-icc-partition-ReleaseSafe-ssot.log`, 위 ReleaseFast 최종 로그 모두 20/20 단계·491/491 네이티브 테스트·WASM 검사 5,717,895건 통과를 기록합니다. 각 모드의 신규 분할 검사는 비교 13,101건·예상 오류 거부 6,917건입니다. 앞의 재실행 예정 문장은 진행 이력이며 최종 결과는 이 절이 소유합니다.

최종 코드 재검토에서는 분할 결과 배열의 최대 개수(선형 3, 거듭제곱 2), count 이내 초기화, 열린 끝점 보존, i32 최솟값 부호 전환, i128 중간값 범위, 테스트 wire의 기존 구간 표현 재사용을 확인했습니다. 이 범위에서 추가 결함은 발견하지 않았습니다. 전체 곡선의 클리핑 후 단조성·역변환이나 전체 ICC 명세 구현 완료를 뜻하지 않습니다.

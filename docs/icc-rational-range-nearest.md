# ICC 유리수 출력 범위의 최근접 값

## 계약과 미완료 경계

`rational_range_nearest.select(target, ranges)`는 정규화 u128 목표와 u256 유리수 끝점으로 표현한 출력 구간들의 합집합에서 실제 최근접 출력값을 구합니다. 구간은 열림·닫힘을 보존하고 서로 겹치거나 중복돼도 됩니다. 목표와 **모든 구간을 먼저 검증**하므로 앞 구간에서 정확한 해를 찾았다고 뒤의 잘못된 구간을 숨기지 않습니다.

결과는 empty(빈 범위 목록), unattained(거리의 하한에 도달하는 실제 값 없음), nearest(정확한 출력값 1개 또는 2개)입니다. 동률인 서로 다른 두 값은 오름차순으로 모두 보존하고 임의 우선순위를 부여하지 않습니다. 같은 값의 다른 분수 표현은 중복 제거하지만 기약분수 정규화나 바이트 단위 표준 표현은 보장하지 않습니다. nearest.values의 count 밖은 읽지 않습니다.

이것은 F.1(b)에 필요한 **유리수 구간 합집합의 거리·존재 판정 기반**입니다. 파라메트릭 곡선에서 전체 출력 범위를 만드는 작업, 기호적 거듭제곱 출력값과의 거리 비교, 선택된 출력의 F.1(a) x 선택 연결은 아직 미구현입니다. caller가 실제 전체 출력 범위를 제공해야 하며 이 모듈 자체가 곡선의 단조성을 검증하지 않습니다. 제품 JS API는 변경하지 않았습니다.

## 열린 범위와 동률

출력 범위 [0,1/2)∪{1}, 목표 3/5에서는 거리의 하한 1/10이 달성되지 않으므로 unattained입니다. 더 먼 실제 출력 1을 대신 반환하지 않습니다. 목표 3/4에서는 열린 경계 1/2와 실제 값 1까지의 거리가 모두 1/4이므로 실제 값 1이 최근접입니다. 범위 {0,1}, 목표 1/2에서는 두 값 모두 최근접입니다. 이는 가장 가까운 경계가 미도달이라는 이유만으로 같은 거리의 실제 후보를 버리면 안 된다는 반례입니다.

## SSOT와 정수 폭

- `ordinate_distance.zig`: 정확한 거리 순서. 목표 n/d와 값 a/b에 대해 |a*d−n*b|는 u384 안에 들어갑니다. 두 거리 비교에서 공통 양수 d를 소거한 뒤 상대 분모를 곱하므로 u640이면 충분합니다. 부동소수점·약분·할당을 사용하지 않습니다.
- `nearest_ordinate_types.zig`: 후보, 결과, 최대 두 개의 최근접 값 표현.
- `nearest_ordinate_candidates.zig`: 최소 거리와 실제 동률 후보 수집. 더 가까운 미도달 경계는 더 먼 실제 후보를 무효화하지만 같은 거리의 실제 후보는 남깁니다. 내부 accumulator는 caller가 검증한 값을 받습니다.
- `rational_range_nearest.zig`: 전체 입력 검증과 각 구간에서 목표에 가장 가까운 후보 구성. 기존 unit_interval 검증·포함 판정을 재사용합니다.

실수선에서 같은 목표로부터 같은 거리에 있는 서로 다른 값은 최대 두 개이므로 후보 저장소는 고정 크기입니다. 전체 범위에 파일 접근·할당·f64 근사는 없습니다.

## 검증 진행

네이티브 566/566가 통과했습니다. 신규 테스트는 미도달 거리, 미도달 경계와 같은 거리인 실제 값, 입력 순서/중복과 두 동률, 정확한 해 뒤에 오는 잘못된 구간, 빈 범위와 빈 열린 단일점, u128 목표의 중간값 직전, u256 최대값 주변의 인접 분수 거리를 검사합니다.

테스트 mode203은 목표 n/d u128 BE, 구간 수 u32 BE의 36바이트 헤더와 구간당 132바이트(start/end n/d u256 BE, flags u32 BE)를 받습니다. probe 입력은 최대 64구간으로 제한하며 길이·flags·자원 한도를 검사합니다. 코어 slice API에는 이 테스트 전용 개수 제한을 적용하지 않습니다. 임시 구간 배열은 defer로 해제합니다. 출력은 status u32 LE(0=empty, 1=unattained, 2=nearest), count u32 LE, 값당 n/d u256 LE 64바이트입니다. 할당 후 오류 가능한 작업이 없고 모든 결과 바이트를 씁니다.

독립 JS 기준은 모든 구간의 양 끝과 포함되는 목표를 후보로 열거한 뒤 BigInt 거리로 정렬합니다. 제품의 구간별 한 후보 선택/누적 알고리즘을 기대값 생성에 사용하지 않습니다. 구간 10종의 순서 있는 쌍과 목표 9개, 중복/순열/열린 동률 사례, 최대 정수, 고정 seed 무작위 넓은 분수 256개, 잘림·과잉·한도·잘못된 flags/개수/좌표/구간·오류 후 복구를 검사합니다.

직접 Debug WASM 검사는 comparisons=1173/rejected=309/unattained=190/ties=17로 통과했습니다. unattained와 ties는 comparisons에 포함된 분류 건수이며 추가 호출이 아닙니다. 신규 호출은 총 1,482건입니다. 동률 하나 삭제, 미도달을 빈 범위로 변경, 동률 순서 반전, 열린 입력을 닫는 네 변형을 각각 ERR_ASSERTION으로 검출했습니다. 제품 파일에는 변형을 남기지 않았습니다. 전체 세 모드 감사는 진행 중입니다.

임시 소스 복사본에서 미도달 후보를 거리 비교 전에 무시하도록 바꾼 변형도 실행했습니다. 신규 네이티브 4개 중 1개가 실패하며 종료 코드 1로 검출됐습니다. 이 변형은 [0,1/2)∪{1}에서 더 먼 실제 값 1을 잘못 고르는 결함을 겨냥합니다. 제품 소스는 변경하지 않았으며 로컬 로그는 `/tmp/hwpjs-nearest-range-mutation-ignore.log`입니다.

## 최종 감사와 재검토

Debug·ReleaseSafe·ReleaseFast 전체 audit가 각각 종료 코드 0, 20/20 단계, 네이티브 566/566, WASM checks=6,561,310으로 통과했습니다. 신규 1,482건이 이전 6,559,828건에 추가됐습니다. 각 모드 신규 결과는 comparisons=1173/rejected=309/unattained=190/ties=17이며 뒤의 두 수치는 비교 건수에 포함됩니다. 로그는 `/tmp/hwpjs-icc-nearest-range-{Debug,ReleaseSafe,ReleaseFast}.log`입니다. 앞의 진행 중 문장은 이력이며 최종 결과는 이 절을 기준으로 합니다.

ReleaseSafe·ReleaseFast 산출물 직접 실행도 같은 신규 수치로 통과했고 동률 후보 삭제 변형을 각각 검출했습니다. 미도달 후보를 무시하는 네이티브 변형도 두 Release 모드에서 각각 1개 실패로 검출됐습니다. 변경 Zig 포맷·JS 문법·diff 공백·문서 로컬 링크 1개를 확인했습니다.

적대적 재검토에서는 전체 입력 선행 검증, 384/640비트 곱의 상한, 공통 양수 분모 소거, 미도달 최단 거리의 우선순위, 같은 거리의 실제 후보 보존, 동치 분수 중복 제거, 최대 두 동률의 수치 정렬, 임시 배열 해제와 출력 초기화를 확인했습니다. 이 범위에서 추가 결함은 발견하지 않았습니다. 파라메트릭 출력 범위 생성·기호적 출력 거리·F.1(a) 연결과 전체 HWP/HWPX 문서 검증은 여전히 미완료입니다.

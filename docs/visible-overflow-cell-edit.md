# 너비 초과 표의 완전히 보이는 셀 편집

[부분 미리보기](inline-table-paper-preview.md)의 원본 폭·종이 클립은 유지합니다. Canvas에서는 셀 전체와 모든 텍스트 행·커서가 최종 종이와 기존 클립 안에 들어오는 경우에만 해당 셀의 텍스트 편집을 허용합니다. 잘린 셀·숨은 셀·단독 표 호스트는 읽기 전용입니다. 표 전체의 조판 동치나 잘린 부분의 편집을 지원한다는 뜻은 아닙니다.

## 책임과 단일 출처

`visible-overflow-cell-edit.mjs`가 최종 scene의 가시성 증명을 소유합니다. Native 모델에서 표·셀·문단 소유권을 색인하고 최종 셀 상자·행·caret 경계를 검사합니다. 원본 폭·높이·ID·참조를 변경하거나 문단을 필터링하지 않습니다. 허용한 셀의 텍스트 행만 편집/선택 가능으로 투영하며 상자·크기 조절·호스트 앵커는 승격하지 않습니다. 캡션 없음은 기존 `inlineTableHasNoCaption`의 형식별 명시 증명을 공유합니다.

원본 소유권은 canonical content, 표시 행의 완전성은 실제 draft를 포함한 display content가 기준입니다. 같은 문단의 첫 행·중간 행·마지막 행이 빠진 경우를 모두 거부하고, 표시 문자열의 0부터 끝까지 각 행이 연속적이며 내용이 일치하는지 확인합니다. draft의 길이를 아직 갱신되지 않은 원문 길이와 비교해 정상 입력을 취소하지 않습니다. Native와 display 및 입력 layout은 불변으로 유지합니다.

`preview-edit-policy.mjs`는 readonly descriptor의 선택적 `editableCells`를 현재 Native 셀의 전체 문단 목록·실제 소유권 순서와 대조합니다. 문단 ID의 크기 대신 원본 순서와 소유권 구간을 사용하며 인접한 두 허용 셀 사이에도 범위가 넘어가지 않습니다. 원문 끝 입력은 이전 ACK 전 커서 규칙을 유지합니다. 색인 구성은 입력과 glyph boundary 총량에 선형이며 point/range 조회는 평균 O(1)입니다. 기존 전체 조판·Native 명령의 복잡도를 이 보장으로 확대하지 않습니다.

## 허용하는 편집

완전히 보이는 셀의 기존 문단에서 입력·일반 텍스트 붙여넣기·문자 서식을 기존 Core/Native 명령으로 수행합니다. 셀의 모든 문단이 표시돼야 허용하며, 여러 문단 문자 서식도 같은 셀 안의 범위여야 합니다. 구조적인 문단 분할·합치기·여러 문단 교체, 표 생성·행열 변경·셀 크기와 개체 속성은 이 단계에서 허용하지 않습니다. Core의 헤드리스 명령 지원 범위와 Canvas의 표시 안전 범위는 별개입니다.

Surface는 최종 비동기 요청에서 같은 정책을 다시 검사하고, 구조 편집을 지원하지 않는 표에서는 grid capture를 발급하지 않습니다. Renderer의 셀 크기·새 표 폭 힌트도 같은 요청 정책을 사용합니다. 셀 속성 대화상자는 Surface의 `canEditCellProperties`를 통해 같은 최종 scene·관측 상태·lease를 검사하며, 포트가 직접 Core를 호출하는 경로에서도 capture와 apply 직전에 재검사합니다. 잘린 셀을 클릭하면 이전 셀의 입력 대상을 해제하되 진행 중이거나 아직 전송하지 않은 입력은 클릭으로 버리지 않습니다. Native의 좌표·권한 검증을 대신하거나 다른 저장 모델을 추가하지 않습니다. 일반 본문·실행 취소·다시 실행·저장은 기존 경로를 유지합니다.

## 재조판 실패와 복구

`overflow-preview-barrier.mjs`는 같은 문서에서 기존 부분 미리보기가 실패한 논리 scene으로 바뀌는 경우를 처리합니다. 이전 문단 번호를 재사용하지 않고 현재 Native의 표·호스트·셀 문단으로 읽기 전용 barrier를 다시 만듭니다. `IncompleteOverflowTableProjection`은 셀 편집 증명을 허용하지 않습니다. 실패 원인은 scene에 유지하고 표의 상자/행/앵커만 제한하며, 성공한 새 페이지 scene은 새 가시성 검사를 거쳐 편집을 복구합니다. Renderer는 문서 자원 identity가 같은 경우에만 이전 barrier를 전달합니다. 표시 범위를 증명할 수 없는 미확정 입력은 Native에 적용하지 않고 취소 안내를 표시합니다. 이때 draft 커서로 이전 revision의 검증된 bookmark를 덮어쓰지 않습니다. 셀 전체가 종이에 들어오지 않는 긴 입력이나 문단 분할까지 지원한다는 뜻은 아닙니다.

## 검증 범위

집중 검사는 원본 불변성, 완전한 셀/문단 소유권, 원본 폭 불일치, 부분/기존 클립, 변환·중첩·캡션 거부, source/display 분리, 행 누락·중복·겹침, 모든 caret의 2px 공간, 빈 셀과 같은 x 좌표의 경계, 허용 철회와 fallback의 새 Native ID 사용을 확인합니다. 실제 브라우저의 입력·clipboard·저장·이력·재열기는 별도 검사입니다. 실행법은 [개발 명령](development-commands.md), 증거 디렉터리는 `zig-out/verification/visible-overflow-cell-edit-r1/`입니다.


## 실제 브라우저 검증

동일 최종 번들에서 Vanilla·React·Svelte 각각 HWP5/HWPX 두 형식, 총 6개 경로로 완전히 보이는 두 번째 열 선택·기존 여러 문단 입력·신뢰된 clipboard 붙여넣기·undo/redo·저장 재열기를 확인했습니다. 독립 CFB/ZIP/XML 비교로 비대상 텍스트·셀 폭·문단 ID가 유지됨을 검사했습니다. 잘린 열의 읽기 전용 전환과 구조/셀 속성 버튼 비활성, 앞뒤 본문 편집도 확인했습니다.

별도 Vanilla 두 형식의 긴 입력 검사에서 10·30·60·120 단어쌍은 전체 요청이 반영되고 표 행이 늘어났습니다. 600·2400 단어쌍은 원본 저장 내용과 정확히 같은 상태로 거부됐으며 미확정 입력 취소 안내와 본문 편집·undo 복구를 확인했습니다. 이는 특정 합성 문서·현재 시스템 글꼴의 경계이며 일반적인 글자 수 제한이 아닙니다.

브라우저 8개 경로 모두 통과했고 소유한 세션은 종료했습니다. `browser-final/summary.json`의 manifest SHA는 `2c0500d407240050450566a824d1f0caa02cf011c589e24b8472f41456fe85bf`, WASM SHA는 `438044e0060fb0f40ab8a4a76eee2027e387f68579d547487fcd74ca88129088`입니다. 소스 회귀 485개와 렌더러 85개, 통합 셀 속성 113개를 구분해 기록합니다. 실제 독립 클릭으로 단독 호스트를 찾는 검증, 전체 사용자 문서와 한컴 조판 동치, Native 전체 suite는 이 근거에 포함하지 않습니다. 공개 서버 정적 바이트 동일성은 배포 후 별도 확인합니다.

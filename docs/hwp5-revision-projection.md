# 관측 변경 추적 범위의 UTF-16 바이트 변환

[필드 계약](hwp5-fields-contracts.md) · [원본 대조 근거](hwp5-merged-line-cache.md)

문단을 같은 흐름의 묶음으로 분류하는 책임은 [변경 추적 병합 인덱스](hwp5-revision-groups.md)가 소유합니다. 이 바이트 변환 함수가 문단 소유권을 추정하지 않습니다.

## 명시적으로 선택하는 코어 API

`hwp5.revision_projection.projectObserved(allocator, text, units, ranges, options)`는 한 문단의 원본 UTF-16 바이트에서 종류 `0x11`의 반열린 범위 `[start,end)` 합집합을 제외한 새 바이트 배열을 반환합니다. 호출자가 반환 배열을 해제하며 입력 텍스트·범위 배열은 변경하지 않습니다. 이 종류의 해석은 issue5169 루트 문단의 실측에 근거한 관측 계약이며 공개 명세가 모든 버전의 삭제 처리로 정의한 것은 아닙니다.

`text=null`은 기본적으로 `UnsupportedMissingRevisionText`입니다. 호출자가 `missing_text=.observed_cr`를 선택하고 선언 길이가 정확히 1일 때만 CR 1유닛을 후보 원문으로 사용합니다. 존재하는 빈 바이트 배열과 부재를 구분하며 선언 크기만큼 빈 문자를 생성하지 않습니다.

이 API는 **원시 코드 유닛 변환**입니다. 문단/리스트/구역의 병합 소유권, 제어문자 토큰·서로게이트 경계의 유효성, 변경 내용·작성자 ID 참조, 스타일/줄 위치 재계산, HWP 레코드 생성·편집·저장은 수행하지 않습니다. 범위가 서로게이트나 확장 제어문자를 자르면 출력도 그 바이트 결과를 그대로 가지므로 이를 저장 가능한 HWP 문단이나 Unicode 문자열로 간주하지 않습니다. 제품 JS 공개 API 및 기본 문서/컨테이너 검사는 이 변환을 자동 적용하지 않습니다.

## 책임·제한·복잡도

`body/range_tags.zig`가 범위 wire 배치와 `Range.validateBounds`의 `start<=end<=units`를 소유합니다. 기존 `metadata.validate`와 새 변환기가 이를 공유합니다. 범위 배열 길이는 기존 `Ranges.parse`가 검사하며 12바이트 폭 규칙을 복제하지 않습니다.

`body/revision_projection.zig`는 선택 범위를 복사·정렬·합집합으로 압축하고, 남는 바이트 수를 계산한 뒤 정확한 출력 크기만 할당합니다. 유지할 연속 부분을 복사하며 중복·중첩·인접 범위를 중복 차감하지 않습니다. 종류가 다른 범위도 공통 위치 경계는 검사하되 삭제하지 않으며 하위 24비트를 해석하지 않습니다. 시간은 O(R log R)와 출력 복사량, 임시 메모리는 선택 범위 수와 출력 크기에 비례합니다. 문자 수와 범위 수를 곱해 순회하지 않습니다.

기본 한도는 입력 텍스트 64MiB, 출력 64MiB, 범위 100,000개입니다. 범위 원문은 텍스트 바이트 한도와 별도로 범위 개수 제한을 받습니다. 출력 한도는 삭제 후 크기에 적용하므로 전체 삭제는 출력 한도 0에서도 성공할 수 있습니다. 입력 텍스트 한도는 여전히 적용하며 명시적 CR 후보도 2바이트로 셉니다. 범위 개수는 선택 여부와 무관한 전체 개수입니다. 홀수 텍스트·선언 길이 불일치, 잘린 범위 배열, 역전·초과 범위는 오류입니다. 실패 시 임시 배열을 해제하고 결과를 반환하지 않습니다.

## 실파일 및 적대적 검증

테스트 mode 100은 한 문단의 존재 플래그·명시적 CR 정책·선언 길이·세 한도·텍스트와 범위 원문을 받아 이 API를 호출합니다. 제품 ABI가 아닌 테스트 전용 경로입니다. 실제 바이트 길이를 검증한 뒤 전달하며 선언 길이로 버퍼를 할당하지 않습니다.

`revision-projection.mjs`는 6유닛 입력의 가능한 두 구간 조합 784개와 고정 seed의 다중 범위 입력 512개를 독립 JS 유닛 마스크와 비교합니다. 정렬·역순·중첩·중복·인접·빈 범위·전체 삭제를 포함하며 다른 종류·최대 데이터, 한도 정확값/부족, 잘림·길이 불일치·부재 텍스트 정책·오류 후 재처리도 검사합니다. 기본 범위 한도 100,000개 성공·100,001개 거부·원본 복구도 포함합니다. 최종 합성 정상 1,317건·거부 65건이며 실제 문단 변형 거부는 270건입니다.

실제 issue5169 ViewText 루트 문단 164개를 각각 WASM 변환한 뒤 관측 병합 순서로 연결해 BodyText 루트 문단 99개와 순서·UTF-16 바이트가 같은지 확인합니다. 각 문단의 정확한 출력 한도, 출력 한도 한 바이트 부족(비어 있지 않을 때), 초과 범위 추가와 오류 후 원본 재처리를 검사합니다. JS 후보와의 일치뿐 아니라 독립된 원본 BodyText가 최종 기대값입니다. 디스크 문서와 스냅샷은 수정하지 않습니다.

`revision_projection_tests.zig`는 성공·늦은 출력 한도 오류의 모든 할당 실패, 원문 보존, 세 한도, 배열 잘림, 부재/빈 값, 선택하지 않은 종류의 위치 오류를 검사합니다. 기본 줄 캐시 검사의 제한은 완화하지 않았습니다. 병합 소유권과 좌표 매핑의 제품 연결은 후속 구현입니다.

## 실행 결과

Debug → ReleaseSafe → ReleaseFast 전체 audit가 모두 성공했습니다. 각 모드 네이티브 269/269, 기존 Node 47/47 및 조사 도구 Node 15/15, 빌드 단계 16/16입니다. WASM 호출은 Debug 1,384,347회, Safe/Fast 1,384,862회입니다. Debug 실행 후 다중 범위·잘못된 플래그 테스트를 추가했고, 최종 100,000개 경계 테스트까지 포함한 전용 회귀 검사는 세 모드 산출물에서 모두 재실행해 위 최종 1,317/65 및 실제 변형 270건을 확인했습니다. 포맷·JS 구문·문서 링크·diff 검사도 통과했습니다. 전체 로그는 `/tmp/hwpjs-revision-projection-{debug,safe,fast}.log`입니다.

# 관측 차트 셀 배열

## 범위와 책임

`chart/grid_cells.zig`는 [격자 전처리](hwp5-chart-grid-prelude.md) 뒤의 행×열 슬롯을 순서대로 읽습니다. 명시적으로 선택한 VtChart v6 / VtString·VtDouble·VtValue·VtObject v1 관측 레이아웃입니다. 모든 차트 버전의 자동 판별, 전체 객체 그래프 또는 차트 편집/저장을 제공하지 않습니다.

슬롯의 `FFFFFFFF` u32는 관측 null 항목으로 네 바이트만 소비합니다. 다른 값은 원본 객체 ID로 보존하고 타입 참조, 값, VtValue 기반 타입 참조, VtObject 기반 타입 참조를 읽습니다. 타입 이름·버전과 재등장 처리는 기존 타입 목록을 재사용합니다. `type_checks.zig`는 전처리와 셀 파서의 기대 클래스/버전 비교를 공유하며, 실패 시 호출자가 전체 로컬 타입 목록을 해제합니다.

셀 좌표는 null을 포함한 배열 위치로 정합니다. 객체 ID를 좌표·배열 크기로 쓰거나 null을 제거해 압축하지 않습니다. 셀 범위 안에서 동일 객체 ID가 재등장하면 UnsupportedChartObjectReference로 거부합니다. 일반 객체 재참조의 본문 생략 여부나 전처리 원시 필드와의 전역 객체 동일성은 아직 해석하지 않습니다. 이를 임의의 빈 셀로 대체하지 않습니다.

`cell_value.zig`는 값 바이트만 책임집니다. VtString은 u16 길이, 해당 길이의 원본 바이트, 뒤따르는 원시 u8을 읽습니다. CP949/UTF-16 판별·문자 해석·NUL 검사·trim·정규화는 이 단계에서 하지 않습니다. VtDouble은 원본 u64 비트와 원시 u16을 읽으며 실수 산술 변환이나 값 크기 필터를 적용하지 않습니다. 두 후속 필드의 의미는 미확정이며 실제 수치 표본의 u16=65535를 모든 입력의 상수로 강제하지 않습니다.

## 수명과 한도

Grid는 셀 배열과 Prelude의 타입 이름을 소유합니다. 문자열 바이트는 원본 Contents를 빌리므로 Grid를 사용하는 동안 호출자가 입력을 유지해야 합니다. deinit은 소유 메모리만 해제합니다. 각 셀의 start/end와 전체 payload_offset을 보존하지만 후자는 셀 배열 이후의 위치일 뿐 격자 객체 전체의 끝이 아닙니다. 나머지 격자 필드·차트 객체·문자열 의미 해석은 후속 범위입니다.

전체 입력·슬롯 수·타입 수·타입 이름 한도는 Prelude/타입 목록에 위임합니다. 개별 문자열과 누적 문자열 바이트 상한은 독립적이며 남은 누적 한도를 먼저 적용합니다. 선언한 슬롯 수만 보고 전체 배열을 미리 할당하지 않고 실제로 소비한 슬롯만 추가합니다. 오류·OOM은 셀 배열, 객체 ID 검사 맵, 누적 타입 이름을 해제합니다.

## 실제 null과 좌표 가설 검증

초기 조사에서 객체 번호를 셀 위치로 보고 읽으면 43개 중 41개만 진행할 수 있었습니다. 실패한 두 표본에는 중간의 `FFFFFFFF` 네 개가 있었고, 그 뒤의 객체 번호는 빈 슬롯 수만큼 셀 위치와 달랐습니다. null 슬롯과 객체 번호를 구분해 읽은 결과 43/43, 총 750개 슬롯·51개 null·699개 값이 순차 소비되었습니다. null 이후 객체 번호와 슬롯 위치가 다른 값은 총 10개입니다. 문자열 검색이나 뒤쪽 형제 마커로 셀 배열 끝을 결정하지 않았습니다.

아래 SHA-256은 외부 HWP 전체가 아니라 내부 Contents 바이트의 해시입니다. 슬롯 번호는 1-based입니다.

| Contents SHA-256 | 치수 | null 슬롯 | 셀 배열 이후 offset |
|---|---|---|---|
| `6e9a21d261ce6f01a404ad003cb68dd4797071677920015b3cf7257fda2d487e` | 5×5 | 1,17,18,19,20 | 772 |
| `5b3cf2ef71fdf03d26c798cb90e14b0b0de746d42b3faa6b7364f79e0ed61fff` | 6×5 | 1,22,23,24,25 | 907 |

같은 내부 CFB의 OOXMLChartContents도 대조했습니다. 각각 ‘계열 4’/‘계열 5’에는 c:val이 없고, 다음 ‘종가’ 계열의 수치 캐시는 32/35/34/35입니다. 슬롯을 보존한 Contents의 마지막 행도 같은 라벨 원본과 수치입니다. `chart-grid-gap-evidence.mjs`의 추출은 이 두 고정 표본용 정규식 조사이며 제품 OOXML 파서가 아닙니다. XML의 32를 33으로 바꾸거나 null 슬롯을 제거한 대조 결과는 assertion 실패했습니다.

rhwp의 `ole_chart/grid.rs`는 현재 cell_header에서 읽은 번호를 인덱스로 취급해 좌표를 계산하고, 내부 숫자 개수를 치수에서 계산한 값과 비교합니다. 이 코드와 조사 가설의 차이는 확인했지만 이번 단계에서 rhwp 실행 결과나 수정 효과까지 측정한 것은 아닙니다. 표본 관측을 전체 차트 직렬화 명세의 증명으로 확대하지 않습니다.

## 검증과 미완료 경계

비공개 mode 311은 개별/누적 문자열 바이트·슬롯·타입 수 상한 u32 네 개와 Contents를 받습니다. 별도 limit은 Contents 길이 상한입니다. 출력은 행·열·슬롯 수·후속 offset·타입 수·문자열 바이트 합계 u32 여섯 개, 이어서 슬롯마다 객체 ID(null이면 FFFFFFFF)·종류·start·end·원시 후속 필드·값 길이 u32 여섯 개와 원본 값 바이트입니다. 숫자는 u64 비트 그대로 반환합니다. 공개 JS API는 변경하지 않습니다.

독립 JS 조사기는 타입 선언과 순차 슬롯을 읽어 바이트 응답을 구성하고 고정 해시/null 슬롯/OOXML 결과를 별도로 대조합니다. 세 모드 전용 WASM에서 각각 정상 291건·오류 28,765건을 통과했습니다. 모든 셀 앞부분 잘림은 extent를 다시 계산해 깊은 읽기까지 도달하게 하고 오류 후 원본을 재호출했습니다. 개별·누적 한도, 중복 객체 ID, 기반 클래스, 타입 버전, 부호 있는 0·무한대·NaN 비트·원시 문자열 변경을 검사합니다.

네이티브는 비연속 ID와 ID 0, 중간 null, 문자열 입력 대여, 원시 후속 필드, 최대 u16 문자열, 0개 슬롯, 실패 시 커서 보존, 각 바이트 잘림, OOM 주입과 명시적 allocator 잔량 0을 검사합니다. 기존 차트 테스트와 합쳐 Debug/ReleaseSafe/ReleaseFast 모두 root 포함 17/17 통과했습니다.

`/tmp/hwpjs-chart-cells-mutants.a15PL6`의 별도 소스에서 null 누락(null), 수치 하위 비트 삭제(bits), 누적 문자열 한도에서 기존 소비량 차감 생략(total), 실패 시 타입 목록 해제 생략(leak), 기대 기반 클래스 검사 생략(base)을 실행했습니다. 다섯 변형 모두 세 모드에서 실제 assertion 또는 MemoryLeakDetected·종료 코드 1로 검출했습니다. 컴파일 실패를 검출 성공으로 세지 않았습니다.

첫 표본의 응답 720바이트를 한 바이트씩 XOR 1 한 변형도 세 모드에서 각각 720/720 검출했습니다. LimitExceeded를 같은 메시지의 WebAssembly.RuntimeError로 바꾼 경우도 정상 오류로 세지 않고 assertion 실패했습니다.

소스와 테스트를 고정해 Debug → ReleaseSafe → ReleaseFast 전체 audit를 순차 실행했습니다. `/tmp/hwpjs-chart-grid-cells-{Debug,ReleaseSafe,ReleaseFast}-audit.log`에서 각 모드 27/27 단계·1,006/1,006 네이티브 테스트·HWP/WASM 7,915,646회 검사 통과를 확인했습니다. Debug 실행 및 뒤이은 두 최적화 모드의 순차 실행 모두 종료 코드 0입니다. 포맷·JS 구문·공백과 문서 로컬 링크 19개도 검사했습니다. 이 결과는 셀 배열의 현재 계약을 포함한 검사이며 전체 차트·전체 문서의 의미 해석 완료를 뜻하지 않습니다.

최종 `zig build test --summary all`은 5/5 단계·1,006/1,006 테스트, `zig build -Doptimize=ReleaseSafe --summary all`은 5/5 단계로 통과했습니다(종료 코드 0).

# ICC 넓은 목표값의 클리핑 거듭제곱 역상

## 계약

`power_preimage.solveWide(precision, curve, n, d)`는 u512 정규화 목표값에 대해 활성 거듭제곱 분기에서 clip(f(x))=n/d인 실제 x의 집합을 보존합니다. [넓은 활성 근 위치](icc-extended-locations.md)가 목표와 전체 곡선 정의역을 먼저 검증합니다. 결과는 inactive/undecided/set이며 빈 set과 inactive를 구분합니다. undecided에는 부분 집합을 노출하지 않습니다.

`Wide.Set`은 source, 최대 여섯 기호 구간, 최대 두 u1024 radicand 기호근을 담습니다. count 밖 항목은 읽지 않습니다. 결과는 점과 구간의 집합 합집합이며 정렬·병합·중복 제거된 목록은 아닙니다. 기호근 순서는 x 순서가 아니고 각 항목에 역상 선택을 개별 적용해서는 안 됩니다. source의 a/b를 통해 x를 뜻하며 근사 좌표를 생성하지 않습니다.

## 완전성과 SSOT

0<y<1에서는 기존 등식 근만 수집합니다. y=0/1에서는 기존 클리핑 분할의 zero/one 구간과 정확한 등식 근을 모두 수집합니다. 분할 끝점 소유권 때문에 평탄 구간만으로는 경계 단독 해를 놓칠 수 있고, (2x−1)^2의 y=0은 단독 근뿐일 수도 있습니다. 전체 분기가 같은 목표값이면 source 전체 구간 하나로 표현합니다.

기존 [u128 거듭제곱 역상](icc-power-preimage.md)과 solveFor의 합집합 조립을 공유합니다. power_preimage_types.Of는 입력 폭별 Located·Set·Result 타입만 구분합니다. source와 클리핑 구간 경계는 고정 원시 계수의 수준 0/1에만 의존하므로 기존 power_clip 표현을 그대로 공유합니다. 이를 재사용하는 것은 u512 목표값을 좁히는 연산이 아닙니다. 임의 내부 목표값의 점은 넓은 근을 그대로 보존합니다.

목표 검증·정의역·근 위치·클리핑 분할 규칙을 이 계층에서 다시 구현하지 않습니다. 코어는 할당하거나 입력을 변경하지 않습니다. 기존 solve/Result와 제품 JS API 계약은 유지합니다.

## 독립 집합 검사

테스트 mode225는 precision u32+n/d u512의 132바이트 BE prefix 뒤 para 태그를 받습니다. status/count/source 및 구간 wire는 기존 mode199와 같으며 점만 location u32+268바이트 넓은 근, 총 272바이트로 확장합니다. inactive/undecided 출력은 count가 0인 12바이트이고 부분 source나 집합을 붙이지 않습니다. 입력 파싱과 출력 serializer는 기존 모드와 폭별로 공유합니다.

JS decode는 독립 wire 계약을 폭별로 해석하고, 기존 critical-cell 기준이 입력의 목표·0·1 근과 밑 영점, source/출력 경계의 모든 점과 그 사이 열린 구간의 포함 여부를 대조합니다. 제품의 점+평탄 구간 수집이나 상하한 계산을 기대값으로 사용하지 않습니다. 넓은 목표값은 끝점에서 512번 이상의 이분 탐색이 필요한 근을 만들 수 있어, 독립 표본 탐색 한도를 목표값 비트 길이에 따라 확장했습니다. 한도 초과는 계속 실패이며 표본을 찾지 못한 구간을 성공으로 건너뛰지 않습니다.

Debug 직접 대조는 comparisons=6,448, rejected=3,447, undecided=1, membershipChecks=19,026으로 통과했습니다. membershipChecks는 반환 집합 내부 검사 수이며 별도 WASM 호출 수가 아닙니다. 기존 u128 경로도 6,440/3,351/1 및 membershipChecks=18,994로 통과했습니다. 다섯 곡선 유형, 양·음·영 지수, 음의 기울기, 상수 밑, inactive, 목표 0/1/1/3, 넓은 분모의 끝점/이웃, 잘림·한도·오류 후 복구를 포함합니다.

활성 시작 출력 바로 위의 넓은 목표 `65537^2*2^448/(2^512−1)`는 128비트 정밀도에서 undecided이고 1024비트에서는 단일 내부 근입니다. 미확정에 부분 집합을 내보내지 않는지 확인합니다.

## 적대적 검사와 실파일 호환성

유효한 count/길이를 맞추면서 점을 모두 제거하거나 구간을 모두 제거하는 변형, 첫 구간의 포함 플래그 제거, undecided→inactive 변형은 모두 ERR_ASSERTION으로 검출했습니다. 임시 복사본 `/tmp/hwpjs-extended-preimage-mutant.leqsIt/icc`에서 내부 목표 판정을 and→or로 바꿔 클리핑 구간 수집을 건너뛰는 소스 변형은 세 모드 모두 네이티브 4개 중 2개가 실패했습니다. 제품에 변형은 남기지 않았습니다.

시스템 ICC 5개 프로파일의 para 태그 15개에서 목표 0/1의 기존 경로와 u512 최대 분모로 표현한 새 경로를 대조했습니다. source·구간·근 위치/부호/역지수·radicand 비율이 30건 일치했습니다. 읽기 전용 수동 호환성 검사이며 공유 구현의 독립 증명이나 실제 렌더링 일치로 세지 않습니다. 정규 audit 호출 수에도 합산하지 않습니다.

## 최종 회귀 결과

Debug·ReleaseSafe·ReleaseFast 전체 audit가 모두 종료 코드 0, 20/20 단계, 네이티브 638/638, WASM checks=6,934,353으로 완료됐습니다. 이전 6,924,457에 신규 9,896회 호출이 추가됐습니다. membershipChecks는 별도 호출로 더하지 않습니다. 로그는 `/tmp/hwpjs-extended-preimage-{Debug,ReleaseSafe,ReleaseFast}.log`이며 임시 로컬 산출물입니다.

Safe/Fast 실제 audit WASM의 직접 집합 대조·기존 경로 회귀·출력 변형 4종도 같은 결과로 통과했습니다. 소스 변형은 세 모드 네이티브 검사로 검출했습니다. 변경 주제 문서의 로컬 링크 8개, Zig 포맷·JS 문법·diff 공백 검사를 확인했습니다. 기존/새 경로가 합집합 조립을 공유하고, 목표 폭과 무관한 클리핑 경계는 기존 타입을 유지하는 것을 재검토했습니다.

## 남은 구현

이 모듈은 상위 거듭제곱 분기의 클리핑 역상을 소유합니다. 하위 선형 분기와의 합집합은 [넓은 전체 도달 역상](icc-extended-parametric-preimage.md)에 분리합니다. 정규화·정렬, 단조성·비상수성 판정, F.1 역상 선택, 최근접 출력과 넓은 TRC 모델 통합은 후속 범위입니다. 전체 ICC/HWP/HWPX 문서 검증은 미완료입니다.

# 클린룸 우선 구현 방침

사용자 결정: 앞으로 가능한 범위에서는 클린룸 방식을 우선합니다. 대상은 새로 작성하거나 대체하는 포맷 해석·편집·조판의 도메인 구현과 호환성 데이터입니다. 일반 SDK·표준 라이브러리·개발 도구의 정상적인 사용까지 금지하는 규칙은 아닙니다.

## 기본 참고 자료

- 한컴이 공개한 HWP5 명세와 HWPX/OWPML 스키마, 관련 표준과 공개 API 문서.
- 출처를 확인한 실제 문서의 원본 필드, 독립적으로 만든 합성 입력과 기대값.
- 허용된 환경에서 직접 관측한 입출력·화면·저장 결과. 대상 구현 코드에서 읽어낸 상수나 정책을 독립 관측으로 바꾸어 표기하지 않습니다.
- 각 자료의 버전·출처·확인 범위를 남기고, 명세의 요구와 제품이 선택한 편집 정책을 분리합니다.

로컬 명세 정리본에는 과거의 구현 참고·보정 주석이 섞여 있을 수 있습니다. 클린룸 담당자에게 전달하기 전에 공식 원문과 대조하며, 타 구현에서 유래한 메모를 명세의 사실로 전달하지 않습니다.

## 구현과 비교의 분리

새 구현 담당자에게 rhwp 등 비교 대상의 소스·포트된 코드·측정 표·내부 알고리즘 설명을 기본 입력으로 제공하지 않습니다. 담당자는 명세·인터페이스·독립 기대값을 바탕으로 구현하고, 비교 담당자가 별도로 대상 제품의 공개 동작과 대조합니다. 차이는 관측 가능한 입력·출력과 재현 조건으로 보고하며 내부 코드나 내부 정책을 구현 담당자에게 전달하지 않습니다.

엄격한 클린룸이 필요한 모듈은 참고 자료의 allowlist와 구현 작업 공간을 분리하고 접근 범위·제공 자료를 기록해야 합니다. 이미 참조 코드를 읽은 에이전트의 재작성이나, 같은 저장소를 자유롭게 읽을 수 있는 새 서브에이전트만으로 독립 절차가 입증되지는 않습니다. 분리·접근 이력을 확인하지 못하면 '명세 기반 재작성' 또는 '클린룸 우선 후보'로 표시하고 엄격한 클린룸 완료라고 선언하지 않습니다.

공식 명세만으로 판단할 수 없는 부분은 미확정 상태와 재현 사례를 남깁니다. rhwp 코드를 열어 빈 부분을 채우는 것을 자동적인 다음 단계로 삼지 않습니다. 직접 코드·알고리즘·측정 데이터 참조가 필요하다고 판단하면 먼저 이유와 필요한 범위, 클린룸 범위에 미치는 영향을 설명합니다. 그런 참조를 한 부분은 엄격한 클린룸으로 표시하지 않으며, 사용자가 허용한 작업 범위 안에서 진행합니다. 기존에 허용된 일반 의존성 사용을 매번 재승인받는 절차는 아닙니다.

## 기존 참조분

[rhwp 참조 원장](rhwp-reference-inventory.md)의 과거 포트·측정 데이터·정책 참조 기록은 유지합니다. 이력이나 고지를 지우고 코드를 바꿨다는 이유만으로 독립 출처로 재분류하지 않습니다. 현재 세션과 이미 해당 자료를 읽은 담당자 역시 그 열람 이력을 무시하지 않습니다.

기존 참조분은 공식 자료만으로 재구성 가능한 부분, 독립 측정이 필요한 부분, 아직 근거가 부족한 부분으로 나누어 대체 여부를 결정합니다. 실제 대체에는 기존 기능의 회귀 검증과 새 구현의 자료·작업자·검증 출처 기록이 필요합니다. 참조 구현이 남는 동안 기존 라이선스·저작권 고지는 보존합니다. 이번 방침 변경 자체로 기존 코드를 삭제하거나 지원 기능을 축소하지 않습니다.

## 완료 표현

코드 가독성·책임 분리를 뜻하는 클린코드와 구현 출처·절차를 뜻하는 클린룸을 구분합니다. 테스트 통과는 동작의 증거이며 독립 출처의 증명은 아닙니다. 새 모듈의 출처 분리와 기존 참조 코드가 남은 프로젝트 전체의 상태도 따로 설명합니다. 이 방침은 작업 절차이며 법적 판정을 대신하지 않습니다.

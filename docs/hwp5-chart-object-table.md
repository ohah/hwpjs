# 차트 객체 목록과 String 재참조

## 범위와 책임

`chart/object_table.zig`는 타입 목록과 별개의 객체 ID 목록입니다. 현재 값 종류는 String v1과 ‘그 외 객체’입니다. 일반 객체 그래프 복원기·전방 참조/순환 해결기·모든 종류의 객체 재참조를 구현한 것은 아닙니다. 현재 참조 해석은 String에 한정합니다.

호출자는 선택한 직렬화 범위에서 앞서 확인한 객체를 빠짐없이 등록해야 합니다. registerString은 이미 파싱한 String 원본을, registerOther는 문자열이 아닌 객체 ID를 등록합니다. 같은 ID의 재등록은 DuplicateChartObjectId로 거부하고 기존 정의를 덮어쓰지 않습니다. ID 0은 유효하며 FFFFFFFF는 관측 null이므로 등록/읽기를 거부합니다. 검사는 기존 object_ids와 공유합니다.

readStringObservedV1은 객체 ID를 먼저 읽습니다. 등록된 String이면 네 바이트만 소비하고 기존 값과 introduced=false를 반환합니다. 알려진 다른 종류는 UnsupportedChartObjectReference입니다. 미등록 ID는 기존 inline String 파서로 새 정의를 읽고 성공 시 등록하며 introduced=true입니다. 바이트 패턴 검색이나 내용이 비슷한 문자열로의 대체는 하지 않습니다. 이전 객체 등록이 빠진 상태에서 완전한 참조 판별을 보장하지 않으며, 미등록 ID 뒤에 정의가 없는 입력을 빈 값으로 복구하지 않습니다.

## 소유권과 실패

목록은 해시 맵만 소유합니다. String의 bytes는 원래 입력을 빌리고 ID·후속 u8은 값으로 보존합니다. 참조 대상은 현재 reader와 다른 입력 버퍼에 있을 수도 있으므로 등록한 모든 원본의 수명을 호출자가 유지해야 합니다. 입력 변경은 빌린 값에도 보이며 내용을 복사해 고정하는 API가 아닙니다. deinit은 원본 바이트를 해제하지 않습니다.

Reference의 start/end는 현재 정의 또는 참조를 읽은 위치입니다. 기존 객체 참조에서는 end=start+4이고, value의 bytes는 앞선 정의의 payload입니다. 새 정의 여부를 별도 보존하므로 참조를 inline 데이터와 혼동하지 않습니다.

등록 실패는 객체 목록의 논리 항목/바이트 회계를 유지합니다. readStringObservedV1 실패는 reader도 유지합니다. 단, 새 String을 읽는 동안 타입 목록은 변경될 수 있으므로 호출자는 오류 뒤 타입 목록을 폐기해야 합니다. Font/Legend처럼 앞서 다른 객체를 등록하는 상위 파서는 실패 시 두 목록 모두 폐기하는 계약입니다.

## 독립 한도

기본 상한은 객체 1,000,000개, 개별 String 65,535바이트, 등록된 String 합계 16 MiB입니다. 개별 String은 관측 u16 길이 범위도 넘을 수 없습니다. 그 외 객체도 객체 개수에 포함합니다. 서로 다른 ID의 정의는 내용이 같아도 각각 합계에 포함하고, 동일 객체의 재참조는 저장 바이트를 다시 부과하지 않습니다.

재참조에서도 호출자의 max_bytes와 개별 String 한도를 확인하므로, 미리 큰 값을 등록했다고 필드 한도를 우회할 수 없습니다. 저장 한도가 꽉 찬 상태에서도 기존 객체는 새 할당/등록 없이 참조할 수 있습니다. 이 합계는 정의 저장량이지 반복 참조의 누적 출력 크기가 아닙니다. 전체 입력, 출력 확장량과 소비자 측 반복 처리 한도는 별도 책임입니다.

## 검증

네이티브는 새 String과 100회 재참조, 독립 한도·누적 저장량, 잘못된 종류·null·중복 정의, 원본 대여 수명, 빈 값/ID 0/비연속 ID, 모든 바이트 잘림을 검사합니다. 타입 선언을 모두 읽은 뒤 처음 객체 맵을 할당하는 늦은 OOM도 별도 주입해 reader·객체 수·바이트 합계가 유지됨을 확인합니다. 타입 목록 자체의 롤백을 통과 조건으로 삼지 않습니다. 성공/오류 경로의 해제와 실제 참조 소비 검증은 [범례 조립](hwp5-chart-legend.md)의 검증 기록과 함께 관리합니다.

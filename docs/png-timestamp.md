# PNG 수정 시각 검증

## 범위와 명세

[PNG Third Edition §11.3.5.1](https://www.w3.org/TR/png-3/#11tIME)의 tIME payload는 정확히 7바이트입니다. `timestamp.zig`가 big-endian u16 연도와 월(1..12)·일(1..31)·시(0..23)·분(0..59)·초(0..60)를 읽습니다. 연도는 전체 값을 보존하며 두 자리 연도를 추정 보정하지 않습니다. 초 60은 윤초를 위한 명세상 허용값입니다.

검증 범위는 PNG가 명시한 필드 범위입니다. 연도 0을 임의로 금지하거나, 2월 31일을 다음 달로 정규화하거나, 초 60을 역사적 윤초 발생표와 대조하지 않습니다. 따라서 성공이 그레고리력상의 실제 날짜·실제 수정 시각을 보증하지는 않습니다. 명세는 UTC 사용을 권고하지만 wire에는 시간대 식별자가 없으므로 입력의 UTC 여부를 검증했다고 주장하지 않습니다. 로컬 시간 변환·시계 접근·날짜 문자열 생성·자동 시각 갱신은 없습니다.

[§5.6 청크 순서](https://www.w3.org/TR/png-3/#5ChunkOrdering)에 따라 tIME는 최대 하나이며 추가 위치 제한이 없습니다. `metadata.State`가 중복과 성공한 청크 카운트를 소유합니다. IDAT 전후 모두 허용하되, IHDR 첫 청크·IEND 마지막 청크·연속 IDAT 규칙은 기존 structure 검사가 그대로 적용합니다. tIME를 두 IDAT 사이에 넣어도 된다는 뜻은 아닙니다.

`pixels.Report.timestamp`는 optional 소유 값으로 입력 바이트 수명과 무관합니다. 부재는 null이며 시스템 시각으로 채우지 않습니다. payload 파싱 실패나 중복은 기존 값을 바꾸지 않습니다. 성공한 tIME의 1청크·7바이트만 ancillary deferred에서 제외하며, 다른 청크 의미 검증 성공으로 대체하지 않습니다. 제품 JS API는 변경하지 않습니다.

## 검증 경로

네이티브는 전체 u16 연도 65,536개, 각 날짜·시간 바이트의 0..255, 길이 경계, 소유 값 보존, IDAT 이후 허용, 오류 시 상태 불변, 모든 할당 실패 시 정리를 검사합니다.

테스트 전용 WASM mode 134는 전체 PNG와 입력 한도를 받아 9개 u32 LE(36바이트)를 반환합니다: 존재 여부·연도·월·일·시·분·초·deferred 청크·바이트. `png-timestamp-evidence.mjs`가 Buffer 읽기와 독립 범위표로 기대값을 계산합니다. 제품 코드나 호스트 Date의 날짜 정규화를 기대값에 사용하지 않습니다.

정규 audit에는 모든 필드 바이트, 연도 경계·byte order, 크기·CRC·전체 파일 잘림, 중복, IHDR 이전/IEND 이후/IDAT 사이 거부, 기존 메타데이터 전후 모든 삽입 위치와 unknown ancillary 유지, 실패 후 정상 재호출, 실제 HWP PrvImage 회귀 비교를 포함합니다.

Debug·ReleaseSafe·ReleaseFast 전체 audit를 순차 실행해 각각 17/17 단계, 네이티브 365/365, 감사 스크립트 3,181,786 checks를 통과했습니다. 전용 결과는 정상 243건·거부 1,437건(정상 입력의 한도 미달 거부 포함)입니다. 실제 PNG 32개에는 tIME가 없어 양성 timestamp 검증은 합성 입력에 한정합니다.

추가 수동 적대적 검사에서는 IDAT 뒤에 tIME를 배치하고 Debug WASM에서 연도 0..65535 전체를 실행했습니다. 월/일/시/분/초를 12/31/23/59/60으로 고정한 보고서 65,536개가 독립 기대값과 모두 일치했습니다. 이 추가 WASM 검사는 정규 audit 횟수에 포함하지 않습니다. 포맷·변경 JS 문법·관련 로컬 문서 링크 27개·diff 공백 검사도 통과했습니다.

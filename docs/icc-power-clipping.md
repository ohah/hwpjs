# ICC 거듭제곱 분기의 클리핑 구간 조립

## 범위

이 구간 방향과 원래 분기 경계의 점프를 합치는 [전체 단조성·상수성 판정](icc-parametric-trend.md)은 별도 계층이 소유합니다.

[ICC.1:2022 Table 68](https://www.color.org/specifications/ICC.1-2022-05.pdf)의 **활성 거듭제곱 분기**에 대해 출력 0/1 클리핑을 반영한 구간을 조립합니다. [밑 영점 분할](icc-curve-partition.md), [정확한 근 비교](icc-power-root-compare.md), [근 위치 판정](icc-root-locations.md)을 재사용합니다. 하위 선형 분기와의 합집합·분기 간 점프·전체 단조성·역변환은 아직 이 결과에 포함하지 않습니다.

`power_clip.partition(precision, curve)`는 기존 전체 실수 정의역 검사를 먼저 실행합니다. 클리핑 때문에 가려질 것 같은 0^0·음의 지수의 영점·음수 밑의 비정수 지수도 유효한 곡선으로 승격하지 않습니다. precision은 기존 128/256/512/1024비트 비교 정밀도입니다.

결과는 inactive(거듭제곱 분기 없음), undecided(현재 정밀도에서 분할 미확정), plan입니다. 미확정 시 이미 계산한 일부 구간을 완성된 plan으로 반환하지 않습니다. 모든 입력이 최대 정밀도에서 반드시 판정된다는 보장은 여전히 증명되지 않았습니다.

## 값과 경계 표현

`Plan.source`는 원본 거듭제곱 분기의 a/b/g/offset과 활성 유리수 구간을 보존합니다. 전체 para 태그나 하위 분기 계수를 저장하는 모델은 아닙니다. source는 `power_partition.Result.source`에서 전달되며 계수/활성 구간을 다시 추정하지 않습니다.

최대 여섯 Piece 각각에 구간, kind(zero/power/one), direction(constant/increasing/decreasing)이 있습니다. zero/one은 최종 출력 상수 0/1이며 방향도 constant입니다. power는 원래 거듭제곱+오프셋 식을 사용합니다. 한 점 구간과 원래 상수 식의 방향 역시 constant입니다. 원래 밑 영점 분할 경계는 유지하므로 인접 상수 구간이 반드시 병합되지는 않습니다.

경계는 정규화 Fraction 또는 LevelRoot입니다. LevelRoot는 0/1 수준 식과 원본 기호적 밑 근을 보존하며, **source의 선형 변환 아래 x 역상**을 뜻합니다. 무리수 x 좌표를 f64/Fraction으로 강제 반올림하지 않습니다. 시작/끝의 포함 여부는 각각 명시합니다. 실제 닫힌 끝점의 클리핑 근은 원래 유리수 끝점으로 보존하고, 그 앞 구간은 끝점을 제외하며 별도 닫힌 한 점 구간이 그 점을 소유합니다.

## 책임 분리와 판정

- `affine_value`: 원본 signed 16.16 a/b와 유리수 x의 `(a*x+b)/65536`을 정확한 i128/u128 값으로 만듭니다. 기존 근 비교와 새 값 비교가 공유합니다.
- `power_level_order`: 포함된 한 점의 **클리핑 전 값**을 raw i32 수준과 비교합니다. 해당 점의 실수 정의역과 구간 포함을 검사합니다. 전체 분기의 유효성은 상위 조립기가 검사합니다.
- `power_root_order`: 같은 역지수의 근끼리 정확히 정렬합니다. 부호가 같을 때 양수 크기를 동일한 양의 거듭제곱으로 비교할 수 있으므로 radicand 정수 순서를 사용합니다. 음의 지수·음수 근·음의 선형 기울기는 필요한 순서를 반전합니다. 두 비영 근의 역지수가 다르면 IncompatibleIccPowerRoots이고, x 역상 정렬에서 a=0이면 NonIsolatedIccAffineRoot입니다. 서로 다른 곡선의 임의 대수적 수 비교기는 아닙니다.
- `power_clip_types`: 구간 경계·수준·종류·최대 여섯 결과의 값 표현을 소유합니다.
- `power_clip_classify`: 시작점 직후의 출력 종류와 수준 통과 후의 종류 변경을 결정합니다. 시작점이 정확히 0/1일 때는 방향을 사용하고, 한 점/상수 분기는 실제 값으로 분류합니다. 비교가 미확정이면 종류도 미확정입니다.
- `power_clip`: 유효한 원본 분할의 각 단조 구간에서 수준 근을 수집·정렬하고, 끝점 소유권을 유지해 결과를 조립합니다.

값 비교는 큰 거듭제곱 자체를 f64로 계산하지 않습니다. 영점과 g=0은 정확한 정수식으로 처리하고, 거듭제곱 부호와 목표값 부호가 다르면 바로 순서를 증명합니다. 같은 부호일 때 해당 밑 부호의 수준 근을 기존 정확한 비교기로 비교합니다. `d(z^g)/dz`의 부호 `sign(g)·sign(z)·sign(z^g)`를 적용하여 원래 값 순서로 바꿉니다. 공통 정수 지수 분류와 표준 Order.invert를 재사용합니다.

원래 밑 영점 분할은 최대 두 구간이며, 각 비상수 구간은 엄격히 단조입니다. 따라서 0과 1 각각의 근은 그 구간에 최대 하나이고, 두 절단점으로 최대 세 구간이 생깁니다. 전체 결과 상한은 여섯입니다. 시작점의 근은 기존 경계를 사용하고, 내부 근은 오른쪽이 소유합니다. 제외된 열린 끝점의 근은 새 한 점 구간을 만들지 않습니다. 배열 한계와 모순된 내부 상태에는 명시적인 invariant 오류를 두었습니다.

## 독립 검증

네이티브 검사는 같은 지수의 양/음 근과 역지수 정렬, i32 최솟값 기울기, 서로 다른 지수 거부, 음수 밑·음의 지수의 값 순서, 실수 정의역 오류, u64 Pell 좌표, 양/음 선형 변환의 여섯 구간 굴곡, 닫힌 끝점 한 점 소유권, 클리핑 후 전체 상수 0/1과 비활성 분기를 포함합니다. 분수는 약분을 요구하지 않고 정확한 동등성으로 대조합니다.

분류기 자체에는 u64 Pell 상위 좌표를 포함된 시작점으로 주었습니다. 128비트는 시작 종류 미확정, 512비트는 one으로 판정됩니다. 이는 내부 분류기의 미확정 경로 증거이며, 원본 para 파라미터로부터 전체 partition의 undecided를 재현한 사례라고 확대하지 않습니다.

독립 JS 기준은 BigInt 정수 거듭제곱·유리수 교차 곱을 직접 전개합니다. 출력 구간은 다음을 검증합니다.

- 원본 계수·활성 범위 일치와 경계 표현의 유효성.
- 첫/마지막 끝점, 인접 구간의 정확한 연결, 오른쪽 소유권, 비어 있지 않음.
- **모든** 포함된 0/1 수준 근과 밑 영점의 경계 보존. 임의 격자 샘플만으로 누락을 판단하지 않습니다.
- 유리수 이분 탐색으로 구간 내부 점을 찾고 BigInt 식으로 종류와 방향 확인. 모든 임계점의 보존을 별도로 검사하므로 내부에서 놓친 클리핑 교차·굴곡이 없다는 조건 아래 대조합니다.
- 닫힌 한 점 구간의 포함 플래그와 constant 방향.

범위가 1/2147483647인 극값 상쇄 구간, 양/음 i32 극값 오프셋, 큰 지수에서 f64가 언더플로하더라도 실제 비영 power 구간을 유지하는 사례도 포함합니다. 구간 양쪽을 모두 닫아 겹치게 만드는 임시 반환값 변형은 ERR_ASSERTION으로 검출됐으며 제품에는 남기지 않았습니다.

## 테스트 wire

mode187은 precision u32 BE, target i32 BE, x의 n/d u64 BE 다음 para payload를 받아 클리핑 전 값 비교 −1/0/+1 또는 미확정 2의 i32 LE를 반환합니다. mode188은 g/offset/두 target i32 BE, 두 root index u32 BE, slope i32 BE의 28바이트 입력으로 x 역상 순서 i32 LE를 반환합니다. 기존 근 선택기를 공유합니다.

mode189는 precision u32 BE 다음 para payload를 받습니다. 출력 첫 8바이트는 status(0 inactive/1 undecided/2 plan), count u32 LE입니다. plan일 때만 기존 40바이트 원본 구간과 a/b/g/offset i32 LE 네 개가 붙어 64바이트 머리가 됩니다. 구간당 76바이트는 32바이트 시작 경계, 32바이트 끝 경계, 포함 flags·kind·direction u32 LE입니다. 최대 출력은 520바이트입니다.

경계 type 0은 n/d u64 LE(위치 4/12), type 1은 level u32 LE(4)와 기존 20바이트 근 표현(8)을 담습니다. 사용하지 않은 바이트는 0입니다. interval/root wire는 기존 소유자를 공유합니다. 제품 JS API에는 새 테스트 모드를 노출하지 않습니다.

## 실행 기록

최초 네이티브 추가 검사는 약분된 분자 1을 기대한 단언 때문에 508/509로 실패했습니다. 실제 131072/262144는 원래 계약대로 1/2이며, 제품을 약분하도록 바꾸지 않고 분수 동등성 단언으로 수정했습니다. 이후 초기 전체 Debug 감사 `/tmp/hwpjs-icc-power-clip-Debug-initial.log`는 20/20 단계·509/509·WASM 검사 6,401,143건으로 통과했습니다. 이 실행은 신규 JS 검사 연결 전이므로 최종 근거와 구분합니다.

확장된 직접 WASM 대조는 값 비교 5,790건·근 정렬 528건·예상 거부 10,485건, 클리핑 비교 7,534건·거부 4,022건·출력 구간 8,480개로 통과했습니다. 극값 상쇄 네 사례는 첫 Debug 실행이 시작된 뒤 추가됐으므로 최종 Debug를 다시 확인합니다.

실제 시스템 ICC para TRC 태그 15개(type0/type3)에서도 30개의 클리핑 구간을 확인했습니다. 이 태그들은 양의 a/g·비음수 b·출력 오프셋 0이므로 상한 경계 `(65536-b)/a`를 정수 유리수로 직접 계산해 위치·종류·방향·끝점 소유권을 대조했고 일치했습니다. 읽기 전용 조사이며 수동 건수는 정규 감사에 합산하지 않습니다. 하위 분기와의 연결이나 픽셀 결과 검증은 아닙니다.

확장 후 최종 기준 로그는 `/tmp/hwpjs-icc-power-clip-Debug-complete.log`, `/tmp/hwpjs-icc-power-clip-ReleaseSafe-final.log`, `/tmp/hwpjs-icc-power-clip-ReleaseFast-final.log`입니다. 먼저 실행된 `/tmp/hwpjs-icc-power-clip-Debug-final.log`는 극값 네 사례 추가 전 이력으로 구분합니다.

ReleaseSafe·ReleaseFast 최종 로그는 각각 20/20 단계·510/510 네이티브 테스트·WASM 검사 6,429,502건으로 통과했습니다. ReleaseFast 산출물 직접 대조도 값 비교 5,790건·근 정렬 528건·거부 10,485건, 클리핑 비교 7,534건·거부 4,022건·출력 구간 8,480개로 통과했습니다. 비상수 power 구간을 zero/constant로 잘못 바꾸는 임시 반환값 변형은 독립 검사가 ERR_ASSERTION으로 검출했습니다. 제품 파일에는 변형을 남기지 않았습니다.

### 최종 확인

극값 사례를 포함한 Debug 재실행도 종료 코드 0으로 완료했습니다. 위 최종 기준 로그 세 파일 모두 20/20 단계·510/510 네이티브 테스트·WASM 검사 6,429,502건으로 통과했습니다.

최종 적대적 검토에서 각 원본 단조 구간의 최대 두 절단점, 최대 여섯 결과, 한 점 끝점의 소유권, 원래 열린 끝점 보존, 같은 지수 조건하의 정확한 정렬, 미확정 시 부분 결과 미공개, 값/근 비교의 부호와 실패 경로를 확인했습니다. 해당 범위에서 추가 결함은 발견하지 않았습니다. 선형 값·표준 순서 반전·기존 근/구간 wire의 SSOT 공유와 포맷·변경 JS 문법·로컬 문서 링크·diff 공백 검사도 통과했습니다. 이 완료 범위는 활성 거듭제곱 분기의 클리핑이며 전체 곡선·문서 기능 완료가 아닙니다.

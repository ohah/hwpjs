# 새 HWP5 구역 하위정보 생성 후보

이 소스 후속은 새 문서 생성의 구역 하위정보 누락 가설을 검증하기 위한 후보다. 실제 실행된 e77 기본 문서 세 개는 5.0.1.7이며 공식 열기에서 각각 4100을 반환했다. 동일 공개 API의 공식 생성 77c 문서는 성공했다. 이 후보의 modern 5.0.3.0 생성·열기는 아직 실행하지 않았고, 하위정보 추가가 오류를 해결한다는 증거도 없다. 차트 writer 지원이나 상호운용 성공을 뜻하지 않는다.

## 명세와 모델의 경계

근거는 한컴 공개 파일 형식 revision1.3의 표25·26·129·133~136과 프로젝트 `hwp5/body/note_shape.zig`, `note_shape_attributes.zig`, `page_border.zig`, `section_validation.zig`다. 공식 출력 원문의 바이트나 수치를 기본값으로 복사하지 않았다.

- 표129의 구역 정의 속성은 26바이트이고 제어 ID 4바이트가 앞선다. 하위 레코드는 별도 레코드이며 구역 제어보다 한 단계 깊다.
- 표133은 구분선 길이를 2바이트로 적어 총26바이트다. 기존 공용 파서는 `observed28`을 명시적으로 사용하여 구분선 길이를 4바이트로 읽는다. 새 typed writer는 두 배치를 명시적으로 직렬화하고 26바이트 배치의 범위 초과를 거부한다. 생성 후보는 기존 재열기 경로와 일치하는 `observed28`을 선택한다. 이를 공식26바이트와 동일하다고 주장하거나 짧은 입력을 자동 판별하지 않는다. 파서와 형식 거부 조건은 바꾸지 않는다.
- 표135는 합계를 12바이트로 표시하지만 개별 필드는 4+2+2+2+2+2=14바이트다. 기존 모델과 동일한 14바이트를 생성한다.
- 표129의 양쪽·홀수쪽·짝수쪽 문장은 바탕쪽 내용에 대한 설명이다. 쪽 테두리 정보 세 개가 필수라는 근거로 사용하지 않는다. 이 후보는 쪽 테두리 정보 한 개만 생성한다. 바탕쪽 내용이 없으므로 바탕쪽 레코드는 생성하지 않는다.

## 직접 작성한 기본 정책

새 기본값의 단일 출처는 `new_document/section_defaults.zig`다. 각주 다음 미주 순으로 두 모양을 생성한다. 번호는 아라비아 숫자, 첫 번호는 기존 `defaults.first_number`, 번호 이어쓰기, 각주는 각 단 배치, 미주는 문서 마지막 배치를 선택한다. 장식 문자는 없고 구분선 길이·여백은 0이다. 선 종류0은 실선, 굵기0은 0.1mm이며 ‘없음’ 부호로 해석하지 않는다. 색은 검정이다. 이 정책의 화면 효과는 아직 검증하지 않았다.

쪽 테두리는 본문 기준, 머리말·꼬리말 미포함, 종이 채움 영역, 간격0, 리소스 ID0을 사용한다. ID0은 기존 `optional_one_based` 참조 규칙의 리소스 없음이다. 새 리소스나 각주 본문을 임의 생성하지 않는다. 레코드 소유자는 첫 본문 문단의 `secd` 하나다.

새 writer는 기존 typed 모델을 입력으로 받으며 필드별로 기록한다. 출력은 고정 길이 값으로 소유되고 할당하지 않는다. 미해석 꼬리 바이트가 있으면 거부한다. 기존 문서의 모양 편집이나 업그레이드 권한을 제공하지 않는다.

명시적 legacy 프로필은 새 하위정보를 생성하지 않는다. 동결된 원 legacy factory의 전체 바이트 비교 시험은 그대로 유지한다. 기존 modern/legacy 본문 전체 동일 시험은 추가 레코드 세 개를 제외한 모든 기존 레코드의 순서·깊이·본문 동일성과 추가 개수3을 검사하도록 바꾼다. 추가 정보 자체의 길이·값·소유권은 별도 독립 검사로 검증한다.

## 준비한 검증과 실행 제한

`new_document_section_probe.zig`는 전용 집중 진입점이다. 기존 `src/root.zig` → `new_document_probe.zig` 경로에도 새 시험을 연결한다. 두 경로가 같은 시험을 각각 실행했다는 주장은 하지 않는다.

새 이름 있는 시험 여섯 개는 두 배치의 필드별 독립 바이트 기대값·디코더 왕복, 정수 범위·꼬리 거부, 쪽 테두리14바이트 왕복, 생성 문서의 독립 원시 레코드 검사와 실제 물리 소유권, Session 저장·재열기·텍스트 편집·실행 취소/재실행, 두 프로필의 생성부터 재열기까지 할당실패 정리를 준비한다. 기존 프로필 시험 둘과 legacy 전체 바이트 오라클도 유지한다. 익명 시험이나 전이 import로 들어오는 시험의 실제 실행 개수는 실행 후 별도 집계해야 한다.

이 단계에서는 컴파일·시험·포매터·SDK·공식 열기를 실행하지 않았다. 전체 Native 입력에는 이 패킷에서 복사하지 않은 기존 바이너리 지원 파일이 있으므로, 집중 및 정규 실행에 필요한 입력 폐쇄성을 별도로 확인해야 한다. 컴파일 성공, 시험 통과, 공식 열기 성공을 소스 준비와 합산하지 않는다. 순서는 독립 소스 검토, 별도 승인된 집중 Native 및 legacy 오라클, 정상 SDK에서 기본 문서 생성·저장·재열기, 별도 승인된 공식 열기 관측이다.

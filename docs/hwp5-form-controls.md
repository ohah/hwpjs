# 양식 컨트롤·payload·속성 트리 조립

[양식 접두부](hwp5-form-object.md) · [속성 문법](hwp5-form-properties.md) · [본문 계약](hwp5-body-contracts.md)

## 실제 소유 관계와 선택 범위

`form-01.hwp`·`form-02.hwp`의 BodyText/Section0에서 양식 10개는 모두 문단의 직접 자식인 `form` CTRL_HEADER와 그 직접 자식인 태그 91로 구성됩니다. 두 파일 모두 컨트롤/양식 레코드 노드 쌍은 12/13, 21/22, 30/31, 39/40, 48/49입니다. 이는 원본 순서의 노드 번호이며 바이트 오프셋이나 instance ID가 아닙니다.

CTRL_HEADER는 두 파일 모두 46바이트입니다. ID 4바이트 뒤에 기존 개체 공통 속성 40바이트와 빈 설명문의 길이 2바이트가 있습니다. 공통 속성 재해석을 위한 별도 오프셋 표를 만들지 않고 기존 `object_common.Properties.parse`를 사용합니다. 실제 출력 대조는 폭·높이뿐 아니라 flags·signed 위치·z-order·여백·instance ID·쪽나눔 방지·설명문·꼬리까지 포함합니다.

공개 명세 표 64는 컨트롤 ID 이후의 배치가 ID별로 다르다고 정의합니다. `form`의 이 연결은 실파일과 rhwp의 관측 구현에 근거한 명시적 선택이며, 표 5의 예시 절대 레벨을 모든 중첩 위치에 적용하지 않습니다.

## API와 책임

`hwp5.form_control.collectObservedUnits(allocator, tree, options)`는 같은 변경되지 않은 `body_tree.Tree.parse` 결과를 받아 양식별 원본 컨트롤/개체 노드 번호, 공통 속성, envelope, 속성 Tree를 반환합니다. 임의로 조작한 Tree의 내부 인덱스를 복구하거나 재검증하는 API가 아닙니다.

- 컨트롤 식별은 `control_rules.form_id = id("form")`가 소유하며 숫자를 정확히 비교합니다. 파일상의 ID 바이트는 `6d 72 6f 66`입니다.
- `form` 컨트롤의 직접 부모는 문단이어야 합니다. 루트나 다른 부모이면 `InvalidFormControlOwner`입니다.
- 태그 91의 직접 부모는 `form` 컨트롤이어야 합니다. 부모가 없거나 다른 컨트롤/중간 노드이면 `InvalidFormObjectOwner`입니다.
- 각 `form`에는 직접 자식 태그 91이 정확히 하나 있어야 합니다. 없으면 `MissingFormObject`, 중복이면 `DuplicateFormObject`입니다. 다른 형제나 더 깊은 자손을 대신 가져오지 않습니다.
- 직접 자식 검색은 기존 Tree의 subtree_end로 하위 트리를 건너뜁니다. 바깥 양식에 중첩된 다른 양식은 별도 문단의 컨트롤로 조립됩니다. 전체 노드 순회와 직접 자식 방문은 선형이며 컨트롤마다 전체 Tree를 다시 검색하지 않습니다.

소유 관계만 새 조립 모듈이 결정합니다. 공통 속성은 기존 파서, 양식 prefix/미지 ID/꼬리는 `form_object.View`, 속성 문법·내부 소유권은 `form_property_tree.Tree`가 소유합니다. `object_common.supports`의 기본 대상이나 `control_rules`의 공식 제어코드 대응표를 확대하지 않았습니다.

## 결과 수명과 미소비 항목

Report는 Form 배열과 각 속성 Tree의 노드 배열을 소유하며 `deinit`으로 모두 해제합니다. 문자열·설명문·꼬리는 원본 Section payload를 빌립니다. 따라서 본문 Tree의 노드 배열은 조립 후 해제할 수 있지만, 원본 바이트는 결과 사용이 끝날 때까지 유지해야 합니다. Property의 위치는 각 양식 속성 문자열 기준이며 Section 전체 위치로 바뀌지 않습니다.

Form의 `other_direct_children`은 태그 91 이외의 직접 자식 수입니다. 중첩 하위 레코드 총수나 검증 성공 개수가 아닙니다. 해당 내용은 원본 Tree/Section에 남아 있으며 Report가 그 원문 전체를 대체하지 않습니다. 공통 속성의 부재 설명문과 빈 설명문, 두 양식 ID·불명확한 길이 값·미해석 꼬리도 기존 View의 구분을 유지합니다.

## 전역 예산과 실패

기본 max_forms는 100,000입니다. `options.properties`는 기존 속성 파서 옵션을 사용하되 max_input_bytes(기본 64MiB)와 max_nodes(기본 100,000)를 **전체 양식이 공유**합니다. 성공한 양식의 실제 속성 바이트/노드 수를 차감한 뒤 다음 파서에 남은 예산을 전달합니다. max_depth(기본 64)는 각 속성 문자열 내부의 set 깊이이며, 본문 컨트롤 중첩 깊이와 구분합니다.

양식 수 초과는 `FormControlLimit`, 속성 한도 오류는 기존 `FormPropertyInputLimit`·`FormPropertyNodeLimit`·`FormPropertyDepthLimit`입니다. 속성 바이트 예산에는 envelope 접두부·설명문·꼬리·다른 자식 레코드가 포함되지 않습니다. 그 입력의 framing/본문 Tree/상위 파일 제한과 결과 메타데이터 메모리는 별도입니다. 빈 속성을 가진 양식도 양식 수 예산을 소비합니다.

오류가 나면 지금 만들던 속성 Tree와 이전 양식의 속성 Tree, Form 배열을 정리하고 부분 Report를 반환하지 않습니다. 선언 크기만큼 버퍼를 만들거나 실패한 양식을 기본값으로 채우지 않습니다. 입력은 변경하지 않습니다.

## 실제·적대적 검증

테스트 mode 106은 버전·양식 수·전체 속성 바이트/노드·속성 깊이 한도의 u32 다섯 값 뒤에 decoded Section을 받습니다. 결과는 양식 수·소비 예산, 원본 노드 대응, 공통 속성·envelope 필드와 문자열/꼬리의 정확한 바이트입니다. 제품 공개 ABI가 아닙니다.

`form-control.mjs`는 독립 레코드/부모 수집과 공통 속성 바이트 읽기를 사용합니다. 속성 노드 수는 기존 독립 `formPropertyEvidence`를 공유하며 속성 문법을 다시 작성하지 않습니다. 정상·오류 보고서와 입력 위치를 바꾼 결과도 전체 바이트로 대조합니다.

| 파일 | 양식 | 속성 바이트 | 속성 노드 | 변조·한도 거부 |
|---|---:|---:|---:|---:|
| form-01.hwp | 5 | 4,306 | 118 | 19 |
| form-02.hwp | 5 | 4,298 | 118 | 19 |

실제 모든 양식의 payload 제거·복제·컨트롤 ID 변조와 각 전역 한도 한 단위 부족을 거부하고 매번 원본으로 복구합니다. 선두 미지 레코드를 삽입하여 고정된 노드 위치에 의존하지 않는지도 확인합니다. 디스크 파일·스냅샷은 수정하지 않습니다.

합성 정상 26건·거부 87건에는 빈 입력, 중첩 양식/중간 노드, 다른 부모·고아·누락·중복·형제 및 자손의 잘못된 사용, 공통 속성과 envelope 잘림, 공유 예산, 음수 위치·큰 unsigned 폭, 부재/빈/비 BMP 설명문과 꼬리 보존이 포함됩니다. 네이티브 테스트는 12개 양식에서 Form 배열 증가·각 속성 Tree 생성·늦은 전역 한도 오류의 모든 할당 실패를 검사합니다. 원본 바이트 보존과 본문 Tree 노드 해제 후의 결과 수명도 확인합니다.

## 실행 결과와 재검토

2026-09-07 최종 소스 기준으로 `zig build audit --summary all`, `zig build audit -Doptimize=ReleaseSafe --summary all`, `zig build audit -Doptimize=ReleaseFast --summary all`을 순차 실행했습니다. 각 모드에서 16/16 단계, 네이티브 285/285개, Node 테스트 47/47개와 줄 캐시 조사 테스트 22/22개가 통과했습니다. HWP5 audit의 probe 호출 계수는 모드별 1,403,640이며, 이는 고유 기능 수나 전체 포맷 지원률이 아닙니다.

전체 실행 후 세 WASM 산출물에 양식 전용 edge/실파일 검사를 다시 실행하여 모두 위 표와 같은 결과를 얻었습니다. Debug 캐시 ID는 `f552ba13fc22b1634c7d87f8be61624b`, ReleaseSafe는 `1ddc88fb5a0d3aed74b228e1d47de3ba`, ReleaseFast는 `8b395df89eb05ef567478019e16a82e0`입니다. 캐시는 재현에 필수인 보관 파일이 아니며, 재빌드한 전체 audit에도 같은 검사가 포함됩니다.

재검토에서는 Tree의 직접 자식 경계, append 실패와 늦은 오류의 해제 경로, 속성 예산 차감의 언더플로 가능성, borrowed 입력 수명, 기본 타입 검사와의 분리를 확인했습니다. 유효한 Tree를 받는 계약 아래 새 결함은 발견하지 못했습니다. 공식 표 64/69의 배치와 관측 `form` 연결을 구분하며, 분할 요약본의 다른 컨트롤 ID 오자를 새 규칙으로 채택하지 않았습니다. 양식 연결의 계약은 이 문서에만 두고 본문 문서는 링크로 연결합니다.

## 남은 범위

기본 미선택 모드에서는 태그 91의 미해석 진단을 유지합니다. [문서·CFB 통합](hwp5-form-document.md)은 명시적으로 선택한 양식 검사와 구역별 진단·문서 전체 공유 예산을 소유합니다. 텍스트의 확장 제어문자와 컨트롤 헤더 연결은 [양식 토큰 연결](hwp5-form-links.md)이 소유합니다. 모든 속성 값·기본값·활성 참조, instance ID의 전역 유일성, 다른 자식 내용의 의미·배치·렌더링·편집·저장은 이 조립기의 성공으로 대체하지 않습니다. 다른 버전과 비 BMP 속성 길이의 원본 프로그램 대조도 남아 있습니다.

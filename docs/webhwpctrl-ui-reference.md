# WebHwpCtrl 공개 UI 비교 기준

2026-10-25 사용자 제공 [공식 웹한글 기안기 데모](https://webhwpctrl.cloud.hancom.com/webhwpctrl/)를 실제 브라우저로 열었습니다. 제공받은 쿠키를 사용하지 않았고 문서를 업로드하지 않았습니다. 공개 초기 문서의 iframe 안에서 메뉴·도구 모음·Canvas·글꼴/크기/줄 간격·쪽 상태를 확인했습니다.

찾기는 숨겨진 메뉴의 같은 이름 항목이 아니라 화면에 보이는 도구 모음 항목을 실제 포인터로 눌렀습니다. 열린 창에서 다음 구성을 확인했습니다.

- 찾을 내용 입력창
- 찾을 방향: 아래로(초기 선택), 위로, 문서 전체
- 다음 찾기, 닫기

산출물은 `zig-out/verification/webhwpctrl-reference/`의 initial/find-dialog 스크린샷, snapshot/find-dialog JSON, cleanup JSON입니다. 초기 자동화의 exact text 조회는 hidden/iframe 대상 구분에 실패했고, visible bounding box를 사용한 최종 포인터 실행에서 실제 찾기 창을 확인했습니다. 소유 브라우저는 inactive=true입니다.

후속 구현에서 우리 데모에도 아래로/위로/문서 전체 방향을 연결했습니다. 위로·아래로의 경계에서 확인 후 계속 찾기, 문서 전체의 현재 위치 기준 순환은 [공식 도움말](https://help.hancom.com/hoffice120/ko-KR/Hwp/edit/find/find.htm)과 대조했습니다. 원본 기안기에서 실제 텍스트를 입력해 각 경계의 결과까지 전부 대조한 것은 아닙니다. 원본의 블록 선택 범위·서식 찾기·바꾸기 전체 옵션도 아직 동치 검증 대상입니다. 우리 공개 API·검증 결과는 [텍스트 도구](headless-text-tools.md), core/host API 대응은 [공식 API 대조](headless-api-coverage.md), JSON 키 설정은 [단축키 계약](editor-keymap.md)이 소유합니다.

## 2026-10-31 운영 화면 재비교: 확인된 범위와 남은 차이

공식 공개 데모의 기본 빈 문서와 현재 운영 Vanilla의 서버 예제 noori.hwp를 전용 headless 브라우저로 순차 관측했습니다. 공식 사이트에는 로컬/사용자 파일을 업로드하지 않았고 로그인·과거 쿠키·저장·공유·메일을 사용하지 않았습니다. 참조 자산 JavaScript를 읽거나 복사한 조사도 아닙니다. 두 화면의 문서가 다르므로 같은 Noori 문서의 조판 동치 비교는 아닙니다. 2026-10-25의 위 기록을 현재 완료 근거로 승계하지 않습니다.

용지 눈금자·가로 구역·배율 변화 반응도 이번 비교에서 확정하지 않았습니다. 공식은 한 쪽의 기본 빈 문서라 caret 이동과 스크롤의 쪽 번호 반응을 분리할 수 없었습니다. 데모125% 선택 시도는 잘못된 selector로 실패했고100%를 유지했으므로, 파일명에 zoom이 있는 스크린샷도 배율 변경 성공 근거가 아닙니다. 같은 캡처의 scroll 명령 성공만으로 실제 문서 viewport 이동까지 증명하지 않습니다.

### 운영·root·미배포 후보를 섞지 않음

운영 비교 기준은 SDK67/history05이며 이번 브라우저에서 실제 Worker1f2e 리소스 경로와 Noori를 읽은 화면을 확인했습니다. 이 감사에서 전체 운영 SDK closure나 응답 바이트를 새로 해시 검증한 것은 아닙니다. 반면 root core dist index는 동결 SDK69 index와 SHA가 같고 typed table command·demo table bridge/tool 소스가 존재함을 읽기 전용으로 확인했습니다. 단일 index 일치를 전체 SDK69 closure 인증으로 확대하지 않습니다.

운영에서 표·그림·도형·각주·미주·하이퍼링크·개체속성·머리말/꼬리말 등은 UI 미연결 안내로 보였지만 root 코드/격리 후보에서 구현·시험한 기능까지 미구현이라고 일괄 판정하지 않습니다. Native 지원은 이 감사에서 export별로 새 시험하지 않았습니다. 기존 API/텍스트·권한·keymap 계약은 위 링크의 SSOT가 계속 소유합니다.

known-none 입력 완료 후보4파일의 현재 root는 후보 after가 아니라 이전 before와 일치했습니다. 그 후보의 source/pure 성공을 실제 운영 UI 성공으로 상속하지 않습니다. 이 변경은 redo 후 선택 부재와 입력/저장 완료 판정의 문제이며 도구 모음 CSS·아이콘·상태바를 같은 모습으로 만드는 수정이 아닙니다. 따라서 운영 SDK/UI 세대 차이와 독립적인 외형·view-state gap을 구분해야 합니다.

### 후속 작업 후보와 완료 기준

1. 기존 read-only host view-state 담당과 연결해 쪽/용지/배율 관측을 상태바로 전달합니다. 눈금자는 별도 희망 옵션이며 공식 대비 확정 누락으로 분류하지 않습니다. 현재쪽의 의미는 caret/scroll을 분리한 근거 전까지 미확정으로 둡니다. 단순히 숫자나 지원 true를 넣지 않습니다.

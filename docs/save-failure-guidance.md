# 저장 거부 후 동의 위치 안내

`save-failure-guidance.mjs`는 저장 실패 문구와 동의 항목의 발견 가능성만 소유합니다. HWP5의 `LayoutReflowRequired` 응답에서 현재 활성화된 동의 항목이 보이면 재조판 경고를 표시하고 체크박스로 포커스를 옮긴 뒤 라벨 전체를 내부 스크롤 중앙에 놓습니다. 체크 상태를 바꾸거나 저장 명령을 재전송하지 않습니다. HWPX·다른 오류·숨김/비활성 항목에서는 포커스와 스크롤을 바꾸지 않습니다.

앱은 기존 저장 응답 경로에서 ready/disabled 상태 갱신 다음 microtask에 안내를 실행합니다. 파일 세대가 바뀐 응답은 안내하지 않습니다. 문서 저장/다운로드·native 편집 모델·CFB 보정 동의와 별도 책임이며 원본 배치를 새로 계산하지 않습니다.

## 실제 브라우저와 실패 경로

2026-10-18 실제 Chromium의 sample1-repro.hwp(3,192문단)를 작업 트리 WASM `35f04c5ac8e52f9b40669df0b658751f4b67cac5fb9af293469e40987077043a`로 열었습니다. 보정 동의 취소 후 편집/이력 비활성과 재승인 후 편집 활성화를 확인했습니다. Canvas 직접 한글·이모지 입력, 실제 Worker 표시, undo/redo, 저장 동의 전 LayoutReflowRequired 거부를 확인했습니다. 이 WASM의 normalized API는 기존 미커밋 작업 트리에 있으므로 main 전체 편집 지원으로 읽지 않습니다.

최초 클릭은 내부 스크롤 밖의 동의 항목을 도움말이 덮어 실패했습니다. 내부 스크롤 후 일반 체크가 가능했으므로 저장 권한 버그로 분류하지 않았습니다. 개선의 첫 버전은 체크박스만 스크롤해 설명 문장을 잘랐고, 라벨 전체 nearest 정렬에도 약 0.16 CSS px의 경계 잘림이 관측됐습니다. 판정 허용 오차를 늘리지 않고 전체 라벨 중앙 정렬로 수정했습니다. 마지막 새로고침 실행에서는 전체 라벨이 명령 막대 경계 안에 있고, 실제 hit 대상/포커스가 체크박스이며 checked=false임을 확인했습니다. 사용자의 Space 조작 후에만 체크가 켜지고 다운로드가 성공했습니다.

두 실제 다운로드의 변경 구역 전체는 독립 CFB/레코드 스플라이스 기대값과 바이트 단위로 일치했고 비대상 스트림 14개도 보존됐습니다. 첫 파일은 문단 0의 입력/undo/redo, 후속 파일은 문단 1 입력을 검사했습니다. 다운로드 파일을 다시 업로드해 입력 내용·편집 재시작과 동의 체크 초기화를 확인했고 마지막 브라우저 오류 목록은 비어 있었습니다. 중간 고정 좌표 클릭이 Canvas를 벗어나 입력되지 않은 timeout 시도는 성공에 포함하지 않습니다. 전체 위치·OS IME·한컴 조판 동치 증거는 아닙니다.

스킬에 따라 브라우저와 이번 임시 서버를 종료했습니다. 세션 active=false/pid=null, 포트 58321 listener 없음, 서버 exit143을 확인했습니다. 첫 잘못된 다운로드 대기의 CLI 두 프로세스만 중단했으며 다른 브라우저·서버에는 조작하지 않았습니다.

별도 단위 검사는 전체 라벨 스크롤과 직접 선택 유지, 형식/오류/hidden/disabled 조합 24개, 동의 노드 부재, 비저장 응답 무시를 검사합니다. 체크박스만 스크롤하는 회귀는 명시적 실패 반례입니다. 기존 저장·메뉴 검사와 함께 실행합니다.

작업 트리의 저장/메뉴/보정 동의/실제 Worker 집중 실행은 14/14·skip/실패 0·종료 0입니다. 게시 변경만 분리한 main 기반 사본의 기존 저장/메뉴 실행은 10/10·skip/실패 0·종료 0이며 앱/모듈 구문 검사도 통과했습니다. 같은 사본의 5개 진입점 정적 연결은 538모듈·평가 0개로 성공했습니다. 두 실행 집합은 다르므로 합산하지 않으며 정적 연결을 실제 브라우저 증거로 쓰지 않습니다. 기본 데모 WASM은 변경하지 않았고 장시간 전체 native 검사는 이 UI 변경 전 바이너리의 별도 실행입니다.

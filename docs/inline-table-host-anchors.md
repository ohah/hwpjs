# 표와 부유 도형이 섞인 문단 앵커

`inline-table-host-anchors.mjs`는 문단의 개체 표시 문자를 확인된 표·부유 도형·인라인 그림·구조 앵커의 UTF-16 위치로 나눕니다. 표 개수를 문단의 모든 U+FFFC 개수와 같다고 가정하지 않습니다. 중복 위치/식별자, 다른 문단/구역, 확인되지 않은 표시 문자는 거부합니다. 기존 표만 있는 입력의 암시적 순서 계약은 유지합니다.

도형 본문 배치는 도형 목록을 제거하기 전에 원본 앵커를 `floatingDrawingAnchors`에 남깁니다. 같은 그룹 root는 한 번만 남기고 소속/위치가 충돌하면 실패합니다. 이 값은 재조판용 소속 정보이며 원본 문서·저장 wire에 가짜 개체를 추가하지 않습니다.

표 본문 조판은 분리한 도형/구조 앵커를 기존 인라인 측정의 `zeroWidthUnits`, 인라인 그림을 `textAnchorUnits`로 전달합니다. 표 크기·그림 크기·줄 나누기를 별도 구현하지 않습니다. 도형 표시 문자는 원문에서 제거하지 않고 0너비로 남겨 실제 도형 배치의 앵커로 사용합니다. 부유 도형 감싸기의 본문 예약 지원 여부는 별도 계약입니다.

## 2026-10-19 검증

독립 Python ZIP/ElementTree에서 `issue5543_carried_anchor_ladder.hwpx`의 전체 순회43번째 문단 직접 자식이 `tbl, rect, tbl, t`임을 확인했습니다. Worker 원본 앵커도 표0/2·도형1과 일치합니다. 기존 모든 표시 문자를 표로 세는 경계에서 거부되던 조합입니다.

`tests/hwpx/inline-table-host-anchors.test.mjs`는 원본 위치·표별 측정 좌표·원문 보존, 알 수 없는/중복/다른 소속 거부와 실제 참조 소속을 검사합니다. 추가 통합 검사는 추적 `table2.hwpx`에서 파생한 합성 장면입니다. 원본의 같은 문단에 있는 두 블록 표를 모두 인라인으로 명시 변경한 뒤, 추가 도형 앵커 유무에 따른 셀 좌표/크기 동일성과 문단 보존을 확인합니다. 원본 table2가 인라인 표라는 주장이나 실제 파일 편집·저장 검사는 아닙니다. 한 표만 인라인으로 바꾼 초기 합성 입력은 혼합 앵커 정책으로 실패했으며 두 표를 일관되게 설정한 뒤 검사했습니다.

현재 전체 작업 트리 후보에서 참조 문서는 이제 `UnsupportedTableBodyHost`(구역0·문단31)로 중단됩니다. 이 문단의 본문 소속 분류는 다음 조사 대상이며, 거부를 무조건 해제하지 않습니다. 전체 문서 표시/조판 동치/편집 완료로 집계하지 않습니다.

검증 결과: 격리 게시 소스의 새 앵커4개·기존 도형 그림4개 검사가8/8, skip0입니다. 현재 작업 트리에서도 새 앵커4개와 기존 인라인 표4개가8/8 통과했고, 추적 HWPX Worker 페이지 분류는45개 paginated를 유지했습니다. 작업 트리와 격리 게시 소스 결과를 전체 main 조판 동치로 합산하지 않습니다.

# Canvas object selection and properties P

A painted hit is an intent, not a selection or Native edit authority. The private host requires a trusted unmodified primary down/up gesture, stable Native token/source/lease/modal identity, the actual direct-controller transition, one exact leased Core selection-clear result, and a fresh completed frame with the same object hit. Chart/drawing decoration must be present in that frame. Pictures reuse the existing picture-selection transition and handles. Drawing owner/activation proof is read through createDrawingObservationQuery(content).get(section, drawingNode) for both formats. No H5 control-node alias or HWPX field inference is used. Unsupported drawing transforms/groups are refused; textbox interiors retain the original caret path.

Only a certified selected object and focused Canvas can emit `properties-shortcut`. The event carries immutable identity and Native token, never mutation permission. The demo dispatcher routes it through the same current-state/unique-owner checks and existing chart/picture/drawing properties tools as the separate `double-click` channel. React/Svelte retain a single properties owner across delayed mount and surface replacement. The default keymap has no bare P entry; no document/window keydown handler is installed.

Between owned pointer down and selection confirmation, the old hidden textarea may still own focus. Its unmodified P (including repeat) is quarantined by the host's input/Canvas capture listener. This opens no dialog, emits no properties event, writes no text, and never replays P after confirmation. Pending textarea `beforeinput` is cancelled before direct input and cancels the intent. Foreign forms, modifiers, IME keys, and body P without an owned intent retain their existing key handlers. Composition/input/history/modal/outside/focus/document/lease changes invalidate the private witness.

A fast second down/up shares the first commit only at the original small movement radius and when its original completed-frame intent query identifies the same object (never the textbox interior); it cannot establish selection independently. The original trusted dblclick is admitted by the private host before direct input's stale-frame capture gate, and its normal activation handler awaits the same commit result. It then rechecks the current completed frame, source, focus and exact target. No event is redispatched, no timer guesses completion, and no stale event falls through the public frame gate. Unowned dblclick continues through the unchanged frame gate and normal activation path. Invalidation or disposal cancels the pending semantic activation.

Selection borders use successful paints from the current renderer pass. Chart provisional previews cannot confirm selection. Drawing rectangles must join the exact current source; rotations/groups, ambiguous owners and conflicting frames refuse decoration. Borders are selection UX, not resize handles or writable geometry. Document/source/resource changes, clear and disposal retire the decoration. Authoritative editing and save continue through existing Native properties ports.

Source tests include the private state machine, real capture/bubble binding order with the direct-input stale-frame gate, dispatcher/relay ownership, and an actual renderer/direct-input source integration using a focused simulated textarea and synthetic metadata. These are not Native execution, browser/IME/device evidence, SDK/gallery or public deployment claims. Independent source review and actual GUI validation remain required.

A certified selection may survive a presentation-only repaint. Renderer-private weak records bind completed raw frames to an opaque scene certificate derived from the existing full frameStamp and to a private submitted-selection receipt. Only consecutive Object.is-equal full stamps reuse the scene certificate; an observed changed/invalid stamp retires it, including ABA. The actor may acknowledge a replacement raw frame only for its existing certified selection with the exact same Native state/token/source/lease/modal context, focused Canvas, current actual selection paint and unchanged private receipt. Reflow/layout/resource/viewport/scroll/scale changes, forged or cross-renderer frames, clear/resubmission and reentrant invalidation cannot acknowledge. Pointer down/up and pending commit confirmation keep exact raw-frame fences and still require a new completed raw frame after the owned Core clear. No Native edit/save authority is derived from this acknowledgement.

Window의 capture blur는 하위 요소의 focus 이동도 관측한다. 이전 입력이나 Shadow DOM 내부 요소에서 Canvas로 focus를 넘길 때 발생한 하위 요소 blur는 window 이탈로 취급하지 않는다. 소유 window 자체가 blur 대상인 실제 이탈은 대기 포인터·선택 확인 중·확인된 개체 선택을 모두 취소한다. 다른 입력으로의 focus 이동은 기존 focusin과 host focus 검사로 거부하며, Core 발행의 정확한 +1·token·lease·source·완료 frame 검사는 그대로 유지한다.

Viewport의 capture scroll은 하위 textarea의 내부 스크롤도 관측한다. 숨은 입력의 값·caret을 정리하며 발생한 textarea scroll은 viewport 이동으로 취급하지 않는다. 소유 viewport 자체가 scroll 대상인 실제 이동은 대기 포인터·선택 확인 중·확인된 개체 선택을 모두 취소한다. 실제 window 이탈·외부 focus·문서/state/lease/source 변경·재진입 취소와 정확한 +1 및 raw frame 검사는 유지한다.

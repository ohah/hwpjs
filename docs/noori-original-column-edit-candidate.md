# Noori 원본 다섯 번째 표 열 편집

이 문서는 공개 원본의 기존 표를 대상으로 한 열 편집 제품 후보와 검증 범위를 기록한다. 실제 통과한 후보19 소스를 정본으로 하며, 현재 Root 통합·배포나 전체 기능 완료를 뜻하지 않는다. 과거 누락된 r10 및 32개 성공 주장은 승계하지 않는다.

## 변경 전 거부의 원인과 순서

공개 noori.hwp와 noori.hwpx를 독립 CFB 및 ZIP/XML 읽기로 확인했다. 대상은 둘 다 다섯 번째 표인 8행 3열 24셀이다. 열 폭은 9096, 18718, 20416이고 합은 48230이다. 같은 행 안에서도 셀 높이가 다르며 표 자체 높이는 62701이다.

HWP5에서는 observed8 셀의 13바이트 확장을 행 전용으로 제한한 검사가 먼저 거부한다. 그 경계를 통과한다고 가정하면 그림을 가진 셀 문단의 중첩 제어 검사와 제어 마스크가 거부한다. 그 뒤의 공용 기하 계획도 셀 높이를 동일 행 높이의 등식으로 취급하여 거부한다.

HWPX에서는 필드 보호 검사 다음의 ContentCheck가 그림의 직접 shapeComment 원문을 일반 구조 텍스트로 분류하여 먼저 거부한다. 그림 run 자식 거부와 공용 세로 등식의 충돌은 뒤에 있다. 이 순서는 현재 소스와 원본 구조의 대조이며 실제 Native 오류 반환을 실행 관측한 결과가 아니다.

observed8의 unknown은 payload 2..4의 u16이고 대상 24셀 모두 0이다. payload 4..8은 전체 u32 속성이며 관측값은 0x20, 0x40, 0x01000020, 0x04000020이다. 상위 바이트를 별도 unknown으로 해석하지 않는다. 방향·줄바꿈·정렬과 보호 비트는 기존 View와 CellAttributes를 유지하고 고위 비트에 새 의미를 부여하지 않는다.

## 공용 계획과 형식별 보존

병합되지 않은 열 편집은 기존 좌표 계획과 가로 구간 등식 풀이를 재사용한다. 셀 높이와 표 자체 높이는 원형으로 유지한다. 전후 행별 최대 높이를 비교해 세로 범위가 변하는 삭제를 거부한다. 행별 최대 높이를 실제 조판 높이나 표 높이의 새 계산식으로 사용하지 않는다. 행 편집과 병합 표의 기하 계획은 기존 경로에 남긴다.

열 1 삽입은 원본 열 0을 빈 셀의 서식 원본으로 사용하며 폭은 57326이 된다. 열 0 삭제는 폭 39134가 된다. 독립 raw 대응에서 두 연산 모두 행별 최대 높이 배열을 유지한다. 이 값은 독립 raw 대응에서 얻은 기대 범위이다. 아래의 실제 파일 변환 검증과 구분한다.

생존하는 직접 그림은 기존 형식별 그림·소유권 읽기를 사용하여 검증하고, 본문 앵커와 그림 원문 전체를 복사한다. 그림 폭·높이·변환·자르기·댓글·이미지 참조를 변경하거나 추정하지 않는다. HWPX의 댓글 허용 색인은 대상 셀에 직접 속하고 그림 읽기를 통과한 pic의 직접 댓글 노드만 포함한다. 다른 위치의 댓글, 중첩 댓글, 알 수 없는 의미 자식의 텍스트는 허용하지 않는다.

새 빈 셀의 서식 원본에 그림이 있거나 그림이 소유한 셀을 삭제하는 경우는 기존 엄격한 본문 검사를 유지한다. 생존 셀의 크기를 바꾸는 경로에서도 그림 보존을 허용하지 않는다. 그림을 복제하거나 참조 수를 조작하는 구현은 없다. 이 경계의 기능은 아직 남은 작업이다.

기존 파일 어댑터의 새 ID 예약과 문서 전체 자원 검사는 그대로다. 원본의 중복 문단 ID는 새 ID가 아니므로 덮어쓰거나 새 전역 유일성 조건을 추가하지 않는다. HWPX의 누락 ID는 생존 문단에 그대로 두고 새 빈 셀에만 예약 ID를 붙이는 기존 경로를 쓴다. HWP5의 필수 헤더 바이트가 없는 손상과 선택적인 HWPX 메타데이터 누락은 구분한다.

계획은 입력 셀, 좌표, 가로 제약, 출력 셀을 각각 상수 횟수로 순회한다. O(셀 수 + 행 수 + 열 수)이며 요청 단위 배열만 사용한다. 그림 댓글 색인은 트리와 알려진 그림 자식을 순회하여 만든다. 범위마다 전체 트리를 다시 검색하거나 전역 캐시를 만들지 않는다. 기존 XML 직렬화나 공용 조판 경로 전체가 선형이라는 주장은 아니다.

## 실제 검증과 정규 등록

동일한 두 검사 교정을 적용한 새 기준 코호트는 명명2와 익명1이 통과했다. Noori 후보 코호트는 신규 명명13과 기존 행·열 회귀 명명6, 익명2가 통과했다. 두 실행은 각각 종료 코드0, 생략0이며, 입력 및 원본·개인 컴파일러 전후 핀과 전체 소유 프로세스 그룹 종료를 확인했다. 이 수들은 별도 코호트의 결과이며 합쳐 한 번의 실행으로 기록하지 않는다.

원본 파일을 내장한 두 검사는 공개 noori.hwp 및 noori.hwpx의 다섯 번째 표에서 열1 삽입과 열0 삭제를 각각 수행하고 출력 파일을 새로 열었다. 입력은 8행3열이며 결과는 각각 8행4열과 8행2열이다. HWP5는 생존 셀의 원래 HEADER·TEXT·글자 모양, 셀 LIST의 비대상 필드, 그림 관련 레코드 payload, 표 높이와 공통 제어 비대상 필드를 비교한다. HWPX는 생존 문단의 시작 태그와 run 원문, 전체 pic subtree와 직접 댓글 원문, 결과 열 수와 표 높이를 비교한다. 이는 실제 파일 어댑터의 변환·저장·재열기 증거이며 관리 세션의 이력이나 화면 검증으로 확대하지 않는다.

합성 검사는 공용 열 계획의 셀 높이와 세로 범위 보존, 잘못된 좌표·폭·병합 경계, 기존 행 정책, typed 그림 앵커와 소유권·알 수 없는 레코드 거부, 그림 서식 원본과 삭제 거부, 댓글 소유권과 중복·누락 메타데이터, detached 할당 실패를 포함한다. 기존 명명6은 HWP5/HWPX의 행과 열, 단일·다중 문단 및 원문 보존 회귀를 선택했다. 전체 Native 검사를 실행한 결과는 아니다.

정규 `build.zig`에는 `src/noori_column_grid_probe.zig`를 사용하는 `test-noori-source-columns`와 정확한 명명13 필터를 등록한다. 기존 editor 확장 및 전체 test 의존 경로를 재사용한다. 등록 블록 한 개를 제거하면 기존 corpus 등록을 포함한 정규 build 전상이 전체 바이트로 복원된다. 정규 build 진입점 자체의 실행은 이번 집중19 결과와 구분해 다음 전체 검증에서 확인한다.

공개 원본2는 기존 `apps/docs/docs/public/editor/fixtures/noori.hwp`와 `noori.hwpx`의 입력 역할이다. 해당 원문을 제품 패치에 중복 추가하지 않는다. 시험이 사용하는 `src/testing/noori-column/noori.hwp`와 `noori.hwpx`는 각각 `../../../apps/docs/docs/public/editor/fixtures/` 아래 같은 이름의 파일을 가리키는 저장소 내부 상대 symlink다. 원문 payload는 복제하지 않고 링크의 literal과 공개 파일의 크기·해시를 별도로 고정한다. private 실행 입력에도 공개 원본과 링크가 모두 있어야 하며, 대상이 저장소 밖으로 벗어나거나 파일이 누락되면 생략하지 않고 준비 실패로 처리한다. 이 링크 구성의 Native embed와 정규 build 실행은 다음 결합 검증에서 확인한다. HWP5의 SHA256은 `b18be0217a5d9f81e587705edc0c514cdd11e6314bbe434f17d256aa21b75a7f`, HWPX는 `6ee9014f23650987803481e7aa51b3b2201f91f549dccfe34880469621d62aab`이다.

캐시 변이 한 경우의 기존 엄격 거부는 `UnsupportedSourceLineCache`로 검사한다. 다른 구조 거부는 그대로다. 새 빈 셀은 전체 HEADER와 ID·문자수1·runs1·cache0, 직접 자식 글자 모양 run의 시작0과 상속 스타일, TEXT 부재·다음 경계·LIST 개수를 확인한다. CR 바이트를 스타일 payload로 대체한 검사가 아니다. 생존 원문 전체 raw 비교와 기존 행·열 조합도 유지했다.

원래 기준 진단2의 실패와 원래 후보19의17 통과2 실패, 최초 fixture 컴파일 실패는 보존한다. 기존 기준 진단 파일과 정규 전상은 직접 같지 않고, 표시된 진단 구간 하나만 제거한 뒤 일치한다. 새 정규 후속에는 그 임시 진단 helper를 넣지 않는다.

## 남은 범위

Main의 실제 Root 통합과 Ampere의 결합 전체 Native 및 Safe 검증은 별도 단계다. 정상 WASM·SDK·CLI와 실제 화면에서 이 원본 표를 선택해 편집하는 경로는 아직 새 후보로 검증하지 않았다. 관리 이력의 단일 커밋·undo 원본·redo 출력, 현재 표·셀 소유권과 일반 파일의 광범위 호환성도 추가 검증이 필요하다.

그림을 가진 서식 원본에서 새 빈 셀 만들기, 그림 소유 셀을 지우는 열 삭제, 행별 세로 범위를 바꾸는 삭제, 병합·비정규/알 수 없는 확장과 다른 버전, 새 조판과 한컴 화면 동치는 완료 범위가 아니다. 알려진 그림의 원문 보존만 허용하며 모르는 의미 자식이나 임의의 댓글을 일괄 허용하지 않는다. 기본 보호·읽기 전용·서명·필드·예산·소유권 검사는 유지한다.

실제 로그와 전체 핀은 비공개 증거 `hwpjs-noori-oracle2-dual-actual-goodall-20261116-r1` 및 각 코호트의 동결 원장에서 관리한다. 이 문서는 저장·재열기 증거를 SDK 또는 실제 화면 성공으로 합산하지 않는다.

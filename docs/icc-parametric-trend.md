# ICC 파라메트릭 곡선 전체의 단조성·상수성

## 계약

후속 [선형 분기의 역상과 평탄 구간 선택](icc-linear-preimage.md)은 별도 계층입니다. 거듭제곱 분기와 합친 전체 파라메트릭 역변환은 아직 미구현입니다.

`parametric_trend.inspect(precision, curve)`는 [ICC.1:2022 §10.18 Table 68](https://www.color.org/specifications/ICC.1-2022-05.pdf) 식에 출력 [0,1] 클리핑을 적용한 **전체 실수 입력 구간 [0,1]**의 방향을 분류합니다. 전체 실수 정의역 검증을 먼저 수행하며 정의되지 않은 입력은 기존 오류입니다. 비단조라도 정의된 순방향 함수라면 오류로 바꾸지 않고 분류값을 반환합니다.

| Trend / wire 값 | 의미 |
|---|---|
| constant / 0 | 전체 구간에서 같은 출력 |
| nondecreasing / 1 | 비상수이며 모든 x<y에서 F(x)<=F(y) |
| nonincreasing / 2 | 비상수이며 모든 x<y에서 F(x)>=F(y) |
| nonmonotonic / 3 | 증가하는 쌍과 감소하는 쌍이 모두 존재 |
| undecided / 4 | 현재 정밀도의 미확정 때문에 위 분류를 증명하지 못함 |

비감소/비증가에는 평탄 구간과 같은 방향의 점프가 허용됩니다. 엄격 단조성·연속성·일대일 대응·역함수 존재·특정 y의 최대 역상이나 최근접값 존재를 뜻하지 않습니다. 예를 들어 [열린 평탄 구간과 열린 값 범위 반례](icc-parametric-inverse-topology.md)는 nondecreasing이지만 해당 역상 선택이 달성되지 않을 수 있습니다. 최대 정밀도에서 모든 입력이 판정된다는 보장은 없습니다.

## 조립과 SSOT

- 기존 parametric_segments가 활성 분기·원본 계수·실수 정의역을 소유합니다.
- [선형 분할](icc-curve-partition.md)과 [거듭제곱 클리핑](icc-power-clipping.md)은 클리핑 후 구간 방향을 소유합니다. singleton과 클리핑된 상수 구간의 방향은 constant입니다. 파라미터의 부호나 클리핑 전 도함수로 전체 판정을 다시 구현하지 않습니다.
- [parametric_jump](icc-parametric-jump.md)가 원래 두 분기 사이의 클리핑 후 좌극한/실제 값 순서를 소유합니다. x=1의 한 점 상위 분기도 이 경계 비교로 반영합니다.
- parametric_trend는 위 결과를 조립합니다. 하위 API마다 자체 검증을 유지하므로 전체 정의역 조립이 재실행될 수 있지만, 검증 규칙은 기존 소유자 한 곳을 공유합니다.
- trend_evidence는 증가/감소 증거와 미확정의 합성 규칙만 소유합니다. 양방향 증거가 모두 있으면 다른 부분이 미확정이어도 nonmonotonic입니다. 그렇지 않고 미확정이 남으면 undecided이며, 이를 constant나 단조성 성공으로 바꾸지 않습니다.

## 판정의 근거

각 선형 분기는 연속이고, 유효한 거듭제곱 분기도 활성 범위에서 연속입니다. 밑 영점을 가로지르는 비양수 지수는 정의역 검증에서 제외되고, 양의 정수 지수는 영점에서 연속입니다. 출력 클리핑 역시 연속입니다. 따라서 각 분기 내부에서 새로 나눈 클리핑/밑 영점 경계에는 추가 점프가 없습니다. 불연속 가능성이 있는 원래 선형/거듭제곱 연결은 별도로 검사합니다.

비상수 증가/감소 Piece는 실제 해당 방향의 값 쌍이 존재한다는 증거입니다. 비영 경계 점프도 좌극한의 정의에 의해 해당 방향의 실제 값 쌍을 보장합니다. 분기 내 모든 구간과 원래 분기 경계가 같은 약한 방향이면 이 관계가 전체 구간으로 이어집니다. 모든 구간이 상수이고 경계 차이가 0이면 전체 상수입니다. 원래 제곱식에 굴곡이 있어도 클리핑으로 양쪽 변화가 모두 가려지면 constant가 됩니다.

## 독립 검증

제품은 0/1 기호근을 포함한 정확한 클리핑 분할을 사용합니다. 독립 JS 기준은 **클리핑 근이나 제품 Piece를 읽지 않습니다.** 원래 밑의 영점과 분기 양끝만으로 원시 단조 구간을 나눈 뒤 BigInt 전체 거듭제곱·유리수 교차 곱으로 양끝 값을 비교합니다. 증가 구간은 작은 끝값이 1 미만이고 큰 끝값이 0 초과일 때만 클리핑 후 변화가 남습니다. 감소 구간은 반대쪽 끝값에 같은 조건을 적용합니다. 원래 구간이 단조·연속이므로 이것은 격자 샘플 추측이 아닌 전체 구간의 판정입니다. 하위 선형 끝값과 원래 경계 점프도 독립 기준을 재사용합니다.

네이티브 검사는 굴곡·상하 클리핑으로 생기는 상수·두 증가 분기 사이의 하향 점프·상향/하향 계단·열린 역상 반례·x=1의 점프·전체 감소·양쪽 상수 연결을 포함합니다. `(2147483647*x-1)^2/65536^2`는 폭 1/2147483647의 초기 감소 구간을 가지므로 nonmonotonic이며, 출력 오프셋 -1을 더하면 그 감소가 클리핑되어 nondecreasing이 됩니다.

trend_evidence의 증가/감소/미확정 플래그 여덟 조합을 따로 검사합니다. 이는 미확정 합성 규칙의 증거이며 원시 para 입력에서 전체 inspect의 undecided를 실측했다는 주장은 아닙니다. 현재 전체 곡선 대조 집합의 undecided 수는 0입니다.

WASM mode192는 precision u32 BE와 para payload를 받아 위 Trend 값의 u32 LE 4바이트를 반환합니다. 네 정밀도, 다섯 곡선 유형, 지수·계수·오프셋·분기점 조합, 극값과 작은 굴곡, 잘림·과잉 바이트·자원 제한·부적합 정밀도·실패 후 복구를 검사합니다. 제품 JS API에는 노출하지 않습니다.

## 실행 기록

초기 네이티브 검사는 5/5 단계·520/520로 통과했습니다. Debug WASM 직접 대조는 comparisons=27381, rejected=21323로 통과했고 Trend별 건수는 [14107,9996,2197,1081,0]입니다. 초기 좁은 굴곡의 결과를 nondecreasing으로 잘못 바꾸는 반환값 변형은 ERR_ASSERTION으로 검출했습니다. 제품에는 변형을 남기지 않았습니다.

실제 시스템 DCI(P3) RGB·Display P3·ITU-2020·ITU-709·ROMM RGB의 para TRC 태그 15개를 읽기 전용으로 조사했습니다. 네 정밀도에서 60건을 확인했고 앞 세 프로파일은 nondecreasing, 뒤 두 프로파일은 nonmonotonic이었습니다. 양의 지수/기울기인 실제 분기들과 이전에 독립 확인한 점프 부호에 따른 기대값과 일치했습니다. 정규 감사 수에는 합산하지 않습니다. ICC.1:2022 식의 해당 곡선 판정이며 OS 색상 엔진 정책·프로파일 전체 적합성 판정은 아닙니다.

전체 문서 검증과 역변환 구현은 아직 미완료입니다.

최종 검토에서 극단 지수의 언더플로 사례 두 개를 정규 검사에 보강했습니다. `(x/2)^(2147483647/65536)`는 전체에서 비상수 비감소이고, x<1/2에서 0·그 이후 `2^-32768`인 곡선도 비상수 비감소입니다. f64 계산에서는 두 작은 출력이 0으로 사라질 수 있지만 실수 곡선의 변화는 보존해야 합니다. JS에서 수십억 비트 거듭제곱을 전개하지 않고 이 단조성·양수성 증명으로 네 정밀도에서 8건을 추가합니다. 초기 Debug 로그와 위 직접 실행 수는 이 추가 전 이력으로 구분합니다.

보강 후 직접 WASM 대조는 comparisons=27389, rejected=21323, trends=[14107,10004,2197,1081,0]으로 통과했습니다. 같은 Node 실행에서 `0.5**(2147483647/65536)`와 `2**-32768`이 모두 0임도 확인했습니다. 이 부동소수점 결과를 수학적 상수성 판정에 사용하지 않습니다.

추가 오류 주입은 클리핑으로 상수가 된 굴곡을 nonmonotonic으로 바꾸기, 두 증가 분기 사이의 하향 점프를 무시해 nondecreasing으로 바꾸기, x=1 한 점의 상향 계단을 무시해 constant로 바꾸기를 각각 ERR_ASSERTION으로 검출했습니다. 초기 좁은 굴곡 변형과 다른 실패 모드를 검증하며 제품에는 변형을 남기지 않았습니다.

# JPEG 프레임·스캔 필드 검사

## 근거와 책임

[ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) B.2.2/Table B.2, B.2.3/Table B.3 및 successive approximation 정의를 참조했습니다. 텍스트 추출에 숫자 잔상이 있어 PDF 40·42페이지의 표를 렌더링하여 확인했습니다. 마커·길이 경계는 [기존 계층](jpeg-framing.md)이 소유하며 여기에는 마커와 길이 필드를 제외한 payload만 전달합니다.

- `process.zig`: 비계층형 SOF0/1/2/3/9/10/11의 프로세스·부호화 방식 및 정밀도 규칙. 계층형 차분 SOF5/6/7/13/14/15는 별도 미지원 오류이며 비계층형으로 해석하지 않습니다.
- `components.zig`: 기존 binary.record_array를 사용하는 3바이트 프레임 성분·2바이트 스캔 성분 view. 원본 sampling/table-selector 바이트를 보존합니다.
- `frame.zig`: 정밀도·치수·성분 수·고유 ID·샘플링·양자화 테이블 selector와 입력 길이 검사. 할당하지 않으며 성분 원문은 입력을 빌립니다.
- `scan.zig`: 파싱된 Frame을 받아 스캔 필드·참조·선언 순서·다중 성분 MCU 샘플링 합을 검사합니다. 프레임 규칙을 복제하지 않습니다.

## 구분해야 하는 경계

프레임 높이 0은 이후 DNL로 결정해야 하는 값으로 보존하며 `Frame.pixels()`는 null을 반환합니다. 폭 0은 오류입니다. 픽셀 한도는 높이가 정해진 경우에만 적용하므로 DNL 수신 때 다시 검사해야 합니다. 기본 프레임 한도는 255성분·100,000,000픽셀이며 호출자가 조정합니다.

프레임 성분 수는 progressive에서 최대 4, 나머지 지원 프로세스에서는 최대 255입니다. 스캔 성분 수는 별도로 최대 4입니다. 성분 ID의 숫자 오름차순을 강제하지 않고 프레임의 선언 순서를 따릅니다. 샘플링 곱의 합 10 제한은 다중 성분 스캔에 적용하며 단일 성분에 잘못 적용하지 않습니다.

Progressive AC 스캔은 단일 성분이어야 하며 DC 구간은 Ss=Se=0입니다. Ah/Al의 개별 범위와 refinement의 한 비트 차이는 검사하되 이전 스캔이 있었는지, 밴드가 중복/누락됐는지는 아직 검사하지 않습니다. Lossless는 Table B.3 필드를 검사하지만 point transform과 유효 sample 정밀도의 복호화 관계를 완료했다고 주장하지 않습니다.

테이블 selector 값 범위와 실제 테이블 존재/활성화/재정의는 다른 검사입니다. 현재는 값 범위만 검사합니다. 계층형 프레임, DNL 수명, 전체 스캔 진행, 압축 계수·픽셀, 메타데이터, 전체 JPEG 문서 지원은 아직 미완료입니다. HWP 보고서의 JPEG 미지원 집계를 줄이지 않습니다.

[DQT·DHT 내용 검사](jpeg-tables.md), [테이블 설치·스캔 선택](jpeg-table-selection.md), [progressive 스캔 이력](jpeg-progression.md)은 별도 계층입니다. 전체 JPEG 파일 수명 검증은 아직 후속입니다.

## 검증 기록

- 네이티브 JPEG 필터: 세 모드 각각 root·기존 경계 테스트 포함 14/14 통과. 전체 Debug 테스트 730/730 통과.
- 정밀도×프로세스, 0~255 성분 수, sampling·quantization·entropy selector의 모든 바이트, progressive Ss/Se 전체 바이트 조합과 Ah/Al, sequential/lossless 각 스캔 필드의 전체 바이트를 검사했습니다.
- 선언 순서와 숫자 순서가 다른 ID, 중복/없는 참조, 합 10/11, 단일 성분 sampling 16, 잘림/꼬리, 높이 0과 폭 0, 한도 및 borrowed view 위치를 검사했습니다.
- 테스트용 mode 246은 프레임 단독 또는 프레임+스캔을 받아 원값/성분 원문을 반환합니다. 세 모드 WASM과 독립 JS 기대값 비교에서 각각 4,148건·거부 3,960건 통과.
- 실제 HWP JPEG 참조 8건과 참고 `s1.jpg`의 프레임·스캔을 세 모드 WASM에서 대조했습니다. 기존 경계 검사 결과는 그대로이며 HWP 표본에는 progressive 7스캔 사례가 포함됩니다. 정규 audit에도 연결했습니다.
- 세 모드 WASM 결과에서 프레임 7개 필드·스캔 5개 필드를 각각 0으로 바꾼 12가지 출력 변형을 독립 JS 기대값이 모두 검출했습니다. 소스 변형 및 전체 의미 검증을 대신하지 않습니다.
- 격리 소스에서 참조 순서 검사 `<=`를 `<`로 바꿔 중복 성분을 허용하면 세 모드 모두 `TestExpectedError`로 검출했습니다. 별도 복사본에서 sampling 합 제한의 다중 성분 조건을 제거하면 세 모드 모두 단일 성분 정상 사례가 `InvalidJpegMcuSampling`으로 실패했습니다. 각 필터는 root 포함 2개 중 1개 실패이며 제품 소스는 변경하지 않았습니다.
- Debug/ReleaseSafe/ReleaseFast 전체 audit가 각각 20/20 단계·730/730 네이티브 테스트·7,003,902회 검사로 통과했습니다. 검사 횟수를 JPEG 또는 HWP 전체 지원률로 해석하지 않습니다.

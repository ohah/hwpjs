# HWP5 BinData 이미지 검사 연결

## 범위와 책임

HWP5 표 17~18의 BinData 항목별 압축 정책으로 얻은 바이트를 기존 PNG 검사기에 연결합니다. `container.Options.images`는 기본 null이며, 미선택을 정상 이미지 판정으로 해석하지 않습니다.

- `container/binaries.zig`: 기존 정확한 경로 조회·항목별 압축 해제 뒤 이미지 예산에 전달합니다. LINK는 외부 접근 없이 보류합니다. 압축·이미지 오류 뒤 원본 fallback은 없습니다.
- `container/images.zig`: 형식 선택·문서 전체 픽셀 바이트/항목 한도·scalar 통계만 소유합니다. PNG 청크·압축·ICC 규칙은 [PNG 검사기](png-profile-inspection.md)를 재사용합니다.
- `container/validation.zig`: 선택 옵션·예산 수명·최종 보고서 연결을 소유합니다. 기존 BinData 보고서와 제품 JS ABI는 변경하지 않습니다.

UTF-16LE 확장자가 ASCII 대소문자 무관하게 png이면 PNG 검사를 요구합니다. 그렇지 않아도 PNG 서명이 있으면 검사하며, 비어 있지 않은 다른 확장자는 불일치 통계로 남깁니다. 경로/확장자 유효성은 기존 paths 책임입니다. 다른 이미지 및 OLE는 `unhandled_binaries`로 남기며 유효성을 보증하지 않습니다.

## 한도와 수명

`max_binaries`는 검사기에 전달된 decoded 항목 수입니다. 동일 물리 스트림의 반복 참조도 항목별로 계산합니다. `max_total_pixel_bytes`는 PNG의 필터 바이트를 포함한 decoded scanline 바이트 합이며 RGBA 크기가 아닙니다. 개별 PNG 한도와 남은 전역 한도 중 작은 값을 적용합니다. 텍스트/ICC 한도는 기존 PNG 옵션의 개별 검사 한도이며, 모든 메타데이터의 문서 전체 합산 한도를 구현했다는 뜻은 아닙니다.

실패한 consume은 누적 보고서를 변경하지 않습니다. 보고서는 scalar만 복사하여 임시 decoded BinData/PNG/ICC 버퍼를 보유하지 않습니다. `semantics_deferred`는 항상 남으며 구조·픽셀 검사 성공을 렌더링/색상 의미 완료로 바꾸지 않습니다. ICC 상세 검사와 v2 UTF-16BE 해석은 기존 명시적 PNG 옵션을 그대로 전달합니다.

## 검증 기록

- 네이티브: 반복 참조의 한도 경계, 미선택 손상 PNG 보존, 선택 시 잘림/CRC 오류 전파, 입력 해제 뒤 보고서 수명, ICC 옵션 전달 및 미지원 의미 유지, 할당 실패 정리 검사.
- 테스트용 WASM mode 244: 기존 mode 25 보고서 뒤 44바이트 선택/이미지 통계를 추가합니다. 독립 JS 생성기로 압축/비압축 × 1/2/5회 참조, 정확한 한도와 한도-1, 오류 뒤 재호출을 대조했습니다. 세 모드 직접 실행에서 각각 비교 26건·거부 14건 통과.
- 실제 표본: Debug WASM에서 일반 HWP 45개는 선택 전후 기존 보고서가 일치했습니다. PNG 참조 3건, 미지원 콘텐츠 10건. 배포용 2개와 암호화 1개는 기존 지원 정책으로 거부했습니다. 해당 검사도 정규 audit에 연결했습니다.
- 네이티브 전체 Debug 717/717 통과. 컨테이너 이름 필터의 7개 테스트는 Debug/ReleaseSafe/ReleaseFast 모두 통과했습니다(기존 XML 연결 검사 포함). 별도 PNG 예산 이름 필터는 Debug 2개 통과했습니다(root 테스트 포함).
- 세 모드 WASM 보고서의 선택 여부·항목 수·PNG 수·픽셀 바이트·의미 보류 값을 각각 0으로 바꾼 5가지 출력 변형을 독립 JS 기대값이 모두 검출했습니다. 소스 변형 검증이나 전체 의미 지원의 증거로 대체하지 않습니다.
- 격리 소스 복사본에서 남은 픽셀 예산 대신 최초 전체 예산을 매 항목에 적용하도록 변형했습니다. Debug/ReleaseSafe/ReleaseFast 모두 반복 참조 테스트가 `TestExpectedError`로 실패했습니다(각 root 포함 2개 중 1개 실패). 제품 소스는 변경하지 않았습니다.
- 독립 JS raw-DEFLATE 해제와 서명 조사에서 미지원 참조 10건은 JPEG 8건·BMP 2건이었습니다. 표본의 참조 수이며 고유 이미지 수나 전체 HWP 이미지 형식 분포가 아닙니다. 다음 형식 검사 연결에서도 미지원 의미와 구조 검사를 분리해야 합니다.
- Debug/ReleaseSafe/ReleaseFast 전체 audit가 각각 20/20 단계·717/717 네이티브 테스트·6,994,874회 검사로 통과했습니다. 정규 실파일 검사에서도 각각 45개·PNG 3건·미지원 10건을 확인했습니다. 기존 대비 추가 181회 중 135회는 실제 45개 문서의 세 경로 대조입니다. 이 기록을 전체 포맷 검증 완료로 해석하지 않습니다.

# 세로·가로 혼합 구역의 페이지 중심

`layoutPageSections`는 각 구역의 조판을 한 번 실행하고, 검증된 실제 용지 경계로 공통 가로 중심을 구합니다. 구역별 차이만큼 용지·본문·머리말·꼬리말·단·행·표·그림·클립과 참조 상자를 함께 이동합니다. 원본 문서의 크기·여백·방향·로컬 좌표는 수정하지 않습니다. 행의 affine 변환은 로컬 좌표 대신 월드 평행 이동 성분만 바꿉니다. 그림의 점유 프레임·캡션 행은 `translatePicturePlacement`를 단일 출처로 사용합니다.

## 재현과 원인

`reference/rhwp/samples/issue6031/3249937_asset_management_rules.hwpx`는 세로·가로·세로의 3개 구역입니다. 방향과 용지 크기는 정상적으로 해석되었으나, 모든 구역을 같은 왼쪽 좌표에 쌓아 가장 넓은 가로 페이지 중심으로 화면을 정렬했습니다. 이 때문에 세로 페이지가 왼쪽으로 약164.4px 치우쳤습니다. 방향 파서 오류로 확정하거나 원본 크기를 덮어쓰는 보정은 하지 않습니다.

실제 Chrome 1440px 화면에서 수정 전 세로 페이지 중심은555.59px, 가로 페이지는719.99px였습니다. 수정 후 첫 세로·가로·후속 세로 페이지가 모두719.99px로 일치했습니다. 전체 스크롤 영역의 오른쪽 경계도 화면 오른쪽에 유지됩니다.

## 검증 범위

- `tests/hwpx/mixed-page-centering.test.mjs`: 혼합/동일 폭, 다른 시작 좌표, 페이지 순서, 행 예산·제한, 잘못된 경계 거부, 원본 불변, affine 좌표와 캡션을 포함한 이동을 검사합니다. 캡션의 최종 좌표는 이동 함수 호출 결과와 별도로 상수 좌표로 검증합니다.
- `tests/hwpx/nested-cell-picture-projection.test.mjs`: 그림·점유 영역·캡션이 셀 배치에서도 한 번만 이동하는 회귀입니다.
- `tools/asset-landscape-browser-audit.mjs ORIGIN --expect-centered`: 실제 예제 열기와 세로·가로·후속 세로 구간을 스크롤하며 중심 오차1px 미만과 오른쪽 스크롤 영역을 검사하고 소유 브라우저를 종료합니다.
- 실제 자산관리규정 Canvas 셀 입력·독립 ZIP/XML 저장 검사·undo/redo·재열기: `zig-out/verification/asset-management-browser-rd4YnE`. 실제 글꼴 측정에서 수정 전후 편집 왕복58페이지와 본문2298문단의 커버리지를 확인했습니다. 이는 한글 원본과58페이지가 같다는 뜻은 아닙니다.

고정8px 폭 측정에서는53페이지·2961행이 유지되고 x좌표만 예상대로 바뀌었습니다. 실제 글꼴 측정과 고정 폭의 페이지 수는 서로 다른 검증 조건이므로 섞어 비교하지 않습니다. 한글 프로그램과의 전체 페이지 수·표 행 분할·글꼴 조판·픽셀 동치는 이번 수정의 완료 주장에 포함하지 않습니다.

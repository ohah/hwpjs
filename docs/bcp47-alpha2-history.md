# IANA 두 글자 언어·지역 이력 조회

## 근거와 데이터

[RFC 5646 §3.1.6](https://www.rfc-editor.org/rfc/rfc5646.html#section-3.1.6)의 Deprecated와 [§3.1.7](https://www.rfc-editor.org/rfc/rfc5646.html#section-3.1.7)의 Preferred-Value를 두 글자 language/region 레코드에 한정해 보존합니다. 폐기 날짜의 부재와 단일 권장 값의 부재는 각각 null이며, 주석에서 임의 대체 코드를 만들지 않습니다. 값은 조회만 제공하며 자동 canonicalization은 하지 않습니다.

단일 출처는 기존 `src/text/bcp47/data/source.json`의 alpha2_history입니다. `tools/language-history.mjs`가 이미 파싱된 레코드에서 필드를 추출하고 Zig 테이블을 생성합니다. 원본 record-jar 파싱·다운로드·공통 목록 확장은 기존 language-registry.mjs가 계속 소유합니다. JSON을 수동 관리하는 별도 IANA 목록이나 중복 다운로드 도구를 만들지 않았습니다. 생성된 `data/alpha2_history.zig`는 직접 수정하지 않으며 기존 --check가 함께 검사합니다.

2026-09-08 IANA의 기존 두 원본을 HTTPS로 읽어 모두 HTTP 200을 확인했습니다. 전체 catalog를 다시 생성한 결과가 메모리 안에서 로컬 JSON과 deepEqual로 일치했습니다. 원본 해시와 File-Date는 기존 스냅샷과 같고 새 필드는 language 6개·region 11개입니다. 새로운 날짜의 등록부로 갱신한 것이 아닙니다. 일반 빌드와 조회 시에는 네트워크 요청을 하지 않습니다.

생성기는 필드 중복, 달력상 잘못된 날짜, 잘못된 자료형·키, 등록되지 않은 이력 코드/권장 코드, 자기 자신을 가리키는 권장 값, 의미 없는 빈 이력 항목을 거부합니다. 지역 권장 값의 대문자 등 원본 표기를 보존하며, 참조 등록 확인은 기존 등록 목록의 소문자 키를 사용합니다. 이력 조회가 재귀 치환을 수행하지 않으므로 전체 canonicalization 체인 검증을 완료했다고 주장하지 않습니다.

## 조회와 책임

`text.bcp47_alpha2_history.inspect(kind, [2]u8)`는 language 또는 region을 명시적으로 받아 registered·deprecated_on·preferred를 반환합니다. 등록 여부는 기존 registry_data.contains를 재사용하며 BCP 47의 대소문자 비구분 규칙을 따릅니다. 결과 문자열은 정적 데이터이므로 할당·입력 보관이 없습니다. ISO의 소문자 코드 조회 정책과 혼합하지 않습니다.

등록된 코드이지만 이력 필드가 없는 경우와 등록되지 않은 코드는 registered로 구분합니다. 등록된 폐기 코드의 권장 값이 없는 경우도 그대로 반환합니다. AN/CS/SU 같은 지역에서 임의 후속 국가를 선택하지 않습니다. sh의 주석을 단일 권장 값으로 만들지 않고, bih처럼 세 글자인 언어 권장 값도 자르지 않습니다. 조회 성공은 원본 코드의 자동 교체를 허가하거나 ISO 3166의 현행 배정 여부를 보증하지 않습니다.

[ISO와 IANA 이력 대조](iso639-history-evidence.md)의 날짜 차이는 유지합니다. 전체 ISO 과거 이력·ISO 국가 코드 등록·ICC 언어 매칭·HWPX 문서 모델·제품 JS API는 아직 남아 있습니다. 기존 mluc_selection의 원시 코드 비교와 locale 보류 상태는 변경하지 않았습니다.

## 검증 진행

Debug 네이티브 5/5 단계·462/462 테스트가 통과했습니다. bh/mo의 IANA 날짜, 권장 값의 원본 길이/대소문자, 폐기 날짜는 있지만 권장 값은 없는 지역, 이력 없는 등록 코드, 미등록 코드·NUL·비ASCII를 검사합니다. 생성기 직접 검사는 정상 4건·거부 20건이 통과했습니다. 윤년·월/일 범위·중복 Type/Subtag/Deprecated/Preferred-Value·중복 레코드·미등록 대상·자기 참조·잘못된 자료형과 source→tables 연결 오류를 포함합니다.

WASM mode169를 정규 감사에 연결했습니다. 독립 JS는 JSON의 원시 범위를 문자열 비교로 확인하고 이력 필드를 객체 조회하며, 제품의 고정 폭 이진 검색이나 생성된 Zig 테이블을 재사용하지 않습니다. language/region 각각의 두 바이트 조합 전체와 잘못된 길이·종류·한도·실패 후 복구를 검사합니다. Debug WASM 직접 실행은 비교 131,073건·오류 거부 7건이 통과했습니다. 대소문자 조합을 포함한 등록 입력은 언어 760개·지역 1,248개, 폐기 필드가 있는 입력은 각각 24개·44개였습니다. 생성기 정상 4건·거부 20건도 이 실행에서 함께 통과했으며 WASM 호출 수에 더하지 않습니다.

최초 세 모드 전체 감사가 각각 종료 코드 0, 20/20 단계·462/462 네이티브 테스트·WASM 5,035,989개 검사로 통과했습니다. 로그는 `/tmp/hwpjs-language-history-Debug-first.log`, `/tmp/hwpjs-language-history-{ReleaseSafe,ReleaseFast}-final.log`입니다. 아래의 추가 날짜 검증 수정 전 결과이며 수정본 전체 감사 완료로 치환하지 않습니다.

추가 수동 적대적 검사로 고정 seed 639의 순열 128개를 만들어 language/region 그룹·이력 항목·원본 레코드의 순서를 섞었습니다. 각 순열에서 추출한 이력 객체와 생성한 Zig 텍스트가 기준과 일치했습니다. locale에 의존하지 않는 코드 키 정렬을 사용하고 필드 출력 순서를 고정하므로 원본 배열/JSON 키 순서가 결과에 영향을 주지 않음을 확인했습니다. 이 수동 검사는 정규 감사 수에 합산하지 않습니다. 기존 --check의 8개 파생 파일 일치와 포맷·diff 공백 검사도 통과했습니다.

추가 적대적 검토에서 기존 File-Date 검사가 정규식 모양만 확인하는 결함을 재현했습니다. 로컬 catalog의 date를 2026-02-30, extension_date를 2014-13-01로 바꾸면 tables가 그대로 승인했습니다. 폐기 날짜에 추가했던 달력 검증을 tools/language-date.mjs로 분리해 두 등록부 File-Date와 Deprecated가 같은 규칙을 사용하도록 수정했습니다. Gregorian full-date의 존재 여부만 검사하며 Deprecated가 Added보다 앞설 수 없다는 등 명세에 없는 순서 제한은 넣지 않습니다.

수정본 생성기 직접 검사는 정상 5건·거부 44건으로 통과했습니다. 원본→catalog와 catalog→tables 양쪽 경로의 두 File-Date 필드에 대해 월/일 범위와 평년/세기 윤년 오류를 검사하며, 2000년·2024년 윤일은 허용합니다. --check의 파생 파일 8개는 수정 전과 여전히 일치합니다. 이 수정 뒤 세 모드 전체 감사도 `/tmp/hwpjs-language-history-{Debug,ReleaseSafe,ReleaseFast}-post-date.log`에서 각각 종료 코드 0, 20/20 단계·462/462 네이티브 테스트·WASM 5,035,989개 검사로 통과했습니다. 세 모드 모두 새 생성기 정상 5건·거부 44건과 이력 비교 131,073건·오류 거부 7건을 확인했습니다.

날짜 수정 후 추가 수동 적대적 검사 189,433건이 통과했습니다. JavaScript Date와 독립적인 정수 윤년 공식·월별 일수 배열을 기준으로 1600~1999의 Gregorian 400년 주기 및 0/1/9/10/99/100/999/2000/2024/9999년, 총 410개 연도의 월 0~13·일 0~32를 대조했습니다. 잘못된 타입·전각 숫자·종결 개행·자릿수·부호·5자리 연도 등의 13건도 거부했습니다. 정상 149,750건·거부 39,683건이 기대값과 일치했습니다. 모든 네 자리 연도를 전수 검사했다는 주장이 아니며, 이 수동 검사는 정규 감사 수에 합산하지 않습니다.

최종 검토에서 입력 등록 여부와 이력 필드 부재의 구분, 원본 권장 값의 길이/대소문자 보존, 정적 반환값의 수명, 등록/날짜 규칙의 재사용을 확인했습니다. 수정 이후 이번 범위의 추가 결함은 발견하지 못했습니다. 변경 문서 3개의 로컬 링크 5개와 포맷·JS 구문·diff 공백 검사도 통과했습니다. ISO 전체 이력이나 ICC locale 의미 검증의 완료를 뜻하지 않습니다.

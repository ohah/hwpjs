# 원본 HWPX 셀 너비 균등화

`EQUALIZE_SOURCE_TABLE_CELL_WIDTH_COMMAND`는 소유 Surface가 현재 F5 직사각형 선택에서 발급한 `SourceTableCellWidthTarget`을 받아 실행합니다. 표 메뉴와 문맥 메뉴는 `Surface.registerCellBlockMenu`를 통해 선택을 보존합니다. 선택의 현재성·문서 token·원본 소유권·전체 사각형을 Core와 Worker에서 다시 검사하고 기존 Native 원자적 셀 크기 batch로 반영합니다.

## 범위

완전한 snapshot의 최상위 원본 HWPX 정적 표, 연속된 비병합 셀과 가로 두 칸 이상의 직사각형을 지원합니다. 각 선택 행의 물리적인 시작 위치와 총 너비가 같아야 합니다. 선택 셀은 최대 4096개이며 잘린 표시, 생성·중첩 표, 병합 셀, 모순된 경계, 내용을 수용하는 여백보다 좁은 너비는 거부합니다.

선택 영역의 총 너비를 보존하고 HU 정수 나머지는 왼쪽 칸부터 하나씩 배분합니다. 새 너비는 최대 1 HU 차이입니다. 이 나머지 규칙은 자체 정책이며 공식 한글의 내부 반올림과 동일하다고 주장하지 않습니다. 대상 밖 셀, 높이, 표 외곽 크기와 나머지 XML은 보존합니다. 높이 균등화와 HWP5 대응은 별도 후속입니다.

## 수명과 이력

다른 editor에서 받은 대상, 복제·만료된 대상, 해제된 lease, 문서 교체·실행 취소 후 대상은 거부합니다. 셀 합치기·나누기 대상과 너비 대상은 서로 바꿔 사용할 수 없습니다. 무변경은 redo를 보존하고, 실제 반영 뒤 응답이 잘못되면 refresh-required로 전환하며 같은 편집을 재전송하지 않습니다. 원본 셀 사각형 검증만 공통 함수가 소유하고 기능별 쓰기 권한은 분리합니다.

공식 기능의 메뉴·사각형 선택 의미는 [셀 너비 같게 도움말](https://help.hancom.com/hoffice130/ko-KR/Hwp/table/table%28eqwidth%29.htm)을 기준으로 했습니다. 표 구조 변경과 저장 계약은 [원본 셀 나누기](hwpx-source-cell-split.md)를 함께 참고합니다.

## 검증

합성 새 문서에서 실제 원본 표를 만들어 독립 ZIP/XML 기대값과 저장 결과를 비교합니다. 너비와 셀 나누기를 같은 문서에 적용하고 두 번의 실행 취소·다시 실행에서 각 중간 저장 바이트를 대조합니다. 원본 보존·정수 나머지·잘못된 대상·읽기 전용·경합·무변경과 반영 후 잘못된 응답을 별도로 검사합니다. 공개 번들의 실제 메뉴·F5·저장·재열기 검증은 소스 검사와 구분합니다.

셀 주소별 슬롯을 한 번 구성해 행마다 전체 셀을 재검색하거나 정렬하지 않습니다. 이 편집 계획의 비용은 전체 셀 수와 선택 셀 수에 선형입니다. 역순 입력 1,024·2,048·4,096셀에서 원본 셀 배열 접근 횟수와 저장 크기 기대값을 확인하며, 이 수치를 전체 문서 로딩·조판 복잡도로 확대하지 않습니다.

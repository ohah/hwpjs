# 종이 너비를 넘는 단순 인라인 표의 부분 미리보기

이 기능은 원본 표 크기를 유지한 화면 투영입니다. 종이 밖 부분을 잘라 표시하며 원본 셀 폭·문단 ID·컨테이너 바이트를 축소하거나 고치지 않습니다. 원본 조판 동치를 주장하지 않으며 `sourceCoverage: incomplete`, `documentPageNumbersExact: false`로 표시합니다.

## 배치와 입력의 책임

`inline-table-paper-preview.mjs`는 완전한 표시 모델의 제한된 표·셀 소유권을 확인하고 최종 종이 사각형과 기존 클립을 교차합니다. `table-body-content-layout.mjs`가 일반 세로 페이지 배치와 연결하며 클립 대상의 선택용 표 앵커를 제거합니다. 저수준 `layoutPageContent`·`layoutTableBodyContent`는 기본적으로 기존 가로 비적합 오류를 유지합니다. Canvas renderer만 `oversizeInlineTablePreview: true`를 선택합니다.

허용 대상은 단일 전체 너비 단의 단순한 원본 표 하나입니다. 절대 크기·단독 인라인 호스트·완전하고 병합되지 않은 셀·일반 셀 텍스트·단일 페이지 인스턴스를 확인합니다. 중첩·분할·캡션·그림·필드·변환·불완전한 측정 결과·혼합 호스트·창 조각은 제외합니다. 본문 단의 너비를 넘더라도 물리 종이 안에 들어가는 기존 표는 이 제한을 적용하지 않습니다. HWP5는 명시적 `has_caption: false`를 사용하고, HWPX의 해당 필드가 없는 경우에는 캡션 reader의 명시적 `sourceCaption: null`을 사용합니다. 둘 다 없는 값을 캡션 없음으로 기본 처리하지 않습니다.

`preview-edit-policy.mjs`가 화면 전용 문단 마스크와 허용 검사를 소유합니다. 클립한 표의 셀 전체와 단독 호스트를 편집 불가로 표시하며 문단 목록·순번·Native 참조를 필터링하지 않습니다. 선택 범위가 제한 구간을 건너뛰거나 오래된 표·셀 대상을 사용하면 거부합니다. 일반 본문은 기존 편집 경로를 유지합니다. Surface는 최종 요청과 공개 선택 경계를 검사하고, Canvas는 남아 있던 입력·조합·선택을 정리합니다. 실행 취소·다시 실행·저장은 Native 모델의 기존 경로를 사용합니다.

정책의 소유권 색인은 모델/배치 세대마다 Map·Set과 순서 경계를 한 번 구성하고 재사용합니다. 일반 입력의 지연 투영을 강제로 계산하지 않습니다. 셀·문단 이동 같은 명시적 geometry 조회는 기존 계약대로 최신 투영을 먼저 계산한 뒤 새 정책을 확인합니다. 활성 제한 구간의 요청은 새 Native 식별자에 대해 다시 검증합니다. 기존 전체 조판 비용이나 모든 API의 복잡도를 이 색인 비용으로 해석하지 않습니다.

## 검증 경계

집중 검사는 strict 기본값, 정상 표의 동일 결과, 종이 경계, 원본 불변성, 소유권 누락·중복·다른 인스턴스, 입력 차단과 일반 본문 유지를 확인합니다. 실제 브라우저·저장·재열기·배포 결과는 후보 아티팩트와 함께 별도로 확인합니다. 근거 디렉터리는 `zig-out/verification/scoped-inline-table-preview-r1/`이며 실행 명령은 [개발 명령](development-commands.md)을 따릅니다.

## ACK 전 입력 커서

화면 정책은 허용된 문단의 임시 입력 커서를 canonical 텍스트 길이로 제한하지 않습니다. 본문 끝에 덧붙인 직후에는 Native ACK 전까지 커서가 원문 길이를 넘을 수 있기 때문입니다. 길이 비교를 owner 거부로 사용하면 input 이벤트에 새 글자가 들어온 뒤 선택·입력을 초기화하고 저장 모델이 그대로 남습니다. 실제 브라우저의 trusted input/keyup과 저장 바이트로 이 현상을 확인했고, 문단 끝 입력 및 ACK 전 새 레이아웃 알림을 회귀 검사에 추가했습니다. 유효한 정수 좌표, 표·호스트 거부와 순서 barrier는 유지하며 실제 명령의 좌표·편집 권한은 기존 Core/Native가 검증합니다.

## 확인한 아티팩트와 남은 범위

WASM `438044e0060fb0f40ab8a4a76eee2027e387f68579d547487fcd74ca88129088`와 정적 manifest `06c5b6f504cd29e4f92b137681228c7d78a644a0db2440499129f1d87cf0f631`를 사용한 로컬 실제 브라우저에서 세 프레임워크·두 형식의 표 선택 차단, 표 앞뒤 본문 덧붙이기·undo·독립 CFB/ZIP/XML 저장 대조·재열기를 확인했습니다. Vanilla의 두 형식에서는 실제 열 추가로 너비 초과 상태에 들어간 뒤 undo로 원본 저장 데이터와 셀 편집·본문 입력이 복구되는 것도 확인했습니다. 각 사례의 console/errors가 비어 있고 소유 브라우저가 종료됐습니다. 근거는 `browser-direct-r5/summary.json`과 같은 디렉터리의 저장 파일·오라클·화면·명령 기록입니다.

이는 승인 원본에서 파생한 검증 파일의 결과입니다. HWPX 초기 후보는 CELL 분할 설정이었고, TABLE로 변경한 다음에도 선언된 가로 용지 안에 들어가 새 미리보기의 양성 사례로 쓸 수 없었습니다. 최종 HWPX 후보는 동일 소유권·내용을 유지하며 60,000HU→90,000HU의 명시 표/셀 폭과 TABLE 설정으로 실제 물리 너비 초과를 확인했습니다. 초기 실패·부적합 후보를 그대로 보존하며 이를 제품 회귀 통과로 바꾸지 않습니다.

호스트에는 독립된 인쇄 글리프가 없어 별도 물리 클릭 차단을 입증하지 못했습니다. 호스트·프로그램 선택·범위·비동기 요청 차단은 합성 Surface 검사에서 확인한 범위입니다. 전체 사용자 파일, 한컴 조판 동치, Native 전체 suite, 공개 원점의 브라우저 실행을 이 결과로 대신하지 않습니다. 공개 서버 정적 바이트 동일성은 배포 후 별도로 확인합니다. npm 게시는 포함하지 않습니다.

# 조합 입력 뒤 줄바꿈

한글을 조합하는 동안 Enter를 눌러 브라우저의 `beforeinput` 줄바꿈 이벤트가 발생했는데도 문단이 나뉘지 않는 문제를 수정했습니다. 이벤트가 `compositionend`보다 먼저 오면 기존 코드는 기본 동작을 막고 즉시 `split()`을 호출했습니다. 이때 `split()`은 조합 중이라는 이유로 거부해 줄바꿈 요청이 사라졌습니다. 조합 확정이 먼저 끝나더라도 텍스트의 Native 반영을 기다리는 동안 Enter가 오면 같은 문제가 발생했습니다.

이제 줄바꿈 의도를 기존 순서 큐에 보관합니다. 조합 텍스트와 앞선 입력이 Native에 반영된 뒤 현재 커서에서 문단을 나눕니다. 새 편집 모델이나 타이머 기반 추측은 추가하지 않습니다. 조합 확정용 Enter만 있고 줄바꿈 이벤트가 없다면 문단을 나누지 않습니다. 두 개의 명시적 줄바꿈 요청은 두 번 적용합니다.

편집 권한이 거부되거나 입력의 기준 문서를 잃어 조합 초안을 폐기하면 그 초안에 이어진 대기 명령도 취소합니다. 폐기된 줄바꿈이 나중의 권한 응답에서 되살아나 원문을 분할하지 않도록 했습니다. 이 취소는 기존 `clearInputIntents`가 소유하고, 텍스트 반영·줄바꿈 순서는 기존 `history-input-intent-queue`를 재사용합니다.

## 확인한 동작

- 합성 이벤트 검사에서 조합 확정 전/후 줄바꿈, Native 응답 대기, 반복 줄바꿈, 권한 거부, 초기화와 종료를 확인했습니다. 새 집중 검사 14개와 기존 입력 큐 검사 11개가 통과했습니다.
- 커밋된 기존 Canvas 검사에 실제 고정 WASM을 공급한 Enter·조합 입력 경로와 새 검사를 함께 실행해 49개가 통과했습니다. 별도 이력 검사 하나는 수정 전 코드와 수정 후 코드 모두에서 같은 `readOnly` 기대값으로 실패했습니다. 이를 이 수정의 성공 증거에 포함하지 않았으며 기존 작업 트리의 Canvas 테스트 변경도 덮어쓰지 않았습니다.
- 실제 Chromium Canvas에서 Noori HWP5/HWPX의 표 안 문단을 포인터로 선택한 뒤 CDP 조합 입력과 Enter를 전달했습니다. `보도일시`에 `한`을 입력하면 `보도한`과 `일시`로 나뉘고 커서는 오른쪽 문단의 처음으로 이동했습니다. 실제 Native 저장본을 다시 열었습니다.
- HWP5는 원문에서 한 글자 삽입을 독립 CFB oracle로 확인한 중간 파일과 실제 브라우저 저장본을 독립 분할 oracle로 비교했습니다. 전체 대상 Section과 비대상 스트림을 확인하고 잘못된 분할 위치는 거부했습니다. 저장은 기존의 명시적 줄 배치 변경 동의를 사용했습니다.
- HWPX는 예상 문단·서식·캐시 변경을 적용한 전체 XML과 비대상 ZIP 항목을 대조했습니다. Python 일반/최적화 모드 모두 정상 기대값을 수용하고 잘못된 분할 위치를 거부합니다. 분할 뒤 추가 입력과 실행 취소를 거치면 원본 HWPX 전체 바이트와 같아지는 것도 확인했습니다.

CDP 조합 입력은 브라우저 입력 경로와 Native 처리를 확인하는 통제된 검사입니다. 실제 운영체제의 한글 키보드·모든 브라우저에서 직접 입력한 증거와 구분합니다. 기존 Native 엔진과 Worker 바이트는 변경하지 않았습니다. 세부 근거는 `zig-out/verification/ime-enter-r1/`에 보존합니다.

# HWP5 원본 셀 나누기 연결

지원 계약은 [원본 셀 나누기](hwp5-source-cell-split.md)가 소유합니다. SDK와 공통 Core 명령을 통해 Canvas F5 선택, 표 메뉴·문맥 메뉴의 셀 나누기 대화상자를 같은 Native Session/history에 연결합니다. 별도 JS 문서 모델이나 CFB writer를 만들지 않습니다.

## 현재 검증

엔진은 기존 필수 export와 함수 인자 수를 유지하며 선택적 HWP5 셀 나누기 ABI를 사용합니다. 정확한 엔진·번들 해시는 배포 manifest가 소유합니다. 전역 ABI 버전은 6이고 이력 프로토콜 버전 2와 구분합니다.

- Native 집중 검사 28개: 관리 이력, 저장·재열기, 실패 시 원상 복구, 두 구역의 비대상 데이터 보존. 병합 입력은 내부 전용 capture 경계 검사이며 공개 병합 셀 지원으로 계산하지 않습니다. 기본 변환의 할당 실패를 전수 검사하고 관리 이력 경로는 125개 할당 중 40지점을 표본 검사했습니다. 관리 이력의 모든 할당 지점을 전수 검사한 결과는 아닙니다.
- SDK/Core 검사 10개: 공개 새 문서·표 생성으로 만든 입력에서 네 모서리 셀 각각 나누기, 정확한 undo/redo, 오래된·다른 문서의 대상 및 구형 엔진 거부.
- 저장 비교는 제품 CFB 파서와 별개의 Python 표준 라이브러리 검사기를 사용합니다. 표 레코드·셀 배치·고유 문단 ID와 CFB 메타데이터·비대상 스트림을 검사합니다. 일반/-O 실행 모두 정상 결과를 승인하고, 나누지 않은 문서·바뀐 root CLSID·잘못된 대상 모서리를 거절합니다.
- 실제 Noori 입력·Worker·COW 및 셀 크기 권한 회귀 40개를 검사합니다.

중복된 시나리오 수를 고유 기능 수로 합산하지 않습니다. 위 검증은 전체 Native 테스트나 모든 실제 문서의 조판 동치를 보장하지 않습니다. 최종 제품 번들의 Vanilla·React·Svelte에서 실제 표/문맥 메뉴로 나누기, 저장·독립 CFB 비교, 원본 그대로 undo·결과 그대로 redo·재열기를 확인했습니다. 각 검사용 브라우저와 서버도 종료했습니다. 공개 배포는 해당 자산 manifest와 배포 CI를 별도로 확인합니다.

## 남은 범위

현재 원본 셀 하나의 전체 span을 검증해 병합 셀과 주변 병합을 포함한 나누기를 지원합니다. 여러 셀 각각 나누기·합친 후 나누기·원본 불균등 높이 유지의 지원 확대는 별도 작업입니다. CLI·MCP는 아직 비병합 표의 단일 셀로 범위를 제한합니다. 표 외곽 선언과 실제 셀 크기 합이 다른 입력은 나누기에서 원래 외곽 선언을 보존합니다. 실제 셀 등식으로 내부 축을 계산하고 원시 control header를 복사하므로 외곽을 내부 합으로 정규화하지 않습니다. 공개 셀 크기 편집으로 만든 같은 입력은 수정 전 엔진에서 거절되고 수정 후 단일 이력·독립 CFB·재열기를 통과합니다. 행·열 삽입삭제는 별도의 기존 extent 입장 정책을 유지합니다.

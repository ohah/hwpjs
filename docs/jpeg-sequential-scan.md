# JPEG sequential 스캔 복호화 작업

Huffman sequential 단일 스캔의 계수 복호화를 구현했습니다. 제품 JS 공개 API나 HWP JPEG 지원 완료로 연결하지 않았습니다.

## 근거와 책임

[ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf)의 A.1~A.2, E.2, F.2를 참조합니다.

- `mcu_layout.zig`: 파싱된 프레임·스캔과 호출자가 SOF/DNL에서 확정한 높이를 받아 DCT 블록 순서를 계산합니다. 단일 성분 스캔은 MCU당 한 블록입니다. 여러 성분 스캔은 각 성분의 H×V 블록을 좌→우·상→하로 순회하며, 프레임 전체의 최대 샘플링 값으로 MCU 격자를 구합니다. 가장자리의 추가 패딩 블록도 포함합니다. 성분은 숫자 ID가 아닌 프레임 선언 위치로 연결합니다.
- `sequential_scan.zig`: 기존 활성 테이블 선택과 [블록 디코더](jpeg-sequential-block.md)를 조합합니다. 성분별 DC 예측값, MCU 단위 재시작 간격, 기존 RST 번호 검증, 구간 패딩 검사와 예측값 초기화를 소유합니다. 코어는 할당하지 않으며 입력·테이블의 불변 바이트를 빌립니다.

입력은 SOS 직후부터 시작하며 종결 마커를 포함해야 합니다. 종결 마커는 소비하지 않습니다. 스캔 다음의 문서/이미지 구조 의미는 호출자가 검사합니다. `next`는 한 블록의 zigzag 계수와 성분 ID·프레임 위치·블록 좌표를 반환합니다. 오류 시 해당 호출 시작의 상태로 유지하지만 앞서 성공적으로 반환한 블록을 취소하지는 않습니다.

마지막 블록을 반환한 것만으로 완료가 아닙니다. 다음 `next`가 남은 패딩과 불필요한 RST 부재를 확인한 뒤 null을 반환해야 `complete`가 됩니다. 더 읽지 않은 전체 byte를 패딩으로 무시하지 않습니다. 옵션은 입력 바이트·총 블록·RST 개수를 제한합니다. 테스트용 mode 253은 출력 크기도 바이트 한도로 제한합니다.

## 검증 현황

- 새 네이티브 5개와 기존 JPEG 검사 포함 Debug/ReleaseSafe/ReleaseFast 각각 61/61 통과.
- 단일/여러 성분의 홀수 크기 격자, 프레임 ID 순서, 서브샘플링, 마지막 패딩, 블록·RST 예산, 잘못된 번호, 재시작 직후 잘림의 원자성, 성분별 예측값 분리, 이른 RST·마지막 추가 RST·남은 전체 byte를 검사했습니다.
- Debug WASM mode 253에서 2성분·MCU당 3블록·MCU 2개의 합성 스캔을 Ri=0과 Ri=1로 확인했습니다. 총 6블록 각각의 모든 64계수·성분·좌표 및 소비한 바이트/RST 수가 직접 작성한 기대값과 일치했습니다.
- 독립 JS는 MCU 행/열→성분→성분 내 행/열의 중첩 순회와 Map 기반 예측값을 사용합니다. 네이티브의 선형 블록 인덱스/slot 변환과 대조합니다. 비트 문자열·prefix Map 기반 계수 리더는 기존 블록 oracle과 공유하며, 블록 단계의 70,422건 비교·613건 거부 회귀 검사도 유지했습니다.
- 세 모드 각각 mode 253 독립 비교 2,560건·거부 20건 통과. 8/12비트, 폭 1/7/8/9/15/16/17/31/32/33, 높이 1/8/9/17, 여러 샘플링 구성, 전체/마지막 단일 성분 선택, Ri=0/1/2/7을 조합합니다. RST 번호 순환도 포함됩니다.
- 실제 HWP의 sequential JPEG 참조 7건에서 총 20,089블록의 모든 계수·성분·좌표, 마지막 패딩 및 재시작 마커 10개를 세 모드 WASM과 독립 JS로 대조했습니다. progressive 참조 1건은 명시적으로 제외했습니다. `reference/rhwp/samples/s1.jpg`도 세 모드에서 1,197블록·재시작 18개를 확인했습니다. 픽셀 대조는 아닙니다.
- 6블록 합성 스캔의 출력에서 헤더와 각 블록의 성분/좌표/계수를 포함한 모든 32비트 필드 414곳을 각각 XOR 1로 변조해 세 모드 독립 대조에서 전부 검출했습니다.
- 별도 샘플링 조사: 두 성분의 H/V를 각각 1~4로 모두 순회하고 H1×V1+H2×V2≤10인 조합을 선택했습니다. 폭 31·높이 29에서 선택 성분 `[0,1]`/`[0]`/`[1]`과 Ri=0/1/3을 조합한 990건이 세 모드 모두 일치했습니다. 샘플링 3처럼 2의 거듭제곱이 아닌 분모도 포함합니다. `jpegScanFixture`와 `jpegScanActual`로 수행한 이 별도 조사 수치는 정규 audit 합계에 포함하지 않습니다.

### 소스 결함 주입

별도 소스 복사본에 결함 하나씩을 적용한 뒤 Debug/ReleaseSafe/ReleaseFast에서 JPEG 네이티브 테스트를 실행했습니다. 모두 컴파일 성공 후 테스트 실패로 검출했습니다.

- 단일 성분도 interleaved 격자로 처리: 각 모드 61개 중 1개 실패.
- 모든 성분이 DC 예측값 슬롯 0을 공유: 각 모드 1개 실패.
- RST 뒤 예측값 초기화 제거: 각 모드 2개 실패.
- `next` 오류 시 변경된 상태를 외부에 반영: 각 모드 1개 실패.

Debug/ReleaseSafe/ReleaseFast 전체 audit는 각각 20/20 단계, 네이티브 777/777 테스트, 총 7,314,803건 검사로 통과했습니다. 전체 회귀 합계이며 전체 문서 구현이나 픽셀 동일성의 증명은 아닙니다.

여러 스캔 간 성분 중복/누락 검사, progressive·lossless·산술 복호화, 역양자화·IDCT·픽셀 출력은 별도 후속입니다.

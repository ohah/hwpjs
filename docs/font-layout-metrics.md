# 공통 글꼴 높이 정책

`font-layout-policy.mjs`는 HWP5/HWPX의 명시적 문서 형식 판정을 소유합니다. `text-style.mjs`는 유효한 양의 정수 글자 크기를 `height / 75` CSS px로 변환합니다. 해당 문서 본문에는 UI용 최소 20px·1.25배 보정을 적용하지 않습니다. 크기 부재·미지원 값은 기존 20px fallback을 유지하며, 형식이 없는 프로토타입의 UI 정책은 변경하지 않습니다.

`layout.mjs`는 documentBody의 각 줄 높이를 그 줄의 측정값에서 집계합니다. 첫 줄의 글꼴이나 UI 최소값을 다음 줄에 전달하지 않습니다. 빈 문단·강제 개행도 현재 위치에서 측정합니다. 이 명목 높이와 실제 ascent/descent·밑줄 영역·언어별 상대 크기·baseline·행간은 서로 다른 값입니다. 명목 크기 일치가 전체 조판 동치를 보장하지 않습니다.

## HWPX 실측과 회귀

2026-10-17 `facename.hwpx` 13줄·`charshape.hwpx` 7줄·`linespacing.hwpx` 26줄의 선언 크기와 저장된 XML textheight를 독립 ZIP/XML oracle로 읽고 짝지어진 기존 HTML의 상자 높이와 대조했습니다. HTML의 mm 반올림 오차 한계는 0.0051mm입니다. 수정 전 처음 두 파일 모두 20px 대 13.333333px로 실패했고, 수정 후 추가 파일을 포함한 46줄이 일치했습니다. HTML은 기존 기준 자료이며 이번에 한글에서 새로 출력한 파일이 아닙니다.

별도 혼합 크기 검사에서 40px 다음 작은 행이 20px로 부풀던 문제도 재현했습니다. 수정 후 40/12px가 유지되며 빈 문단·개행은 12px입니다. 기존 HWP5 근거는 [형식별 기준 자료](hwp5-font-layout-reference.md)에 있습니다. 확대 검사 40개에서 글꼴·행간·PDF 선언 크기·페이지·표 셀·실제 다단 도형 파일이 통과했습니다. 이는 작업 트리 집중 검사이며 전체 suite 통과와 구분합니다.

실제 Chromium Canvas에서도 동일한 혼합 크기를 측정해 행 높이 40/12px와 작은 글꼴 `12px sans-serif`를 확인했습니다. 형식 부재는 20px를 유지했습니다. 통제된 Canvas 수치 검사이지 실제 한글 문서의 픽셀·페이지 동치 검사가 아닙니다. 브라우저 전용 세션과 서버는 종료했습니다.

기존 미커밋 변경을 제외한 분리 소스에서도 양 형식 메타데이터·구형 ABI 부재·실제 Worker·높이·행간·PDF 검사 32/32가 skip 없이 통과했습니다. 제품 파일 두 개만 수정 전 정책으로 되돌린 음성 대조에서는 처음 두 실제 파일과 혼합 크기 검사가 모두 실패했습니다. 기대값만 바꿔 통과시킨 검사가 아님을 확인했습니다. 전체 native 4,033개 실행은 별도 진행 중이므로 완료로 계산하지 않습니다.

## 남은 조판 근거

짝지어진 `text-align-2.pdf`에서 두 Type0 부분 글꼴과 ToUnicode/CIDToGIDMap=Identity를 확인했습니다. 제목·본문에 해당하는 문자들의 glyph advance도 읽을 수 있었지만 PDF는 개별 Tm/TJ와 변환 행렬을 사용합니다. 부분 글꼴의 단순 advance 합, PDF 텍스트 상자 폭, 원본 문서 자간을 서로 같은 값으로 취급하지 않습니다. 분석용 추출 글꼴은 임시 경로에만 두며 프로젝트 자산·런타임 의존성으로 배포하지 않습니다. 원래 전체 글꼴 복원·한글 font matching·baseline 동치는 아직 검증되지 않았습니다.

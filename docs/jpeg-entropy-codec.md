# JPEG 엔트로피 비트와 Huffman 심볼

## 근거와 책임

[ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) Annex C와 F.2.2.3~F.2.2.5, 엔트로피 구간의 byte stuffing/1-bit 패딩을 참조합니다. 외부 코드를 추가하지 않았습니다.

- `entropy_bits.zig`: 종결 마커를 제외한 한 엔트로피 구간의 MSB-first 비트를 읽습니다. FF00을 FF로 해석하고 다른 FF 뒤 값은 마커 오류로 반환합니다. 읽기 폭은 0~32비트이며 0비트는 입력을 소비하지 않습니다. 오류 시 원시 offset·현재 byte·남은 bit 수를 보존합니다.
- `huffman_decoder.zig`: 기존 Huffman 길이 검사를 재사용해 canonical 코드 범위·길이별 심볼 시작 인덱스를 구성합니다. 최대 16비트를 검사하며 잘못된/잘린 prefix에서 입력을 소비하지 않습니다. 코드 범위는 자체 값, 심볼 순서는 DHT 입력을 빌립니다. 빈 테이블·BITS와 심볼 개수 불일치·예약 all-ones 코드 공간 위반을 거부합니다.

코어는 할당하지 않습니다. 입력은 수명 동안 불변이어야 합니다. `Bits.init`은 호출자가 정한 바이트 한도를 적용합니다. `finish`는 호출자가 모든 부호화 데이터를 소비한 뒤 호출해야 하며, 남은 부분 byte가 모두 1인지와 읽지 않은 전체 byte가 없는지 검사합니다. 추가 FF00 전체 byte를 패딩으로 무시하지 않습니다. RST마다 새 비트 리더를 만들어야 하며 마커 처리/번호는 기존 구조 계층이 소유합니다.

## 지원 범위

Huffman 출력은 원시 u8 심볼입니다. 중복 심볼도 prefix 해석 차원에서는 보존하며 DC category·AC run/size 의미 검증을 대신하지 않습니다. amplitude 부호 확장·DC 예측·AC 계수 배치·progressive 보정/EOB run·lossless 예측·산술 복호화·MCU 간격/행·역양자화/IDCT/픽셀은 후속입니다. 한 심볼 복호화 성공을 완전한 JPEG 이미지 복호화로 인증하지 않습니다. 제품 JS API와 HWP JPEG 미지원 집계는 변경하지 않았습니다.

## 검증 기록

- 새 네이티브 7개와 기존 JPEG 테스트 포함 세 모드 각각 48/48 통과. 첫 바이트 전체 값 × bit offset 0~7 × 읽기 폭 0~32, byte별 모든 패딩 위치, 스터핑·잘림·실패 원자성, 길이 1~16 × 모든 심볼 값, 여러 코드 길이·임의 심볼 순서·중복 심볼을 검사합니다.
- mode 251 독립 JS 비교는 세 모드 각각 74,028건·거부 1,829건이 통과했습니다. JS는 unstuffed 비트 문자열과 prefix Map으로 읽고, 고정 분모 코드 공간으로 코드열을 만들어 네이티브의 길이별 구간 탐색과 대조합니다.
- 실제 HWP JPEG 참조 8건의 엔트로피 구간 24개를 비트 리더로 끝까지 읽어 원시 unstuffed 데이터와 세 모드에서 대조했습니다. 이 대조는 패딩 비트도 일반 비트로 읽으므로 실제 패딩 시작 위치를 인증하지 않습니다. 실제 DHT 정의 31개의 모든 코드로 만든 합성 코드열도 심볼 순서대로 복호화해 확인했습니다. 이는 실제 이미지 데이터의 DC/AC 계수 복호화나 픽셀 대조가 아닙니다. 참고 `s1.jpg`의 같은 검사 연결도 세 모드에서 통과했습니다.
- Debug/ReleaseSafe/ReleaseFast 전체 audit는 각각 20/20 단계·764/764 네이티브 테스트·7,241,163건 검사로 통과했습니다. 이는 전체 회귀 검사 합계이며 JPEG 픽셀 복호화나 전체 문서 구현 완료를 뜻하지 않습니다.

### 추가 적대적 검증

별도 소스 복사본에 각각 아래 결함 하나를 적용하고 `zig test <copy>/src/root.zig --test-filter JPEG`를 Debug/ReleaseSafe/ReleaseFast로 실행했습니다. 모든 변형은 컴파일 성공 후 각 모드에서 48개 중 1개 테스트에 의해 검출됐습니다.

- `entropy_bits.zig`: 각 비트를 읽은 직후 실제 커서에 부분 반영 → 잘림/마커 오류 뒤 상태 보존 검사가 `TestExpectedEqual`.
- `huffman_decoder.zig`: 다음 길이의 코드 시작값 계산에서 현재 길이의 코드 개수를 누락 → 여러 길이를 섞은 정상 코드열이 `UnexpectedEnd`. 길이별 단일 코드만으로는 잡지 못하는 사례입니다.
- `entropy_bits.zig`: 남은 패딩의 all-one 조건 비활성화 → 잘못된 패딩을 허용하여 `TestExpectedError`.

출력 변조는 mode 251의 비트 읽기 결과 오프셋 0/4/8/12, 심볼 읽기 결과 오프셋 0/4/8/12/16에서 각 첫 바이트를 XOR 1로 변경해 독립 JS로 대조했습니다. 세 모드 각각 9종 모두 assertion으로 검출했습니다. 소스 결함과 출력 대조 민감도는 별도 결과입니다.

# ICC 선형 분기의 역상과 실제 극값 선택

## 범위

거듭제곱 쪽의 같은 u128 목표값은 [클리핑 후 분기 역상](icc-power-preimage.md)에서 다룹니다. 두 분기를 합친 전체 역상 구성은 아직 미완료입니다.

`linear_preimage.solve(linear, n, d)`는 [파라메트릭 곡선의 선형 분기](icc-parametric-segments.md) 하나에 대해 `clip((a*x+b)/65536)=n/d`를 만족하는 **모든 실제 x**를 구합니다. n/d는 정규화 u128 입력이며 u16/16.16 격자로 양자화하지 않습니다. 결과는 u256 분수 끝점과 포함 플래그를 가진 하나의 WideInterval, 또는 역상이 없음을 뜻하는 null입니다.

이는 전체 파라메트릭 역변환이 아니라 선형 분기의 기여분입니다. 거듭제곱 분기의 역상과 합치기 전에 한 분기의 결과를 전체 역상으로 간주하면 안 됩니다. null에 대해 해당 분기 끝값을 최근접 출력으로 임의 선택하지 않습니다. 전체 곡선의 단조성/비상수성 검증, 거듭제곱 역상, 분기 간 합집합, 값 범위의 틈에서 최근접 출력의 존재 여부는 별도 후속 작업입니다.

## 공통 분수·구간

- fraction.Normalized는 u64/u128/u256 정규화 분수의 검증·순서·명시적 근사 변환을 소유합니다. 교차 곱은 각각 u128/u256/u512를 사용합니다. 기존 Fraction은 u64 별칭, WideFraction은 u256 별칭입니다. 분수 약분은 요구하지 않습니다.
- unit_interval.Of는 같은 좌표 타입의 구간 검증·포함·교집합을 소유합니다. 기존 Interval과 새 WideInterval이 같은 규칙을 사용합니다. 잘못된 입력 구간은 오류이며, 두 유효 구간의 교집합이 없거나 열린 한 점만 남으면 null입니다. 같은 경계의 포함 여부는 AND로 합칩니다.
- widen은 기존 u64 구간을 검증한 뒤 손실 없이 넓힙니다. 원래 시작/끝 포함 플래그를 보존합니다.
- sampled_inverse의 기존 u256 결과도 공통 WideFraction을 사용합니다. 필드 폭·반환 wire는 바꾸지 않습니다.

## 선형 역상 계산

기울기가 0이면 원시 상수와 목표값을 정확히 비교합니다. y=0/1에서는 출력 클리핑을 반영해 전체 활성 구간 또는 null을 반환합니다. 내부 목표값은 정확히 같을 때만 전체 구간입니다.

기울기가 0이 아닐 때 원시 식의 목표값 교점은 `(65536*n-b*d)/(a*d)`입니다. 분모 부호를 양수로 맞추며 i256 중간값을 사용합니다. 32비트 계수와 u128 입력의 곱은 160비트 미만이므로 손실 없이 계산할 수 있습니다. 결과 분모가 u128보다 커질 수 있어 출력은 u256입니다.

0<y<1에서는 교점의 닫힌 한 점과 원래 활성 구간을 교차시킵니다. y=0은 원시 값 <=0인 반구간, y=1은 원시 값 >=1인 반구간과 교차시킵니다. 교점이 [0,1] 밖이면 활성 구간 내부에 부호 전환이 없으므로 시작점의 정확한 비교로 전체/부재를 판정합니다. 시작점 비교의 교차 곱은 224비트 미만으로 i256에 들어갑니다. 정의역 밖의 교점을 정규화 좌표로 강제 변환하지 않습니다.

## 평탄 역상의 선택

[ICC.1:2022 Annex F.1(a)](https://www.color.org/specifications/ICC.1-2022-05.pdf)를 다시 확인했습니다. 끝점 1을 실제로 포함하는 평탄 역상에서는 가장 작은 x를, 그 외에서는 가장 큰 x를 선택합니다. preimage_choice.select는 **이미 구한 완전한 연결 역상 구간**에 이 규칙을 적용합니다.

- 끝점 1을 포함하면 왼쪽 끝을 선택합니다. 그 끝이 열려 있으면 UnattainedIccPreimageMinimum입니다.
- 그렇지 않으면 오른쪽 끝을 선택합니다. 그 끝이 열려 있으면 UnattainedIccPreimageMaximum입니다.
- `[0,1)`은 끝점 1을 포함하지 않으므로 최대값 부재이지, 최소값 0을 고르는 말단 평탄 구간이 아닙니다.
- 실제 최대/최소가 없을 때 상한/하한을 반환하지 않습니다. 이 오류 이름은 명세에 직접 정의된 이름이 아니라 실수 구간에서 달성되지 않는 선택을 표현하는 구현 계약입니다.

이 선택기는 곡선 자체의 비상수성·단조성을 인증하지 않으며 최근접 y를 찾지도 않습니다. 기존 샘플 역변환은 전체 배열 검사·상수 거부를 유지한 뒤 닫힌 평탄 역상에 이 공통 선택기를 호출합니다. 샘플 곡선에 대한 기존 [역변환 계약](icc-sampled-inverse.md)은 유지합니다.

## 검증

네이티브 검사는 최대 u256 분수의 교차 곱, 열린/닫힌 접점의 교집합 네 조합과 순서 반전, 빈 교집합과 잘못된 입력의 구분, 열린 최대/최소 부재, u128 최대 분모의 항등/감소 역상, u128을 넘는 결과 분모, 열린 선형 끝점에서만 목표값에 도달하는 경우, 클리핑 평탄 구간과 상수·범위 밖 교점을 포함합니다.

독립 JS 기준은 제품의 반구간 교집합 알고리즘을 복제하지 않습니다. 0/1/목표 수준의 임계점과 그 사이 열린 구간을 열거하고, 각 점과 구간 내부에서 원래 선형 식을 BigInt로 계산한 뒤 일치하는 조각을 합칩니다. 이 조각들이 연속된 하나의 역상인지도 확인합니다. 반환 분수는 교차 곱 비교 전에 양의 분모·정규화 범위를 확인하여 0/0이 같은 값으로 통과하지 않게 합니다.

WASM mode193은 76바이트 BE 입력(활성 시작/끝 n/d u64 네 개, 포함 flags u32, a/b i32, 목표 n/d u128)을 받습니다. 출력은 136바이트 LE로 존재 u32·flags u32·시작/끝 n/d u256 네 개입니다. null은 전부 0입니다. mode194는 끝점 n/d u256 네 개와 flags u32의 132바이트 BE 입력으로 선택값 n/d u256 LE 64바이트를 반환합니다. 제품 JS API에는 새 모드를 노출하지 않습니다.

정규화 샘플 역변환과 새 검사가 u256 wire 읽기를 같은 테스트용 도우미에서 공유합니다. 기대값 계산은 제품 생성기나 serializer로부터 만들지 않습니다.

## 실행 기록

공통 타입·선택기 연결 후 기존 네이티브 520개가 통과했고, 새 검사를 추가한 실행은 5/5 단계·526/526로 통과했습니다. 초기 직접 WASM 결과는 comparisons=1947, empty=5110, rejected=2626, chosen=1330, unattained=662였습니다. 기존 정규화 샘플 역변환도 비교 905건·거부 5808건으로 통과했습니다.

최종 검토에서 반환 0/0의 정상화 검사, 약분하지 않은 최대 u256/최대 u256 끝점, 선택기 자체의 잘못된 좌표를 보강했습니다. 새 직접 대조는 comparisons=1947, empty=5110, rejected=2655, chosen=1337, unattained=674로 통과했습니다. 반환 분모를 0으로 지우기, 열린 끝점을 닫힌 것으로 바꾸기, 큰 결과 분모의 상위 바이트를 잘라내는 임시 변형을 각각 ERR_ASSERTION으로 검출했습니다. 제품에는 변형을 남기지 않았습니다.

초기 Debug 실행은 위 검증기 보강 전 이력으로 구분합니다.

실제 시스템 Display P3·ITU-2020·ITU-709·ROMM RGB의 type3 r/g/bTRC 태그 12개에서 원시 c/d를 읽어 하위 선형 구간 `[0,d/65536)`을 구성했습니다. 시작점·중간점 출력은 정확한 한 점 역상을, 제외된 끝점의 출력은 null을 반환했습니다. 읽기 전용 역상 비교 36건과 한 점 선택 24건이 일치했습니다. 이 수동 건수는 정규 감사에 합산하지 않으며, 상위 거듭제곱 분기의 기여분이나 전체 곡선 역변환 검증으로 확대하지 않습니다.

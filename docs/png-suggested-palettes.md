# PNG sPLT 추천 팔레트

## 지원 계약

`image.png_suggested_palette.parse(payload)`는 [PNG Third Edition §11.3.4.4](https://www.w3.org/TR/png-3/#11sPLT)의 이름·샘플 깊이·RGBA/빈도 항목을 해석합니다. 샘플 깊이는 8/16, 항목 너비는 각각 6/10바이트입니다. 빈도는 깊이와 무관하게 big-endian u16입니다. 원본 순서와 값을 보존하며 정렬·스케일 변환·알파 적용을 하지 않습니다.

항목 배열의 부분 잘림과 증가하는 빈도를 거부합니다. 같은 빈도·반복 색상·0 빈도는 허용합니다. 모두 0인 빈도는 사용 비율의 근거가 되지 않으며 오류가 아닙니다. 명세의 any number와 배열 배수 조건에 따라 0항목도 허용하고 empty_palettes로 구분합니다. sPLT에는 PLTE의 256개 제한을 적용하지 않습니다. 모든 이미지 색상 유형에서 사용할 수 있으며 이미지 비트 깊이·색상/알파 범위·PLTE 항목 수로 추천 팔레트를 제한하지 않습니다.

팔레트 이름은 기존 PNG 키워드 규칙을 재사용합니다. 파일 내 이름은 바이트 단위 대소문자 구분으로 고유해야 합니다. [청크 순서 표](https://www.w3.org/TR/png-3/#5ChunkOrdering)에 따라 첫 IDAT보다 앞에 있어야 하지만 PLTE 전후는 모두 허용합니다.

이 검사는 추천 팔레트의 구조·필드·순서·이름 고유성 범위입니다. 실제 픽셀 사용 비율, 색공간 일치/변환, 양자화·렌더링·편집·저장을 검증하거나 구현하지 않습니다. HWP 이미지 스트림 연결과 제품 JS 팔레트 API도 별도 미완료 범위입니다.

## 책임·수명·SSOT

- `suggested_entry.zig`: 깊이에 따른 항목 너비와 5개 unsigned 값의 wire 해석.
- `suggested_palette.zig`: 키워드 공유, 항목 배수 검사와 비증가 빈도 검사, borrowed Value/count/get.
- `suggested_palettes.zig`: 파일 전체 이름 인덱스와 IDAT 순서, 성공 통계.
- `pixels.zig`: 기존 청크 순회 중 Collector 호출과 종료 시 해제, scalar 보고서 조립.

Value.name/raw는 입력을 빌립니다. get은 인덱스를 검사해 범위 밖이면 null을 반환합니다. 항목 배열을 새로 할당하지 않습니다. 이름 Collector는 해시 인덱스만 소유하고 이름 bytes는 빌리므로 deinit까지 입력을 변경·해제하지 않아야 합니다. PNG 검사 종료 후에는 이름 포인터를 보고서에 남기지 않습니다.

고유 이름 검사 때문에 필요한 할당 수명은 별도 Collector가 소유합니다. 기존 비할당 metadata.State에 소유 버퍼를 추가하지 않습니다. 같은 PNG를 별도로 재탐색하지 않고 pixels의 기존 순회를 공유합니다. 중복/순서/항목 오류와 할당 실패는 전체 PNG 검사에 전파하며, 통계는 검사·checked 합산·이름 등록이 모두 성공한 뒤에만 갱신합니다.

Report.suggested_palettes는 청크 수·이름 바이트·총 항목·8비트 항목·16비트 항목·0 빈도 항목·빈 팔레트·원본 payload 바이트를 가집니다. 검증한 청크/원본 payload만 ancillary deferred에서 차감합니다. 해시 인덱스 크기는 이름 수에 비례하고 항목 검사는 입력 길이에 비례합니다. PNG 파일·청크 크기·청크 수 한도는 기존 구조 옵션을 재사용합니다.

## 검증

네이티브는 깊이 0..255, 헤더/항목 잘림, 빈 팔레트, 1024항목, u16 전체 65,536개 값을 RGBA와 빈도에서 확인합니다. 빈도 경계 쌍·같은 이름/다른 깊이·대소문자 구분·IDAT 뒤 배치·통계 오버플로·이름 인덱스 확장 시 모든 할당 실패와 뒤늦은 중복 오류 정리를 검사합니다.

테스트 전용 WASM mode 140 입력은 PNG이며 외부 limit는 PNG 입력 한도입니다. 출력은 위 8개 통계와 deferred 청크/바이트의 10개 u32 LE입니다. 이후 팔레트마다 깊이·이름 길이·항목 수(u32 LE 각각), 이름 원문, RGBA와 빈도 5개 u16 LE를 항목 순서대로 붙입니다. 8비트 샘플은 값만 u16로 넓히며 스케일을 곱하지 않습니다. 제품 JS ABI는 바뀌지 않습니다.

독립 JS는 Buffer BE 읽기·이름 원문 Set·항목 배열로 기대값을 만들며 제품 파서·해시맵을 재사용하지 않습니다. 초기 합성 정상 10,148건·거부 12,104건, 바이트 변형 11,264건을 비교했습니다. 다섯 이미지 색상 유형, PLTE 전후, 서로 다른 팔레트 1024개, 미지원 청크 보류, 입력 한도/실패 후 회복도 포함합니다. 이후 첫·중간·마지막 이름 재삽입과 79바이트 이름의 마지막 글자 경계를 보강한 전용 WASM 실행은 정상 10,149건·거부 12,107건이 일치했습니다. HWP 미리보기 PNG 32개는 통과했으나 그 안의 sPLT는 0개였습니다.

최종 코드로 Debug·ReleaseSafe·ReleaseFast 전체 회귀를 순차 실행해 각각 17/17 단계, 네이티브 391/391 테스트, HWP5 감사 스크립트 3,742,392 checks를 통과했습니다. 세 모드의 전용 결과도 정상 10,149건·거부 12,107건으로 일치했습니다. 로그는 `/tmp/hwpjs-png-suggested-{Debug,ReleaseSafe,ReleaseFast}.log`입니다. 전체 PNG/HWP 명세나 렌더링까지 완료했다는 의미는 아닙니다.

추가 수동 적대적 검사에서는 비정렬 위치에서 시작하는 16비트 sPLT 항목의 RGBA/빈도 5개 필드에 0..65535를 각각 대입해 WASM 결과를 전수 확인했습니다. 65,536개 입력 모두 길이·항목 수·다섯 u16 값이 기대값과 일치했습니다. 정규 audit 집계에는 포함하지 않습니다. 관련 로컬 문서 링크 48개와 변경 JS 문법·Zig 포맷·diff 공백 검사도 통과했습니다.

필드 위치 편향도 별도로 확인했습니다. 나머지 네 필드를 서로 다른 고정값으로 채우고 한 필드씩 0..65535를 변형하는 327,680개 추가 WASM 입력에서 다섯 반환값을 모두 비교했습니다. 필드 교환·동일 값 재사용을 놓치지 않도록 한 검사이며 모두 일치했습니다. 이 수동 검사 역시 정규 audit 집계와 구분합니다.

### 외부 PNG 양성 교차 검증

[PngSuite 미러의 고정 커밋](https://github.com/lunapaint/pngsuite/tree/8cd768dd0d0063195174d0d01cacbd5a7d1e5605/png)에서 다음 네 파일을 메모리로 읽어 mode 140 원문/필드와 mode 130 픽셀 보고서를 독립 JS와 비교했습니다. 모두 일치했습니다. 파일마다 이름 8바이트, 항목 216개이며 빈도는 모두 0입니다. 이미지 깊이와 sPLT 깊이가 다른 사례도 포함합니다. 실제 HWP의 sPLT 사례와는 구분합니다.

| 파일 | 파일 바이트 | sPLT 깊이 | SHA-256 |
|---|---:|---:|---|
| ps1n0g08.png | 1456 | 8 | `b321b9ac8f2aa641475b6936365954181726dcb8662dbf641284d82a83cc22a5` |
| ps1n2c16.png | 1620 | 8 | `6c59d673032fe2d04dbd2ea91cc9bc7bebe7d5ab84911f00e36fb28994793576` |
| ps2n0g08.png | 2320 | 16 | `bd2ae1b45fd771aaa8c57dccd183f3834fc9742f6dfc692606865049efb116e5` |
| ps2n2c16.png | 2484 | 16 | `120c62ce9d014f7772c4b38a446991b5bbe6a22ef5ea59239d32e023bc167585` |

외부 이미지는 저장소 의존성이나 fixture로 추가하지 않았습니다. 이 수동 실행은 정규 audit 집계에 포함하지 않으며 기본 audit는 네트워크를 사용하지 않습니다.

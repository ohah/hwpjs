# hwpjs

HWP/HWPX 읽기·편집·저장을 목표로 하는 Zig/WASM 프로젝트입니다.
현재 CFB v3/v4 읽기·명세 검증·스트림 편집 후 새 컨테이너 저장을 지원합니다. **HWP/HWPX 전체 문서 모델·레이아웃·본문 편집·저장은 아직 구현되지 않았습니다.**

HWP5 FileHeader·압축 스트림·레코드 경계 읽기와 DocInfo 문서 속성·ID 매핑·BinData·글꼴·탭 정의·문단 번호·글머리표·스타일·테두리/배경·글자 모양·문단 모양 해석, 주요 리소스 개수·알려진 활성 참조 검증은 Zig 코어에 구현했습니다. 구역 정보가 필요한 참조와 미지원 유형은 검증 보류로 구분합니다.
지원 범위와 적대적 검증 5회 기록은 [HWP5 기반 구현](docs/hwp5-foundation.md)을 참고하세요.
HWP5 본문은 문단 헤더·UTF-16 텍스트/제어문자 토큰·글자 모양 구간·줄 캐시·영역 태그를 해석합니다. 레코드 계층 인덱스와 문단 직접 자식 연결을 통해 개수·위치·글자/문단 모양·스타일 ID를 검증합니다. 논리적 리스트/개체 연결·렌더링은 별도 단계이며 미검증 항목을 보고서로 구분합니다.

컨트롤 ID와 리스트 기본 헤더도 읽습니다. 리스트의 명세 6바이트/관측 8바이트 배치는 명시적으로 선택합니다. 같은 부모의 리스트 그룹·문단 수를 검증합니다.

구역 정의·용지·쪽 테두리·각주/미주 모양을 해석하고 구역 소유권·개수·참조를 검증합니다. 주석 문단/번호와 구역 번호 ID 0의 의미는 아직 남아 있습니다.

확장 텍스트 제어문자와 컨트롤 헤더는 같은 문단 내 순서/ID로 연결하고, 알려진 ID의 제어코드 종류를 검증합니다. 미등록 ID는 보류로 구분하며 개별 컨트롤 속성 검증은 별도입니다.

단 정의는 동일 너비/가변 너비 배치와 개별 너비·간격을 보존하고 개수·부모·잘림을 검증합니다. 실제 단 레이아웃 계산은 아직 별도입니다.
표·그리기·수식의 공통 속성은 위치·크기·여백·설명 원문과 미지 꼬리를 읽습니다. 설명 부재와 빈 문자열을 구분합니다. 표 본체·셀·캡션은 소유권·셀 수·병합 범위·영역 좌표·알려진 테두리 참조와 셀 겹침·논리 격자 채움·행별 분포를 검증합니다. 확장 꼬리·개별 도형과 실제 배치는 아직 별도입니다.
아직 제품 JS/WASM 공개 API에 HWP 문서 파싱 기능을 추가한 단계는 아닙니다.

셀의 여백 지정·보호·제목·편집 가능 플래그와 관측 꼬리의 텍스트 폭/표시값도 별도 뷰로 읽습니다. 공통 ParameterSet 파서는 중첩·관측 배열·문자열 경계와 자원 제한을 검사하고, 별도 셀 필드명 API가 직접 자식의 이름 타입/중복을 검증합니다. 캡션 미지 꼬리와 문서 전체 참조 연결은 아직 남아 있습니다.
ParameterSet 소스 검사기는 DocInfo/본문/표 셀에서 파싱·바이너리 참조 검증을 수행하고 미지원 타입·미지 꼬리·남은 바이트를 별도 집계합니다.
`hwp5.document_validation.inspectDecoded`는 압축 해제된 DocInfo·구역에 기존 검사기를 연결하고 구역 수/인덱스·전역 바이트/레코드 한도를 검증합니다. 보고서는 구역 순서와 개별 보류 항목을 유지합니다.
`hwp5.container_validation.inspect`는 CFB 파일 바이트에서 필수 스트림을 정규 경로로 조회하고, DocInfo·구역·내부 BinData를 한도 내에서 압축 해제해 검증합니다. 외부 링크는 열지 않으며 미지원 BinData 유형과 아직 검사하지 않은 스트림 수를 보고합니다. 그림/OLE 자체의 의미 검증과 전체 HWP 기능 지원을 뜻하지 않습니다.
선택적인 루트 `PrvText`도 UTF-16LE 구조를 검사합니다. 길이 오류는 거부하고 고립 서로게이트는 원문 보존·별도 진단하며, 텍스트 부재와 빈 텍스트를 구분합니다. HWP 단일-set 요약 정보는 속성 경계·중복·Unicode 문자열·정수·FILETIME을 해석합니다. dictionary/미지원 타입은 보류하며 일반 OLEPS 전체 지원은 아닙니다. 미리보기 이미지 등은 아직 미검사 범위입니다.
요약 코드페이지가 명시된 경우 VT_LPSTR의 바이트 길이/종결/패딩과 dictionary 항목 경계·ID 중복도 검사합니다. 코드페이지 부재는 추정하지 않으며 문자 변환·dictionary 이름 의미 검증은 별도입니다.
`Scripts/JScriptVersion`과 `Scripts/DefaultJScript`는 bounded 압축 해제 후 버전 원값·네 UTF-16 문자열 경계·종료 표식을 검사합니다. 추가 바이트는 별도 보고하며 JavaScript 문법·실행·안전성 검증은 하지 않습니다.
XMLTemplate은 이미 압축 해제된 세 문자열 입력의 길이·총 한도·부재·꼬리를 해석하는 코어까지 구현했습니다. 합성 자료로 검증한 단계이며 실제 CFB 연결·XML 문법/스키마 검증은 아직 미구현입니다. `_LinkDoc`는 공개 명세에 필드 배치가 없어 원문 보존·미검사 상태를 유지합니다.
DocHistory는 decoded VersionLog의 별도 레코드 경계·시작/끝·포함 비트를 검사합니다. 명세와 관측 시작 필드 순서는 명시적으로 구분하며 실제 이력 4항목으로 대조했습니다. 암호화·날짜 의미·DiffML/HWPML·최종 문서 연결과 파일 단위 자동 검증은 아직 남았습니다.
DocInfo 호환 문서·레이아웃 호환성은 대상 프로그램과 다섯 DWORD, 레벨·최소 길이를 검사합니다. 미지 대상값·비트·확장 꼬리는 보존하며 레이아웃 동작 자체를 검증한 것은 아닙니다.
문서 단위 검사에서는 레이아웃 호환성 레코드가 호환 문서 루트 그룹에 속하는지도 확인합니다.
머리말·꼬리말은 관측 컨트롤/리스트 분리 배치의 속성·영역 필드와 소유 리스트를 검사하고 구역 보고서에 진단을 반환합니다. 실제 페이지 배치와 참조 비트의 의미 검증은 남아 있습니다.
자동 번호·새 번호 지정의 저장 필드와 예약 번호 종류도 검사합니다. 자동 번호는 실제 32개와 대조했으며 새 번호 지정은 합성 검증 단계입니다. 번호 순서 재계산·렌더링은 아직 구현하지 않았습니다.
쪽 번호 위치도 속성·네 문자 원값을 검사합니다. 실제 표본의 마지막 문자 0과 명세의 '-' 차이는 별도 진단하며 원본을 바꾸지 않습니다.
찾아보기 표식은 두 키워드의 길이·원문·dummy를 해석합니다. 현재는 합성 검증 단계이며 실제 찾아보기 생성·페이지 연결은 미구현입니다.

본 제품은 한글과컴퓨터의 글 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다.

## 시작하기

Zig 0.16.0을 사용합니다 (`mise install` 또는 별도 설치).

```sh
zig build test
zig build -Doptimize=ReleaseSafe
zig build compare -Doptimize=ReleaseSafe
zig fmt --check build.zig src
```

`zig-out/bin/hwpjs.wasm`은 외부 import 없이 CFB 읽기·쓰기를 제공합니다. JS 비교 검증에는 Node 24를 사용합니다.
Zig/JS API와 자원 제한·검증 범위는 [CFB 읽기·쓰기](docs/cfb-reader.md)를 참고하세요.

## 디렉터리

| 경로 | 역할 |
|---|---|
| `src/` | 신규 Zig 구현과 WASM 진입점 |
| `js/` | 브라우저/Node 읽기·쓰기 API, 메모리·엔트리·편집 모델 변환 어댑터 |
| `tests/cfb/` | 레거시 JS 비교와 브라우저 검증 |
| `docs/` | 현재 설계·개발 안내 |
| `legacy/rust/` | 이전 Rust 코어, JS/RN 래퍼, 예제, 문서, 테스트, 실험 |
| `legacy/`의 기존 파일 | 초기 JS 구현 — 기존 위치 유지 |
| `reference/` | 외부 참고 소스, Git 추적 제외, 제품 의존성 아님 |

Rust 구현 실행은 `cd legacy/rust` 후 기존 Cargo/Bun 명령을 사용합니다.
자세한 이동 내역과 CI 변경은 [전환 기록](docs/migration.md), 새 구조는 [설계](docs/architecture.md)를 참고하세요.
